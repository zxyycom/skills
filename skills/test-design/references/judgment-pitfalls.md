# 易错判断集

本文件用于[主流程](../SKILL.md#主流程)中投入裁决前的校准。

以下反例区分容易混淆的裁决，不是逐条补测清单。维护时只增加能改变判断的新边界，合并重复情形；效果验证使用未收录的材料。

1. **关键契约必须自动化。** 某关键 GUI 行为只能用昂贵且脆弱的环境验证，仍要求补齐自动化。
   契约重要不等于投入划算；无硬性验收要求且风险取舍获授权时，可以明确不自动化。出现低成本可靠入口或新的强制要求时重新判断。
2. **便宜就值得保留。** 一个稳定、瞬间完成的测试锁定无消费者依赖的私有计数，因开销小便长期保留。
   低成本不能代替保护价值；有具体资源、兼容或消费依据才考虑锁定，否则可移除。
3. **测试有缺陷就必须修。** 发现某条断言失效，立即设计更强探针，却未判断所测行为是否值得投入。
   先裁定目标；不投入则结束为不新增或移除，只有入选后才修复。不能把无效测试改得更复杂当作审查成果。
4. **把局部测试扩成全链路证明。** 验证状态计算函数的幂等性，却因其结果最终用于文件更新，要求同条测试再监视写入。
   按计算函数自身契约验证幂等；执行副作用另属执行函数，缺少其断言不构成本条测试的缺陷。
5. **相同输出就是重复。** 规则测试与参数映射测试都返回成功，就删去其中一个；反过来，同一矩阵经重入口重复运行又全部保留。
   先核对保护点。计算与接线可以各有价值；同一责任的等价样例则选择代表，独有参数解释仍在所属层验证。
6. **能辨错就证明必要。** 为每条断言构造一个能使其失败的实现，再据此保留全部断言。
   辨错只证明有效性；还须说明该类错误的影响及为何值得自动拦截，条款或可构造错误数量不决定投入。
7. **为精简删掉有价值的唯一保护。** 关键恢复行为有稳定、低成本的测试，却因想减少数量而删掉关键观察，只剩成功返回。
   此时应保留有效保护；只有目标不再值得投入、明确接受风险或有合适替代时才改变裁决。不设删除配额。
8. **把未调查清楚当成无必要，或反过来。** 未读完就判删；事实已清楚却提不出投入理由，又以“待确认”原样保留。
   前者标明具体未决事实，不能判删；后者属于举证不成立，应作不投入或精简裁决，不能用未决代替取舍。
9. **正确预期照搬当前实现。** 规则要求“小于 100 才通过”，源码使用 `<= 100`，测试手写“100 应通过”；或保存未经审核的当前快照。
   入选目标的预期仍需独立依据，用契约校准等于阈值时的结果。只有当前输出时可以刻画行为，不冒充正确性证明。
10. **混淆协议与内存表示。** 文件契约要求字段有序，测试却断言解析后 JS 对象的 `Object.keys` 顺序。
   文本格式由解析或序列化层验证；解析器改变属性构造顺序不应使业务测试失败。
