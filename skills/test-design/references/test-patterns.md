# 测试范式

本文件用于已决定投入的保护点，按需选择设计方法。投入裁决与判断校准分别由[主流程](../SKILL.md#主流程)和[易错判断集](judgment-pitfalls.md)承接。

## 设计与实现要点

选择证明充分、总成本较低的现有入口，层级作为默认参考；已有上层测试更简单、稳定且成本可接受时可以保留。

| 待证明的责任 | 默认边界 |
| --- | --- |
| 规则、状态计算、文本转换、解析与组合矩阵 | 纯函数或领域 API |
| 实际文件读写、路径身份、权限与恢复 | 必要的真实文件系统 |
| Git index、历史、锁或跨进程语义 | 隔离的真实 Git／进程 |
| 参数解析、输出、诊断与退出结果的接线 | CLI；参数矩阵可在等价入口下沉 |
| 制品启动、模块解析及安装位置 | 真实制品和目标运行时的代表性 smoke |

- 替身控制非目标依赖，目标行为仍实际执行；替身假设由真实边界证据或依赖契约支持。利用已有职责分离，不为降层擅自重构生产代码。第三方通用机制仅在具体兼容风险或上游 Bug 需要保护时补测。
- 输入能区分目标错误：排序有乱序，过滤有命中与干扰，消歧有冲突。同一等价类先选代表，规模只跨过目标边界。
- 预期来自契约、独立算例、经审核的 fixture 或独立模型；观察聚焦当前责任，允许无关细节变化。数量、存在性或配置透传可充分证明相应限定责任。
- 负向场景从健康基线改变目标因素，观察对应失败原因及本层受保护状态；来源、身份或真实环境属于目标时经过相应入口。
- 名称、helper 和断言表达实际范围，独立意图按原生节点组织。被测对象可能捕获 callback、getter 或 hook 异常时，按[回调与失败传播](#回调与失败传播)确保失败能传到运行器。
- 控制无关环境，共享只读材料，隔离可变资源；等待实际完成并回收资源。随机反例可复现且不泄露敏感数据。

## 规则与边界矩阵

适用于阈值、过滤、排序、解析和参数组合。

- 阈值样例应能区分 `<` 与 `<=`。
- 每个样例尽量让目标条件单独决定结果，使遗漏该条件能被识别。
- 参数化行保留名称、输入和独立预期；只组合有真实交互的维度。
- 矩阵集中在规则所属层；上层只展开其自身解释、选择或映射会改变结果的维度。

例如“总耗时、P90、均值都必须低于各自上限”：分别构造只有一项达到或超过阈值的数据，直接断言判定及具体违反项。

### 准备复用与独立执行

矩阵包含昂贵准备或进程启动时，按状态契约选择隔离粒度：

- 复用与变化维度无关的准备工作，每行仍执行目标操作、重置观察器并建立独立初态；有意保留状态时，明确表达状态序列。
- 冷启动、首次加载、跨进程身份或缓存失效属于目标时，保留相应的新进程或状态变化。确定性或重复调用测试实际调用多次，不用一次结果的自比较替代。

例如只验证每次读取配置的规则时，可在一个隔离进程内执行“合法 → 多个非法 → 合法”的矩阵，每步实际读取当前输入；这不证明每种配置都能在新进程中正确启动。

## 回调与失败传播

适用于被测对象会捕获、转换或忽略 callback、getter、hook 异常的场景。

- 回调记录实际输入、结果或调用轨迹，外层验证必要观察确实发生及其内容；流程完成与内部操作成功分别检查。
- 异常保证传到运行器，或外层精确结果必然拒绝内部断言失败时，可以保留回调内断言。
- 本条直接承担“未调用”约束时，使用外部可观察的记录或计数。例如 getter 内仅抛错可能被捕获并转成预期的拒绝结果，零调用计数才直接观察该约束。
- 故障注入中的抛错是被测输入：记录故障命中，再在外层检查目标失败原因和状态保护。

## 状态转换、失败保护与恢复

适用于更新、缓存、事务、快照和生命周期。

按被测函数或组件的职责选择观察。

执行与恢复测试以“合法初态 → 动作或故障 → 目标终态＋本层不变量”组织：

| 契约 | 有区分力的观察 |
| --- | --- |
| 只更新所选对象 | A 发生预期变化；未选择且具有可辨认内容的 B 保持不变 |
| 刷新不改变已绑定快照 | 新读取获得新值；旧 reader 仍获得旧值 |
| 重复操作幂等 | 对同一状态转换重复应用，检查结果稳定 |
| 写入失败可恢复 | 目标错误被报告；文件内容、成员或权限等受保护状态按契约保持或恢复 |

在声明的阶段注入故障并确认命中；区分提交前回滚、提交后清理待完成和无法确认的部分状态，更早的初始化错误不构成目标恢复证据。

按恢复契约选取内容、成员或权限等观察；对象存在本身不能证明内容完整。

## 并发与时序

适用于锁、取消、竞争、超时和跨进程协作。

- 明确参与方和关键事件，用屏障、受控 Promise、可观察的锁持有或协议事件构造目标交错。
- 保留契约所需的真实边界：同进程 `Promise.all` 不能自动证明跨进程锁，fake clock 不能证明操作系统锁释放。
- 验证允许的结果集合与不变量，为等待设置有界失败及参与方清理。超时用于限定等待和诊断，性能结论需要相应测量。
- 重复运行用于发现不稳定，不能穷尽所有交错；报告实际观察范围。

## 性质、变形关系与独立模型

适用于输入空间较大、存在稳定不变量或关系，但手写完整结果困难的场景。

- **性质测试**：生成满足前置条件的输入，检查领域不变量；对生成与执行设置预算，失败时缩减并保留可复现反例。
- **变形关系**：依据契约确定输入变化与结果的关系。例如契约保证局部性时，增加无关对象不改变所选对象的查询结果；有序或有状态操作的交换律需要单独依据。
- **独立模型或差分**：用更简单、独立实现的可信模型或已知兼容参考进行比较，并说明模型覆盖范围。复制生产算法或调用同一 helper 不构成独立依据。

性质或关系只证明所选保护点：幂等性不证明每次转换结果正确，编码／解码往返可能两端错误抵消，两个实现也可能同错。需要锁定具体计算结果时使用独立预期；重要反例固化为稳定回归输入。

没有现成框架时，优先使用有界表驱动或确定性生成。

## 快照、输出与结构断言

适用于序列化协议、CLI 输出、生成文件和渲染结果。

- 按消费者依赖选择稳定字段、顺序和格式。结构化结果优先比较目标结构，整段快照用于整体输出值得审阅和维护的契约。
- 规范化只移除无关噪声；被测顺序、错误字段和对象完整性保持可见。
- 根据独立契约解释快照差异，再接受新预期。
- 文件内容本身是产物契约时检查源码文本；运行行为通过执行观察，而非匹配函数名、语法或 import 写法。

例如验证图输出的归属关系时，可以断言节点、边及其所属块；只有字节级兼容确有消费者时，才要求整段输出逐字相等。

## 性能政策、工作量与真实测量

先确定要证明哪一种目标，分别选择证据：

| 目标 | 合适方法 | 证据边界 |
| --- | --- | --- |
| 性能政策判断正确 | 构造测量值，测试阈值、统计口径、缺失与非法样本 | 只证明政策判断，不证明真实系统满足预算 |
| 已声明的工作量或增长约束 | 在稳定的 I/O、访问或协议边界计数，比较规模／结构变化，同时检查结果 | 有限样例不等于任意输入上的复杂度证明或实际提速 |
| 真实容量、延迟或吞吐 | 明确运行时、硬件、负载、冷热状态、采样与判定预算的基准或集成测量 | 结论限于测量条件，不替代功能验证 |

功能测试的规模只需跨过真实分页、批次或其他路径边界。选择小阈值注入时确认仍走同一逻辑；固定生产上限本身是契约时保留对应边界证据。

工作量测试优先观察被保护的资源操作；patch 语言内建方法并锁定次数会耦合具体集合算法，精确计数须有契约依据。计时失败应区分环境噪声与性能回归。

## 针对性变异与回归敏感性

在缺陷影响较大或辨错证据存疑，且预期收益值得额外成本时使用。

可选旧缺陷版本对照或目标变异。前者确认旧版因目标断言失败、修复后通过；后者按以下步骤执行：

1. 从目标错误选一个小变异，例如把边界改错、跳过过滤、返回旧值或省略必要恢复；不追求无关变异数量。
2. 在隔离副本或安全可恢复的授权范围运行，保护共享工作区已有改动。先确认未变异基线通过，再确认变异版本因目标断言失败，而不是语法、依赖或初始化失败。
3. 恢复后重跑并核对文件状态。无法隔离或恢复时仅做静态反事实审查，明确没有取得执行证据。
4. 存活变异需要判断是否等价、不可达、超出契约或确实暴露缺口；不为提高分数追加无意义测试。

版本对照或目标变异提供辨错执行证据，不替代契约依据，也不证明覆盖完整。
