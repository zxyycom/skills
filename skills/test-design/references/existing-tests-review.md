# 存量测试审查 SOP

用于判断指定范围的现有测试应保留、精简、降级还是退出。采用[共同准入原则](../SKILL.md#共同准入原则)，从空的准入集合逐项建立有据可查的保留结论。

## 1. 确定范围与待审清单

按用户范围和项目原生入口盘点候选，包括参数化场景与被共享 helper 实际建立的检查；说明静态声明、展开场景和执行节点的计数口径。只审查与取舍有关的共享材料，不因调用关系扩大全仓范围。

全部候选初始为待审。复用现有清单，在当前任务中保留候选定位、状态和裁决依据；不要求固定文件格式、专用数据库或长期账本。读取过、执行通过或已有 Case 均不改变待审状态。

## 2. 恢复实际锁定内容

对照实际测试体、helper、输入和断言，恢复每个候选的责任、独立预期、全部锁定内容及准备和运行边界。有效性有疑问时再按收益选择针对性验证；静态审查不冒充执行。

原生节点是定位入口，不是整体保留的理由。区分有价值的观察与附带约束：一条关键断言不能替其他场景、精确文本、规模或执行成本取得资格；必要时拆到场景或观察裁决，不要求逐行撰写长证明。

## 3. 举证并构造保留集合

逐项应用三项门槛，按[准入结果与处置](../SKILL.md#准入结果与处置)更新状态及依据。只有三项依据均成立者才加入最终保留集合；未审和未决留在未完成范围。

同一依据确实覆盖多个候选时可以成组举证，但须明确成员及共同依据，并逐一确认适用；独有锁定内容另作判断。目录或模块分组只是组织方式，不是准入依据。

缺陷清单只说明不准入的一部分，不能生成剩余项的保留结论。即使所有文件都已读取，也须完成各候选的三项裁决；抽查仅用于核对裁决质量，不替未审项取得资格。

## 4. 处置与复核

按裁决确定当前形态的处置；不准入项可无替代退出。精简、降级或替代方案另按[测试设计 SOP](design-workflow.md)举证，分别报告旧形态退出与新方案准入。

按[误删复核要求](../SKILL.md#执行与交付边界)复核。声称“其他检查已承接”时，须指向最终确实保留且具有相应证据能力的检查，避免互相引用待删项。

如任务已委派，交接须包含已审成员、保留依据、不准入与未决；汇总方核对这些内容与原范围，而不只合并问题清单。复核发现成组依据不适用时，重审受影响成员，不只修正抽中的一个。

按授权停在只读裁决或执行处置；实施后验证实际变化并重新核对受影响候选的准入，按实际状态交付。

## 5. 对账后交付

以完整裁决结果为主体，至少能从现有清单或交付内容追溯：

| 内容 | 要求 |
| --- | --- |
| 范围 | 清单覆盖请求范围，定位和计数口径明确 |
| 保留集合 | 每项均已裁决，有适用的三项依据；成组说明能还原明确成员 |
| 不准入与未决 | 各项有原因、处置或具体缺口，并说明保护变化和风险 |
| 实际工作 | 读取、裁决、改动和运行范围分别说明，新方案与旧形态分别计入 |

范围内候选全部完成裁决、保留项均具适用依据，才可全量结项。存在未审或未决时交付已完成部分与剩余范围。汇总数量仅供对账，不能替代判断。
