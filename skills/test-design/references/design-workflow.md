# 测试设计 SOP

用于功能开发、Bug 回归及具体测试改进。按[共同准入原则](../SKILL.md#共同准入原则)选择最小方案；此流程不要求盘点全部存量测试。

## 1. 明确保护点

从行为 owner、消费者或独立确认的缺陷恢复当前要处理的责任、错误风险与投入约束。已有实现时区分应有行为与当前行为，读取相关测试和设计，确认哪些保护已经存在。

## 2. 形成最小候选

明确候选的限定责任、区分性输入、独立预期及来源、实际观察、执行边界与准备方式。按需用[测试范式](test-patterns.md)比较可行方案，先选代表和必要边界，再考虑额外场景。

测试困难可能改变取舍时，按[设计反馈](../SKILL.md#设计反馈与重新裁决)比较实现与测试的整体得失。

## 3. 举证并选择

对具体候选应用[三项门槛](../SKILL.md#共同准入原则)，按[准入结果](../SKILL.md#准入结果与处置)裁决。方案比较聚焦会改变选择的差异。

不成立者退出，替代或改进方案重新准入；可行方案的成本不可接受时，可以不自动化。必要事实缺失则列明未决。

## 4. 实现与验证

方案任务交付可评估设计；实施任务在授权范围落地已准入方案，并按[执行与交付边界](../SKILL.md#执行与交付边界)验证。依据实际代码、fixture 或设计变化，重新核对受影响候选的准入。

## 交付与完成

- 拟建立或保留的候选：定位、限定责任与三项准入依据，可将判断相同的候选合并说明。
- 退出或未决的候选：原因、失去的保护、风险与具体缺口；实施任务另交代实际处置。
- 设计反馈及验证：实际变化、条件建议、已运行与未运行范围分别说明。

已提出候选均有裁决，拟建立或保留者均有适用依据，交付深度符合方案或实施授权，方可按本次范围完成。
