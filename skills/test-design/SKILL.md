# Test Design

## 目标

选择经得起举证的关键、必要、低成本测试。建立与保留都须通过准入；现有测试、Case 声明和历史覆盖率不授予保留资格。重要契约也可以不自动化，契约本身仍然有效。

## 任务路由与读取

按任务意图选择 SOP，而不是按是否改动旧测试区分：

| 任务意图 | 必读 SOP | 完成结果 |
| --- | --- | --- |
| 为功能、Bug 回归或具体测试改进设计方案 | [测试设计](references/design-workflow.md) | 最小候选及准入取舍；获授权时实现并验证 |
| 判断一批现有测试是否值得保留、精简或退出 | [存量测试审查](references/existing-tests-review.md) | 范围内全部候选的裁决，以及有据可查的保留集合 |

混合任务先划分范围，分别采用对应 SOP；存量审查产生的新方案，按设计 SOP 重新准入。

1. 读取项目约定、行为 owner、消费者及相关实现和测试，核对 diff、范围、授权与明确的自动化要求。
2. 读取所选 SOP；举证前读[易错判断集](references/judgment-pitfalls.md)，校准职责、成本与误删边界。
3. 形成、比较或实现候选时，按需读[测试范式](references/test-patterns.md)的相关章节。方法比较可以先于准入，详细实现只投入已选方案。

## 共同准入原则

候选是具体测试方案或现有测试形态。先说明其自身要保护的责任、输入和观察；契约由行为 owner 确定，区分契约、当前行为与假设。源码、测试名称及 Case 自述用于恢复现状，不能自证正确或必要。

每条测试只在自身职责内举证；交互本身值得保护时另作候选。单条测试不必包办下游副作用，也不要求建立全链路证据组合。

每个候选同时通过三项门槛：

1. **有效性**：独立预期、关键输入和实际观察如何识别目标错误，失败能否传到运行器；保持契约的合理实现替换仍能通过。断言或替身只复述实现不成立。
2. **保护价值**：谁依赖该行为，错误影响和现实风险是什么；相对实际适用的设计约束与最终保留检查，增加什么值得自动拦截的保护。模块重要或可构造错误不足以成立。
3. **形态与开销必要性**：证明这些场景、断言、规模、准备及执行边界为何必要；比较现实可行方案的准备、运行、理解、变更、环境和不稳定性总成本，有更低成本且充分的方案时说明为何仍采用当前形态。有效且有价值，也不能豁免当前或拟建形态的举证。

依据落实到具体候选及其实际锁定内容。静态判断对照测试体或可评估的方案；关键有效性存疑时，按收益选择[针对性验证](references/test-patterns.md#针对性变异与回归敏感性)，或标明具体缺失事实。

## 准入结果与处置

| 结果 | 含义与处置 |
| --- | --- |
| 准入 | 三项均成立，当前形态可保留或新方案可建立；方案通过与实现已验证分别标明 |
| 不准入 | 事实已核对，任一项不成立；当前形态不保留，选择删除、精简、降级或退出自动化 |
| 未决 | 必要事实尚未核对，或所需决定超出授权；列明缺口，不计入已证明应保留 |

事实查清却提不出依据，判不准入。修复、精简、降级和替代方案都是新候选，须独立准入，不能作为旧形态继续保留的理由。

不准入可无替代退出，说明失去的保护及风险；人工检查等按需选择，不自动产生补测任务。硬性自动化要求交 owner 决定处置，不自行绕过，也不作为通过三项门槛的证据。

## 设计反馈与重新裁决

当准备过重、职责混杂或边界难观察，且实现调整可能改变准入结果时，比较保留现状、调整测试、退出自动化与有限实现调整：

1. 区分测试范围、价值不足、实现职责问题与固有复杂性；难测不自动证明设计有错。
2. 比较实现与测试的整体成本、行为与兼容性变化、新增状态或失败风险。行为或实现 owner 决定方案；生产改动按授权实施，契约变化先确认再改预期。
3. 实际变化后，仅对受影响候选重新准入，允许退出、降级或重设计，新风险同样举证。未落地方案只支持条件处置，不能计作已有保障。

反馈限于会改变当前测试取舍的实现问题，按授权交付当前结论与条件方案。

## 执行与交付边界

- **授权**：设计交付方案，只读审查保持被评估材料不变；实施按授权处置测试、fixture 和入口。删除、动态验证、生产改动、安装及外部调用服从当前授权。
- **误删复核**：核对真实产品缺陷、局部职责和不同责任，避免因失败、缺少职责外观察或输出相似而误删。声称保护已承接时核对实际保留项；不设删除配额，也不要求保护总量不减少。
- **执行验证**：获授权实施后运行目标、受影响的邻近测试及项目检查，核对 runner 选择、实际节点、意外 skip、异步完成与清理。修改后重新核对准入；产品缺陷与测试缺陷分别报告，首次失败须解释。
- **交付证据**：按所选 SOP 交付候选取舍及依据、处置与失去的保护、具体未决；分别说明读取、裁决、方案、实际改动和执行验证范围。静态判断、已有运行记录与本轮执行不相互冒充。
- **相邻 owner**：账本、覆盖率政策与 Gate 由项目管理。采用 `test-evidence-review` 时交接最终入口、实际证明范围和保护变化；本 skill 不自行新增账本或管理流程。

## 自更新

本 skill 的指令使用不需要安装依赖。仅在本 skill 目录运行自更新入口 `node scripts/update-skill.ts` 时，需满足随包 `package.json` 的 Node 版本与兼容依赖。
已有兼容宿主依赖即可复用；普通运行、导入与检查不自动安装。依赖不可用时，使用随包 manifest 固定的 pnpm 显式执行：

```bash
pnpm --dir "<skill-directory>" install --ignore-workspace --prod --frozen-lockfile --config.node-linker=isolated
```

运行时文件或 manifest/锁文件损坏时，重新获取完整 skill 后再安装并重试。更新覆盖正式包中的同路径文件、保留其余本地文件。源码更新成功不证明依赖兼容；需要时按新包锁文件显式安装。
