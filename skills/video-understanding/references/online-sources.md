# 网站视频材料获取

取得网址对应的素材，供主流程读取和理解。先定位对象，再获取足以开始任务的材料；后续发现缺口时只补缺失部分。

## 1. 确定对象与材料范围

1. 确认指定视频、分 P 或帖子内媒体，短链接以解析目标为准；合集或多视频范围不清时询问。
2. 用已授权的浏览器、连接器或下载工具取得标题、发布账号、发布日期、时长和可用材料概况。已有文件先核对对应版本与完整性。
3. 首轮一起读取简介与少量热评，补充视频语境。默认取当前热评排序下可见的 3–5 条，置顶或 UP 主补充可优先纳入；不足时按实际条数返回，用户指定范围时服从其要求。
4. 内容材料按任务选择：讲述任务优先所需语言的字幕，画面任务获取合适清晰度的视频，章节辅助定位；弹幕与更多评论按具体缺口展开。

| 材料 | 选择条件与解释边界 |
| --- | --- |
| 视频、音轨、字幕 | 内容理解的材料；保留人工／自动／翻译字幕与 ASR 的类别、语言和时间轴 |
| 标题、简介、章节 | 定位与作者上下文；简介中的来源、补充和更正按任务核对，与视频观察分开 |
| 上传者、作者、制作署名 | 来源或制作背景任务使用；按页面角色与出处记录，署名本身不证明权利归属 |
| 热评、置顶与作者回复 | 解释、质疑或遗漏线索；保留正文、定位、排序／角色标记、可见热度和取得时间。评论是观众反馈或作者补充，不因高赞成为已验证事实 |
| 弹幕、直播聊天 | 按需获取即时反应或时点线索；区分播放偏移、发送时间和视频对白，不作为首轮必需材料 |

评论范围为选中条目及理解它们所需的有限回复；弹幕先定条数或时间窗，扩大采集范围另取同意。样本结论限于该排序与取得时点。

## 2. 选择获取方式

优先复用已有素材、官方完整文字与能力；核对来源、版本和覆盖后，再决定是否下载或 ASR。需要下载器时，先从 PATH 或已登记／交接的独立位置定位 `yt-dlp`，核对版本与 `--help`，再按[官方参数](https://github.com/yt-dlp/yt-dlp#usage-and-options)和[支持站点](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)调用。确认缺失后才交接[工具准备](runtime.md#网站获取工具)；下载、认证和付费按本次授权。

只获取本批所需材料：

| 目标 | 参数与核对 |
| --- | --- |
| 探查字幕与媒体 | `--list-subs`、`--list-formats`；核对分 P、语言、音轨和媒体 |
| 字幕 | `--skip-download` 配合 `--write-subs`；自动字幕用 `--write-auto-subs`，`--sub-langs` 指定已探查的轨道；`all` 可能额外包含聊天／弹幕 |
| 视频 | `--format` 选择媒体与清晰度，`--paths`、`--output` 固定目录和文件名；需要合并时核对依赖 |
| 简介与元数据 | 用 `--print` 的 UTF-8 JSON 字段投影取得标题、规范网址、ID、角色、发布日期、时长、简介与章节；与消费者核对字段、数组和换行形状，缺失字段如实保留，不输出完整信息对象 |
| 少量热评 | 使用能限制排序与条数的浏览器、连接器或工具；下载器不支持有界获取时改读公开页面样本，仍不可用则报告缺口 |

### 下载器调用与材料保留

1. 恢复程序入口与原生配置的加载方式，按下节核对认证授权。已核对的受控自动发现入口直接调用；存在未核对配置时，用 `--ignore-config --config-locations "$downloadConfig"` 隔离并显式加载已确认文件。插件默认用 `--no-plugin-dirs` 禁用，需要时另行授权。原生配置位置、搜索隔离与消费验证见[网站获取工具](runtime.md#网站获取工具)。
2. `--no-playlist` 只约束兼含视频与合集的 URL，实际对象数仍须核对。调用前确认本次进程输出与读取端同用 UTF-8；下载器支持时显式使用 `--encoding utf-8`，不修改系统代码页或持久环境。
3. URL、轨道和格式来自本次探查。媒体与字幕存入授权任务目录，与 CLI 证据目录分开、位于 skill 包外；重试保留来源不明的已有文件。合并失败先盘点已有视频、音轨及依赖，用已授权工具继续处理，下载仅补缺失部分。
4. `--write-info-json` 可能包含个人信息、签名链接或账号数据，确需保存时放在授权的仓库外位置，筛选字段后才交给模型；`--clean-info-json` 不是脱敏保证。cookie、token、认证头仅由已授权的网站获取工具消费，不得进入仓库、日志、代理交接或本地媒体处理进程。
5. 下载限于用户有权访问和保存的内容，不绕过访问控制。登录限制按下节处理；其他运行时或访问失败说明具体缺口，保留已取得材料供主流程判断下一步。

### 认证来源与登录受限材料

1. **恢复可复用来源**：从项目说明、已有交接或用户指定位置恢复获取配置。已有授权覆盖本次账号、站点、消费者及文件读写／保留范围时，直接使用其来源；配置已引用来源时，命令只需本次材料选项。缺少授权、需要新增账号凭据或范围改变时，说明收益、读取范围及替代路径后询问。
2. **按需接入来源**：没有可复用来源且登录能弥补材料缺口时，依据当前响应区分无字幕、登录受限与请求失败。交互登录由用户完成；浏览器页面登录与下载器取得登录态分别核对。选择一种已确认来源：

   | 来源 | 原生入口 | 使用条件 |
   | --- | --- | --- |
   | 浏览器 profile | `--cookies-from-browser "$browserProfile"` | 明确 `BROWSER:PROFILE`，必要时指定 Firefox container；授权覆盖实际 profile 读取范围，并核对当前实现支持其存储格式 |
   | 仓库外 cookie 文件 | `--cookies "$cookieFile"` | 使用获准读写和保留的 Netscape 文件绝对路径；引用可由原生配置拥有，应用及默认位置由项目说明承接 |

   参数与文件要求见[官方参数](https://github.com/yt-dlp/yt-dlp#filesystem-options)和[FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)。来源切换须核对授权，不同时加载未经确认的文件与浏览器来源。

   `--cookies` 使用读写 jar：下载器按域、path 等作用域匹配发送 cookie，某站账号 cookie 不会发给无关域。共享 jar 可保存其他站点匿名响应产生的 cookie；新增域本身不证明新增账号登录，未导入账号的站点仍按未登录处理。确认授权时同时确认这一读写范围，新增账号凭据另行授权。需要不读写文件的匿名排查时，可用 `--no-cookies --no-cookies-from-browser` 覆盖来源。

3. **接入手工导出的文件**：用户在已登录的目标站点导出“当前站点”，优先选 Netscape 格式；需要安装扩展等额外能力时先确认权限，操作按当前官方说明，不要求用户粘贴或上传凭据。Agent 接收路径后，通过获准的本机工具完成以下核对，只返回状态、必要计数或布尔：
   - 核对精确路径、Netscape 格式、授权账号范围与文件权限；导入未授权账号时停止接入。JSON 等格式可在授权范围内本地转换，保留必要值及作用域；转换前明确覆盖与失败恢复，临时凭据先限制访问再写入并按约定清理。
   - 确认复用文件及其消费者，优先原位接入；迁移或留副本时先确认目标、权限与留存。文件路径及配置引用可以交接，cookie 值、密钥、认证头和账号完整响应不得进入模型上下文、仓库或日志。
   - 有效期按下载器的会话语义解释；例如 yt-dlp 可将会话 cookie 保存为到期字段 `0`，不能仅按普通时间戳计数判定登录失效。文件存在、会话字段存在或可解析都不证明站点认可登录。

4. **分层验证并取材**：分别核对来源加载、站点登录有效性、轨道列出与文件取得。登录有效性用站点正常提供的登录状态或受限材料响应证明；字幕验收语言、覆盖与同步，媒体验收完整性。含凭据配置的核对仅输出路径、选项名、必要计数或布尔，禁止输出未脱敏 verbose、完整账号响应或认证值。登录有效而无字幕时，按任务补媒体或 ASR。
5. **按失败阶段处理**：区分文件发现／读写、格式／解密、站点登录／请求和材料可用性。文件缺失、为空或不可读写时报告来源不可用，核对路径及执行身份；这可能影响所有复用配置的调用。yt-dlp 可能为缺失路径创建新 Netscape jar，而空文件可能导致解析失败；命令成功或文件存在均不证明原登录态有效。格式或解密问题核对数据类别与工具支持，再按授权选择来源；来源切换、工具安装、安全设置修改与更换账号分别授权。浏览器占用应有对应证据再请求关闭；HTTP 失败或无轨道本身不足以要求重新登录或导出。
6. **刷新与停用**：确认会话失效后，由用户恢复登录并刷新同一文件，重新核对范围、权限及登录有效性；账号、来源、路径或消费者变化时确认受影响边界。认证仍不可用时回到主流程选择匿名取材、ASR 或用户处理，说明采用的状态。停用撤去认证引用；凭据删除、导出副本清理和站点会话撤销分别按授权执行。

## 3. 按平台核对差异

| 来源 | 必须核对的差异 |
| --- | --- |
| B 站 | 视频 ID、分 P 与字幕登录条件；`danmaku` XML 归为弹幕，本地字幕入口使用实际 SRT/VTT。[提取器依据](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py) |
| YouTube | 原语言、自动／翻译字幕及直播聊天的类别；JS challenge 和部分请求的 PO Token 条件按当前版本核对。[EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS)、[PO Token](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide) |
| X | 帖子内具体媒体；正文作为发布者补充，字幕、回复和登录可用性分别核对。[提取器依据](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/twitter.py) |

其他站点沿用材料分类，以实际取得结果为准。限制原因依据当前视频、请求及其响应；响应未给出原因时保持未知。平台机制或工具变化时核对上游，升级和账号访问仍按授权处理。

## 4. 返回理解主流程

1. 返回简短清单：源网址、媒体身份／分 P、取得时间、材料类别、语言、位置与可用性；视频／字幕、简介与热评分项核对。未请求、缺失、受限和失败分别列出，取得时间不冒充发布日期；仅被工具列出或发现不算已获取。评论／弹幕附排序、条数与抽样范围，原始结果留在可回查位置。
2. 回到主流程按任务读取和理解材料。本地视频按需进入[字幕操作](subtitle-tools.md)或[画面操作](frame-text.md)；外部字幕核对版本、时长、零起点与同步，片段时点保留原视频偏移。
3. 只有文字时按原 cue、行号或页面引用分析，说明文字材料的覆盖；本地视频证据 ID 仅用于真实生成的对应对象。完成这批处理后，主流程再决定交付或补取。
