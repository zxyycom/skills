# 本地工具入口

首次本地调用时确认启动方式与位置，随后执行所选操作。位置已就绪可直接使用；读取和保存已有证据见[证据管理](local-evidence.md)，安装与升级见[环境维护](runtime.md)。

## 调用前准备

1. `$skill` 取完整 skill 的实际安装目录，`$video` 取授权视频的绝对本地路径，可选 `$subtitle` 取 SRT/VTT 路径。CLI 接收本地文件，URL/UNC 不接受；纯文字任务直接读原文件。
2. 使用 Node 24.18+ 或已符合[执行支持](runtime.md#执行支持)的 Bun。下文 `node` 代表已核对的程序，PATH 不满足时用其绝对路径；安装或升级另行授权。

   ```powershell
   $cli = Join-Path $skill 'scripts/video.ts'
   node "$cli" --help
   ```

3. 沿用包外用户配置中有效的 dataRoot/appRoot；需要项目覆盖时显式传 `--config`，精确规则见下节。新媒体采集在 Windows 上按[阶段依赖](runtime.md#分阶段前置条件与缺失路径)准备，OCR 按[支持状态](runtime.md#ocr-profile-与资格)判断；读取、校正与纯复用仅需完整包、兼容依赖和运行程序。
4. 新素材由 `prepare` 或 `frames` 初始化，已有证据按[继续已有证据](local-evidence.md#继续已有证据)定位与核对。后续 `$evidence`、`$material`、`$frame` 分别取实际响应的完整绝对 output、M ID、F ID，同时保留 scopeId。
5. 新媒体操作按[媒体输入前置](#媒体输入前置)核对时长、时间轴和轨道，轨号与尺寸取当前素材信息。

准备就绪后，按任务进入[字幕与听写](subtitle-tools.md)、[取帧与看图](frame-text.md)或[证据读取](local-evidence.md#继续已有证据)。

### 媒体输入前置

CLI 通过 PyAV 读取时长与 `start_time`，以秒核对以下字段：

| 检查字段 | 要求 |
| --- | --- |
| `duration` | 已知且大于 0 |
| `container.start` | 等于 0 |
| `streams[index=...,type=video/audio].start` | 每条已存在的音视频 stream 都等于 0 |

不满足时在 `input` / `inspection` 失败，诊断给出字段、实际值和要求。保留原输入；CLI 不自动归零或重写时间轴，需要派生素材时另行授权。

取帧不要求音轨，ASR 的音轨与语言选择见[字幕操作](subtitle-tools.md#音轨与语言)。轨道使用绝对 stream index，多音轨 ASR 会列出候选供显式选择。CLI 无独立探查命令，需要更多元数据时使用已授权的媒体信息工具。

## 稳定位置与显式目录

### 配置字段与读取

默认读取 `os.homedir()/.config/video-understanding/config.json`。项目配置通过 `--config <完整绝对本地 JSON 路径>` 显式选择，不搜索项目根或自动加载环境文件。两种配置只接受下列可省略字段，格式参考 [config.example.json](../config.example.json)：

| 字段 | 用途 | 合法值 |
| --- | --- | --- |
| `appRoot` | 媒体运行时根 | 完整绝对本地路径字符串；省略或 `null` 继承低优先级值 |
| `dataRoot` | 运行数据根，证据集合位于其 `evidence/` 下 | 完整绝对本地路径字符串；省略或 `null` 继承低优先级值 |

配置文件、媒体根和数据根保持 skill 安装目录之外，目录别名按物理位置核对。JSON 不接受注释或环境变量插值；路径按字面值处理，不接受相对形式、URL、UNC，Windows 路径须带盘符。

CLI 只读配置，位置参数只覆盖本次选择，不写回文件。默认用户文件缺失表示未配置；显式项目文件缺失，或任一已读取文件的 JSON、字段、路径非法，在 `arguments` 阶段失败，即使高优先级参数覆盖该值。`--help` 跳过配置读取且不创建运行数据。

### 位置优先级与目录

1. **显式 CLI**：`--output` 直接选择叶目录；未指定时，`--evidence-root` 选择集合根。`--app-root` 指定媒体根。
2. **显式项目配置**：`--config` 所选文件按字段覆盖用户配置，省略或 `null` 保留低优先级值。
3. **用户配置**：未指定 `output`/`evidence-root` 时使用 `dataRoot/evidence/`；未指定 `app-root` 时使用 `appRoot`。
4. **项目适配缺省**：宿主短入口可补证据根和延迟解析的媒体根。独立入口没有该层缺省，也不从 `cwd` 或 `home` 推测媒体或数据根；需要的根仍未确定时失败。

写入时按需创建目录；`ocr` 使用已有 F。已读取配置中的路径始终校验绝对本地形式与物理包外边界；`appRoot` 的存在和媒体依赖就绪性仅在新媒体操作需要时核对。

`--evidence-root <absolute-local-directory>` 在该根下按 `<规范素材路径SHA256>/` 派生单视频叶目录。规范路径取 input 的 realpath；cwd、JSON 版本、文件大小和 mtime 不参与目录身份。源文件改变仍须通过[当前性与完整性](local-evidence.md#当前性与完整性)检查。

1. `prepare`/`frames` 必须提供 `input`；`read`/`refine`/`ocr`/`logs` 提供 `input` 或 `output`。两者同时提供时核对 `input` 与目录的素材身份。
2. `--output "$evidence"` 指定单视频叶目录而非集合根，其父目录须存在。
3. 只传 `input` 且没有显式 `evidence-root`/`output`、有效 `dataRoot` 或项目缺省时明确失败；只有 `prepare`/`frames` 可创建所选证据根的父目录，`read`/`logs`/`refine` 定位不建目录。
4. `input` 须能解析到现存本地素材。素材移动或丢失后，用先前返回的 `output` 查询 `logs`，不附失效 `input`。

尚无证据时按任务用 `prepare` 或 `frames` 初始化；空叶目录与已有目录的处理见[复用、状态与失败恢复](local-evidence.md#复用状态与失败恢复)。CLI 写入所选运行目录，保持 skill 包和原素材不变。

### 复制与更新

完整程序包不包含真实用户配置。复制或更新程序时保留包外配置和数据，另按[依赖安装](runtime.md#随包依赖维护)恢复兼容依赖；换机器核对路径后显式建立用户配置。更新覆盖正式同路径文件并保留其他文件，旧文件退场需单独清单，不能依赖 updater 自动删除。改根只改变后续定位，既有证据用原 output 访问；数据迁移单独授权。

替换现有安装时，先保留成套程序、配置与必要依赖供回退。需要调整配置位置时，核对现有 `appRoot`、`dataRoot`，在上述用户位置建立或合并 JSON；已有配置先确认合并范围，不直接覆盖。验证新包读取与纯复用成功后，才按明确清单退场已替换文件。回退恢复成套程序、原配置与依赖，保留外部运行时、模型、缓存、素材和证据原位。

## 失败分流

1. 核对本次退出、stderr 和已发布结果。参数／位置问题修正本次输入；缺运行程序、依赖或模型时，按[环境维护](runtime.md)说明所需准备，安装与下载另行授权。
   证据路径报 `ENOENT` 时，先逐字比较诊断的精确 target 与交接的完整绝对 `output`（manifest 目标为该目录下的 `evidence.json`）。抄写有误就恢复确知原值后重试；原值无法确认时向交接方索取，不猜斜杠或目录。目标一致仍缺失时按[证据恢复](local-evidence.md#复用状态与失败恢复)判断，不将路径缺失直接归因为权限。
2. 运行失败用响应或已知 output 查询[日志](local-evidence.md#运行日志与诊断)，区分本次结果和最近保存记录；保留仍可读材料供任务继续使用。
3. 协议、素材当前性、产物或锁问题按[证据恢复](local-evidence.md#复用状态与失败恢复)确定影响范围。备份、清空、删除、迁移或终止进程先确认精确目标与授权；超时、取消及回收要求见同一参考。

### 长任务续接

调用工具返回“仍在运行”时，保存其实际提供的续接句柄和最后确认状态，按该工具契约继续等待至终态；句柄字段与等待接口以本次工具响应为准。视频 CLI 已返回的 `output`、`scopeId` 与 `runId` 另用于证据和日志定位。

外层脚本完成、普通进程查询未命中或已保存 `running` 记录，都不能代替执行该命令的工具返回终态与退出状态。尚未结算时如实交接；停止任务前核对具体归属、影响与授权。
