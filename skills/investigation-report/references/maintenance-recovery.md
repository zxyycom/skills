# 调查报告维护恢复

本手册帮助操作者根据实际命令结果，恢复可解释的候选、正式报告、资源、索引或 pending 状态。领域事实以[固定契约](investigation-report-contract.md)为准，操作范围以 [CLI 操作契约](cli-operations.md)对应章节为准；恢复保留权威来源，再处理派生状态。

## 先确认发生了什么

1. 读取诊断中的 code、对象、原因和下一步。按存在的结果字段和声明范围判断已知与未知写入。
2. 保留当前 candidate、正式 Markdown、资源、索引与可用的可信版本；区分本次命令涉及哪些路径，以及哪些属于其他工作。
3. warning、候选准备、正式建立、索引同步和 Git pending 分别判断，不从单个成功或失败推断其他范围已完成。

## 状态分流

| 当前结果或故障 | 下一步 |
| --- | --- |
| 来源配置、key 引用或选择错误 | 用相同定位参数读取 help 的来源诊断，按[来源配置与帮助](source-selection.md)核对并修正配置或选择。 |
| 组合查询只有部分来源成功 | 保留逐源成功结果与失败诊断，修复失败来源后按需重查；后续写入先按 [CLI 定位与选择](cli-operations.md#定位与选择)确认单源目标。 |
| new 已成功，正文或资源 readiness 未就绪 | 候选已创建，继续编辑和 show-candidate；需要写前审阅预计影响时再显式 publish preflight。 |
| new 返回失败但结果表明已创建或改变 | 保留已创建候选，核对真实 ID、路径与内容；先处理实际残留，不重做 new。非零不表示未创建。 |
| 候选单独未就绪 | 用 show-candidate 或 publish preflight 核对正文、关系和直接资源，按具体缺口修正。 |
| content 或 metadata 搜索报索引不可用 | 先修复来源并显式恢复索引；content 只匹配发布范围内的当前文本。 |
| 搜索结果被截断 | 收紧筛选或调整允许的返回预算，保留记录发现的覆盖边界。 |
| 只有搜索预览被截断 | 用 show 读取已返回 ID 的完整正文；预览不完整不代表记录发现不完整。 |
| 手工正式来源变化，或索引缺失、损坏、陈旧 | 核对完整正式报告与资源后运行 `sync-index`（默认写入，`--preflight` 零写入预演）；publish 只处理所选候选，不接纳这些变化。 |
| 严格 check、关系事务、正式删除报索引陈旧或无效 | 未解释的异常先运行默认全量 `check` 区分来源与索引问题；已知合法来源变化直接 `sync-index` 发布当前投影，再重试原动作。 |
| stage 的发布索引无效，或所选来源不符合发布投影 | 先按诊断区分 metadata 与所选来源问题：索引无效时修复或重建；所选来源用局部 `check --id` 定位，合法变化由 `sync-index` 发布后重试。stage 的验证范围见[待提交快照](cli-operations.md#待提交快照)。 |
| 资源路径、owner、可见性或引用无效 | 修复相应资源与声明引用；资源字节变化本身不要求同步索引，正式链接变化需要同步。 |
| `history-check-unavailable` 历史检查不可用 | 按 [HEAD 历史基线](#head-历史基线)核对所读提交、原因及对应恢复路径。 |
| 权限不足或锁忙 | 按下节解除操作条件，保留当前领域状态。 |
| 写入中断或恢复范围不清 | 按实际结果对账，暂停后续 mutation。 |

## 候选身份发现与索引状态

候选动作从当前来源发现候选，并按索引状态取得正式身份与位置：

| 索引状态 | 身份依据与下一步 |
| --- | --- |
| 合法现行索引 | 使用已发布的正式身份与位置，准备所选候选及必要直接依赖。 |
| 真正缺失 | 仅枚举目录成员以判断是否已有正式来源，不读正式 header。确无正式成员时可继续首次候选操作并独立首次发布；已有正式成员时，候选和正式操作均须先显式恢复合法索引。 |
| 已有坏索引或 definition 不兼容 | 显式修复来源与全量 `sync-index`；不能退为空集合或来源 fallback。 |

合法发布索引是普通操作的正式身份与位置基线；未发布正式路径不从 header 补入。候选自身可有限枚举以兼容旧 locator，不扩展为正式正文扫描，也不建立候选索引。资源 owner 的正式声明来自索引，仅所选候选的直接资源及 owner 树按本次行为检查。

stage 丢失旧非 canonical pending 定位时，先恢复可信来源或索引定位；重跑其他 scope 不保证找回未知位置。domain 对 pending 索引的定位读取、有限容错与保护按 [CLI 待提交快照](cli-operations.md#待提交快照)执行。

legacy ID 与日期 ID 同 name 时，先从合法索引取得 sourcePath 读取原来源；legacy 文本或追加 `.md` 均可能歧义。确需更正身份时另取得对应授权并显式同步；新建不以迁移旧记录为前置。

候选 locator 已确定但 ID/结构无效时，列表 warning 后跳过，显式目标失败；身份歧义、非法成员与读取不安全始终拒绝。

## HEAD 历史基线

前序历史检查从本次固定的 Git HEAD revision 读取索引并定位必要正文。当前集合与 HEAD 分别验收；`history-check-unavailable` 表示历史判断不可用，前序是否已记录仍待确认。

诊断分别展示 revision、仓库相对 path 和原因 code、detail、可用的 stateId。自由文本逐字段净化、限长，定位独立保留；最多展示前三项原因，`omittedCauses` 表示其余数量。解析位置以运行时提供的信息为准。

| 原因 | 恢复边界 |
| --- | --- |
| JSON／结构损坏、索引缺失或类型错误、所选历史身份不可用 | 从可信正式来源校验或恢复当前索引与报告，再按下述步骤形成新 HEAD。 |
| schemaVersion、definition 或 namespace 不兼容 | 核对工具与索引版本，选用兼容工具或适用的迁移流程。 |
| Git／文件系统访问或其他系统失败 | 根据实际系统诊断解除条件后重试。 |

确认历史数据损坏后：

1. 保留可信正式 Markdown 与资源，核对当前来源和索引；需要重建索引时执行 `sync-index`，已正确的工作区内容保持不变。
2. 运行全量 `check` 验证当前集合。工作区或暂存修复尚未改变 HEAD，此时历史 warning 仍可能存在。
3. 取得 commit 授权后，将验证后的修复纳入新提交，再运行全量 `check` 确认历史检查恢复。修复通过新提交形成可信基线，既有历史保留。

## 中断写入

停止后续 mutation，先读取错误、诊断和实际存在的 `changed`、`committed`、`writtenPaths`、`unknownPaths`；未知不代表未写入。检查 Markdown、索引、资源及 Git pending，与可信版本逐项对账。已有文件替换和新文件独占创建不提供多文件原子事务；初始化失败可能留下部分文件。工具不承诺普遍备份或自动回滚。

仅在当前授权覆盖目标与影响、且可信来源足以确定完整旧状态或新状态时恢复；不能确定时保留现场并请求判断。修复原因并重新观察后才显式重试，不因非零退出直接重做操作。stage 不提供并发 CAS，pending 不是工作区备份。

## 权限与重试

- 权限问题只取得当前进程所需访问授权，不使用 `sudo` 扩大权限。
- Git 锁忙时确认活动进程；不得自动删除锁。
- 处理原因并重新观察后，由操作者显式重试。恢复不完整、归属不清或原因未知时保持现场，先对账再取得必要判断。
- 索引从合法正式来源重建；来源内容和资源事实依据可信材料修复，不能反向用索引补造。

## 恢复验收

恢复出完整正式集合后运行全量 `check`。需要重建索引时，先核对正式报告与资源，再 sync-index，随后 check；合法 candidates 保持独立。候选问题用 show-candidate 或 publish preflight 验证。

交付说明实际恢复的对象、旧/新状态判断、运行的验证及剩余未知。清理未完成或范围仍不确定时，明确下一步所需的用户决定，不将局部成功报告为整体恢复。
