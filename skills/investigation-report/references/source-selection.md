# 调查来源配置与帮助

本文维护来源 key 的定义、配置合并、展开身份与帮助展示。执行命令时，按 [CLI 定位与选择](cli-operations.md#定位与选择)决定读写目标，按[逐源结果与回读](cli-operations.md#逐源结果与回读)解释返回；资源策略字段由[资源诊断](resource-review.md#配置)承接。

## 配置发现与合并

所有业务命令及 help 使用调用工作区的配置；version 不读取配置。工作区由 `--root` 选定，缺省为调用目录，不向上查找，依次应用：

1. 内置默认值。
2. 项目配置 `.investigation-report.json`。
3. 本地配置 `.local/.investigation-report.local.json`。

`--config PATH` 用显式文件替代项目／本地两层，再补内置默认值；相对配置路径以调用目录为基准。选中来源后，继续使用调用工作区的设置。

| 字段 | 合并与合法性 |
| --- | --- |
| `version` | 可省略或为 1。 |
| `defaultKey` | 后层覆盖前层；提供时须指向已有 key，有来源定义时必填。 |
| `sources` | 按 key 合并，同 key 的完整定义由后层替换，包括单源对象与组合数组。 |
| `resources` | 对象按字段递归合并，数组整体替换；每层策略独立验证。字段见[资源诊断](resource-review.md#配置)。 |

默认文件缺失时使用剩余层与内置值。显式文件缺失、不可读、非普通文件、超过 1 MiB、非法 JSON、未知字段、null 或非法策略均报错。

## 来源定义与展开

每个非空 key 的值是单源对象或非空有序数组。单源对象完整提供 `root` 与安全相对路径 `investigationsDir`；数组项为 key 引用字符串或内联单源对象，不接受裸嵌套数组。仅含内联对象的原有数组配置继续有效。

以下示例位于工作区的 `.local/.investigation-report.local.json`：

```json
{
  "version": 1,
  "defaultKey": "related",
  "sources": {
    "workspace": { "root": "..", "investigationsDir": "research/reports" },
    "related": [
      "workspace",
      { "root": "../../shared-lib", "investigationsDir": "notes/investigations" }
    ]
  }
}
```

内联 `root` 可绝对或相对；相对值以定义它的配置文件目录为基准，因此示例中的 `".."` 指调用工作区。将定义移到其他配置层时，须保持预期定位。

完整合并后才解析 key 引用，后层可以补齐引用目标；未知引用与循环报错。引用按数组顺序深度优先展开为扁平来源列表，同一来源保留首次出现项。

### 来源身份与执行路径

来源身份由工作区 `root` 与调查目录共同确定：root 可由系统解析时使用规范路径，否则使用声明的绝对路径；调查目录按当前平台路径语义比较。身份仅用于去重，根路径暂时无法解析仍可进入逐源执行并报告实际错误。

执行保留原来源路径及其中的 `..`，遵循操作系统的符号链接解析；不以词法折叠后的路径替换执行目标。根路径身份解析只读取定位所需元数据，不证明索引或报告可用。

## 帮助中的来源信息

顶层 help、`help <command>` 和 `<command> --help` 在基础帮助后附：

- 本次配置路径。
- 可用 key、single／composite 类型及默认标记；类型对应定义形式，与最终展开数量分别判断。
- 当前选择，以及按执行顺序排列的各源绝对 `root` 与根内相对 `investigationsDir`。

展示尊重 `--key`、`--config` 与显式定位。无来源配置时显示当前单源；写命令未传 key 时显示工作区目标，显式 key 展开多源时给出单源要求诊断。

帮助读取配置及根路径解析所需元数据，不打开索引或扫描报告。配置路径不保证文件存在，根路径无法解析时保留声明定位；集合可用性由业务操作核验。配置或选择错误时仍显示基础帮助与来源诊断，而非报告单源回退成功。
