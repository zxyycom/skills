# 资源选择与示例

资源只承接正文判断不可缺少、且不能用更精简表达替代的材料。本参考解释如何裁剪；路径、引用、共享与事实忠实要求由[资源引用与归属](investigation-report-contract.md#资源引用与归属)承接。

## 从正文依赖判断去留

逐项问：**删去或概括这部分后，正文哪一个判断会失去必要依据？** 指不出具体损失就省去；能用正文一句话、一个对照或小表承接，就采用该表达。有信息、独有、真实产生、容易重跑或已经被引用，都不是充分的保留理由。

先裁剪信息，再选择载体，最后复核文字质量。文字也要去掉流水账、重复说明、无关细节和含混堆砌；必要内容重写为清楚的事实、条件、对照或概括。仅换成 Markdown、CSV 或代码文件，不算完成精简。

## 各类材料的最小表达

| 材料 | 优先保留 | 何时才保留更多 |
| --- | --- | --- |
| 日志、命令输出 | 关键结果、错误、判断转折及适用边界的概括 | 正文依赖具体措辞、时序或故障上下文时，补相应最小片段。 |
| 测量数据 | 支撑比较的条件、样本口径、指标与必要异常 | 判断依赖的分布、反例或逐次差异无法由概括承接时，保留对应数据。 |
| 环境与文件清单 | 版本、关键条件、实际核对结果和覆盖缺口 | 正文确实依赖具体文件或内容身份时，保留相关条目；完整清单与哈希不默认留存。 |
| 方法文字、`.txt`、代码 | 解释触发条件、动作和推理的最短流程或关键片段 | 某个细节改变判断时保留该细节；准备环境、运行包装、完整驱动和重复代码按同一标准裁剪。 |
| 合成输入 | 与判断有关的构造特点、规模和关键内容 | 精确内容或编码本身参与判断时，保留相应公式、片段或指纹。 |
| 图片、音视频及其他非文本材料 | 能承接判断的文字描述、表格或局部材料 | 正文依赖无法由这些表达承接的像素、声音、时序或编码特征时，保留最小必要原形式。 |

格式有信息也不等于格式不可替代。例如，图片只是白底中央红方形，正文只判断接口接受图片并返回颜色时，构造说明和关键响应可以足够；调查像素损坏或编码差异时，相应图像字节才可能成为必要依据。

## `.txt` 与代码按思路阅读

调查资源中的方法文本（含 `.txt`）、语言代码文件和方法代码块都用于表达思路。除正在负责实际操作的人员外，读者均按伪代码理解，不默认语法、依赖、路径、接口或行为保真可用。扩展名和“当时运行过”均不产生现行代码保证，也不要求为整理资源而改名、补环境或维护脚本。

操作负责人在任务确需实际执行时，才核对所需片段、环境和当前入口，承担实现与验证；阅读历史方法不自动触发执行或修复义务。实际观察与方法说明分别表达，概括方法不能补造执行结果。

## 检查裁剪结果

精简后，正文及必要资源仍应支持原判断、条件、转折、反例和未知；不把一次观察写成普遍结论，不把概括伪称完整原始记录。需要说明时，简记概括或节选范围即可，不为每次裁剪另建一套清单与阅读副本。

[资源诊断](resource-review.md)只提供体积、重复等线索。历史资源也按正文依赖审阅；具体精简与删除服从资源契约和当前授权，秘密及认证材料不得保存。
