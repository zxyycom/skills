# Investigation Report

## 目标与适用范围

用一份报告保存**一轮调查在形成时的认识**，使未参与原对话的读者仍能复核：为什么调查、实际检查了什么、依据是什么、得出了什么，以及结论的适用边界。

当前请求或生效项目规则明确要求记录或维护报告时使用，适用于各领域；其他调查在当前任务中交付。领域方法由相应任务承接，当前事实、长期方向、实施任务与稳定测试义务各归其 owner。

正文解释关键认识，随附资源补充现场与做法，派生索引支持查找和追溯。可独立复核，是指读者能审查结论如何形成及其适用边界；可信度取决于来源、方法与推理，而非附件是否齐全。

## 工作流程

### 1. 恢复已有调查认识

开始或继续调查前，用已知信息选择最小查询入口，恢复相关已有报告。查询在足以区分复用、同轮完善、独立新轮次或无需记录时停止；准备新建时，同时确认相关候选与正式报告未覆盖同一问题。

| 当前情形 | 下一步 |
| --- | --- |
| 已有报告大致回答同一问题，用户未说明是否需要当前验证 | 概述已有认识，再询问复用既有结论还是按当前事实复查。 |
| 用户只要求查找、总结或审阅已有材料 | 直接交付已有结果及其形成时边界。 |
| 用户明确要求重新调查、最新结果或当前事实，或项目规则要求当次调查 | 以旧报告为背景，直接按当前事实复查。 |
| 没有足够相关的已有报告 | 继续正常调查。 |

概述包含报告身份、形成时间、原问题、关键结果、主要依据、适用范围、未覆盖内容和剩余未知，说明它尚未证明当前事实。询问复用还是复查用于减少重复调查，不替代真实性判断。

### 2. 确定本轮报告边界

按[报告边界与有效演进](references/investigation-report-contract.md#报告边界与有效演进)先判断是否需要独立报告，再判断真实直接前序：

- 同轮补证、纠正误述或继续收敛，完善原报告或候选，并标明依据的实际时点。
- 新问题或新条件下的认识需要独立保留和复核时，新建完整报告；关系可以为空。
- 既有格式、链接或记录错误原地修正。分篇依据是独立轮次的保留价值，而非编辑或提交次数。

需要新建时，按 [候选创建与发布](references/cli-operations.md#候选创建与发布)用 `new` 创建 candidate，随后继续完善该候选。

### 3. 形成可独立复核的认识

按当前任务适用的方法取得证据，四项核心共同回答本轮问题：

| 核心内容 | 必须让读者恢复的内容 |
| --- | --- |
| 形成时背景 | 当时发生了什么，以及促成调查的已知事实、假设、未知和约束。 |
| 调查目的 | 本轮具体问题、准备支持的判断和预定边界。 |
| 调查范围与依据 | 实际检查对象、来源、时点或版本、方法、覆盖范围和未覆盖内容。 |
| 调查结果与边界 | 已确认事实、推断、建议、实际动作和未知；适用条件、不可外推范围与重新调查条件。 |

按判断需要补足条件：因果解释说明观察与预期、触发条件、候选解释及排除依据；计量说明来源、样本、指标、窗口与误差；方案比较说明比较条件、取舍、授权、恢复与验证边界。相关性、因果判断、建议与实际结果按各自证据强度表达。

渐进探索保留使判断改变的转折：初始问题 → 实际动作与观察 → 解释的保留或修正 → 当前认识与剩余未知。依据标明实际取得的时点；尚未闭合的环节保留为阶段性结论。

例如，性能调查从“接口变慢”缩到“重复读取”，再定位缓存失效 Bug，正文解释每次收窄依赖的观察；详细测量和诊断代码按需随附。

### 4. 选择随附资源

正文独立解释关键认识、依据与边界；资源用于进一步了解细节和当时做法。按以下顺序取舍：

1. **判断是否保留**：短而关键的内容放正文，稳定来源足够时直接引用，需要随报告保存的细节再附资源，其余省略。
2. **确定保留范围**：长日志、数据或输出可节选、去重、汇总、脱敏和简化，保留影响判断的状态、顺序、差异及反例，简要标明处理方式。
3. **选择表达形式**：优先采用可直接阅读、便于 Git 比较的等价纯文本、表格或代码。文本会丢失判断信息时，保留必要的最小非文本材料并说明用途。
4. **说明阅读用途**：正文交代资源的来源、条件、关键内容及何时需要读取。

一次性分析代码、测试代码或查询可以原样或节选保留，解释当时动作与逻辑。代码保持真实语言形式，节选说明省略范围；纯伪代码用 `.txt` 等明确的文本形式区分。资源默认供阅读，复现准备、重跑验证和工具维护按任务要求承担；执行及其他副作用仍须相应授权。

资源路径、owner、共享与内容保真按[资源引用与归属](references/investigation-report-contract.md#资源引用与归属)维护。秘密和认证材料不得保存。

### 5. 维护分类与直接关系

tags 表达有正文依据的可检索主题。无真实直接前序时使用空关系；存在前序时，按[认识演进关系](references/investigation-report-contract.md#认识演进关系)表达具体补充、复查或变化。

新建或调整关系时，依据两端正文为每条边填写 `summary`。候选在起草时声明完整关系，正式关系通过 `set-relations` 事务维护；涉及同批候选时核对最终图闭合。

### 6. 审核、建立与交付

agent 在当前授权范围内，自行审查证据、报告边界、资源与关系。关键事实或取舍无法确定且影响结果、超出委托范围或明确要求人工确认时再询问；删除等高风险操作须有覆盖精确目标与影响的授权。

1. 用 `show-candidate` 核对结构、正文与资源 readiness，再独立完成语义审查和 publish 授权判断。
2. 按[候选创建与发布](references/cli-operations.md#候选创建与发布)执行；需要写前审阅预计影响时单独预检。正式编辑、关系维护、身份更正或删除按对应契约执行。
3. 已知合法正式来源手改先 `sync-index`。普通维护（含删除、身份更正）按发布索引、所选及实际改写来源和最终组合图交付；未选正文或候选引用不作当前性证明。任务要求当前全集健康时，在维护批次验收运行全量 `check`。索引异常与恢复按[维护恢复](references/maintenance-recovery.md)处理；只读审阅保持集合状态不变。
4. 任务要求 Git 待提交快照时，再按[暂存操作](references/cli-operations.md#待提交快照)执行 `stage`。commit 与 push 分别服从当前授权。

## 完成标准

- 正文独立说明背景、问题、关键依据、结果与边界；探索转折和未知清楚，主张强度与证据一致。
- tags、直接关系和资源各有正文依据；资源必要、安全，节选性质清楚，复现要求按任务单独验证。
- 只读交付说明可确认范围、问题与未知；写入交付说明实际变化、同步和检查结果、语义审查结论及未证明边界。机械检查与内容可信分别交付。

## 工具运行前置

运行下文公开 `.ts` CLI/import 或自更新入口时，使用 Node.js `>=24.18` 的原生类型擦除。
依赖沿 Node 正常解析，可复用宿主兼容版本，不要求本地 `node_modules` 或与锁文件精确版本一致。
依赖缺失、实际不兼容或需要复现随包基线时，使用随包 `package.json` 固定的 pnpm 显式安装：

```bash
pnpm --dir "<skill-directory>" install --ignore-workspace --prod --frozen-lockfile --config.node-linker=isolated
```

运行、import、help 和检查不自动安装。安装副本中的 `scripts/runtime/tools/` 可直接修改，无需构建；
更新会覆盖正式包中的同路径定制文件。领域操作的其他前置仍由各自操作契约承接。

## CLI 入口

在**目标工作区根目录**执行，用实际安装位置的脚本绝对路径调用：

```text
node <skill绝对路径>/scripts/check-investigations.ts help <command>
node <skill绝对路径>/scripts/check-investigations.ts [global-options] <command> [command-options]
```

当前目录默认就是工作区根。若从 skill 安装目录或其他目录调用，显式在 command 前提供 `--root <workspace-root>`；自定义集合使用工作区内相对 `--investigations-dir`。help 不读取集合状态。项目已提供维护短命令时优先使用该入口。

## 自更新

在本 skill 目录运行 `node scripts/update-skill.ts`，运行前置与依赖修复见[工具运行前置](#工具运行前置)。
运行时文件或 manifest/锁文件损坏时，重新获取完整 skill 后再安装并重试。
更新覆盖正式包中的同路径文件、保留其余本地文件。源码更新成功不证明依赖兼容；需要时按新包锁文件显式安装。
