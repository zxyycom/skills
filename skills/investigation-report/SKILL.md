# Investigation Report

## 目标与适用范围

用一份报告保存**一轮调查在形成时的认识**，使未参与原对话的读者仍能复核：为什么调查、实际检查了什么、依据是什么、得出了什么，以及结论的适用边界。

当前请求或生效项目规则明确要求把调查沉淀为报告，或创建、更新、审阅报告时使用。skill 本身不因普通调查、排障或问答自动建立报告；领域调查方法由相应任务承接。当前事实、长期方向、实施任务与稳定测试义务继续交给各自 owner。

正式报告 Markdown 保存该轮认识；可选资源提供复核材料；派生索引支持查找和关系追溯。所有已建立报告留在同一正式集合，后继关系描述认识演进，不改变前序的可见性。当前口径须回到当前事实 owner，并按需综合相关报告。

## 自行审查与授权

agent 在当前请求或生效项目规则授权的范围内，自行审查证据、报告边界、资源、关系与发布条件，并执行维护。机械 readiness 与 preflight 只证明相应准备情况，语义审查由 agent 另行完成。

只有关键事实或取舍无法从现有材料确定、超出委托范围，或当前指令明确要求人工确认时才询问。删除等高风险操作仍须有覆盖精确目标与影响的授权。

## 读取路径

1. 先读目标工作区指令，按当前问题定位报告与事实来源。
2. 创建、修改、publish、剔除或结构审阅前，完整读取[固定契约](references/investigation-report-contract.md)。它承接身份、正文结构、关系、资源、索引和维护不变量；索引精确机器结构由相邻 [Schema](references/investigation-index.schema.json) 承接，命令参数查 `help <command>`。
3. 出现 CLI 诊断、锁、权限或中断写入等恢复条件时，读取[维护恢复](references/maintenance-recovery.md)，只对诊断声明的范围判断结果。

| 已知信息或阅读目的 | 入口 |
| --- | --- |
| 准确 Investigation ID 或唯一 name | `show <selector>` |
| tags、形成时间、关系类型或直接关系目标 | `list`；按需筛选、翻页或用 `--detail` 展开摘要 |
| 主题、概念、原因或正文措辞 | `search <text>` → 用结果中的完整 ID 继续读取 |
| 完整认识演进图 | `trace <selector>` |
| 审核尚未建立的候选 | `candidates` → `show-candidate <selector>` |

Investigation ID 是 frontmatter `id` 声明的稳定身份，`sourcePath` 只定位文件。查询后使用返回的完整 ID 继续操作。

`list` 与 `search` 只查正式报告，候选通过独立入口读取。默认搜索读取报告 Markdown，`--in metadata` 只反映已发布索引快照。遇到降级或截断 warning 时，先按[索引与查询](references/investigation-report-contract.md#索引与查询)确认来源与结果边界，再据此下结论。

## 工作流程

### 1. 确定本轮报告与维护方式

先按[报告边界与有效演进](references/investigation-report-contract.md#报告边界与有效演进)判断是否需要独立新报告，再判断是否存在真实直接前序。新证据、结论纠正或 Git 提交本身都不决定分篇；真实独立的历史轮次仍须保留。

| 当前需要 | 处理 |
| --- | --- |
| 判断已有报告是否可复核 | 只读审阅正式报告；未建立内容先审阅 candidate。 |
| 同一轮调查补充材料、纠正误述或继续收敛认识 | 完善原报告或候选，准确标明依据及其实际时点。 |
| 形成需要独立保留的新一轮认识 | 创建完整新报告；再单独判断是否存在真实直接前序，关系可以为空。 |
| 既有报告存在记录、格式或链接错误 | 原地修正；已提交不改变这一选择。 |
| 更正稳定 ID/name | 使用 `rename` 统一维护身份、关系、位置和资源引用。 |
| 明确剔除正式报告或候选 | 分别用 `discard` 或 `discard-candidate`，按契约确认删除范围。 |

需要新建时，先用 `new` 创建集合外的 candidate，再完成正文、资源与关系。创建成功后继续编辑、查看候选或运行预检；未就绪表示需要完善现有候选，而非重跑 `new`。

### 2. 形成可独立复核的认识

按当前任务适用的方法取得证据，将一份报告限定为一轮能够独立汇报的认识。四项固定核心共同回答本轮问题：

| 核心内容 | 必须让读者恢复的内容 |
| --- | --- |
| 形成时背景 | 当时发生了什么，以及促成调查的已知事实、假设、未知和约束。 |
| 调查目的 | 本轮具体问题、准备支持的判断和预定边界。 |
| 调查范围与依据 | 实际检查对象、来源、时点或版本、方法、覆盖范围和未覆盖内容。 |
| 调查结果与边界 | 已确认事实、推断、建议、实际动作和未知；适用条件、不可外推范围与重新调查条件。 |

把决定主张强度的条件写入相关核心：计量说明样本、指标、窗口与误差；因果说明候选解释、直接证据与未闭合环节；方案说明授权、恢复与验证边界。结论强度须与实际依据一致。

实验和其他副作用遵循当前任务授权，正文与资源只保留复核所需的最小非敏感信息。审阅先判断报告是否忠实、完整地保存该轮认识；需要判断当前适用性时，再对照相关报告与当前事实 owner。

### 3. 确定分类、直接关系与资源

- **分类**：tags 表达有正文依据的可检索主题。
- **认识演进**：无真实直接前序时使用空关系；存在直接前序时，按变化选择 `补充`、`复查`、`修正`、`推翻`、`归并` 或 `拆分`。关系由后继指向前序，合法语义与图形见固定契约。
- **关系维护**：candidate 在起草时声明完整关系，已建立报告用 `set-relations` 事务替换完整关系集合。发布同批互相关联候选时，按契约核对最终关系图闭合。
- **资源取舍**：正文与稳定事实 owner 足够复核时直接引用；确需形成时材料才保留最小必要资源，并在正文说明来源、条件、关键事实与支撑作用。
- **资源位置**：candidate 与正式报告统一用 `./_resources/<resource-id>` 链接。自有资源预置在最终 owner 路径，也可共享既有正式 owner 资源；publish 保持链接与资源位置，不自动暂存资源。
- **资源修正**：新增实质材料使用新资源，归属由报告边界决定；同轮完善可归于原报告，独立新轮次归于新报告。已保留材料的原地修改只用于准确恢复、格式修复或移除敏感信息，不能覆盖旧样本来伪造证据。秘密与认证材料不得进入报告或资源。

### 4. 审核并建立候选

1. 用 `show-candidate` 核对 `scaffoldValid`、`bodyReady` 与 `resourceReady`；它们分别表达结构、正文和资源的机械准备情况。
2. 自行审查完整内容，确认正文可信、关系真实、资源必要且安全，并核对当前任务的 publish 授权。
3. 用 `publish <selector...> --preflight` 只读预演显式选中的最终集合。正式 publish 仍会重新读取基线、候选和资源并完整验证，预检不保存确认凭据。
4. 授权和审核均满足后 publish。若存在手工正式来源变化，先按下一节同步，再发布候选。

正式根目录的完整报告一旦写入即已建立。候选通过 `publish` 正常建立；手工正式来源变化按下一节用 `sync-index` 接纳。

### 5. 同步、验证与交付

1. 只读审阅运行适用的 `check` 或 `publish --preflight`，保持集合状态不变。
2. 一批手工正式报告编辑可先共同完成，期间用 scoped check 获取局部反馈。在索引查询、已有关系事务、正式删除、默认全量检查、暂存或交付需要当前集合前，统一运行一次 `sync-index`。它验证完整正式集合；`--select ... --write` 仅接纳所选 ID 的变化，合法 candidates 不参与同步。
3. `set-relations` 与正式 `discard` 要求当前索引，并在成功事务中同步索引。只改资源字节时保留索引；暂停、失败或 cleanup 诊断按契约与恢复手册处理。
4. publish、同步或事务完成后运行默认全量 `check`，并按下列完成标准复核实际结果。
5. 需要 Git pending 快照时，同步和全量检查后用 `stage-index` 选择正式 Investigation ID；报告与资源按实际交付范围另行暂存。

## 完成标准

1. 报告能独立恢复形成时背景、目的、实际依据、结果与适用边界，主张强度与证据一致。
2. tags、直接前序关系和资源各有正文依据；候选在 publish 前具备完整 readiness、preflight、语义审核和授权依据。
3. 只读审阅说明可确认范围、问题与未知；写入交付说明实际变化、同步和全量检查结果、语义审查结论及未证明的边界。

## CLI 入口

从 skill 目录运行，或使用脚本绝对路径：

```text
node scripts/check-investigations.mjs <command> [options] --root <workspace-root>
```

操作前用 `help <command>` 取得精确参数。本文负责报告形成与审阅，格式、命令前置和恢复范围沿“读取路径”取得。
