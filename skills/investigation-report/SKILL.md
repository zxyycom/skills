# Investigation Report

## 目标

以单份报告保存一轮形成时认识。每份报告拥有稳定 Investigation ID，能够脱离原对话和其他报告独立阅读；tags 提供分类，关系图提供认识演进。报告保存形成时输入、依据、结果和边界，不自动成为当前事实、长期采用方向或实施授权。

所有已建立报告始终留在调查根目录的正常集合。被修正、推翻或拥有后继的报告仍是可发现的历史记录；关系、形成时间和叶节点都不推断当前结论、优先级或待办。

报告可以按需引用本地形成时资源。资源引用不是必需组成；没有资源的报告仍完整有效。维护入口只管理报告已声明的引用、资源完整性与派生索引，不为未声明资源补造关系。

## 使用条件

1. 用户明确要求记录、沉淀、创建、更新或审阅调查报告时使用。
2. 普通调查、排障和问答没有沉淀要求时，不主动建议或创建报告。

## 内容 owner

1. 本文件承接报告导向的调查流程、形成时内容质量、报告之间的关系判断，以及原地修正与新建报告的边界。
2. [固定契约](references/investigation-report-contract.md) 唯一承接 Investigation ID、目录、frontmatter、固定章节、tags、关系图、资源路径与 owner、索引、CLI 和事务的精确规则；创建、更新或结构审阅前完整读取。
3. `scripts/check-investigations.mjs` 提供 `check`、`sync-index`、`list`、`show`、`trace`、`set-relations` 与 `stage-index`；命令的参数、证明范围、诊断、索引新鲜度和写入边界只由固定契约定义。
4. [索引 Schema](references/investigation-index.schema.json) 提供机器可读的当前 JSON 结构；报告 Markdown 是标题、形成时间、问题、tags、关系、正文和资源引用的唯一事实源，资源文件保存材料内容。
5. 代码、规范、配置、决策和测试材料继续承接当前事实与长期选择；调查报告保存某一时点的调查输入、证据基础、认识和边界，不取代这些 owner。

## 工作流程

### 1. 确定本轮报告

1. 先确定任务出口：只读审阅不写文件；新证据或实质认识变化创建新的完整报告；只有当时认识没有被准确保存、格式或链接错误时才原地修正。
2. 读取目标工作区指令，通过固定契约定义的 `list`、`show` 和 `trace` 发现相关报告，再读取当前任务需要的事实 owner。索引缺失或失效时不使用旧投影猜测成员；需要维护时按固定契约恢复索引并核对资源。
3. 一份报告只承接一轮能够独立汇报的认识，不按命令、来源或每次试错拆分。把未来读者视为没有参与当前对话的人；报告不能依赖“同上”、相邻报告或未写出的默认前提。
4. 形成时信息无法可靠恢复时，将缺口标为未知并说明现有依据；缺口会改变本轮问题或结果解释时，再向用户确认。

### 2. 固定形成时输入与结果

1. 调查开始前能够取得信息时，先在工作记录或草稿中固定本轮背景与目的；整理已经完成的调查时，从当时材料和原对话恢复，不能用后来认识替换形成时输入。
2. `形成时背景` 保存当时发生了什么、基于哪些已知事实、假设、未知和约束意识到需要调查，以及影响结果解释的版本、环境、样本或工作区状态。
3. `调查目的` 写明本轮具体要回答的问题、准备支持的判断和预定边界；`调查范围与依据` 记录实际检查对象、来源、时点或版本、方法、覆盖范围和未覆盖内容。
4. `调查结果与边界` 区分已确认事实、基于证据的推断、建议、实际动作和当前未知，并说明适用条件、不能外推的内容以及需要重新调查的条件。
5. 计量或比较依赖的时间窗口、样本、指标、单位、纳入排除规则和误差；因果或机制依赖的候选解释、直接证据、反证和未闭合环节；方案、授权、恢复与验证等场景信息，都写入与其直接相关的四项核心。其他可选语义 H2 只能位于四项固定核心之后；声明资源时，`随附资源` 固定为第五个 H2，其他可选语义 H2 只能位于其后。
6. 调查默认只读。实验或其他副作用只在当前任务已经授权时执行；敏感材料只保留复核主张所需的最小信息。

### 3. 判断报告关系

1. 无直接前序的独立认识使用空关系。新报告只在正文和形成时条件足以支持时，声明一条或多条真实直接前序关系。
2. `补充` 增加不否定核心结果的证据、范围、视角或更细认识；`复查` 在新的时间、版本、环境、样本或约束下重新检查；`修正` 纠正部分解释、方法或结论；`推翻` 认定关键依据、方法或假设不足以支持主要结果；`归并` 整合多个前序；`拆分` 将过粗前序拆为可独立演进的多个后继。
3. 不从相同 tags、时间相邻、资源复用、普通 Markdown 链接或历史文件位置推断关系。间接祖先和后继通过 `trace` 恢复，不重复写入关系。
4. 推翻、修正及其他关系都不修改前序位置或可见性。需要当前口径时，显式综合相关报告与当前事实 owner。
5. 默认全量 `check` 若提示直接前序尚未进入 Git `HEAD`，复核该关系是否应保留为独立调查演进；这是非阻断提示，精确条件以固定契约为准。

### 4. 按需引用形成时资源

1. 正文和稳定事实 owner 已足以复核结论时，不创建资源。只有接口参数、原始响应、日志、截图、规范摘录或二进制样本不适合完整写入正文，且未来复核需要保留形成时内容时，才保存最小必要的非敏感材料并由报告声明引用。
2. 资源引用不能代替正文。报告仍在四项核心中说明材料来源、观测或处理条件、材料如何支撑结果，并概括影响结论的关键事实。
3. 已有稳定事实 owner 足以复核时直接引用该 owner，不复制快照。秘密、认证材料和其他不应进入仓库的信息不得写入报告或资源。
4. 报告不需要资源时省略 `随附资源`；需要资源时，按固定契约以 `./_resources/<resource-id>` 链接声明。资源 ID、owner、共享引用与版本控制可见性的精确约束不从本文件推断。
5. 新取得的实质材料使用新的资源 ID 并创建新报告；只有修正当时材料未被准确保存、无语义格式问题或移除不必要敏感信息时才原地修改已有资源。

### 5. 写入与维护

1. 按固定契约写入标题、formedAt、question、tags、relations 和四个固定非空核心 H2。新认识创建新的 Investigation ID 文件；改 basename 是身份变化，不从内容猜测改名。
2. 创建报告时可以直接声明合法关系。已建立报告需要调整关系时，只使用 `set-relations`：每个 `--source` 提供完整关系集合或显式清空，全部 source 在同一图预演和事务中处理。
3. `set-relations` 只改写选中报告的 relations 与工作区派生索引；它不改写其他 frontmatter、正文、资源或 Git pending。来源、索引或完整图预演漂移时命令必须零写入；发布失败时按固定契约恢复完整旧组合或报告明确恢复诊断。
4. 创建、删除、改名报告或改变资源引用后，使用 `sync-index` 从权威 Markdown 重建投影，再运行默认全量 `check`。删除已建立报告必须有当前任务的明确授权，并先修复指向它的关系和受影响资源 owner；不手工修补派生索引。
5. 多份报告共享索引但只交付其中一部分时，完成维护后使用 `stage-index` 选择对应 Investigation ID 的索引变化；报告 Markdown 与资源仍按实际提交范围单独选择。

### 6. 审阅与检查

1. 只读审阅不修改报告。逐份检查是否能够恢复形成时背景、目的、调查依据和结果边界；再审阅 tags 是否有内容依据、关系是否确属直接前序，以及资源是否确实支撑结论。
2. `check` 验证报告结构、完整关系图、资源与索引；scoped check 只提供局部反馈，不能证明完整图、拆分闭合、未引用资源集合或索引新鲜度。结构检查通过后仍按完成标准人工审阅正文和关系语义。
3. 可使用 CLI 的实际安装路径：

   ```text
   node <investigation-report-skill>/scripts/check-investigations.mjs sync-index --root <workspace-root>
   node <investigation-report-skill>/scripts/check-investigations.mjs --root <workspace-root>
   node <investigation-report-skill>/scripts/check-investigations.mjs list --root <workspace-root>
   node <investigation-report-skill>/scripts/check-investigations.mjs trace <investigation-id> --root <workspace-root>
   ```

## 完成标准

1. 任取一份报告，都能独立恢复形成时背景、调查目的、调查范围与依据以及调查结果与边界。
2. 背景没有隐藏默认前提，事实、假设与未知能够区分；证据范围与方法足以判断主张强度，结论没有超过证据。
3. tags 有内容依据且不表达状态或演进；关系使用真实直接前序，关系图不被解释为当前结论、任务或实施授权。
4. 报告一旦声明资源，正文已经说明其来源、观测或处理条件和支撑作用；资源没有取代关键事实与结论，链接完整性及未引用资源的诊断严重性符合固定契约。
5. 所有已建立报告保持正常发现路径；需要当前口径时没有把最新、叶节点或后继关系等同于累积完整，报告也没有取代决定、实施计划或当前事实 owner。
6. `set-relations` 只在关系需要调整时使用，且完整替换组、原子图预演和事务结果已按固定契约核对。

## 交接

调查形成长期采用方向、实施任务或稳定验证义务时，分别交给决策、规划或测试 owner。没有下游决定或任务，也不影响调查报告成立。
