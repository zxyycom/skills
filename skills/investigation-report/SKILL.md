# Investigation Report

## 目标与模型

用一份报告保存**一轮形成时认识**，使未参与原对话的读者仍能复核：为什么调查、检查了什么、依据是什么、得出了什么，以及结论不能说明什么。报告保存历史调查，不自动成为当前事实、长期采用方向或实施授权。

调查集合由下列对象组成；各自 owner 和精确结构以[固定契约](references/investigation-report-contract.md)为准。

```text
报告 Markdown（唯一语义事实源）
  ├── tags：可检索分类
  ├── 直接前序关系：认识演进
  ├── 可选形成时资源：复核材料
  └── 重建 ──> investigation-index.json（派生查询投影）
```

1. 每份 Markdown 是一个带稳定 Investigation ID 的报告。它完整承接该轮的问题、形成时内容、tags、关系和资源引用；索引不拥有第二份事实。
2. 关系从新报告指向真实的**直接前序**。它只表达认识怎样演进，不表达当前有效性、优先级、任务依赖或实施授权；间接脉络由 `trace` 恢复。
3. 所有已建立报告始终留在同一正式集合。被补充、复查、修正、推翻、归并或拆分的报告仍可发现；没有归档、隐藏或“后继自动取代前序”的语义。
4. 形成时资源是按需保留的支撑材料，不是正文或当前事实 owner 的副本。资源不存在时，报告仍可完整有效。
5. 默认全量 `check` 对直接前序尚未进入 Git `HEAD` 的关系给出非阻断 warning。它要求复核是否确应独立保留该演进关系，不表示关系错误，不阻断写入，也不以时间间隔判断。

## 使用条件

1. 仅在用户明确要求记录、沉淀、创建、更新或审阅调查报告时使用。
2. 普通调查、排障和问答没有沉淀要求时，在当前任务内完成；不要因“可能有用”自动创建报告。
3. 调查形成长期采用方向、实施任务或稳定测试义务时，分别交给 Decision、Change/Task 或测试 owner。没有下游决定或任务，不影响报告成立。

## 内容 owner 与读取路径

1. 本文件承接报告导向的调查、关系判断、资源取舍、维护流程与语义审阅；它不定义机器格式或事务细节。
2. [固定契约](references/investigation-report-contract.md) 唯一承接 Investigation ID、目录、frontmatter、固定章节、tags、关系类型与合法形状、资源路径及 owner、索引、CLI、诊断和写入事务。创建、更新、调整关系或结构审阅前，完整读取该契约。
3. [索引 Schema](references/investigation-index.schema.json) 是当前 JSON 投影的机器结构；报告 Markdown 是语义事实源，资源文件只承接材料字节。
4. 按以下顺序取得当前任务所需上下文：
   1. 读取工作区指令与固定契约。
   2. 通过契约定义的 `list`、`show`、`trace` 查找并读取相关报告；索引缺失或失效时，不把旧投影当作集合事实。只读审阅报告该缺口，并仅按可读 Markdown 审阅能够确认的范围；只有当前任务已授权维护时，才按契约用 `sync-index` 恢复索引。
   3. 读取能够证明或更新当前事实的代码、规范、配置、决策或测试 owner。报告只保存调查形成时的认识，不取代这些 owner。
   4. 若形成时材料、原对话或可靠事实无法恢复，将缺口写为未知；缺口会改变问题或结果解释时，再向用户确认。

## 工作流程

### 1. 选择正确操作

1. 只需要判断既有报告时，执行只读审阅，不写文件。
2. 新证据、不同条件下的复查或实质认识变化，创建一份新的完整报告；不要把后来认识回填成旧报告的形成时内容。
3. 只有原报告未准确保存当时认识，或存在格式、链接等记录错误时，才原地修正。改报告 basename 是身份变化，不从内容猜测改名。
4. 完整报告写入集合即已建立；草稿仍留在当前任务或其他草稿 owner。删除已建立报告属于破坏性操作，必须有当前任务的明确授权，并先按契约处理受影响关系和资源。

### 2. 形成可独立复核的报告

1. 将一份报告限定为一轮能够独立汇报的认识，而非一次命令、一个来源、一次试错或一条待办。
2. 让四项固定核心共同回答本轮问题：

   | 核心内容 | 必须让读者恢复的内容 |
   | --- | --- |
   | 形成时背景 | 当时发生了什么，以及促成调查的已知事实、假设、未知和约束。 |
   | 调查目的 | 本轮的具体问题、准备支持的判断和预定边界。 |
   | 调查范围与依据 | 实际检查对象、来源、时点或版本、方法、覆盖范围和未覆盖内容。 |
   | 调查结果与边界 | 已确认事实、推断、建议、实际动作和未知；适用条件、不可外推范围与重新调查条件。 |

3. 把决定主张强度的条件写在相关核心中：计量说明样本、指标、窗口、纳入排除与误差；因果或机制说明候选解释、直接证据、反证和未闭合环节；方案类说明授权、恢复和验证边界。
4. 不依赖“同上”、相邻报告、视觉位置或未写出的对话前提。区分已确认事实、基于证据的推断、建议、实际动作与未知；结论不得超出依据。
5. 调查默认只读。实验或其他副作用只在当前任务已授权时执行；正文和资源均只保留复核所需的最小非敏感信息。

### 3. 分类并表达认识演进

1. tags 只表达报告的可检索分类，且应有正文内容依据；不要用 tags 表示状态、当前有效性、关系、时间顺序或结论。
2. 没有真实直接前序的独立认识使用空关系。有直接前序时，先确认正文和形成时条件足以说明“本轮如何直接承接它”，再按固定契约选择关系类型。
3. 按认识变化选择语义：`补充`增加而不否定前序核心结果；`复查`在新时间、版本、环境、样本或约束下重检同一问题；`修正`只纠正部分事实解释、方法或结论；`推翻`确认关键依据、方法或假设不足以支持主要结果；`归并`综合多个直接前序；`拆分`将过粗前序发展为多个可独立演进的后继。关系类型的合法形状、排序和图约束只由固定契约定义。
4. 不从相同 tags、时间相邻、共享资源、普通 Markdown 链接或历史目录位置推断关系；不要重复写入间接祖先或后继。
5. 关系不会改变前序的位置或可见性。需要当前口径时，显式综合相关报告，并核对当前事实 owner；不要把最新报告、叶节点或后继关系等同于完整或当前结论。
6. 新报告可直接声明合法关系。已建立报告需要调整关系时，只使用契约定义的 `set-relations`，以完整关系集合进行图预演和事务化写入；不要手工修改索引或只更新局部投影。

### 4. 按需保存形成时资源

1. 正文与稳定事实 owner 已足以复核时，不创建资源。只有不适合完整写入正文、且未来复核确实需要保留的形成时材料，才保存最小必要的非敏感资源并由报告声明引用。
2. 资源引用不能代替正文：正文仍须说明材料来源、观测或处理条件、关键事实及其支撑作用。已有稳定 owner 足以复核的当前事实，直接引用该 owner，不复制快照。
3. 秘密、认证材料和其他不应进入仓库的信息不得写入报告或资源。资源 ID、链接写法、owner、共享引用和版本控制可见性的精确约束，以固定契约为准。
4. 新取得的实质材料通常随新报告使用新资源 ID；只有纠正未准确保存的当时材料、修复无语义影响的格式问题或移除不必要敏感信息时，才原地修改既有资源。

### 5. 同步、检查与交付

1. 只有当前任务已授权写入时，才创建、原地修正、删除、改名报告或修改资源；`sync-index` 写工作区派生索引，不能由只读审阅隐式执行。删除已建立报告仍须明确授权并先处理受影响关系和资源。
2. 除 `set-relations` 事务外，任何报告 Markdown 变动（包括创建、原地修正、删除、改名、tags、关系或资源引用变化）后，都从权威 Markdown 运行 `sync-index`，再运行默认全量 `check`；不得手工修补派生索引。只改资源字节时不运行 `sync-index`，但仍运行默认全量 `check`。
3. 已建立关系经 `set-relations` 成功调整后，事务已更新工作区索引；仍须运行默认全量 `check`，并审阅其中的 Git `HEAD` warning。warning 只要求复核该直接关系，不表示错误或阻断写入。
4. 默认全量检查覆盖报告、完整关系图、资源和索引；scoped check 只提供局部反馈，不能证明完整图、拆分闭合、未引用资源集合或索引新鲜度。
5. 多份报告共享索引但只交付其中一部分时，先按固定契约完成 `sync-index` 和默认全量 `check`。当前任务需要 Git pending 快照或为提交准备时，使用 `stage-index` 选择对应 Investigation ID 的索引变化；它会写 Git pending，报告 Markdown 与资源仍按实际提交范围单独选择。
6. 检查通过只证明结构、图、资源和索引符合契约。仍要人工审阅正文证据质量、敏感信息、历史修正正当性，以及关系是否真实且直接。

## 完成标准

1. 从任一报告本身能恢复形成时背景、目的、范围与依据、结果与边界，无需原对话或相邻报告补足关键前提。
2. 事实、推断、建议、实际动作和未知清楚区分；证据范围、方法和条件足以判断主张强度，结论没有越过依据。
3. tags 有内容依据且只作分类；每条关系均为真实直接前序，关系图没有被误读为当前结论、任务、优先级或实施授权。
4. 所有已建立报告保持正常发现路径；被修正、推翻或拥有后继不产生归档或隐藏。需要当前口径时，已综合相关报告并核对当前事实 owner。
5. 已声明资源确实支撑正文主张，正文说明了其作用，且未取代关键事实或泄露不应保存的内容。
6. 已按变更范围完成索引同步、默认全量 `check` 与人工语义审阅；关系调整后的 Git HEAD warning 如出现，已复核其直接关系而非将 warning 当作错误。
