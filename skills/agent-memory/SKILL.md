# Agent Memory

## 何时调用

用户要求查看或管理记忆时，按请求处理。主动召回前，先说清既有经验、纠正或待回访条件可能改变哪项当前判断；仅属同一项目或工具不足以触发查询。记忆提供线索；现行规范、当期事实和操作权限分别以对应规则、证据和当前授权为准。

调用前读 [CLI 操作](references/cli.md)，只使用宿主显式绑定的项目根和库。绑定或工具不可用时，报告缺口并继续不依赖记忆的工作。

## 召回与采用

1. **构造线索。** 从问题提取对象、动作和场景，换成项目术语。用精确标签和短原文片段调用 `recall`，无需原标题或 ID；未命中可换同任务的线索，截断时收窄查询。
2. **核对可用性与适用性。** 对候选用不带版本的 `show`。仅采用当前可用、确实回答本任务问题的证据；核对适用条件和重查条件。条件未知时只给带前提的结论，确需且获授权时回查来源。显式历史只用于回看。
3. **交代采用结果。** 区分材料记载、限定条件下的直接观察、推断和用户确认；说明采用的依据，以及影响判断的适用范围和未知。区分未查询、未命中、命中未采用、采用与查询失败。

### 待回访意图

当前任务涉及活动意图指定的问题且满足其触发条件时，才核对证据；新证据会改变判断才提醒，并说明改在哪里。意图不授权轮询、后台执行或其他行动。结束意图保留原证据但停止主动回访；独立任务后来需要同一证据时，按该任务的授权处理。

## 保存与修订

1. 只保存用户明确要求保留的项目内容，排除凭据等敏感值。说明要改善哪项判断，先查是否已有同一认识；记录出处、适用条件、未知及形成时间或重查条件。标明推断，用对象、动作、场景和常用换述作标签。
2. 基础认识保存实际依据。联合认识引用确切前提版本，解释每项前提的作用，并用新问题检验解释；一般的支持、限制和冲突不算构成依赖。待回访意图记录触发条件和要核对的问题。
3. 修订须核对当前版本，说明结论、范围、确定性或状态是否实质改变。用现行可用前提复核，或明确移除不再采用的前提。含义不变与实质改变分别声明；冲突未解则保持待复核。

## 用户控制

按 [遗忘预览与提交](references/cli.md#遗忘预览与提交)选择停用、隐藏或库内清除。清除前说明将删除的单元和历史、保留单元将失去的关联，取得用户对本次预览的明确确认。连带删除不可接受时，在授权范围内选择保留历史的操作。

保存、修订或控制后核对后态，说明实际生效的范围和保留的内容；不能核对时说明缺口。
