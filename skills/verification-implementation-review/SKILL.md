# Verification Implementation Review

## 目标与触发边界

审查“用来判断代码或工程产物是否正确的实现”，并让值得保留的测试与工程校验能够按证明目标和实现入口快速查找。触发对象必须是验证实现本身：

1. `test` 通过安排输入、状态或交互并断言可观察结果来证明行为。
2. `check` 通过脚本、规则、配置或工具入口判断代码、schema、生成物、依赖或工程状态是否满足约束。

普通业务实现和它需要满足的契约只在 skill 已由测试或 check 任务触发后作为判断上下文，不独立触发本 skill。修改业务运行时的参数校验、权限判断或表单校验属于产品实现；只运行既有测试、lint、类型检查或构建也不触发。任务同时修改业务实现和验证实现时，因为后者进入本流程。

测试框架、编译器、linter 和项目命令负责实际执行；项目测试策略拥有层级、覆盖要求和常规验证入口。本 skill 不替代这些 owner，也不把命令成功或目录登记当成证明质量成立。

审查、查询和评估请求保持只读；只有修改请求才更新验证实现、行为 owner、case 目录、配置或派生索引。

## 内容 owner

1. 本文件承接触发判断、语义评估、处置流程、写入授权和完成标准。
2. [catalog-contract.md](references/catalog-contract.md) 是 case 字段、派生索引、配置、CLI 和机器接口的固定契约。
3. `scripts/verification-catalog.mjs` 只校验、同步和查询显式 case；它不发现验证入口、不执行 Entry、不修改 case 正文，也不判断证明价值。
4. [migrate-from-test-evidence-review.md](references/migrate-from-test-evidence-review.md) 只在工作区仍使用旧名称、旧配置、旧 CLI、源码 marker 或旧 case 字段时读取。
5. 项目行为 owner 承接需要长期保持的产品、接口、schema、安全或工程规则；case 的 `Contract:` 只压缩当前验证实现必须证明的背景，不取代 owner。

## 读取与范围

1. 先读取项目指令、测试或校验策略、当前 diff、目标验证实现及其执行入口。确认当前任务确实新增、修改、删除或审查验证实现；否则停止使用本 skill。
2. 已有目录时先运行 `list --query <text>`，按 case ID、标题、契约摘要或 Entry 定位相关 case；主题不明确时再用无查询的 `list` 恢复有界概览，然后用 `show` 只展开目标 case。
3. 读取相关行为 owner 和被验证实现，只恢复判断证明价值所需的上下文，不把所有普通业务改动扩成验证审查。
4. 纯语义审查先使用本文件和查询结果；准备写入、修复结构、调整配置或诊断精确字段时才完整读取固定契约。
5. 目录不存在时，修改任务在完成语义评估并至少保留一个验证实现后初始化；只读任务只报告拟登记 case，不创建文件。
6. 遇到 `.test-evidence.json`、`test-evidence-ledger.mjs`、`test-entry-regex.mjs`、`@test-evidence` 或 `Verification: automated|review|exempt` 时读取迁移文档。

## 语义评估

先恢复验证实现要证明的契约，再判断它如何产生可信信号：

```text
Contract：需要长期保持的行为、边界或工程不变量
验证路径：输入、目标、规则或执行阶段
Proves 项：条件或检查点 -> 可观察结果
Entry：实现位置或项目拥有的调用入口
```

保留或新增验证实现前同时确认：

1. **契约背景**：能说明产品规则、接口行为、schema、安全边界、错误语义或明确工程不变量。
2. **证明信号**：失败能指出哪项契约不再成立，而不只是提示实现文本发生变化。
3. **可观察性**：测试断言可观察结果或当前层拥有的不变量；check 判断可复核的工程状态。
4. **可靠性**：输入、环境、fixture、规则和结果足够确定，不依赖偶然顺序、未声明环境或自证循环。
5. **独立性**：验证没有直接复述被验证实现或仅确认自己的 mock、fixture、快照或生成逻辑。
6. **重复与成本**：没有被既有 case 等价覆盖，执行、维护和故障定位成本与新增证明价值相称。

验证器自身的测试证明验证器实现正确；运行验证器证明目标符合规则。二者是不同证明，不合并为一个 case。聚合命令只负责调用其他验证时不是独立 case；只有它自身还固定了顺序、输入组合、失败汇总或其他稳定契约时才单独登记。

## 主流程

1. **界定验证实现**：列出本次新增、修改、删除或审查的测试、校验脚本、规则、配置和入口，以及它们预期证明的契约。
2. **搜索既有 case**：按契约、输入类别、错误、输出、实现入口和规则名查询目录；比较证明语义，不只比较文件名或命令名。
3. **选择处置**：每个验证实现只选择一个主要结果。
   - **待确认**：缺少稳定契约、可观察结果或可信信号；不创建 case。
   - **不保留**：没有独立证明、可靠性不足或成本明显高于价值；不新增或删除。
   - **复用**：既有实现和 case 已经承接相同证明；不重复登记。
   - **合并或扩展**：共享契约、验证基座或连续执行链路；合并重复实现，或向既有 case 增加独立证明点和 Entry。
   - **新建 test case**：测试实现形成独立契约、观察入口、运行环境或维护周期。
   - **新建 check case**：工程校验实现形成独立规则、目标集合、失败信号或维护周期。
   - **交给其他 owner**：风险只能由人工流程、运行时监控或发布治理承接；报告交接，不在本目录创建伪验证 case。
4. **按授权实施**：使用最小输入、规则和断言完成处置；契约与实现冲突且无法从现有 owner 判断时，只确认应改变哪一方。
5. **显式登记**：只为已经存在且决定保留的 test/check 实现写 case；填写 `Verification`、`Entry`、`Contract` 和 `Proves`。不为计划、豁免、人工风险或发现结果建 case。
6. **同步索引**：case 内容变化后运行 `sync-index --write`。索引是可重建查询副本，不手工编辑。
7. **验证结果**：运行直接证明验证实现行为的最小项目命令，再运行目录 `check`；按项目要求补充类型检查、lint、构建或更大范围测试。

## Case 与索引原则

1. 目录按稳定契约和共享验证链路组织，不按测试函数、规则条数或 CLI 子命令机械枚举。
2. 多个证明点共享 fixture、输入集合、规则上下文或连续链路，且拆分会复制准备、丢失顺序关系或增加同步成本时保留在同一 case；形成独立契约、入口、运行环境或维护周期时拆分。
3. `Entry:` 是显式登记的实现定位信息，不是自动发现结果。一个 case 可以登记多个文件、规则、任务或命令入口；CLI 只索引文本，绝不执行。
4. Markdown 目录是权威源；索引只保存 case ID、标题、类型、首条契约摘要、Entry 和源范围。完整 `Contract:`、`Proves:` 和图示只由 `show` 按 ID 展开。
5. 不扫描源码、不要求 marker、不统计未登记函数，也不自动创建或修复 case。登记发生在 agent 已完成语义处置之后。

## CLI

从 skill 目录运行，或使用脚本绝对路径：

```text
node scripts/verification-catalog.mjs list --query "<contract or entry>" --root <workspace-root>
node scripts/verification-catalog.mjs show <case-id> --root <workspace-root>
node scripts/verification-catalog.mjs sync-index --write --root <workspace-root>
node scripts/verification-catalog.mjs check --root <workspace-root>
```

`list` 可组合 `--query`、`--verification test|check`、`--limit` 和 `--offset`；`show` 只展开一个 case；`sync-index` 默认检查，增加 `--write` 才原子重建；`check` 校验配置、目录结构和索引新鲜度。需要机器输出时增加 `--json`。精确字段、输出 Schema、退出状态和导入签名以固定契约为准。

## 完成标准

### 只读审查

1. 先给总体判断；对每个需要动作的验证实现说明位置、处置、契约、证明信号和成本依据。
2. 没有越过只读授权；拟登记 case、未运行环境和结论边界已经说明。

### 修改验证实现或目录

1. 每个保留 case 都对应已存在的 test 或 check 实现，具有可定位 Entry、可独立理解的 Contract 和可观察 Proves。
2. 没有把计划、人工风险、普通业务实现、运行时输入校验或发现豁免登记为验证实现。
3. 派生索引已从合法目录同步；已运行最小相关项目命令和目录 `check`，或明确报告无法运行的边界与残余风险。

### 通用交付

报告实际改动、项目验证、目录校验、未执行环境和残余风险，并区分验证实现失败、被验证对象失败与目录结构失败。
