# Novel Cards

## 目标

用卡片承接作者的当前规划，从构思或已有文本建立小说结构，按受影响层级修改，再依据细纲与导演视角写作。正文反推提供可定位的差异证据，卡片或正文如何修订由作者决定。

## 读取路径与运行前提

1. 建卡、修改或理解引用前读 [卡片契约](references/card-contract.md)：字段、目录、身份、引用和变迁效力由它承接。
2. 调用工具前读 [本地 CLI 操作契约](references/local-cli.md)：命令、批量输入、索引、恢复与运行时边界由它承接。
3. 正文反推或检查前读 [反推与对照报告](references/review-report.md)，按提取、对照与回查阶段执行。
4. 本地工具需要 Node.js >=24.18，无其他 skill 运行时依赖。实际稿件、卡片与报告保存在小说项目；已安装 skill 提供通用流程、契约与 CLI。

## 卡片模型

- **详情**承接领域实质：剧情详情保存细纲与导演视角；人物/设定详情保存核心信息与明确剧情位置上的状态。
- **总结**递归压缩组成卡或来源，保留因果、转折、条件与残余矛盾。顶层剧情总结叫剧情卡，卷、册、弧线等组织自由；章也可以是总结，执行写作前展开到详情。
- **定位**分别使用稳定 ID、版本、可变章号与可重用标题。`chapter.scope` 指实际剧情卡，表达全作或卷等计数范围；日常按章号/标题列候选，选择后再读取。
- **变迁**以事件和锁版本端点连接多个对象的完整前后状态。故事演进保存真实阶段，作者修订保存旧设定但明确其失效；历史总结承接压缩解释，专门记录承接变迁事实。
- **来源与状态**独立：本作卡放 `cards/`，来源放 `reference/`，旧版放快照，当前变迁放专门区。`expected` 表达未来预期，`planned` 表达待展开；二者不由目录或版本推断。
- **正文**承接小说文本，对应、定位与版本证据放外部报告，无需维护性回标。人物关系分方向表达态度和所知，共同事实与各方理解分别复核。

## 主工作流

### 1. 恢复任务与阅读范围

1. 确认小说项目根、作者意图、当前故事位置、叙述范围、已有卡片/稿件以及写入授权。已有文本与原创构思走同一工作流，只是事实输入不同。
2. 对同人确认原作 cutoff。cutoff 之后的设定/弧线可由作者选入本作卡作为可修改预期；后续单章详情可完整提取至独立参考区。区分已保存的参考内容与作者已采用的当前规划。
3. 先运行 `check`；未初始化或索引陈旧时核对来源，合法集合经授权显式 `sync-index --write`，再查询。未结算批量事务先按诊断恢复。
4. 已知身份用 `show ID` 或 `show ID@N`；日常定位用 `find --title TEXT` 或 `find --chapter N [--scope ID]`。按候选的标题、章号、`scopeTitle` 与实际来源选择，不猜测重名卡。
5. 先 `show` 顶层或最高相关总结，再用有界 `expand` 逐步下钻；从返回的 `frontier` 继续读取。`expand.complete` 只描述本次 `children` 闭包，所需的 `sources`、`refs`、关系与状态锚点正文须另行显式读取。
6. 参考内容用具体 ID 与 `--include-reference` 显式选择。CLI 全体机械扫描会读取参考区字节校验，但查询只输出被选内容；分别记录校验范围、agent 实际阅读范围与作者采用范围。

### 2. 建立或反推卡片

1. 从作者意图或来源正文恢复剧情结果、动机、代价、因果与信息变化；不确定项留为作者问题，不补造发生事实。
2. 从顶层剧情卡逐步展开，组织标签按实际小说采用。待展开规划使用 `planned`，可以保留无下级总结。
3. 剧情详情分“细纲”和“导演视角”：细纲记录事件因果、行动与变化，导演记录多线组织、切场、焦点人物、视角、信息显隐及节奏，不强迫严格电影分镜。
4. 人物/设定详情通过 `state_at` 锚定剧情位置；核心信息与位置状态分别写清。关系态度、人物所知与作者所知分开，不把单向认识当双向事实。
5. 用总结承接下层因果与条件，`sources` 引实际依据，`children` 引实际组成卡。
6. 时间元数据附在相关卡，分别写故事时间与叙述位置。`expected`（预期/未来）表示作者安排但尚未发生；`planned`（待展开）表示规划完整度。混合范围总结使用 `mixed`，正文分清已发生与预期段，保持 `occurred` 的真实发生含义。
7. 完成机械检查与语义复核，再同步索引。

### 3. 修改与传播

1. 作者先确认修改意图，从**最高受影响卡**向下复核：改变顶层结果先处理顶层；局部变化先判断是否影响更高总结，再从最高实际受影响处下传。
2. 查实际 `children`、`sources` 与 `refs` 依赖，列出受影响卡、原因、正文范围和待决定项。位置状态与预期分别核对，预期不自动覆盖已发生状态。
3. 实质内容改变时保留完整旧卡并提升版本。新节点发生采用 `evolution`，作者纠正采用 `revision`；先确认事件和各对象前后版本，再按 CLI 契约准备完整记录与更新，用 `apply-transition --input FILE --write` 批量维护。关联由记录自动派生，无需反向回填。
4. 修改既有变迁保存同 ID 新版本；替代另一演进使用 `supersedes`，撤回使用 `withdrawn`。替代影响整条记录，局部作者更正也须完整保留其他仍成立的对象关系；具体效力见卡片契约。
5. 用 `history` 查有效关联，再显式读取所需前后版本。区分演进、作者修订、撤回与计划；快照未锁引用仍指当前，历史语境未保证时如实说明。
6. 重写总结时恢复原因、转折、条件与残余冲突，复核是否准确概括实际组成或来源。索引同步只确认机械当前性，摘要有效性由作者与 agent 判断；交付列出已核对/未核对项。
7. 正文发现新构思先报告，由作者决定改卡并下传，或改正文回到规划。正文反推不自动回写卡片。

### 4. 按卡写作

1. 读取目标详情、必要祖先约束、实际依据、人物/设定位置状态；引用只证明可定位，需要显式读取所需正文，不以索引标题推断内容。
2. 明确这次章节采用的细纲、导演约束、可自由调整的表达及允许的差异。若章为总结，先展开到本次执行详情；需要留存对应时，由外部报告记录所用目标 ID 与版本。
3. 写作时保留因果和信息义务，允许语言、镜头密度和局部呈现的合法变化。输出正文是无需回标的纯文本，不改卡或发生状态。

### 5. 正文反推与独立对照

1. 先按报告契约锁定正文版本与定位方式，提取阶段读取正文和必要背景，不读取目标细纲/导演规划；若无法隔离已有上下文，如实标记，不冒充盲审或独立模型。
2. 先交付证据化细纲、实际导演视角与模拟读者信息/期待，再独立读取目标卡逐项对照；模拟读者不是实际读者测试。
3. 缺漏或冲突先回查正文，并区分“正文未表现”和“提取未发现”。差异分类：合法差异、偏离、证据不足、待作者决定。
4. 检查只产出报告，作者决定改正文，或先改卡再传播。本 skill 提供本地流程，未接通独立远端审稿 API；外调需要独立接口契约及显式稿件传输、费用授权。

## 完成标准

- 卡片模型、稳定身份/版本、章节计数范围、发生与完整度、状态位置、参考使用和传播路径清楚；所有受管引用可定位。
- 批量变迁保存完整旧卡，历史关联自动派生；演进、作者修订、撤回与预期效力明确。正文对应保存在外部报告，快照的版本锁定与未保证历史语境可辨。
- 本次机械校验与语义复核分别说明：身份、引用和索引正确不证明因果、人物理解或文学质量；读取预算与未读 `frontier` 明确呈现。
- 报告引用正文定位，缺漏有回查记录，提取与对照隔离程度如实呈现；卡或正文修订由作者决定。
