# 路径权限诊断

## 适用范围

目标程序已经启动，但读取、写入、执行、删除或元数据访问返回 `EPERM`、`EACCES`、`Access denied`、`permission denied` 或等价路径权限错误时读取。本文件用于确定哪一层拒绝了什么访问，再选择范围准确的处理动作。

进程没有启动时回到 [SKILL.md](../SKILL.md) 的创建进程分支；目标程序已经完成路径访问并返回测试、编译、HTTP 或其他业务错误时退出权限诊断。

## 核心权限模型

Shell 不是以当前交互用户或管理员的完整身份运行，而是使用沙箱专用的低权限账户和受限 token。`elevated` 表示沙箱部署阶段可以建立账户、ACL 等边界，不表示目标命令以管理员身份执行。

该执行身份通常只能写入专用账户自身可写位置和当前 profile 明确授予的 write roots；其他路径可能广泛可读，但受保护路径、显式 deny 和程序额外请求的访问权限仍可使读取失败。因此，文件访问结果必须由**执行身份、permission profile、有效 ACL 和请求权限**共同判断，不能从当前用户权限或单个 read root 推断。

## 保留诊断事实

开始处理前保留：

1. 完全相同的原始命令、完整错误和失败路径。
2. 目标程序的实际运行身份、token/integrity 信息；未提供的事实标记为未知，不从当前交互用户推断。
3. 本次 task 实际注入的 permission profile 和 read/write roots；未提供的事实不从配置文件推断。
4. 程序请求的动作：读取、写入、执行、删除或元数据访问。
5. 路径来自显式参数、仓库入口，还是工具自动寻找的配置、缓存或默认文件。
6. 命令副作用，以及离开当前 sandbox 执行是否仍在用户授权范围内。

只检查定位拒绝层所需的路径、配置键和 ACL；不要输出包含 remote、credential helper、token 或其他无关敏感值的配置全文。

## 判断拒绝层

| 权限层 | 可核对证据 | 处理方向 |
| --- | --- | --- |
| 执行身份与 token | `whoami`、用户组、integrity 或 privilege 表明目标程序使用沙箱专用受限身份 | 不从当前交互用户的访问能力推断命令权限；后续检查和 ACL 判断都使用目标程序的实际身份 |
| Permission profile | 目标路径或请求动作不在本次 read/write roots 内，或 profile 明确拒绝访问 | 当前命令确有必要时申请精确 escalation；长期修改 profile 前取得用户授权，并在 profile 实际注入后验证状态 |
| 文件系统权限 | 当前运行身份缺少所需 allow，或有效 ACL 存在覆盖它的 deny | 不重复增加 read root，也不修改 shell rule；选择精确 escalation，或由权限 owner 批准 ACL、产品或布局修复 |
| 程序请求权限 | 用户意图是读取，但运行时同时请求写入、删除、同步或其他被拒绝权限 | 保留运行时错误；当前任务可精确 escalation，长期方案调整工具入口、访问方式或文件布局 |
| 工具隐式路径 | 错误路径不在原始参数中，而是工具自动寻找的配置、缓存或默认文件 | 只查询相关配置键和来源；经用户授权后改到可访问位置，并验证工具实际读取新来源 |
| Shell permission rule | runner 在进程启动前返回 `allow/prompt/block` 或 `execpolicy` decision | 该层控制命令是否启动，不授予目标程序文件访问权限；若进程未启动，回到 [SKILL.md](../SKILL.md) 的审批分支；长期 rule 只有用户批准后才维护 |

配置文件、旧调查和其他 task 的成功结果只能提供线索，不能代替本次执行身份、profile、有效文件系统权限和实际命令结果。

## 选择一个处理动作

1. **精确 escalation**：命令对当前任务必要，失败路径、请求动作和副作用均已确认。批准后可能使用不同的执行身份或权限上下文；成功只说明该命令完成，不说明原身份的路径权限已经修复。
2. **配置修复**：工具自动访问不可读路径，且存在范围更窄的显式配置。经用户授权后修改对应配置 owner，并验证配置来源和原错误都已改变。
3. **布局或工具入口修复**：日常运行入口稳定落在受保护路径并持续需要 escalation。把运行时代码或普通数据移到符合权限边界的位置，同时验证原生入口和引用。
4. **ACL 或产品修复**：有效权限与产品承诺不一致。单独调查并由对应 owner 修复；不要在一次失败处理中删除 deny、放宽整个目录或切换 full access。

## 机制校准

以下是权限层的校准，不是按特定目录分流的规则：

1. Permission profile 中的 read root 不能覆盖文件系统上的显式 deny；部分运行时的“只读”打开也可能请求同步或 generic access，因此错误必须按实际请求权限判断。
2. 工具因隐式默认配置路径失败时，应修复该工具的路径来源，而不是改写 `HOME`、禁用整类配置或放宽整个用户配置目录。

## 完成边界

1. 精确命令成功：只说明该命令已完成。
2. 普通 sandbox 内同一入口成功：只说明当前 task 的该入口已恢复。
3. 配置或布局修复完成：必须验证工具使用了新来源或入口，并且原权限错误消失。
4. Permission profile、文件系统权限或 rules 已修复：必须分别取得对应层的直接证据，不能从一次 escalation 成功推断。
