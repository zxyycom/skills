# JEV 使用边界与任务验证

本文供选择任务、调整输入和解释结果时按需查阅。模型特性由下列官方文档支持；验证建议用于当前任务，不表示该任务已经测得效果。随包 CLI 的配置、输入输出与失败处理以 [CLI 操作契约](cli.md) 为准。

## 输出空间与问题拆分

JEV 通过 Choice、Score、Noul 返回候选、等级位置或命题概率；每题对同一 state 独立判断。开放文本生成与依赖前题答案的后续推理需要另外组织。原语定义见 [Primitives](https://docs.typesafe.ai/primitives)，字段定义见 [API reference](https://docs.typesafe.ai/api)。

按答案实际用途拆题：

- 从既有对象中选择时，发送必要候选内容与稳定 ID，得到答案后按 ID 取回对象。
- 可以同时成立的性质分别提问；只选主项时，给出择优标准。
- 需要表达缺证、无匹配或冲突时，提供相应输出；字段是否存在、数量与精确比较由代码先行检查。
- 候选发现、模型判别和最终采用分别验收。每题答案按实际材料和所问维度解释，整体任务仍按自己的覆盖要求完成。

## 输入条件与验证重点

官方 [JEV 1.13 局限说明](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 提醒：数值精度、间接推理、无关长上下文、对抗内容和候选顺序可能影响判断。这些说明针对该型号；以下是据此采用的任务准备与验证方法：

| 当前任务条件 | 准备与验证方法 |
| --- | --- |
| 算术、计数、日期顺序或精确字符串匹配 | 用代码得到确定结果，JEV 只承担其中仍需要理解含义的部分 |
| 隐含前提、复杂否定或多步依赖 | 明确对象、条件与字段路径；独立题合并，依赖题分次调用 |
| 候选多或材料长 | 先检索相关材料并保留出处；声称完整覆盖时核对完整集合，筛选结果保留实际覆盖范围 |
| 候选顺序、命名或表示方式可能影响答案 | 保持稳定 ID，选择等义变体检查语义答案是否稳定；把变化作为诊断信号，不据此挑选有利答案 |
| 输入包含试图改变任务的指令 | 将输入限定为被判断数据；用对抗样例验证集成，权限和后续操作由调用方控制 |

类型影响语义时，保留必要类型或显式说明；数字与同形字符串的精确等同性仍由代码确认。调整格式时保持事实、候选与判据不变，才能区分表达变化和任务变化。

官方 [Models](https://docs.typesafe.ai/models) 将英文列为主要训练语言，建议对非英文工作负载使用自身材料验证。本 skill 默认保留任务语言；翻译作为待验证的输入方案，需核对专有名词、条件与否定是否等义。

## 概率、评分与采用

`confidence` 概括 Choice／Score 概率分布的确定程度，Noul 使用自身的肯定概率表达不确定性。官方建议按领域与风险测试阈值，见 [Confidence](https://docs.typesafe.ai/confidence)。

采用时分别核对：

1. **字段含义**：Score 是等级位置，不是从等级之间插值得到的精确业务数值；Noul 接近 0.5 不是程度中等，也不能单独区分缺证与证据冲突。
2. **有效与正确**：CLI 的 schema 校验、服务返回的 confidence 和目标任务中的正确率是不同事实。返回字段保持原样，复核结论另行表达；异常先按 [CLI 校验边界](cli.md#输出与校验)定位。
3. **采用条件**：阈值用于排序、待复核路由还是自动采用，要分别说明。多题组合仍保留各题的不确定状态；模型答案不授予业务操作权限。

## 按目标任务验证

准备规模化采用、设置自动采用阈值或调整输入方案时，按错误代价选择验证范围；新服务调用仍需在外发与费用授权内。

1. 选取正常、边界、缺证和易混淆样本；区分随机样本与定向问题样本，并为参考判断保留依据。复核意见存在分歧时单列，不当作确定金标。
2. 保留实际输入、原始答案、模型版本和复核结论的对应关系；留存受数据权限约束，需要正文日志时显式开启。
3. 调整题目、表示或阈值后，用未参与调整的样本检查。分别报告技术失败、覆盖率、接受项错误与待复核项，不把对同一样本的反复调整当作独立验证。
4. 候选集合、量尺、模型或领域变化后，复查采用条件是否仍适用。协议成功、重复同答及某次零错误都不单独证明可靠性。

样本量不足时只报告已观察结果及其边界；用来发现问题的定向样本不估计总体准确率。流程收益比较还须计入下节的总开销。

## 通道、成本与耗时

上下文窗口、限额、报价与别名指向由所选服务维护。直接 TypeSafe 通道查 [Models](https://docs.typesafe.ai/models)，OpenRouter 查 [System One 接口说明](https://openrouter.ai/docs/guides/community/typesafe-sdk)及其模型入口；调用时保存实际返回的 model。文档可访问不证明账户鉴权、余额或服务可用。

评估是否更省、更快时，比较直接处理与委托判断的整体质量和开销，委托侧计入输入准备、CLI 启动、请求、复核与回退。超时和并发按实际通道及任务期限设置，单次请求耗时不能代替端到端收益。

已有日志可通过 [stats](statistics.md)核对调用数、用量覆盖、耗时分布与显式批次。它只汇总已留存的调用，不提供模型准确率，也不触发新推理；没有服务报告的费用保留缺失。
