# 保留数据的版本迁移

需要把旧数据用于新版本时，按来源 → 目标选择记录，核对字段如何保留、回填或保持未知。无需旧历史时，按[重新建库](../references/call-logging.md#不保留历史重新建库)移走旧库，后续日志写入会自然创建新库。

## 选择迁移记录

日志版本由 SQLite 的 `PRAGMA user_version` 标识，`application_id = 1246058033` 标识本工具的日志库；日志、skill 的 `metadata.version` 与 JEV 模型各自独立版本化。

| 来源 → 目标 | 版本含义与变化 | 迁移记录 | 附带脚本 |
| --- | --- | --- | --- |
| 日志 v1 → v2 | 保留 v1 的 19 个字段，增加批次 ID／序号、标签、请求／响应字节数与批次唯一索引 | [字段映射与使用条件](log-v1-to-v2/README.md) | [migrate.sql](log-v1-to-v2/migrate.sql)：已知原始 UTF-8 日志的简单转换 |

先读对应记录的适用条件与字段映射，再决定是否使用附带脚本。没有匹配记录时，先查明数据结构与字段语义。迁移由使用者显式执行，日常命令与 skill updater 不自动运行或串联迁移脚本。

## 维护版本迁移记录

本节面向迁移方案的维护者。每个来源 → 目标方案在按对象与版本命名的独立子目录中维护一份记录，供重复使用；新增版本转换另建记录，保留各版本的含义。记录说明：

- 来源与目标的身份、结构和适用条件。
- 字段含义、单位、允许值，以及 NULL、零值和默认值的区别。
- 数据来源、转换方法、可靠性条件与缺失对目标能力的影响。
- 与转换相称的执行、验证和数据保护方法，以及所需人工输入或决定。

脚本可选，只为来源可得、转换可确定且能验证的部分提供。附带时须说明前置与覆盖范围，并验证支持路径、失败处理和数据保留。缺少必需数据或依赖未知映射时，记录缺口与人工处理条件；目标允许缺失时保留未知值，不提供猜测性或占位脚本。
