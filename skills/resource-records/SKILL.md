# Resource Records

## 何时使用

希望以后能找到一组持续变化的内容时，登记目录或文档入口即可，里面的文件可保持原样。需要选用或追溯某个确切文件时，再登记文件及版本。

探索过程的调用和观察保存在项目记录中；资源卡记录值得留用、独立修改或复用的对象。媒体保管、备份和验收由项目负责。

## 按任务读取

- 查询、同步和恢复：读 [CLI 操作](references/cli-operations.md)，参数以实际 `--help` 为准。
- 判断对象粒度和用途选择：读 [组织与选择](references/organization.md)。
- 填写或审阅记录：读 [记录模型](references/record-model.md) 和链接的 schema；按需复制[集合模板](templates/collection.md)、[资源模板](templates/resource.md)或[逻辑入口模板](templates/logical-resource.md)，替换占位内容。
- 学习完整记录和查询：读[共享示例](references/examples.md)。

## 查询：从候选到可用结果

1. 确定工作区和用途。已知集合、标签或用途槽用 `list`；线索是名称或已登记路径用 `search --metadata`；线索在记录正文中用 `search`。这些命令查的是记录，不是入口所指目录的内容。
2. 用 `show` 回读当前源记录，核对所选版本、成员或用途。需要解释来源时用 `trace`，检查关系类型、方向、终点和截断。空结果只说明本次查询范围没有命中。
3. 交付可回查的入口或精确引用、依据及未核实之处。只读任务保持工作区不变；索引缺失、过期或 CLI 不可用时，按[失败分流](references/cli-operations.md#失败分流)回读源记录并说明覆盖范围。

## 维护：登记并验证

1. 先查询已有记录，按[组织与选择](references/organization.md)确定身份粒度。导航到持续变化的内容用逻辑入口；固定某次选用的文件用确切版本和成员。
2. 在授权范围内编辑源 Markdown。保留历史和可回查证据；未知来源、未知哈希或位置、已知文件缺失分别说明。原始调用、媒体保管和核验由项目负责。
3. 有用途选择时，在相应集合的 slot 记录目标、scope、证据和 basis，区分代理暂选、用户偏好和用户确认。更改已确认选择须有当次授权。
4. 维护授权包括必要的 `sync-index` 和 `check`；通过后用 `show` 或按需 `trace` 回读。交付实际改动、验证结果和待决定事项。记录校验不证明媒体可用、许可或备份，也不授予媒体操作权限。
