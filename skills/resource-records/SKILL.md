# Resource Records

## 何时使用

需要决定可留用对象怎样登记、追溯确切文件或维护某用途的选用时使用。探索调用只需依项目要求保留真实调用及观察，不强制逐张建资源卡；无产物调用不是资产。有留用、独立修改或复用价值时再登记，保管、备份和媒体验收由项目负责。单纯查原始调用或管理媒体，不因主题相近而改写资源记录。

## 按任务读取

- 查询或执行命令：读 [CLI 操作与恢复](references/cli-operations.md) 对应命令；参数以实际 `--help` 为准。
- 登记或审阅结构：读 [记录模型](references/record-model.md)；精确结构以随包 schema 为准。复制 [集合模板](templates/collection.md) 或 [资源模板](templates/resource.md)，替换占位内容。
- 不确定对象粒度、关系或选择：读 [组织与示例](references/organization.md)；例子仅用于隔离工作区，不是真实资产。

## 工具和工作区

安装包的可执行文件位于本 skill 目录的 `bin/resource-records`，Windows 为 `bin/resource-records.exe`；源码试用使用实际构建的程序，不假定已安装。工作区默认当前目录；跨目录调用加 `--root <工作区根>`。默认读取其 `resources/records/`，自定义时以 `--resources-dir <相对工作区根的目录>` 指定资源目录。先运行该程序的 `--help`，操作与失败分流见 [CLI 操作与恢复](references/cli-operations.md)。

CLI 不可用时，可直接读取源 Markdown 回答只读问题，或在授权范围内按模型起草真实记录；说明没有机械校验、索引及查询覆盖的局限，不声称工具验收。

## 查询：找到并交付

1. 确定工作区、用途和需要的精度。按集合、标签或 slot 用 `list` 找候选；名称、ID 或标签线索用 `search --metadata`，正文线索用默认 `search`。空命中不等于资源不存在；必要时换查询范围或回读源记录。以 `show` 回读确切 ID、版本和成员。
2. 多个标签是 AND；`list --slot` 返回声明该 slot 的集合，须 `show` 才能看到选择。索引查询不保证新鲜，注意 freshness 和搜索覆盖。
3. 需要来源时用 `trace`。默认仅直接来源而非全图；按问题显式选类型、方向、深度及节点/边限额，检查截断和终点。
4. 交付结果、确切引用、来源及缺口，然后结束。只读请求不附带登记或同步；索引缺失或陈旧时按 [失败分流](references/cli-operations.md#失败分流)处理。

## 维护：判断、登记、选择

1. 先按查询路径恢复已有事实。集合表达稳定层级，资源表达独立选用对象或制作分支，版本固定既有文件身份、内容和图包成员；文件或图包成员固定确切身份。标签可用于横向筛选，但不代替层级、版本或现行选择的权威记录。
2. 按 [组织与示例](references/organization.md) 判断新位置、内容变化、预览、裁切和重设计。保留真实沿革和输入，不猜测来源。
3. 在授权范围内新增或更新 `resources/records/` 的权威 Markdown，不手改索引。模板填真实 ID、版本、文件、位置及证据；保留历史。`input` 定位实际调用条目，其他关系和选择引用各自原 owner 的原始证据。
4. 未知哈希或稳定位置填写 gap，未知来源明确为追溯终点；与已知媒体缺失分开报告。记录位置和哈希不证明核验或备份。
5. 需要维护用途时，在适用集合的 slot 选择确切版本，涉及文件时指定 member，并记录 scope、证据与 basis。代理暂选、用户偏好、用户确认不可互相冒充；新版本不自动替换选择，历史作品引用不漂移。改变用户确认的选择须符合当次授权。

## 验收与交付

获准维护记录时，必要的索引同步及验收属于该维护范围：运行 `sync-index`、`check`，再以 `show` 或按需 `trace` 回读对象、选择和关系。检查新鲜度、截断及终点；失败按 [CLI 失败分流](references/cli-operations.md#失败分流)处理。

报告改动、查询及检查结果、未核实媒体与证据缺口，以及仍需用户决定的选择。媒体操作、覆盖或删除和用户确认的选择仍按项目及当次授权处理。同步不传输媒体、监听变化或更改 Git；文件核验、许可、备份与使用验收各自独立。
