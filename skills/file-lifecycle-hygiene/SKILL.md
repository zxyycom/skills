# File Lifecycle Hygiene

## 目标与适用

让 agent 自行安排的文件输出与移动有可理解的结果：最终产物容易找到，旧位置和留存的辅助物能解释用途与下一步。已有项目或工具约定时沿用其 owner；对位置和去留仍不明的文件，先盘点再决定。

本 skill 是可按场景取舍的风格偏好，不要求统一目录、逐文件日志或额外审批。创建、覆盖、迁移、清理及仓库外写入仍按当前任务与环境的授权执行。

## 归位习惯

1. **选择去处**：按消费者和用途区分最终产物、短期工作物、回退副本与过渡物。优先使用用户指定或内容 owner 的位置；自行集中短期工作物时，可在适合当前操作的范围采用 `.tmp/`，回退物可采用 `.backup/`。这些只是位置示例，实际还要满足工具、权限、容量和恢复条件。
2. **保持关系清楚**：复制时确认是否真需保留两个版本；移动后核对旧位置、引用和消费者。自选名称表达对象与用途，重试或并行时加入区分符。
3. **决定归宿**：操作结束时区分最终产物、可收尾的中间物和仍需留存的辅助物，同时核对失败半成品。需要保留的回退或过渡物说明当前原因和下次复核条件；来源不明或可能含唯一数据的文件只盘点，不凭名称推断可删除。

## 留存物的可识别样式

- 自行命名的辅助文件或目录，可按 `<对象>-<用途>[-<区分符>]` 命名；文件保留消费者需要的扩展名。区分符可使用时间或短唯一标识，但文件名中的时间不代替旁注的时间记录。已有命名契约时沿用，不为套用样式而改名。
- 预计会跨多个步骤使用或跨任务保留的回退、过渡物，可在创建时放置同级的 `<产物完整名称>.artifact-note.md`；意外决定留存时补记。一个操作的多个产物可以共用一份旁注，前提是能逐一定位。旁注不混入必须保持原样的回退内容；无法同级放置时，沿用可从产物定位的受管说明。
- 旁注以 `file-lifecycle-hygiene` 为可搜索标识，记录产物形成时间和当前状态最近一次确认的时间，建议使用带时区的 ISO 8601 写法。形成时间无法核实时写明未知，不用旁注编写时间冒充。状态变化时更新说明和确认时间；普通短命文件收尾后无需旁注，已有可靠记录时不另写一份。

旁注可以采用以下简短格式，字段按实际需要取舍：

```markdown
# file-lifecycle-hygiene：<产物完整名称>

对象：<路径；多个产物时逐一列出>
来源：<原路径或新建>
用途：<为什么产生>
形成时间：<带时区的时间；无法核实时写未知>
状态确认时间：<最近一次核对当前状态的带时区时间>
状态与保留原因：<现在为什么还在>
后续处理：<可观察的复核或清理条件>
恢复：<仅回退物填写实际步骤或其位置>
```

交付时指出最终产物与仍保留的辅助物；清理只作用于已确认、获授权的精确目标。别人能找到结果并理解留存物的用途与后续处理，就达到了这项习惯的目的。
