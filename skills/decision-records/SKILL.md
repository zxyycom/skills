# Decision Records

## 目标与记录对象

维护可回放、可验证、可演进的长期判断，让后续工作恢复**采用什么方向、为什么采用、适用边界，以及如何演进**。决策 Markdown 保存判断；代码、配置、规范和项目文档提供当前事实。任务进度与执行日志由当前任务承接。

一条决策应能作为整体独立修订、替代、归档和判断对齐：

| 状态 | 含义与使用方式 |
| --- | --- |
| `candidate` | 尚未建立的候选，留在正式索引外；先完成正文、语义审核和建立授权判断。 |
| `active` | 已建立且仍须恢复的判断，可以是当前基线或约束选择的未来方向。 |
| `archived` | 已退出当前依据的历史判断，保留最后对齐状态与演进历史。 |

已建立记录的 `aligned` 表示完整方向已成为当前事实并经核对，`unaligned` 表示已确认的未来方向；未来方向仅在当前任务明确纳入交付时实施。归档状态只反映最后一次核对，不能证明今天仍适用。对齐作用于完整方向，不产生任务、优先级或实施授权。

## 任务路由

先读目标工作区指令和直接相关的当前事实来源，再按任务补读。**维护决策记录仍是使用工具；修改 CLI 实现才是工具维护。**

| 当前任务 | 读取路径 |
| --- | --- |
| 查找、阅读或内容审阅 | 按下方查询表选择入口；使用查询前读 [CLI 查询与结果解释](references/cli-operations.md#查询与结果解释)，以实际来源和覆盖解释结果。 |
| 起草、编辑或结构审阅 | 先读规则的[记录身份与集合](references/decision-record-rules.md#记录身份与集合)、[正文与候选准备](references/decision-record-rules.md#正文与候选准备)、[记录边界与有效演进](references/decision-record-rules.md#记录边界与有效演进)及[生命周期与对齐](references/decision-record-rules.md#生命周期与对齐)。涉及关系时再读演进关系章节。 |
| 创建候选、建立、演进、归档、调整关系、删除、更正身份、同步或暂存 | 先读 [CLI 操作前提](references/cli-operations.md#操作前提)，再读所选操作章节及其链接的领域规则；精确参数用 `help <command>` 获取。 |
| 首次候选集合、工具或索引异常、写入中断 | 按[维护恢复](references/maintenance-recovery.md)的实际状态分流。 |
| 修改 CLI、SDK 或测试实现 | 从源码项目的维护入口读取实现与验证约束，再读取所改公开行为对应的契约；这些实现材料不是普通记录维护的前置。 |

索引精确机器结构由 [Schema](references/decision-index.schema.json) 承接。整体审阅某一层契约时完整读取该层；普通任务沿上述路径按需展开。

| 已知信息或阅读目的 | 查询入口 |
| --- | --- |
| 准确 Decision ID 或唯一 name | `show <selector>` |
| 状态、alignment、tags、时间或直接关系 | `list` |
| 主题、概念、理由或正文措辞 | `search <text>` |
| 演进关系 | `trace <selector>` |
| 尚未建立的候选 | `candidates` → `show-candidate <selector>` |

## 工作流程

### 1. 确定当前任务需要什么

- **恢复或审阅**：交付查询或审阅结果，保持集合不变。
- **起草候选**：当前请求或生效项目规则授权相应对象与范围时创建或继续候选；起草不代表采用。
- **建立或维护**：在授权范围内自行核对完整采用方向、回放价值与 alignment；委托未包含该取舍时再请求决定。
- **普通工作形成重要取舍**：按已有授权起草或建立；尚无记录授权时，在自然更新或交付阶段提出建议，只有继续任务必须先确定取舍时才即时询问。

集合级审阅先确定覆盖维度：tags、正文、直接关系或记录边界（含归并、拆分），同时核对既有内容与拟议变更；结论以实际覆盖为限。

### 2. 恢复并使用已有判断

完整读取全部直接相关的 active 判断，从目的、背景和决策恢复方向、理由及限制，再对照当前事实：

| 情形 | 处理 |
| --- | --- |
| 已对齐基线适用 | 遵守基线。 |
| 未对齐方向与当前方案有关 | 作为方案输入，仅实施本次交付或验收明确包含的范围。 |
| 已对齐记录与当前事实偏离 | 报告一致性问题，保留已核对的对齐历史；新的未来目标另行表达。 |
| 当前工作涉及例外或长期改变 | 区分一次性例外与长期修订，按相应授权处理。 |
| 同一记录包含可独立演进的方向 | 建立自包含后继拆分；不可独立演进的局部落地仍保持整条 `unaligned`。 |

### 3. 形成值得保留的判断

候选同时满足以下条件才进入决策根目录：

1. 会持续影响后续行为、责任边界、兼容性、风险处理或验收。
2. 缺少记录时，未来难以恢复为何采用该方向。
3. 内容是判断或取舍，而非事实、任务、进度或执行结果。
4. 能作为整体独立演进和判断对齐。

先按[记录边界与有效演进](references/decision-record-rules.md#记录边界与有效演进)区分原地完善、独立新判断与真实后继。准备新建时，同时确认相关 candidate 与已建立记录未覆盖同一判断；应继续候选或完善原记录时沿用原对象。

按[候选创建契约](references/cli-operations.md#创建与继续候选)通过 `new` 起草，随后围绕原候选完善“目的、背景、决策”：说明长期结果、促成选择的事实与约束、采用方向及核心理由。摘要忠实概括正文，tags 与直接关系有正文依据。新建或调整真实关系时，依据两端正文为每条边填写简短 `summary`。

### 4. 按判断性质选择维护动作

| 需要的结果 | 操作与读取入口 |
| --- | --- |
| 建立已审核候选或形成真实后继 | 单个候选用 `publish`，完整演进用 `evolve`；读[建立与生命周期](references/cli-operations.md#建立与生命周期)。 |
| 纠正误述、补足既有理由，方向与范围未实质变化 | 原地完善正文，再按[检查与同步](references/cli-operations.md#检查与同步)验证。 |
| 完整未来方向已成为当前事实 | 核对事实后 `mark-aligned`。 |
| 退出当前依据或重新启用历史记录 | `archive` 或 `reactivate`；读[建立与生命周期](references/cli-operations.md#建立与生命周期)。 |
| 只调整正式关系，生命周期不变 | `set-relations`；读[关系输入与核对](references/cli-operations.md#关系输入与核对)。 |
| 更正 ID/name 或明确删除 | `rename` 或 `discard`；读[身份更正与删除](references/cli-operations.md#身份更正与删除)。 |

拆分或重划前，按[后继集合与语义闭合](references/decision-record-rules.md#后继集合与语义闭合)确认完整后继承接前序继续有效的长期含义；各后继可以使用不同关系。

agent 在委托范围内自行完成语义审查与采用判断。“已确认”包括用户明确选择及 agent 基于约束和证据作出的授权内判断。关键事实缺失且会改变结果、超出范围或明确要求人工确认时才询问；删除等高风险操作仍需覆盖精确目标与影响的授权。机械 readiness、预检与语义审核分别判断。

### 5. 验证与交付

1. 已知合法来源变化先 `sync-index` 再严格 `check`；未解释的索引异常先检查诊断。已建立集合维护后运行严格 `check`；首次候选集合按恢复手册验收。
2. 任务要求 Git 待提交快照时，再按[待提交快照](references/cli-operations.md#待提交快照)运行 `stage`。commit 与 push 分别服从当前授权。
3. 只读任务说明适用判断及结果边界；候选任务说明回放价值与 readiness；维护任务说明实际状态、关系、删除或对齐变化及验证证据；暂存任务说明所选完整 ID 与 pending 结果。

完成前确认：记录值得回放，方向和边界清楚，关系真实直接，alignment 有完整事实依据。机械验证与语义判断分别交付；未验证内容明确标出。

## 工具运行前置

运行下文公开 `.ts` CLI/import 或自更新入口时，使用 Node.js `>=24.18` 的原生类型擦除。
依赖沿 Node 正常解析，可复用宿主兼容版本，不要求本地 `node_modules` 或与锁文件精确版本一致。
依赖缺失、实际不兼容或需要复现随包基线时，使用随包 `package.json` 固定的 pnpm 显式安装：

```bash
pnpm --dir "<skill-directory>" install --ignore-workspace --prod --frozen-lockfile --config.node-linker=isolated
```

运行、import、help 和检查不自动安装。安装副本中的 `scripts/runtime/tools/` 可直接修改，无需构建；
更新会覆盖正式包中的同路径定制文件。领域操作的其他前置仍由各自操作契约承接。

## CLI 入口

在**目标工作区根目录**执行，用实际安装位置的脚本绝对路径调用：

```text
node <skill绝对路径>/scripts/decision-records.ts help <command>
node <skill绝对路径>/scripts/decision-records.ts [global-options] <command> [command-options]
```

当前目录默认就是工作区根。若从 skill 安装目录或其他目录调用，显式在 command 前提供 `--root <workspace-root>`；自定义集合使用工作区内相对 `--decisions-dir`。help 不读取集合状态。项目已提供维护短命令时优先使用该入口。

## 自更新

在本 skill 目录运行 `node scripts/update-skill.ts`，运行前置与依赖修复见[工具运行前置](#工具运行前置)。
运行时文件或 manifest/锁文件损坏时，重新获取完整 skill 后再安装并重试。
更新覆盖正式包中的同路径文件、保留其余本地文件。源码更新成功不证明依赖兼容；需要时按新包锁文件显式安装。
