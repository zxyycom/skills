# 决策记录状态与维护恢复

本手册帮助操作者在首次候选集合、工具或索引异常、写入中断时，恢复可解释且可验证的决策集合。身份与生命周期以[决策记录规则](decision-record-rules.md)为准，具体操作范围以 [CLI 操作契约](cli-operations.md)对应章节为准。

## 先保留来源并判断范围

1. 保留当前 Markdown、索引和 Git 中可恢复的最后可信基线。Markdown 拥有决策事实，索引只用于定位和对账。
2. 按工作区根（当前目录或显式 `--root`）与可选 `--decisions-dir` 确认同一决策根，检查根目录、`archive/` 和索引的可读性。
3. 从诊断的 code、对象、原因和下一步定位；有 scope/outcome 时，只对声明范围判断是否已写入或恢复。
4. 根据可信来源自行恢复可确定的内容。关键事实或取舍无法确定且会改变恢复结果时，保留相关内容并询问；不从派生索引补造来源事实。

## 状态分流

| 当前事实 | 下一步 |
| --- | --- |
| 根目录整体不存在，且项目从未记录决策 | 视为尚未初始化；按当前任务决定是否起草。 |
| 只有合法 candidates，没有 active、archived 或正式索引 | 用 `candidates`、`show-candidate` 核对所选准备；需要候选集合结构结论时运行 `check`。经授权首次 publish 才建立索引，此时不运行 sync-index。 |
| ID、tags、状态与位置或 Markdown 结构无效 | 按可信来源和领域契约，在授权范围内修复权威 Markdown；关键判断无法确定时保留并询问。 |
| 已建立来源的 alignment 缺失、为 null 或非法 | 停止集合维护，按[已建立 alignment 无效](#已建立-alignment-无效)恢复；不能用生命周期操作或默认值补造状态。 |
| 已建立来源合法，索引缺失、损坏或陈旧 | 完整核对来源后，按下节重建索引。 |
| 写入中断或恢复结果不完整 | 按“中断写入”对账，暂停后续 mutation。 |
| CLI 无法启动或分发文件不完整 | 先按“工具恢复”修复执行入口。 |

## 候选身份发现与索引状态

候选动作从当前来源发现候选，并按索引状态取得正式身份与位置：

| 索引状态 | 身份依据与下一步 |
| --- | --- |
| 合法现行索引 | 使用已发布的正式身份与位置，准备所选候选；正式目标的身份与关系使用索引，不为 readiness 读取其正文。 |
| 真正缺失 | 报告缺失状态，安全读取所需 header，确认是否为没有任何正式来源的首次候选集合。只有候选时可继续起草与候选读取；已有正式来源时，创建、候选读取和普通维护均须先显式恢复合法索引，不能把局部选择误判为空集合。 |
| 已有坏索引或 definition 不兼容 | 显式修复来源与全量 `sync-index`；不能退为空集合或来源 fallback。 |

header 发现只服务身份与不覆盖检查，不建立索引或证明正式全集健康，也不验证无关正式正文、完整关系图。候选完整 ID 的潜在目标允许尚未建立，但不据缺失索引宣称正式身份不存在。首次 publish 独立确认正式来源为空与所选候选闭合。

候选 locator 已确定但 ID/结构无效时，列表 warning 后跳过，显式目标失败；身份歧义、非法成员与读取不安全始终拒绝。需要候选身份发现的索引外来源须能可信区分 candidate 与 established；必要发现中的无法分类成员拒绝。合法发布路径不读取正文 header；未选候选不提供关系修复承诺。

## 历史与 pending 定位恢复

历史门禁只由合法 HEAD 索引定位必要历史正文。HEAD 在所选集合已有 Markdown 却缺少合法索引时，先恢复可信历史索引；不能靠扫描所有 blob 猜测所选对象从未记录。首次没有历史来源的集合仍可使用空历史基线。

stage 的旧位置由 HEAD、工作区、pending 索引或所选 canonical basename 可靠定位。仅 pending 存在、basename 任意且索引均已失去该身份时，保留 pending 并先恢复可信来源或索引；重跑其他 scope 不保证找回未知位置。

domain 仍从合法可用的 pending 索引收集所有所选 ID 的旧位置，并始终核对所选 canonical pending 路径。该索引自身读取或解析失败时，仅在其他可信定位已足够的前提下继续；所选正文错误仍失败。已读索引字节、完整 pending 身份和独立 fresh 的保护按 [CLI 待提交快照](cli-operations.md#待提交快照)执行，索引原状态保持。

## 已建立 alignment 无效

已建立记录的缺失、`null` 或非法 alignment 阻断全量检查／同步，以及读取该来源的维护。按以下顺序处理，范围只限受影响记录的该字段：

1. 保留当前 Markdown、索引以及 Git 中可恢复的最后可信基线；确认受影响 Decision ID、其原位 Markdown 和非法字段值。
2. 从可信 Git 历史或能够直接证明该记录既有状态的历史材料确定每个正确值。派生索引、目录位置和缺失值都不是证据；无法确定时保留来源并请求判断。
3. 取得明确授权，使其覆盖这些 ID 的原位 `alignment` 字段修复及影响；该授权不等同于建立、重新激活、归档或改变关系的授权。
4. 仅在原位 Markdown 修复已获证实的字段，保留 status、createdAt、关系和正文；不执行 publish、archive 或其他生命周期命令，也不默认写入 `unaligned`。
5. 再按下节全量重建索引并运行严格 `check`。验证失败时停止，不以旧索引、selected 同步或补值绕过来源错误。

## 索引恢复

content 与 metadata 搜索都需要合法发布索引；content 只匹配发布范围内的当前文本。索引缺失、损坏或 definition 不兼容时，先显式恢复。截断提示出现时收紧筛选或继续读取已知 ID，不把缺失输出当作不存在记录。

来源完整、满足当前 definition 且已取得维护授权后，在目标工作区根目录用实际安装脚本的绝对路径执行全量重建：

```text
node <skill绝对路径>/scripts/decision-records.ts sync-index
node <skill绝对路径>/scripts/decision-records.ts check
```

当前目录默认是工作区根；从 skill 安装目录或其他目录调用时，为两条命令在 command 前提供相同的 `--root <workspace-root>`。项目提供维护短命令时优先使用该入口。自定义目录时，两条命令使用相同工作区内相对 `--decisions-dir`。definition 过期但来源合法时，完整同步建立新投影；不使用 `--select`，也不把旧索引作为正常 reader 或来源。已建立来源的 alignment 无效时，同步和检查均失败并保持零写入，不能只修索引。完成后按需用 `list --status all --alignment all`、`show` 或 `trace` 核对预期身份、位置、内容、非空 alignment 与关系。

## 中断写入

根据[操作契约的 outcome](cli-operations.md#结果与恢复)选择动作：

| 诊断结果 | 操作者动作 |
| --- | --- |
| `no-change` | 修正前置条件，重新观察后显式发起命令。 |
| `rolled-back` | 复核旧范围已完整恢复，再决定是否重新操作。 |
| `partial-or-unknown` | 停止重试和补写，比较 Markdown、索引与可信版本；无法唯一确认完整状态时交给用户。 |
| `committed-cleanup-pending` | 先核对已完成的 Markdown、索引及诊断列出的残留，再决定后续维护。 |

先按[操作结果](cli-operations.md#结果与恢复)确认是否越过本动作提交点，再区分验收失败/未知与仅清理或解锁未完。已提交结果不自动回撤；验收与清理同时失败时分别保留诊断，不能只按清理残留处理，也不据非零退出重做领域操作。

提交前自动恢复只处理实际已写且仍与本事务已写字节、inode 和 mode 一致的路径；已删除旧路径只在仍缺失时独占恢复，索引遵循同一 CAS 边界。后来修改、新建、未选成员或身份/权限漂移必须保留现场。只有完整旧范围与未写成员均得到证明时才报告 `rolled-back`。

对账目标是完整一致的旧状态或新状态。若权威 Markdown 已形成完整新状态，以它重建索引；若只完成部分写入，且可信副本能确定操作前完整组合，则在恢复授权范围内恢复 Markdown 与索引。保留无法解释的记录、关系与建立时间，不根据部分索引补造事实。

所有重试都由操作者在处理原因并重新观察后显式发起。权限不足时只取得当前进程所需授权，不使用 `sudo`；锁忙时等待或确认活动进程，确认没有活动进程后才人工检查残留锁，agent 和工具不自动删除锁。

## 工具恢复

- Node 不可用但有兼容运行时时，可用该运行时执行同一 CLI，在目标工作区用该运行时调用实际安装脚本的绝对路径。
- 依赖损坏时先按随包锁文件显式 frozen 安装；updater 的兼容依赖和运行时完整时，才用相邻 `scripts/update-skill.ts` 检查并按更新授权恢复完整 skill。运行时或 manifest/锁文件本身损坏时重新获取 skill，保持 CLI、声明和 Schema 同一分发单元。
- 入口仍不可用时，保留全部来源，停止索引和状态维护，交付已确认的故障与阻塞范围。

## 恢复验收

已建立集合运行严格 `check`，再核对受影响 ID、位置、tags、生命周期、正文、非空 alignment 与关系。首次候选集合只证明 scaffold 结构，且继续保持 `alignment: null`、`createdAt: null` 与正式索引外；正文准备、语义审核和建立仍分别判断。

交付说明恢复目标、实际完成的范围、验证结果及剩余未知；不能完整证明旧/新状态时，明确需要用户判断的部分。
