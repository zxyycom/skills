# Image Creation

## 目标与执行边界

把“想要什么图”变成可检查的视觉要求，选择合适的输入与生成路线，执行后对照图片修正，最终交付符合用途的图像。提示词、骨架、草图和局部样稿都是手段；用户要成图时，不以完成这些中间物代替交图。

本 skill 拥有需求表达、参考分工、路线判断、视觉验收和迭代；不自带生成器或 API 客户端。实际调用依赖当前可用且获授权的图像工具。当前环境提供 `imagegen` 等执行 skill 时，读取其入口并遵循其工具选择、附件、参数、保存和输出契约；没有该 skill 时，以实际工具契约为准，不推测其参数。两者可以协作，不要求安装整个 skills 仓库或某个固定生成服务。

工具不可用、调用失败或所需控制不受支持时，保留已知输入与失败阶段，说明尚未出图／尚未修好。可以交付可复制提示词及所需附图，但不能把它称为成图完成；不自行切换收费 API、安装模型或建立凭据。用户明确只要提示词、方案或诊断时，止于该交付，不额外生图。

## 读取策略

先读本文件，按当前缺口选读，不把全部资源当必填问卷：

- 需求模糊、风格堆叠、材料／光线／动作难以表达：读 [视觉简报与表达](references/visual-brief.md)。
- 使用参考图、编辑现图、局部设计回填或重复出现结构偏差：读 [参考与编辑诊断](references/references-and-edits.md)。
- 组图、多视图、文字／事实密集图，或需要提示与交接示例：读 [任务分支与样例](references/task-patterns.md) 的相应章节。

## 主流程

### 1. 锁定这次要交付的结果

从当前请求和已有材料恢复下列信息，只补会影响结果的缺口：

- **用途与产物**：预览还是项目资产，单图还是分别可用的多张图，面向谁、承担什么作用。
- **任务与状态**：新创作、参考引导还是编辑；展示／静息、动作瞬间、能力启动等应在画面中呈现何种状态。
- **必需与自由**：必须出现、必须保留、禁止改变、可自然调整的部分，以及本轮真正要改的内容。
- **验收重点**：优先用两三项可见结果表达成败；精确文字、事实、数量和文件规格等硬要求仍完整保留。

简单且清楚的请求直接执行，不强制先出表、列菜单或等待确认。缺省只补支持用途的构图、光线等必要选择，不擅自增加角色、故事、品牌、文案或关键设定。核心要求互斥，或缺失真实内容会迫使编造时，先问一个决定性问题。

恢复旧任务时，按明确用途找到基准图及当前候选；区分用户已认可的范围、代理暂选和仍待确认的部分。最新文件、目录叫“current”或某一局部获赞，都不自动表示整体定稿。遇到冲突先查当前入口与反馈，不让旧模板压过本次任务。

### 2. 核对实际输入并选择路线

1. 有图时先实际查看待使用位图，不只读文件名、旧评语或文字反推。确认编辑目标、参考版本与可见细节；看不清或无法访问关键图时说明影响，必要时请用户重新提供。
2. 为每张图指定本次职责和不应继承的内容：身份／产品、姿态／布局、风格／材料或局部设计。冲突时说明哪张图对哪个属性优先；减少无任务职责的输入，而非固定参考数量。
3. 主体已可用且主要是保留后局改时选编辑；没有可用基底、目标形态尚待探索或旧基底持续牵制时，考虑新生成／重建候选，并显式承认身份、布局可能重置。参考仅借用风格或姿态，不意味着该参考就是编辑目标。
4. 需要精确几何、真实数据、可编辑矢量或像素级区域保护时，选择能兑现该要求的原生工具或合成流程；生成位图不冒充工程源。草图／骨架只约束任务需要的结构精度，不自动升级为逐点重建验收。
5. 执行前确认实际调用会收到正确的图、顺序及职责。人工看过、在提示里提到、在上游扩写节点读到，都不等于最终生成器已收到；有可见的中间扩写文本时，核对关键约束是否丢失、反转或被截断。

### 3. 组织提示并执行

以用途、核心画面和本轮变化为主线，按需加入主体关系、环境、取景、光色、材料及精确文字。描述数量、属性归属、连接、遮挡和承载表面，不只罗列名词；抽象情绪／风格要落到能看见的选择。用简短自然语言或当前工具适合的结构即可，不强制 JSON、英文、固定词数或万能词序。

编辑提示同时说明“哪里变成什么”和“哪些维持”；参考以实际图序指代。每轮重申仍有效的关键不变量，删除已过时或与当前状态矛盾的要求。允许符合用途的自然透视、遮挡和曲率调整；精确规格只有用户或下游用途确实依赖时才成为硬线。

画幅与像素由交付用途和当前工具能力决定。“4K”、相机／胶片名或质量形容词只表达观感，不保证真实尺寸、物理成像或身份保真。权重、seed、负向槽、蒙版、参考强度等只使用当前入口实际支持的形式；旧教程的语法和数值不能直接移植。未暴露的模型版本或设置保持未知。

在当前授权内调用生成工具。一次尝试优先解决当前最重要、彼此相关的一组变化；不为证明提示词有效而额外生成收费对照，也不在失败后无界重抽。重试、数量与预算遵循用户要求和执行工具规则；需要扩大成本或范围时先取得授权。

### 4. 看结果，再决定下一步

实际查看输出（可使用当前已显示的结果），并按风险从整体到局部检查：

1. **任务兑现**：用途、状态、动作、主要内容和取景是否符合本次请求，而非只问画面是否漂亮。
2. **身份与关系**：角色／产品识别点、数量、属性归属、连接与遮挡是否成立；多格图逐格检查。
3. **表达与内容**：材料的层次／厚度／透光、姿态与透视、效果的来源与方向是否可读；文字逐字核对，事实与数据对源。
4. **保留回归**：对照输入检查目标邻域与非目标区域，特别是脸、肢体、产品轮廓、标签和其他面板。自然语言保留项不等于像素锁，局部改好也不能掩盖整图退化。
5. **真实交付规格**：需要时检查文件尺寸、透明通道、裁切边界和资产数量。棋盘格观感、拼板或工具成功消息不能代替这些检查。

分开表达“实际看到”“用户反馈”和“尚待验证”。没有查看输出不能宣称视觉验收；缩放、遮挡或分辨率使关键特征不可判断时，标为不确定，不脑补。

未合格时，先定位是哪层失败，再做下一项有依据的动作：

- 原词要求错状态、扩写漏属性、参考没传入或底图含错误：先修输入／任务，不归咎为生成器不服从。
- 画面遗漏或关系含混：补具体归属、位置、范围与可见构造，减少无关冲突。
- 局部近景成立而全图不可读：分开检查设计、尺度、透视与回填执行，不把局部正例算作整图完成。
- 同类偏差反复出现、或修一处持续损伤其他处：回看路线与控制能力，考虑裁剪／区域编辑、合成或换基底；先确认当前工具支持及授权，不只追加更强语气。

保存较好的基准，不以每轮最新图自动替代。达到用途要求、触及授权预算或需要用户决定下一条路线时停止；剩余缺陷如实展示，不把暂选称为用户认可。

### 5. 交付并保留足够的恢复信息

按执行工具的展示契约交付实际图像。项目资产放到授权项目位置并确认真实文件；默认新版本，不覆盖原件。仅预览时沿用工具预览约定，不强制另建产物目录。用户只要提示词时，交付最终提示、图序／职责及仍需用户填入的内容。

需要跨轮、系列创作或项目继续使用时，在已有记录入口保存最小可恢复信息：本次意图与保留项、实际原词、实际附图顺序／职责、工具／模式及可见设置、输出身份／路径、观察、反馈认可范围和当前用途。沿用项目资产 ID／哈希约定，不为每次随手预览建立数据库或全套日志；记录中不含凭据和无授权的私有素材副本。

交付时区分已生成、已查看、已归位与已获用户认可；说明影响用途的剩余问题。提示词、自动测试、文件存在和静态成图都不能单独证明跨视角精确一致、视频连续性或真实物理成立。

## 完成标准

- **成图任务**：实际图像已交付并可查看；已对照输出验证本次重点与非目标回归。项目资产已归位，输入与引用足以恢复；暂选、用户认可和未验部分清楚。
- **仅提示词任务**：最终提示、所需图序／职责、规格与验收点足以继续执行，未提供的关键输入明确；不宣称已生成或验证图像。
- **诊断任务**：结论能回到实际查看的输入／输出或明确标注的文字记录，分清观察、假设和下一项处理；无需为完成诊断额外生成图像。
- **无法执行的成图任务**：说明失败阶段、已有阶段成果与所需下一步，不标记成图完成。任何分支都不以另一类交付冒充用户所求。

## 自更新

本 skill 的指令使用不需要安装依赖。仅在本 skill 目录运行自更新入口 `node scripts/update-skill.ts` 时，需满足随包 `package.json` 的 Node 版本与兼容依赖。已有兼容宿主依赖即可复用；运行、导入与检查不自动安装。

需要修复依赖时，使用随包 manifest 固定的 pnpm 显式执行：

```bash
pnpm --dir "<skill-directory>" install --ignore-workspace --prod --frozen-lockfile --config.node-linker=isolated
```

运行时文件或 manifest／锁文件损坏时，重新获取完整 skill 后再安装并重试。更新覆盖正式包中的同路径文件、保留其余本地文件；源码更新成功不证明依赖兼容。
