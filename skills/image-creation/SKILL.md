# Image Creation

## 目标与执行边界

把用户意图变成可检查的视觉要求，结合实际参考与可选结构引导，完成提示构建、生成、回看和定向迭代。用户要成图时交图；只要提示词、方案或诊断时，止于相应交付，不额外生图。

本 skill 不自带生成器。使用当前获授权的图像工具；环境提供 `imagegen` 等执行 skill 时读取其入口，调用协议、附件、参数、保存与展示以当前运行时契约为准。工具不可用、失败或控制不受支持时，保留输入与失败阶段，交付已有成果并说明尚未生成／修好；不自行切换收费 API、安装模型或建立凭据。

## 主流程

### 1. 锁定这次要交付的结果

从当前请求和已有材料确认：

- **用途与产物**：预览还是项目资产，单图还是分别可用的多张图，面向谁、承担什么作用。
- **任务与状态**：新创作、参考引导还是编辑；展示／静息、动作瞬间、能力启动等本次状态。
- **必需与自由**：必须出现、必须保留、禁止改变、可自然调整及本轮真正要改的部分。
- **验收重点**：两三项主要可见结果；精确文字、事实、数量与文件规格等硬要求仍完整保留。

简单清楚的请求直接执行，不强制出表、列菜单或等待确认。按内容来源决定自主空间：

- **开放虚构创作／受托设计**：可自主构思服务用途的主体、情境、叙事、文案及视觉表达，作为可调整的设计候选继续推进。
- **详细既定请求**：以归一化和保真为主，只补自由项；保留项不得越界，真实事实不得编造。
- **内容层停问**：仅在核心要求实质冲突，或完成任务必需的真实依据缺失时，问一个决定性问题；普通设计取舍不设确认门槛。

恢复旧任务先定位基准、当前候选与反馈，区分用户已认可范围、代理暂选和待确认部分；最新文件或局部获赞都不自动表示整体定稿。

### 2. 核对实际输入并选择路线

1. **实际看图**：查看本次要用的位图，确认版本、编辑目标与可见细节。关键图不可访问或看不清时说明影响，必要时请用户重供，不靠文件名或旧评语推定。
2. **分配职责**：逐图说明身份／产品、姿态／布局、风格／材料或局部设计职责、优先依据与不继承内容。只用有职责的参考，图数服从任务与接口。
3. **选编辑或重建**：基底可用、主要是保留后局改时选编辑；缺基底、仍在探索形态或旧基底持续牵制时考虑新生成／重建候选，说明身份与布局可能重置。风格／姿态参考不自动成为编辑目标。
4. **按需结构引导**：文字难稳定表达连接、姿态或机位时，按结构指南选草图、三视图或简易3D；所需渲染须真实附入，辅助图与最终成图分别检查。辅助应消除歧义，不扩成任务外工程。
5. **匹配精度**：精确几何、真实数据、可编辑矢量或像素级区域保护，使用能兑现要求的原生工具或合成流程；生成位图不冒充工程源。
6. **核对最终传入**：确认生成器实际收到正确版本、图序与职责。人工看过、提示里提到或上游节点读过不算实际传图；可见扩写文本还须检查关键要求是否遗漏、反转或截断。

### 3. 构建提示并调用

按必读提示词指南将本次需求编译成完整 prompt；编辑同时给出变化与关键保持项，每轮更新仍有效的要求。格式、画幅与控制字段按用途和当前接口选择，未暴露的设置保持未知。

**每次实际调用**（含重试、失败和局部试作）按生成记录指南保留目的、完整实际提示词、真实输入／输出及回看结果：调用前保存实际词和附图身份／顺序，返回后补状态与检查。模板或摘要不代替实际原词，失败也保留可辨认记录。

一次优先处理最重要且相关的一组变化。数量、重试与预算服从用户和执行工具要求；扩大成本或范围先获授权，普通成图不额外运行收益实验。

### 4. 回看、诊断与选择候选

实际查看每次输出，可复用当前已显示结果；从整体到局部检查：

1. **任务兑现**：用途、状态、动作、主要内容与取景。
2. **身份与关系**：识别点、数量、属性归属、连接与遮挡；多格图逐格核对。
3. **表达与内容**：材料层次／厚度／透光、姿态与透视、效果来源／方向；文字逐字核对，事实数据对源。
4. **非目标回归**：对照输入看目标邻域及其他区域，特别是脸、肢体、产品轮廓、标签与其他面板。局部改善不能掩盖整图退化，自然语言保持项不是像素锁。
5. **真实规格**：按需核实文件尺寸、alpha、裁切边界与资产数量，不凭棋盘格观感、拼板或接口成功消息认定。

每次返回后保存回看结果，才能选为候选或下一轮输入。取图／查看受阻时记录“未检查”及原因并处理阻塞；缩放或遮挡使特征不可判断时标为不确定。实际观察、用户反馈和未验证部分分开记录。

不合格时按[参考与编辑诊断](references/references-and-edits.md)区分输入／提示、尺度、设计／回填或控制能力问题，再定向改词、改输入或换路线。保留较好基准，不以最新图自动替换。

达到用途要求、触及授权预算或需要用户选择下一路线时停止；如实呈现剩余缺陷，不把暂选称为用户认可。

### 5. 交付与恢复

按当前工具展示契约交付实际图像。项目资产放到授权位置，确认真实文件并默认新版本、不覆盖原件；预览沿用工具约定，无需另建目录。

按生成记录指南保存可恢复的调用关系与资产去向。源图、输出和有损代理身份分明；代理只支持其精度范围内的回查，不授权覆盖或删除原件。交付时区分已生成、已查看、已归位与用户已认可，说明影响用途的剩余问题。

## 完成标准

| 任务 | 应交付与可核对证据 |
| --- | --- |
| 成图 | 实际图像可查看；重点与非目标回归已检查，调用／回看记录及项目资产可恢复；认可范围与未验项清楚 |
| 仅提示词／方案 | 最终提示或设计方案、图序／职责、规格、保持项与验收点足以继续执行，必要缺失输入明确；不宣称已出图 |
| 诊断 | 结论回到实际查看的输入／输出或标明的文字依据，分清观察、假设与下一项处理；无需额外生图 |
| 成图受阻 | 说明失败阶段、已有成果与所需下一步，不以提示、骨架或占位图冒充成图完成 |

## 自更新

本 skill 的指令使用不需要安装依赖。仅在本 skill 目录运行自更新入口 `node scripts/update-skill.ts` 时，需满足随包 `package.json` 的 Node 版本与兼容依赖。已有兼容宿主依赖即可复用；运行、导入与检查不自动安装。

需要修复依赖时，使用随包 manifest 固定的 pnpm 显式执行：

```bash
pnpm --dir "<skill-directory>" install --ignore-workspace --prod --frozen-lockfile --config.node-linker=isolated
```

运行时文件或 manifest／锁文件损坏时，重新获取完整 skill 后再安装并重试。更新覆盖正式包中的同路径文件、保留其余本地文件；源码更新成功不证明依赖兼容。
