# AI-ready 文档判断原则

本文件解释入口流程中需要取舍的判断，不重复执行步骤。以目标 AI 实际获得的文本和预期任务为准；“AI-ready”是可验证的使用结果，不是固定的 Markdown 模板。

## 实际消费与单一内容源

AI 只能依据进入上下文的文本及可解析结构工作。先确认目标 AI、文档用途、实际可用文本、预期操作和可观察结果，再决定哪些信息必须在当前文本出现，哪些可以通过可访问的引用展开。

事实、规则和关键判断由稳定 owner 完整表达；摘要、索引、附录和机器消费视图应指向或映射回同一权威内容。必需信息无法进入 AI 上下文时，补足最小语境，或把获取、解析、索引、召回和组装缺口作为外部依赖说明。独立机器产物只有既有契约需要时才维护。

## 主承诺与正负描述

标题、开头、适用范围、触发条件、资源名、字段与输入输出会先建立文档承诺。正文反复解释的主题、篇幅、层级、结论和验收应兑现它；正文偏题时调整内容位置，入口承诺过宽时收窄入口。目标状态或受保护对象负责建立方向，必要条件和精确规格负责定义与检验结果。

判断负向表述时，看它在当前文档承担的**角色**，而不是统计否定词：

1. 目标方向、可选方案的选择标准和验收依据应能从文档恢复；孤立的排除项不能代替这些信息。
2. 安全、权限、隐私、协议或合规禁止项可以是完整且独立的契约，保留其可审计的适用范围与检查条件。
3. 只重述已确立的合法入口、反复点名退场方案或描述旧错误的句子，若无新增边界或判断价值，合并或移除。
4. 正负表达都可能精确或模糊。只有能证明语义等价时才改写句式；不把“正向”当作自动更优的形式规则。

| 文本片段 | 判断 |
| --- | --- |
| “发布流程”的正文主要比较三种 CI 产品，却未说明触发、阶段或产物。 | 正文偏离主承诺；产品比较应进入选型说明，发布流程补足自身主线。 |
| “构建日志不得出现访问凭据”，并说明检查范围。 | 这是独立、可检查的禁止边界，应保留。 |
| “安全、平稳地迁移数据”。 | 目标缺少受保护对象、判断条件与验收方式，单纯改成肯定句仍不够。 |

## 用途骨架与信息恢复

不同用途需要不同阅读顺序；混合用途以最容易造成误用的职责为主线。下表是可选骨架，不要求补齐与任务无关的字段。

| 用途 | 优先呈现 |
| --- | --- |
| 执行 | 目标、范围、输入、步骤、边界、验收、输出 |
| 流程 | 前置条件、状态转移、步骤、失败处理、恢复路径、验收 |
| 规则 | 触发、规则、例外、优先级、检查方式 |
| 说明 | 问题、概念、推理、取舍、结论 |
| 参考 | 索引、概念、条目、示例、链接 |
| 契约 | 字段、合法值、约束、兼容性、校验 |
| 检查或评估 | 检查项、通过标准、失败表达、残余风险 |
| 协作 | 目标、范围、所有权、协作边界、输出、阻塞表达 |

复杂结构先给整体轮廓，再按主题和关系类型展开。相关定义、条件、例外和依赖尽量置于同一局部上下文；标题、列表项和表格行脱离相邻视觉位置后仍应能识别对象与范围。用稳定术语与明确标签表达指代、优先级、依赖方向、因果、条件、例外、权威性及当前与历史状态。

先遵循目标已有格式契约。没有契约时，顺序用有序列表，简单对照用每行自足的表格，结构化输入输出用适合其消费方的既有机器格式或稳定表达。图示按关系类型和环境选择：少量局部关系可用 ASCII，多层概念结构在环境支持时用思维导图，流程或时序用能标明方向与条件的图示。关键对象、关系、方向和范围须能从 AI 可读取的文本或图源恢复；不支持图示时改用结构化文本。

## 内容 owner 与语义保真

owner 是使用者最可能查找、拥有触发上下文与验收责任、后续变更时需要同步的位置。同一判断在 owner 处完整解释，其他位置保留摘要、触发条件或引用，避免多份表述漂移。

优化表达不授予补造事实或替换要求的权限。区分结构调整、事实补充、要求变化和领域决策；无法从现有依据确定含义且不同解释影响结果时，标明歧义并交由相应 owner 确认。例如，将“网关完成鉴权。它随后转发请求”中的“它”明确为“网关”只恢复指代；把“合理重试”改成“最多重试三次”则补造了规则。

## 关联、示例与历史信息

被点名的对象占据当前文本，也可能被误读为当前目标、推荐方案或仍有效的例外。检查每次点名是否提供新信息或说明对象的角色、适用范围与主目标的关系；没有新增判断时，合并到主要解释或引用。这里检查的是文本可恢复性，不推断某种措辞必然改变模型的生成概率。

坏示例、旧版描述、迁移过程和单次错误先作为诊断材料。能提炼成当前目标、必要边界或验收标准时保留提炼后的规则；仍需供复核的历史材料放入明确标记的参考位置；既无当前判断价值也无复核价值时删除。已有完整契约覆盖的旧方案禁令，只有仍承担独立兼容或审计义务时才继续留在主线。

## 人类可维护性与验证

AI 优化以准确使用为主，也要保留人类理解取舍所需的问题脉络、概念递进和自然阅读。细节多时渐进展开，避免把说明压成机械字段堆；纯视觉润色不代替语义修复。

把“更好”“合理”“适当”等词落实为目标状态、选择优先级、触发条件、范围、上限或验收方式，但缺失参数不能由改写者猜测。用代表性 AI 阅读或使用任务检验实际文本能否支持预期结果，再检查人的阅读和维护；格式、链接或 schema 检查只证明相应机械边界。

## 风险与冲突

安全、隐私、机密性、权限、合规、真实性、不可逆操作、更高优先级指令或明确契约冲突时，说明冲突并确认可行路径。低风险的项目惯例或相邻做法冲突可按用户目标作可逆取舍，并在交付中说明；风险性质无法确定且会改变结果时，只问一个具体问题。
