# 共同记录操作模型

本模型帮助维护 Decision Records（DR）与 Investigation Report（IR）的共同操作；它描述事实和证明的边界，不替代领域 CLI、SDK、持久格式或具体实现契约。普通使用从各自 skill 进入；修改实现时结合[共同操作维护](README.md)、[Index Runtime](../index-runtime/README.md)和[版本管理中间层](../shared/version-control.md)读取。

## 一次操作涉及什么

一次记录操作可能读取领域正文、使用派生索引定位或查询记录，并修改正文、索引或待提交内容。正文承载领域事实；索引是可重建的投影，不能单凭它证明正文当前未变。待提交内容是下一次版本将纳入的快照，不等同于工作区。

四个主体分工：

| 主体 | 拥有什么，负责什么 |
| --- | --- |
| DR 或 IR 领域 | 拥有记录身份、正文、关系、资源和生命周期；决定选哪些对象、如何解析及结果含义。 |
| 共同操作 | 编排两域的候选、查询、同步和非暂存事务；在各阶段交接证据，不重定义领域语义。 |
| Index Runtime | 拥有索引 schema、严格读取、通用同步和记录暂存的共同协调。 |
| 版本管理中间层 | 拥有 revision、pending（待提交快照）、文件表示和受期望保护的范围替换。 |

领域将共享层的事实映射为各自结果，不能把底层失败臆造为领域写入结果。具体操作和公开格式由各领域契约承接。

## 事务如何推进

一次写操作先确定选择和基线，再准备提案；正式写入前重新观察可变事实，确认没有漂移；按实际写集提交后独立回读验收，最后收尾。失败时依据是否越过提交点和实际写入情况恢复或对账。预检只是无持久写入的准备，不能代替正式执行的准备。这是责任顺序，不表示跨文件原子事务。

## 操作范围与证明

全量检查使用首次安全采集事实比较完整投影，不证明结束时新鲜或跨文件原子快照。同步和写操作另有独立写前复核（fresh）；同阶段内已验证的事实可在事实和边界相同的前提下交接，不能把旧阶段成功当作新阶段证据。安全来源证明绑定真实根、路径、身份、字节、mode 和父链；完整正文读取使用同份字节核对身份，不受搜索预览预算截断。

选择性操作只读取其契约要求的所选来源、实际写集和必要依赖；未读来源沿合法基线处理，不声称其当前性。DR/IR 的选择性同步与通用选择性同步的来源范围不同，具体见[同步范围](README.md#同步的来源范围)和[通用契约](../index-runtime/README.md#revisionsync-与-selected-scope)。暂存操作的 index、all、domain 范围各有不同选集：完整待提交成员身份受保护，但不因此读取未选内容；目标外内容和文件表示保留。不能以局部成功宣称全集健康，也不能自动修复未选内容。

## 写入、结果与恢复

1. **准备**建立适用的选择、基线、领域证明和实际提案；预检不写持久文件，不代替正式执行的准备。
2. **写前 fresh**独立取得适用的可变来源、路径、索引和 pending 事实，拒绝漂移；包括无变化操作。锁内比较当前事实与预期，再有条件替换（CAS），防止覆盖竞争者。
3. **写入与提交**以实际写集和各操作的提交点为准，记录已完成或结果未知的写入，不从计划推测成功。
4. **写后验收**独立读取实际写入及适用索引和成员，核对字节、身份、表示及领域不变量；写前证明不能代替它。
5. **收尾或恢复**按提交事实区分结果。提交前只在当前事实仍匹配本事务写入时恢复，不能覆盖后来编辑或新建的内容；提交后不自动回滚。无法证明恢复完整或写入结果未知时保留现场，对账后再决定下一步。清理和解锁失败保留真实变更与失败事实。

这些保证不提供非合作外部编辑的原子隔离。读取、权限、安全、原生工具与取消失败保持真实语义；取消或消费提前结束须收束后台资源，返回后不继续读取或回调。授权及具体恢复操作仍由领域操作契约和当前任务决定。
