# Design

以使用故障家族复核测试组合，依据证据确定删改，保持运行时行为不变。

## Context

提交 `ddbb4ca3` 的全仓注册快照包含 1443 个最小原生测试入口。本轮以真实使用故障、不可替代的接线责任和证据质量判断保留价值；断言有效本身不足以证明测试必要。测试粒度与 Case 维护遵循 [Test Evidence Review](../../skills/test-evidence-review/SKILL.md)，实现约束遵循[编码规范](../../docs/coding-style.md)。

## Goals / Non-Goals

- 目标：删去无当前使用义务或没有额外证明价值的测试；修正仍有独立价值的弱证据。
- 保留：领域格式、安全、数据完整性、公开命令行与真实 Git 的必要接线边界。
- 非目标：速度或删除数量指标、运行时 API 调整、新增测试框架或抽象、重复验证上游机制。

## Decisions

### Intended Change

三个子代理分别复核记录工具、基础设施和其他产品工具，覆盖基线全部入口。经正确性复核与实施边界核对，批准分类为 122 个删除入口、43 个实质调整、1277 个保留入口和 1 个保留原状的未决入口；数量是核对结果，不是验收目标。两个 metrics 调整入口合并为一个生产策略测试，最终注册快照为 1320 个入口（1443 − 122 − 1）。

删除重复项需要明确当前保留证据及其有效部分；测试的其他断言仍需调整，不妨碍其中已经有效的部分承接去重责任。先按切面复核，再由独立实现者执行；Case 与索引在测试实现稳定后统一更新。

命令行实际启用链接检查有独立接线责任，应保留对应测试。长流程、多断言本身不是强制调整依据；局部性测试证明其局部预检责任，完整生命周期副作用由对应成功矩阵承接。

调查历史的真实 corrupt-object fixture 已在不锁定 Git 文案的前提下证明项目 warning 映射；现有调用链没有更小的注入边界，因此保留原测试，不为替换真实 Git 增加运行时接口或 mock 框架。

### Resulting Impacts

- 测试删除或调整会影响聚合入口、imports、fixture 和 Case；只处理直接失去用途或证明范围变化的内容。
- Case 按意图连续性保留、收窄、合并或删除，再通过公开入口同步派生索引并核对注册覆盖。
- 使用现有测试与 Gate 验证保留边界；不增加新的 Gate 或上游机制测试。

## Risks / Trade-offs

不同层或不同领域可能拥有相同底层调用但不同接线责任。跨切面的保留证据必须一致，不能互相指向已删除入口；安全矩阵不能只因路径相似而删除。质量问题只有在保留价值成立后才需要修复。

## Open Questions

调查报告非法 relation type 的 CLI 退出码在现有说明中存在输入形状与领域错误分类歧义；本次保留该入口及原断言，不以清理测试为由选择新产品语义。已知 `scripts/validate.test.ts` 有独立项目接线价值但未进入当前 `test:*`，本次不新增 Gate 或冒称默认执行覆盖。

## Verification Evidence

- 最终公开注册快照为 1320 个入口，1174 个 Case 完整覆盖；11 个旧调整身份对应 10 个新身份，包含 metrics 合并和恢复测试移动，不增加测试意图。
- 提交前常规 Gate 首次仅被恢复测试文件规模拦截；将独立的 cleanup 失败恢复测试移至相邻容器，公开测试与真实 Gate 聚合均显式接入，保留原有完整恢复证据。原文件与新文件代码行数分别为 321、69，未调整 360 行阈值或增加豁免。
- `npm_config_offline=true bun run check` 复跑为 61 passed、0 failed、3 release-only 不适用；目标测试、最终独立正确性、编码规范和 ai-ready 文档优化均通过。两项显式启用的集成环境未运行，依赖恢复仅在测试私有 fixture 内离线执行。
