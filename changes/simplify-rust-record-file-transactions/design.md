# Design

以合作型工作区工具为边界，使用局部内容比较、文件替换和可操作的恢复材料简化 Rust 候选。

## Context

`tools/record-cli/README.md` 明确候选有两个二进制，生产维护和分发仍使用 TypeScript；本次验证平台为现有 Linux 候选，Windows 原生支持、manifest、CI 和 Windows 测试不属本次范围。`tools/record-operations/model.md` 描述现行共同事务，实施后须分层说明新候选与未改变的生产 TS。候选不承担发布、上线、入口切换、批量或常驻服务。

实施前只读审计的基线：`source/file_write.rs` 和 `transaction/writes/update.rs` 当时以句柄原位更新并证明身份；`source/resolve.rs` 允许受管根内目录链接而不跟随最终文件链接；`transaction/model.rs`、`mutations/identity/*/change.rs` 和 `transaction/writes.rs` 区分创建、更新、退出、更名及索引发布提交点。`git/publish/attempt.rs`、`alternate.rs` 使用真实锁与备用 index；`protocol.md` 已有独立结果及恢复字段。上述文件描述的是审计时的基线，不是实施后的现状；当前候选契约见 `tools/record-cli/protocol.md`。

## Goals / Non-Goals

保留领域和数据正确性、受管路径、无覆盖创建、合作锁、必要局部冲突检测及真实故障结果。工具不是数据库，不保证对非合作进程的跨文件原子隔离，也不引入 WAL、通用重放、领域持久格式或新业务权威源。

## Decisions

### Intended Change

| 操作 | 顺序、提交点与结果 |
| --- | --- |
| 普通更新 | 持合作锁，确认目标为受管普通文件并比较准备时的完整字节和必要普通权限；内容或权限变化则冲突。仅 inode 变化而字节、权限相同可继续。先在同目录独占建临时文件、完整写入并设置必要权限，再立即比较并原子替换，回读目标字节及权限；替换已发生即记录实际写入，普通更新以回读通过为提交点，回读失败报告已写/未知，不假报未变。最后比较到 rename 存在非合作编辑竞争窗口，不是 CAS；普通编辑器也可原子替换。 |
| 新建 | 直接独占创建目标，不以 `exists` 加普通 rename 替代；创建并验证后为提交点。写入或验证失败时按实际报告部分创建或未知，不能覆盖竞争者。 |
| 索引发布 | 必要正文和资源先准备完成，发布索引的实际替换为提交点，之后回读及领域验证；验证或清理失败保留 committed 与真实结果。无变化不虚构提交。 |
| 退出/更名 | 删除对象以旧路径退出为提交点；更名以目标建立、必要引用/索引更新及旧路径退出均完成为提交点。资源先逐项独占创建目标、复制并验证，再更新引用及必要索引，最后重查旧源的成员、字节及权限后删除；任何冲突停止并保留已完成和未知事实。涉及索引发布的操作仍以其实际发布点记 committed，并单独报告旧源退出与清理状态。 |
| Git stage | 保留真实 `.lock`、备用 index 与 `git update-index`，在锁内核对 HEAD/pending；精确处理选择范围、模式、删除，保留未选暂存与未跟踪数据。真实 index 发布为提交点；发布后验证或清理失败保留该事实。Git 不是工作区备份。 |

受管路径遵循现有根内目录链接规则：最终文件和资源树成员链接不跟随，越界或无法安全判定时拒绝；多写集别名须拒绝，避免意外扩大影响。替换遵守 OS 和原文件普通权限；只读目标拒绝替换，不因目录可写而绕过目标只读，也不提权或清除只读。替换改变 inode，不保证硬链接同步；涉及写集内硬链接别名须拒绝，其他硬链接保留旧内容。特殊属性、ACL 和 Windows 全属性保真不作承诺，不能静默扩大破坏。

正式正文、未提交或未跟踪资源和不能从正文无歧义重建的索引事实均须保护；IR 发布身份和成员按业务事实保全，不因正文可解析就丢弃发布基线。只有操作将覆盖或删除这些不可重建旧数据、且该旧数据在安全完成前没有可验证保留副本时，先独占保存并验证恢复副本；资源迁移的原源在最后删除前即为副本，删除前须确保验证过的目标及所需旧正文/索引备份足以恢复。备份和简短清单只是运维材料，不改变领域 schema 或成为权威源。

失败时保留真实原因、已完成及未知路径、备份位置；计划不等于实际。仅清理可确定由本次创建且仍匹配预期的临时物；恢复前核对现场，目标已有后来编辑、状态未知或无法证明安全时停止，保留材料人工对账。所有必要新数据经回读及领域验证、旧数据保护不再需要且清理目标仍匹配时才清除副本。允许部分完成，不强制自动跨文件回滚；只有确实证明完整恢复才能报告 rolled-back。

### Resulting Impacts

按 `source` 文件捕获、创建、替换、目录解析和资源复制接口，迁移 `transaction` 的模型、执行、fresh、postverify、recovery、resources 和 writes；再迁移两域 mutation、`stage/source_capture.rs` 与 `cli/transaction_output.rs`。保留 `ValidatedIndex`、ID、关系和生命周期；删除确无消费者的证明与类型，不以文件数或平台代码删除量为目标。

保留候选现有 JSON 字段和程序化信息，包括 `changed`、`committed`、`verification`、`outcome`、实际与未知路径、错误及适用备份；内部状态变化映射为真实事实。更新候选 README/protocol 与受影响的共同和两域 owner，明确 TS 行为未随候选改变。历史调查不改写；按实际长期取舍评估决策记录。

## Risks / Trade-offs

原子替换不能消除最后比较后的编辑竞争，复制资源增加 I/O，部分完成需要人工对账。恢复材料须以可核对内容保护不可重建事实，而不是为每阶段复制整个树。权限、硬链接和特殊属性与原位写不同，调用者须在候选协议获得明确边界。

## Open Questions

无阻止按本设计实施的产品选择。实现若发现必须改变生产契约、持久格式或现有候选 JSON 机器契约，先停下评审范围和迁移。
