# Design

以当前测试实际观察和既有替代入口决定层级，逐项收敛 Git 验证而不扩展实现结构。

## Context

审计基线为 `d5f9fde2821f03088a2a1850a3c2819b23224db5`：调查报告 67 项、决策记录 30 项，共 97 个最小原生入口。独立复核后分类为保留 50、下沉 24、Git 部分重复 16、替代未闭合 7；各项身份及处理范围见 `boundary-items.json`。

前序工具能力 Gate Change 已结项，本计划承接其后续测试必要性整改。仓库内其他 Change、调查报告及调查索引改动不属于本轮范围。

## Goals / Non-Goals

- 目标：40 项逐项落地，领域观察有去向，真实 Git 只承担必要运输、接线或外部状态证据。
- 目标：测试、Case 与当前可独立选择的原生入口一致，失败仍能定位对应契约。
- 非目标：修改产品行为、调整 Gate 订阅或 learned 调度、增加速度阈值、扩展 7 项待证测试、重新验证上游原生机制。

## Decisions

### Intended Change

1. 两领域分别由实现代理负责测试，先复用现有纯规则、真实文件系统和源码入口。保留真实 Git 代表时明确它承担的不可替代观察。
2. 重复节点优先移除其 Git 部分，保留独有规则；只有意图和观察均由现有入口承接时才合并节点。Case 按意图连续性维护，不机械按节点数量删除。
3. 决策记录三 scope 的来源漂移失败发生于公共准备校验，保留一个真实失败阻发布代表；已有 index→domain 命令行组合继续证明 scope 成功接线。
4. 调查报告 01/14/26/28/36/40/67 的替代未闭合，原测试不动。其他下沉项若发现完整替代仍依赖新 seam，回报证据并重新判断该项，不临时修改生产结构。

### Resulting Impacts

1. 测试名称、移动或合并影响实体身份时，显式同步 Case；账本 owner 在两实现切面稳定后统一更新派生索引和引用覆盖。
2. 下沉仍验证真实 FS 的身份、内容和失败保护；Git 级 mode、symlink 表示、暂存 CAS 与 HEAD 状态由现有必要代表维护，两个领域的写入接口不互相冒充证据。
3. 真实 Git 数量和操作减少用于说明边界变化，不作为正确性的替代。验收不设置新的耗时目标，不为计时新建抽象或基准。
4. 本次不改变长期维护契约或 skill 行为，不另建决策记录；逐项实施事实留在本短期计划，Case 仅保存当前有效的 Contract 与 Proves。

## Risks / Trade-offs

- 概念上可分离不代表已有无 Git 入口。原断言的完整替代必须在当前调用边界成立。
- 共享 Git 测试只证明其 API；不能代替本领域输入构造和命令行接线。路径相似和同用 helper 也不自动证明领域规则重复。
- 少建仓可能改变旧断言的可观察性，独立审查须核对保留观察，而不仅统计测试通过数。
- 工作区存在并行调查材料，提交只包含本轮明确归属路径，不暂存或清理其他来源改动。

## Open Questions

无；用户已授权按审定分类实施。7 项待证保持现状，不作为本 Change 的新增调查任务。
