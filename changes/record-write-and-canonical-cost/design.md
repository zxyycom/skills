# Design

按一次操作的可信事实复用工作，不跨阶段缓存。

## Context

本 Change 基线 `eea1d03e`；pending 替换在锁内取得和核对当前事实并在完成后提交或恢复。索引 build/parse 返回规范化、复制隔离和冻结的结果；公开序列化仍接受外部输入。

## Goals / Non-Goals

减少重复对象写入与已规范化结果的二次规范化；不改变独立 fresh、失败恢复、内容边界或第三类候选。

## Decisions

### Intended Change

待写字节以内容摘要分桶并以实际字节相等确认；固定上限 worker 处理唯一字节，失败停止新增派发并等待所有已启动任务。Git 自行计算仓库对象格式，结果再按原路径和 mode 组装。索引内部仅从同次可信 build/parse 流入序列化的位置直接消费其规范结果；外部公开入口继续完整规范化。

### Resulting Impacts

对象存储写入可能留下不可达对象，但失败不得更新 index 或在释放锁后继续写入。所有路径的顺序、表示与当前事实验证保持；验证 SHA-1/SHA-256、故障和实际消费者。必须逐个核实内部调用的冻结与 definition 边界；不能安全证明时不切换该调用。

## Risks / Trade-offs

并发失败时选择首个观察到的错误，等待已开始的写入；不承诺对象库回滚。直接序列化只能用于已证明的规范内部结果，禁止把它作为公开不受信输入接口。Windows 需目标环境独立复测。

## Open Questions

无用户决策问题；实现前验证每个规范化传递链的约束。
