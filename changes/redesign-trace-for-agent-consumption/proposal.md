# Proposal

本 Draft 规划将 Decision 与 Investigation 的 `trace` 收敛为受限、关系事件闭合的索引切片；具体输出契约在进入 Plan 前确定。

## Why

Agent 使用 `trace` 的核心任务，是在一次查询中恢复指定演进范围及其完整关系语义。现有结果分别提供节点、ID 或边，缺少主遍历成员、事件上下文和截断边界的统一表达，调用方需要追加读取并自行重建图，也难以判断结果是否完整。`trace` 应直接提供可遍历的领域索引投影，并明确本次查询的选择范围与覆盖状态。

## Outcome

`trace` 默认按深度 5、最多 50 条唯一记录选择关系子图，以完整事件为单位补入拆分、归并与重划上下文，并返回领域 entries、成员 ID、覆盖状态和续查边界。Agent 可以直接消费单次结果，并能区分完整结果、受限结果和仅用于事件闭合的上下文。
