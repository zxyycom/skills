# Design

仅消除已证明可省的工作，在各原有 owner 内实现并以独立证据验收。

## Context

基线为 `1bee5bdc`，工作区起始干净。上一轮已处理 Git 对象写入及符合稳定定义条件的规范化复用；本轮依据[剩余成本调查](../../docs/investigations/261028-record-cost-reachability-boundaries.md)继续，不重写报告形成时认识。

## Goals / Non-Goals

目标是完成四项保守优化及其生产接线验证。不改变叶节点文件身份检查、未选记录保护、trace 排序或 canonical definition 的冻结覆盖；不安装依赖、不发布，也不在缺少原项目时声称完成 Windows 复测。

## Decisions

### Intended Change

1. selected：revision 已不同即可判变更；revision 相同仍比较完整 state，仅对 changedIds 排序。
2. 重划闭包：保留组件访问与首命中顺序，降低集合相交查询成本。
3. 查询字段：仅在静态字段描述存在重复根校验时，由原有克隆过程生成调用内纯数据证明，首次根校验成功后复用。单字段、动态描述或无法证明的克隆产物沿用原路径；保持原数组 `map` 的结果与访问行为。
4. 长行：按有序命中合并得到最终范围，只有输出及截断结论已确定才停止；保留完整范围与 Unicode 坐标。

### Resulting Impacts

- 每项实现先覆盖对应结果与错误矩阵，再验证真实 consumer；使用确定性计数或差分，不以计时阈值代替算法证据。
- 长行接线另覆盖跨行 all、预览、abort 和错误传播；重叠命中仍可能需要遍历全部匹配。
- 通过公开同步入口更新实际消费闭包，按最终新增和受影响原生节点维护 Case 及 Gate 订阅。
- 主实现与独立代码、测试审查均使用 GPT-6.1 Terra；主代理负责文档语义复核、整体验收与提交。

## Risks / Trade-offs

短路可能改变动态对象读取时序，缓存可能误用公开输入，提前停止可能丢失重叠范围或截断证据。上述边界必须以实现归属及测试证明，无法保守保持时先报告，不静默放宽契约。

## Open Questions

无待决授权问题。用户在审查暴露查询缓存成本后明确选择继续寻找简洁方案，当前已改为构造期局部证明；外部 Windows 原场景仍需具备目标项目的执行方复测。

## Implementation Observations

独立审查排除了全局改写数组克隆以及事后递归判定缓存资格的方案：前者改变此前接受输入的行为，后者在单字段场景增加工作。最终候选把证明限制在既有构造步骤和一次字段物化内，不建立跨调用身份库；局部实验同时记录减少的校验和新增的数组描述检查，不推断端到端收益。
