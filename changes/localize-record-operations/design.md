# Design

以发布快照和局部操作事实分担一致性责任，删除普通操作的全集当前性兜底，而非给全集扫描增加缓存。

## Context

用户已确认缩小读取承诺、完整日期 ID 文件名、创建返回身份与位置、候选身份在转正时稳定，以及收窄未选候选引用维护。基线为 `54024a17`，已有性能证据见 `docs/investigations/record-tools-entry-matrix-10k.md`。Markdown 仍是事实源，索引是普通操作使用的发布快照。

## Goals / Non-Goals

目标是读取成本随所选和实际影响集合增长，并保留本次写入的安全与一致性。全量索引 JSON 读写及内存图处理仍可能随集合增长；本 Change 不承诺 O(1)。不新增随机／高精度 ID、候选索引、跨调用缓存、后台修复、持久数据库或通用事务框架；不批量迁移旧记录。

## Decisions

### Intended Change

1. 正式身份、位置、关系、生命周期与引用者发现使用合法发布索引；读取所选实际正文并验证身份与适用 revision。纯索引依赖不额外读取依赖正文，实际改写的依赖进入写集并独立验收。
2. 同一事务的准备、写前和写后阶段只重取本阶段必须验证的局部事实。索引 fresh/CAS 与实际写集保护继续存在，未选集合成员漂移不自动成为全局失败。
3. 创建沿用现有 UTC 日期语义，默认完整 ID basename；占用目标零覆盖失败。旧身份／路径通过索引或显式 locator 兼容；必要候选发现不扩展为正式正文扫描，具体最小接线由实现者在现有入口中确定。
4. candidate→formal 保持 ID，只改变生命周期／路径及投影。完整 ID 唯一，name 只是可歧义查询键；移除旧同名记录强制先迁移的创建前置。
5. 正式删除／更名根据索引计算正式影响集合；未选候选的关系与资源引用不参与自动修复或全局阻断，其未来发布需通过当时完整发布图与资源验证。显式同选候选限于现有 batch、evolve/group sources 等事务能表达的范围，不为未选候选修复新增批量选择接口。
6. stage 只消费本 scope 所选 payload，未选 pending 以完整 Git 路径、mode、OID 保持并做并发保护；历史门禁读取索引可定位的必要历史对象，移除全集 blob 身份发现。无法可靠定位的历史基线明确诊断，不默认为未记录。仅 pending 存在且所有可用索引均无定位的任意旧 basename，也明确要求恢复可信来源／索引，而非读取其他 pending blob 猜身份；canonical pending-only 路径仍可直接核对。
7. 全量 sync/check、显式正文搜索、候选列表或明确全范围发现保留相应范围；选择性 sync 也保留自身明确的 selected-and-dependencies 当前来源契约。已有集合缺失／损坏索引要求显式恢复，首次空集合按独立建立分支处理。

stage 的身份选择与旧位置收集分别判断：合法可用的 P 索引为所有所选 ID 提供旧 sourcePath，不能因 H/W 已含该 ID 而遗漏；所选 canonical pending 路径也始终核对。domain 遇到不可用的 P 索引时，只有在 H/W／canonical 已能定位所选的前提下才不以它阻断，并保持其成员身份与原状态；成功消费的 P 定位和实际所选正文仍进入独立 fresh 与 payload 保护。

### Resulting Impacts

- 两域修改行为 owner 与测试中的旧全集保证；保留真实失败传播和不覆盖、symlink、权限、锁、fresh、CAS、readback、cleanup 诊断。
- 候选定位、首次建立及历史基线兼容须用真实输入验证；API 变化只在确实承接所选范围时加入，不新增与 Outcome 无关的选择机制。
- 两域实现者分别拥有领域源码／测试／专属 Case／行为文档；共同实现者拥有共享操作与 Git/index-runtime 源码／测试及其专属 Case。共享生成、Case 索引和 skill 版本由主代理协调串行处理。
- 主代理维护 Plan、长期决策、集成与结项；阶段 reviewer 只判正确性。实现稳定后分别派文档和源码优化代理，随后复核必要受影响边界。

## Risks / Trade-offs

发布索引不代表未选正文当前；外部未同步修改可能在后续显式同步／检查或其成为所选对象时才被发现，这是已选择的责任边界。未选候选可能因删除／更名失效，发布时诊断而非隐式全仓修复。旧非 canonical 候选路径需要最小兼容定位；不能为兼容退回全集正式正文扫描。legacy 字面 ID 仍按 name 选择，跨格式同名时可歧义；旧来源通过索引实际 sourcePath 保持可读，不为消歧自动更名。索引、图和 Git 元数据仍有集合成本，性能验证需区分这些成本与正文 I/O。

## Open Questions

无需要用户决定的产品取舍。实现者已确认：候选定位优先精确路径，旧 locator 的兼容发现排除发布索引中的正式路径；缺索引时只在能证明不存在正式成员的独立 bootstrap 分支初始化；历史索引缺失且无法证明该领域历史为空时明确诊断。若实现中发现无法保持这些边界的真实冲突，由主代理协调后更新本设计。

## Implementation Observations

- 阶段正确性复核已关闭 no-op、逐路径历史身份及两域 stage 旧位置与可选 P 索引问题。最终文档优化完成；源码优化已移除不可达全集回退链和无消费透传。
- 首轮完整 `check:changed` 暴露新增输入归属、DR 语义测试容器接线，以及函数和文件指标缺口。已沿既有领域职责拆分并补齐真实消费者，同源窄指标零 findings，输入快照无未归属路径；没有改变门禁阈值、测试意图或局部读取契约。
- 同轮两个测试容器出现默认 5 秒超时；独立重跑 IR collection/resources 62/62、Task Graph public-distribution 6/6 通过。保留首轮失败事实，最终 Gate 仍单独验收，不以重跑替代它。
