# Design

以同输入、同行为的 Rust 原生查询切片，对照现有 CLI 和直接导入路径，独立测量性能与调用方式变化。

## Context

[当前查询契约](../../tools/decision-records/README.md)区分发布索引、当前正文、全图验证和搜索覆盖范围。现有 `list/search` 输出文本，`trace --json` 提供机器结果；[公开入口](../../tools/decision-records/src/cli.ts)还导出可捕获 stdout／stderr 的 `runDecisionRecordsCli`。

用户的使用者盘点支持将 CLI＋JSON 作为迁移候选，深层 SDK 兼容不作为实验目标。现行生产仍按 [TS 分发决策](../../docs/decisions/distribute-editable-typescript-runtimes.md)运行；本 Change 的实现曾位于独立实验目录，验收后清理。

## Goals / Non-Goals

目标是量化相同行为任务的实际收益，并暴露程序化调用迁移的成本。实验完成后再决定是否采用。

正式替换、SDK 退出、全面 JSON 协议、批量接口和跨平台发布属于迁移阶段；本轮的证明范围限于试点只读命令和实际运行平台。

## Decisions

### Intended Change

#### 试点与行为

| 命令 | 主要负载 | 本轮输出 |
| --- | --- | --- |
| `list` | 普通／关系筛选、排序与分页 | 现有文本 |
| `search --in metadata` | 全量匹配、精确计数与窗口输出 | 现有文本 |
| `search --in content` | 安全读取、Unicode 匹配、返回与预览预算 | 现有文本 |
| `trace` | 链、分叉和合法复杂演进事件 | 现有文本及 `--json` |

1. 以各命令实际 help 和领域契约冻结参数矩阵；Rust 独立完成查询、验证和输出。
2. 正确性覆盖索引／definition 校验、按需全图验证、稳定排序、截断与 coverage，以及当前来源的 ID、路径、文件身份和严格 UTF-8 检查。
3. Unicode 核对 NFKC、大小写、空白、组合字符、非 BMP 字符和原文 UTF-16 偏移。现有预算保持一致。
4. 独立预期取自行为 owner，TS 用于差分。文本、stderr、退出码及 JSON 语义字段与数组顺序分别比较；只对预先登记的绝对工作区根作等价替换。行为未达契约的单元先修复，再冻结匹配组进行性能测量。

#### 对照路径

| 对照 | TS 基线 | Rust 候选 | 回答的问题 |
| --- | --- | --- | --- |
| 命令行 | Node 启动分发 CLI | 直接启动 release 二进制 | 完整 CLI 改用 Rust 后快多少 |
| 程序化调用 | 常驻 Node 导入 `runDecisionRecordsCli` 并捕获输出 | 同类 Node 宿主启动二进制并收集输出 | 取消进程内调用后是否仍有收益 |
| 安装入口 | 上述冻结基线 | npm 启动器、下载器安装后的命令 | 安装入口保留多少原生收益 |

程序化对照中，模块首次加载单列，稳定调用从请求开始计时至结果可用；两侧执行相同任务，`trace --json` 两侧都计入 JSON 解析。`list/search` 对照现有文本，JSON 能力缺口列入迁移清单。以当时仓库中的调用作为对照基线，外部使用者样本有来源时另列。

#### 输入与计量

1. 冻结经同步检查的 TS 分发制品、Rust 锁定依赖的 release 制品、工具版本和平台；改动运行输入后建立新的匹配组。
2. 计量时冻结真实仓库只读快照及确定性生成器的 seed／参数。100／1,000／10,000 条合成输入通过既有同步与检查入口验收；准备成本与查询计时分离。
3. 搜索覆盖零命中、末尾稀疏命中、早期密集命中、长 Unicode 行；图负载使用合法关系。预算内和超限单元分别核对结果与失败。
4. 每个主要单元至少 10 对交替顺序采样。CLI 对照每次启动新进程，程序化对照在稳定宿主内逐次调用；记录预热、首次运行和缓存条件，独立进程不代表冷文件缓存。
5. 墙钟覆盖请求到完整输出消费；CPU 计入宿主与已等待子进程，RSS 按相同采样边界报告，独立峰值不相加。npm 启动器成本属于对应调用路径。
6. 构建、安装、断言与插桩 profile 在计时循环外执行，测量期间独占实验负载。保留全部原始值、失败与超时，报告中位数、离散程度、绝对值和相对变化；尾延迟和冷缓存结论需要另有充分证据。
7. 算法与工作量变化单列；需要归因于语言时补同策略 TS 对照，否则只报告方案整体收益。本轮按逐场景实测形成建议，迁移收益门槛留给采用决策，批量化收益另行评估。

正式计量在查看配对结果前选定下列主负载，每项分别运行无插桩墙钟与资源 profile；错误用例和重复参数组合用于行为验证。

| 输入 | 主要计量单元 |
| --- | --- |
| 100／1,000／10,000 条合成输入 | `page`、`metadata-zero`、`content-zero`、`content-dense`，覆盖分页、索引全扫、文件全扫与早停 |
| 固定真实快照 | `real-list`、`real-metadata`、`real-content`、`real-reallocation`、`real-relations` |
| 合法长 Unicode 行变体 | `unicode-preview`，覆盖原文映射与预览预算 |
| 100 条合成输入的 npm／本地安装入口 | `metadata-zero`，与同一原生二进制的直接调用对照 |

#### trace 查重优化与关系图补测

后续[复杂度调查](../../docs/investigations/261105-rust-query-algorithmic-complexity.md)确认了 Rust 普通 trace unit 的平方查重。本轮扩展仅移除这一冗余工作并保护预算、排序及事件行为，计量时旧源码和二进制作为独立对照，不用新结果覆盖旧版本。

计量前选定固定 N=8,193 的普通 fan-in，d=16／512／8,192，分别比较预算 1 和足量输出；另比较 N、E 相同的深链与宽层（E=272），以及小型重划事件的阻断／完整控制。合格单元用 TS／旧 Rust／新 Rust 三臂在同轮交错，12 轮覆盖六种顺序各两次；10 个 CLI wall 单元、6 个独立资源单元和 3 个常驻宿主单元分列，预热不混入正式样本。输入由生产同步与检查确认合法，独立预期与三臂差分先于计时；指纹漂移或行为不匹配停止计量。图形、字节量、输出规模及调用边界共同报告，局部算法对齐不等于纯语言归因。

#### 本地交付验证

同一版本化制品提供最小 npm 平台包／启动器和使用本地制品源的安装原型，核对版本、平台、完整性、错误传播与安装后离线执行。分别记录首次安装和安装后调用成本；运行 smoke 证明当前平台，其他 OS／架构及发布供应链列入采用成本。

### Resulting Impacts

- **源码与入口**：实验位于独立目录，验收后清理源码、测试和本地交付原型；生产源码、生成闭包和 TS SDK 保持原样。正式迁移另建源码、测试与 CI。
- **测试与证据**：本轮按用户明确的性能专项范围验收，规则矩阵使用原生测试，CLI 接线和来源安全使用必要的真实进程／文件系统。逐项记录真实原生节点、Contract／Proves 与执行结果；正式 Cargo 实体采集、项目 Case 账本和 CI 接入留待迁移，不作为本轮完成条件，也不宣称已接入。Cargo 与受影响的现有项目检查分别报告。
- **文件生命周期**：临时实验目录及其源码、锁文件和测试在验收后清理；方法、指纹和必要测量证据归入[调查报告](../../skills/investigation-report/SKILL.md)。留存材料供审计，不承诺完整重跑。
- **采用交接**：报告 CLI／JSON 对实际用例的承接缺口及 SDK 退出成本。若决定迁移，按批量优先、单项为数量 1 的批次设计新接口，并更新领域与分发 owner。

## Risks / Trade-offs

- 启动、I/O、进程边界与 JSON 编解码可能抵消计算收益，程序化对照用于识别这类退化。
- 跨语言的 Unicode、图语义和来源安全差异会造成假提速；行为不合格单元只作为原型观察。
- release 编译成功与本地安装通过只证明实际环境；写入事务、其他 skill 和未测平台仍有独立迁移成本。
- 实验写入限于源码及隔离测试／安装目录。真实记录修改、生产切换和外部发布须另获对应授权。

## Open Questions

无阻塞实施的设计问题。参数矩阵、实际基准 revision、环境清单与当时命令由 Readiness 任务冻结；性能收益和迁移价值由实验回答。
