# Design

以卡片组织创作，以正文反推验证执行；作者规则已明确，卡片协议与接口设计待现实样例核定。

## Context

作者规则如下，具体卡片样例和受控接口契约待补充：

- 人物卡、设定卡、关系卡、时间卡提供全局约束；剧情卡下辖覆盖若干章的弧线卡，弧线卡下辖单章卡。
- 单章卡包含细纲与导演视角。导演视角即镜头规划，处理多条叙事线、视角和场景切换，采用灵活的呈现规划。
- 修改先调整卡片，再由上到下传播；正文不会默认反向更新卡片。
- “预期”统一表示作者预期会发生、在故事中尚未发生的内容；“未来”是同义称呼。
- 已有文章可按同一规则反推卡片。原作后续设定或弧线可作为预期修改；后续单章卡可提取至独立参考区。
- 成稿通过受控接口反推细纲、导演视角与读者视角，再与单章卡对照。

## Goals / Non-Goals

- 目标：用一套工作流承接建卡、修改、写作与检查，保持作者既有创作方式。
- 交付边界：skill 保存通用规则、模板和必要工具；具体卡片、参考材料与正文由小说项目保存。

## Decisions

### Intended Change

以 Context 中的作者规则为约束，暂定以下实现方案：

1. **主工作流。** 从构思或原文建立、补齐卡片；写作读取当前规划，修改从最高受影响层向下复核。卡片字段与读取范围从现实样例提炼。
2. **参考使用。** 原作后续单章卡存于参考区，仅按任务读取；成为执行依据前须纳入作者的当前规划。预期是作者安排，AI 推断与人物知情状态另行辨明。
3. **反推对照。** 提取阶段读取正文及必要上下文，对照阶段读取目标单章卡。优先隔离目标规划，实际输入方式由接口契约确定。
4. **检查报告。** 提取结果附正文定位，读者视角表达对读者信息与期待的模拟；缺漏先回查，差异按计划偏离、允许的表达差异、证据不足和待作者判定分类。
5. **修改权限。** 检查只产出报告，作者决定改正文或先改卡片；机械检查承接所选协议中的确定性结构、引用和响应约束。

### Resulting Impacts

1. **接口。** 核定运行前置、输入输出、失败处理和稿件传输范围；外部调用按当前授权执行，敏感值不得写入配置、日志或分发包。
2. **工具与集成。** 按[项目工具链](../../docs/tooling.md)维护必要工具的源码、构建和生成产物，同步新 skill 入口、独立版本及分发检查。
3. **验证。** 覆盖构思建卡、原文反推、参考区隔离、预期修改的下层影响、多线呈现、实质偏离与合法差异、提取遗漏及接口失败；新增测试按项目证据约定登记。

## Risks / Trade-offs

- 卡片协议需要兼顾作者习惯与可检查性，字段从实际使用中收敛。
- 反推可能遗漏事件、误读视角或受目标规划诱导；报告须允许无法判定，并区分表达自由与计划偏离。
- 参考区隔离依赖实际读取路径；接口还涉及费用、稿件隐私和运行依赖，须分别验证。

## Open Questions

转为 Plan 前核定：

1. 真实卡片的字段、引用、预期标注，以及章节卡、参考区、报告的布局与读取约定。
2. 受控接口的可复用情况、执行边界、必要上下文、输入输出与失败契约。
3. 检查粒度、允许的镜头与语言变化，以及偏离报告是提示还是交稿门禁。
4. 最终 skill 名称、工具范围和原创／续写验证样例。
