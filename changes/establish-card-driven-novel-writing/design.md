# Design

以稳定卡片身份、递归内容、版本快照与统一变迁连接写作事实；文件为事实，索引与查询承担机械定位和关系投影，文学语义由作者与 agent 复核。

## Context

- 详情与递归总结承接写作内容；章节编号和计数范围用于日常定位，稳定 ID 用于引用。
- 演进与作者修订共享完整快照、专门变迁和维护流程，以旧状态的故事效力区分；正文对应保存在外部报告。
- 当前行为、字段效力和工具操作分别由 [skill 入口](../../skills/novel-cards/SKILL.md)、[卡片契约](../../skills/novel-cards/references/card-contract.md) 与 [CLI 契约](../../skills/novel-cards/references/local-cli.md) 承接。独立远端审稿接口不在本 Change 内。

## Goals / Non-Goals

- 目标：可用的本地卡片维护与写作流程，以实际扫描证明引用存在，以证据报告支持作者复核。
- 非目标：通用图引擎或事件溯源平台、自动小说质量评分、正文自动回写、远端审稿服务或安装发布。

## Decisions

### Intended Change

1. 本作卡片直接位于 `cards/`，独立参考按来源区分，未来仍由卡片发生状态表达。稳定 ID、版本、章节编号与显示标题分别维护；按编号或标题查询返回真实候选，不以同名覆盖或近似猜测替代身份。
2. 总结可先保存待展开远期目标，也可仅依据来源完成压缩；详情承接细纲/导演或人物/设定位置状态。`children` 表示组成，`sources` 表示依据，递归层次继续自由。
3. 历史快照保存被接替的旧卡，专门变迁记录用锁版本关系连接多个对象的前后状态及依据剧情。故事演进保留过去阶段的故事真实性，作者修订替代既有内容；两者复用同一记录和维护流程。工具从明确关系派生反向查询，不从自然语言猜测变迁。
4. CLI 复用现有 Index Runtime，来源指纹包含实际路径和完整文本；查询全扫合法来源并核对完整投影，使索引与实际卡片共同支持精确定位。
5. 变迁写入显式授权，先验证完整集合，再统一归档旧卡、接续新版本、记录变迁并重建索引；保留可复核的失败和恢复结果。修改已存在变迁保留其旧版本，当前关系查询只采用有效版本。
6. `expand` 只递归 `children`，预算到界输出 `frontier`；依据、关系与状态锚点按实际需求读取。版本快照和历史关系可独立查询，组成查询完成不表示所有背景已读。
7. 原创与文本恢复统一建立卡片；从最高受影响卡下传并复核总结。反推阶段隔离目标规划，对照阶段读目标；缺失证据回查，合法差异不当偏离。正文只保留小说文本。

### Resulting Impacts

1. 通过共享 bundler 生成 Node 自包含 MJS/source map，接入 updater、package scripts 与 Gate，源码与生成物保持一致。
2. 测试分别证明章节定位、版本引用、跨对象变迁、修订后关系有效性、预期边界和批量写入恢复，并保留来源安全、索引当前性、预算与生成分发验证。
3. 长期行为取舍集中在该 skill，测试 Case 和决策仅记录各自 owner 的证据与理由。

## Risks / Trade-offs

- 每次查询扫描全集合，以本地查询成本换取来源与索引的直接核对；文件/总字节/卡数有界，超限失败而非截断成功。
- 索引同步不标记或证明摘要语义有效；摘要、关系含义和混合状态需要人工复核。
- 受信本地工作区单写者，无恶意并发文件系统隔离承诺。
- 历史维护涉及多文件写入；完整预检、失败恢复与进程中断后的显式恢复必须按实际实现分别验证，不把文件移动成功当作变迁整体成功。

## Open Questions

无阻塞本 Change 的开放问题。真实作者使用、独立审稿 API 与大规模性能不属于本次已证明结果。
