# Design

暂定以同一不可变索引快照的进程内准备复用探索批量调用，待真实证据支持后决定方案。

## Context

[Index Runtime](../../tools/index-runtime/README.md) 的 reader 已固定 definition 和不可变快照，并复用字段物化；[共同记录操作模型](../../tools/record-operations/model.md) 区分同阶段证明、写前 fresh 和写后验收。当前尚无真实调用频率或可共享准备开销的量化依据。

## Goals / Non-Goals

优先研究同一命令处理多个目标，例如 `trace A B C`。暂不引入复杂通用编排、跨请求引用、跨进程常驻缓存或整批事务。

## Decisions

### Intended Change

暂定在同一进程或显式会话内，对同一工作区、领域集合和不可变索引快照共享加载、解析、验证、字段物化及惰性图。不同只读命令顺序执行时，未来可讨论复用同一上下文；具体接口和是否实施均待证据决定。

### Resulting Impacts

复用须保持快照及领域边界；当前正文仍须安全读取，写前 fresh 和写后验收须独立执行，不能以旧缓存替代。重新讨论或升级 Plan 前，采集真实调用样本，并对照测量加载、解析、验证、物化、图构建与逐目标查询等阶段，确认实际可节省的开销及正确性边界。

## Risks / Trade-offs

批量使用可能不足以抵消接口和生命周期复杂度；快照复用也不能证明可变正文或写入结果的当前性。现有 Rust 实验不构成批量收益证明。

## Open Questions

真实调用中哪些命令和目标组合足够常见？阶段计时显示哪些准备可共享、收益有多大？这些证据是否支持实施，以及应选择怎样的接口和会话生命周期？
