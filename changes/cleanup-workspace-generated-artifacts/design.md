# Design

先确认各类产物的生命周期和恢复方式，再对获授权的精确目标实施清理。

## Context

候选范围包括 `tools/record-cli/target/`、`dist/` 和 `.log/vibe-check/`；具体内容及其用途须在实施前盘点。

## Goals / Non-Goals

目标是安全回收可释放空间，保留报告所需证据与用户工作。不建立全仓自动删除框架或额外定时任务，也不修改 Rust、CI 或生产入口。

## Decisions

### Intended Change

暂定按来源、用途和生命周期逐项确定去留；仅清理确认可重建或不需保留且获得授权的精确目标。

### Resulting Impacts

清理前需确认保留项、删除项和恢复入口；清理后核对回收空间，并通过适当的重建验证确认所需产物可恢复。

## Risks / Trade-offs

产物可能包含唯一数据、报告证据或用户工作，误删不可仅靠重建补救；来源或用途不明时应保留。

## Open Questions

各候选目录中的具体保留和删除清单、重建入口、验证方法及所需清理授权，均须在实施前确认。
