# Proposal

以小工具能力输入和 Check 显式订阅表达变更影响范围，并按不可替代观察确定调查报告、决策记录测试的必要边界。

## Why

本 Change 的基线按整个领域复用输入声明，共享搜索输出改动会触发两领域全部 611 个测试。
改进须同时核对实际加载闭包与触发范围；测试保留真实 Git 等边界的理由应来自断言所需观察，而非既有层级标签。

## Outcome

每个可独立维护的小工具能力拥有明确输入和 flag，Check 自行声明订阅。
测试在足以证明契约的最小边界运行；保留必要 Git、文件系统与命令分发证据，将规则矩阵放回领域/API。

## Scope

### Intended Change

- 按现有源码职责定义工具能力输入及 flag，用原生条件组合表达各 Check 的订阅。
- 在现有成功 receipt 事务内表达能力输入变化，保持完整输入、保守执行与起止漂移保护。
- 逐项复核调查报告、决策记录的 611 个基线测试，按当前执行和断言重定层级及证据去向。
- 整理现有 fixture、CLI 支持及 wrapper 职责，解除无关加载耦合，使能力输入与实际执行一致。

### Resulting Impacts

- 同步 Gate 配置、诊断、项目测试、Case/index、稳定维护说明与必要决策。
- 生产源码确有必要调整时同步分发生成物和独立版本；测试重排不扩大公开 SDK。
- 复测无变化、搜索输出、暂存、共享基础能力及冷路径的实际触发与成本。
- 原生智能调度、资源隔离、环境前置、CI/cold 全执行和发布同快照事务保持。

## Success Criteria

1. 每个能力输入与每个 Check 订阅可从当前源码、fixture、生成物和外部输入恢复；不按领域名称推导全部订阅。
2. 搜索输出变化触发真实消费者和相关集成边界；没有该输入的矩阵可复用，有源码 CLI 加载边的矩阵仍如实订阅。
3. 只有完整当前输入与成功证明精确匹配才复用；未知、读取失败、缺失证明、失败或漂移保持保守。
4. 每个原测试都有明确证据去向；真实 Git 等保留项以不可替代观察说明必要性，下沉和合并不丢失独立失败语义。
5. 层级与 Case 描述以实际执行和断言为准；弱断言补强或退出，不用测试数量代替证明。
6. 受影响入口、最低支持 Node、项目类型/规范/生成/覆盖及完整 Gate 通过；记录成本而不设任意统一时限。

## Affected Owners

- `scripts/lib/vibe-gate/`、`scripts/vibe-check*.ts`：输入、能力 flag、订阅、成功证明与接入测试。
- `tools/investigation-report/`、`tools/decision-records/`：测试意图、实际边界、支持文件及必要内部职责。
- `docs/test-evidence/`：长期 Case 与派生索引；本 Change 的 `boundary-audit/` 只承接短期逐项证据。
- `docs/tooling.md`、`docs/gate-check-authoring.md`、`docs/decisions/`：维护契约及长期判断。
- 对应 `skills/` 与 `scripts/build/`：有实际分发字节变化时的版本和同源同步。
