# Design

本设计把 Git `HEAD` 限定为归档前的发现证据，并通过显式重试或单前序折叠解决同一变更内的无意义决策演进。

## Context

- `createdAt` 是候选与已建立记录的唯一生命周期边界；Git 不拥有决策成员身份。
- 当前 `evolve` 和带关系的 `activate` 会归档活动直接前序，`archive` 会让活动记录退出当前依据，但这些命令不区分目标是否已经进入已提交基线。
- 当前 `discard` 只删除完整、未激活且未被引用的候选；放宽它会把候选清理与已建立历史重写混在一起。
- 关系只表达真实直接前序。删除中间决策后，后继与更早上游之间的关系类型不能由两条关系机械合成。
- 共享 `VersionControlRepository` 已提供仓库发现、当前修订和修订文件列表；decision-records 可以消费这些证据而不复制 Git 命令。
- 决策集合允许位于非 Git 目录，因此版本证据缺失不能反向变成生命周期前置条件。

## Goals / Non-Goals

目标：

- 在可能永久保存未提交中间判断前暂停，让调用者作出明确选择。
- 让简单的单前序折叠仍能由一个重试命令原子完成。
- 保持最终关系完全由调用者声明，并机械拒绝越过已知直接前序边界的归档目标。
- 保持现有事务回滚、索引重建、非 Git 使用和候选清理边界。

非目标：

- 不从 Git 推断用户是否确认过决策，也不改变首次激活的生效语义。
- 不自动判断一个中间决策是否“无意义”，只报告版本证据和动作后果。
- 不支持一次命令折叠多层链路、分叉或多个中间记录。
- 不引入通用 remove 命令、关系重写命令或自定义提交基线。

## Decisions

1. 预检默认读取当前 Git `HEAD`。Git 仓库存在但尚无提交时，已建立路径都视为未进入基线；决策根不在 Git 工作树内或工作区不是 Git 仓库时，不启用该预检并保持现有行为。Git 仓库已发现但基线读取失败时，命令失败且不写入。
2. `evolve`、带关系的 `activate` 和 `archive` 在准备完成、写事务开始前检查即将归档的已建立记录。任一目标不在 `HEAD` 且未提供 `--keep-unrecorded-history` 时，返回“已暂停”的警告、退出码 1，并保证没有文件或索引变化。
3. `--keep-unrecorded-history` 是显式确认：调用者接受保留未提交记录及其演进历史。它只跳过本次预检，不放宽关系、生命周期或事务校验。
4. `evolve --collapse-unrecorded <decision-path>` 把一个活动、已建立且不在 `HEAD` 的记录声明为待折叠中间前序。该路径不能是后继本身、不能同时出现在最终关系中，也不能被后继以外的其他当前记录引用。
5. 折叠命令中的零个或多个 `--relation` 是后继的完整最终关系集合。活动目标按普通演进归档；已经归档的目标只允许是被折叠记录原有的直接前序。调用者可以明确选择不承接某个上游，CLI 不继承或合成关系。
6. 折叠的删除、中间记录空目录清理、活动最终前序归档、后继建立和索引重建复用现有可恢复事务。任何源校验、索引同步或读回验证失败时，恢复受影响 Markdown 与原索引。
7. `evolve` 至少需要一个最终关系或一个折叠目标；普通不带折叠的 `evolve` 仍要求关系。`activate` 不提供折叠选项，避免两个入口同时拥有历史重写语义。
8. `discard` 继续只面向未激活候选。复杂分叉、多层未提交链路、其他入站引用或无法确定最终直接关系时，不自动断链或删除，调用者保留现场并人工设计后续维护。

## Risks / Trade-offs

- 预检使用当前 `HEAD`，只能发现尚未进入当前提交基线的记录；它不识别已经分多次提交但仍属于同一更大逻辑变更的历史。
- 非 Git 根目录无法提供“未提交”证据，因此继续保守保留历史；这保持可移植性，但不能在该环境中使用折叠选项。
- `--keep-unrecorded-history` 是命令级确认，不证明该历史具有长期价值；调用者仍需做语义判断。
- 单前序折叠不会覆盖所有图结构。限制范围减少错误关系合成，但复杂场景仍需要人工操作和额外审阅。
- decision-records 分发 CLI 会打包共享版本管理实现，运行预检依赖目标环境可执行 Git；非 Git 路径通过明确降级保持可用。
