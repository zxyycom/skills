# Design

由只读召回者提供逐项证据，主审确认结论，单一写入者修复历史字段并交接完整集合的非空证明。

## Context

当前模型见 [Decision Records](../../skills/decision-records/SKILL.md) 及其
[生命周期与对齐规则](../../skills/decision-records/references/decision-record-rules.md#生命周期与对齐)。
调查基线 `0215c38fbf1228a9265bfd3beda15286f97a8ae2` 中有 338 条已建立记录，其中 92 条
archived/null。[召回线索](recall-evidence.md) 保存 31 条归档前 aligned 的提交定位及 61 条待召回 ID。
它是证据入口，不是已经批准写入的结果；实施时重新盘点来源。

历史登记值恢复、重新核对历史事实与本地线索推断分别记录。用户确认旧仓库已删除，要求仅用现有
本地材料尽力重建；允许有根据但未证实的历史推断，不要求补齐不可取得的原件。当前 CLI 的 mark-aligned 只接受
active/unaligned，没有保持 archived 的历史补值命令；本 Change 不通过生命周期命令重新建立旧记录。

## Goals / Non-Goals

恢复记录退出当前集合前的最后对齐判断，而非评价今天是否仍满足决策。目标、字段保持范围和验收
以 proposal 为准。

本 Change 不升级 skill 或 CLI，不新增通用迁移工具，不操作其他项目，不重新实施旧决策，
不修改真实采用方向，也不为每条回填创建后继决策或独立报告。

## Decisions

### Intended Change

#### 召回与审计

1. 从当前来源盘点 archived/null，冻结目标 ID、来源字节与索引基线。用 ID、历史路径和 rename
   证据确认对象，定位当前这次归档对应的最后活动阶段；不取任意一次历史 aligned。
2. 对明确旧值组，读取归档直接父版本、字段清空 diff 及后续正文演变。归档后未改变完整判断且无
   反证时恢复最后登记值；路径或格式调整不改变身份，实质方向变化或矛盾证据转入语义召回。
3. 对缺少可靠旧值的记录，按领域分批委派只读子代理。每批最多 10 条，读取完整决策以及相应历史
   tree 中的实现、配置、规范和验证材料。优先用 Git 只读查询；需要运行历史代码时使用隔离目录，
   不切换主工作区，不自动安装依赖或访问外部系统。
4. 每条交接包含 ID、归档与核对 revision、完整方向、建议值、具体证据位置和反证/缺口。
   可直接核对时，aligned 需支持历史完整方向成立，unaligned 需支持未完成或未建立基线。原件缺失时，
   可综合同次本地实现、gitlink 更替、维护记录、方案演进和保留快照作最合理推断；单一采用声明、
   指针移动或未找到材料均不足以单独决定值。推断项使用 method=inferred，明确列出无法核实的部分，
   不伪称当时验证过，也不排除缺失材料可能改变结论。
5. 主审逐项复核对象、时点、整体方向与证据强度；召回者和主审分离。矛盾项返回补证，确认项进入
   显式回填集合。主审分别确认直接证据是否支持结论、推断是否为现有材料支持的合理判断且不确定性已披露。
   连合理推断都无法形成的项停写交接，不以随机填值通过验收。

#### 来源修复与索引发布

本 Change 已获用户明确授权，采用一次性历史来源修复：仅将逐条审计通过的 archived/null 原位
恢复为已确认的值，保持 archived 和全部非目标字段不变。这是现行“对齐通过 CLI 事务维护”规则
在本次召回中的限定例外，不推广为通用手工状态维护，也不新增 CLI 命令。修复不构成新的对齐事件，
不通过 activate、mark-aligned、archive 的组合伪造历史。

单一写入者执行每批修复：

1. 先运行 `bun run decision-records -- check`，确认基线合法；核对目标字节与召回基线一致，
   当前没有其他集合写入者。存在漂移或混合改动时先重新对账，不覆盖他人工作。
2. 只编辑显式审计集合中目标 frontmatter 的 alignment 行。保留可恢复的原始字节及 ID 到结论映射，
   不重序列化整份文档，不改派生索引；写后直接检查完整 diff。
3. 严格 check 此时只能出现预期的索引陈旧差异；来源、关系或其他错误先修复，不继续发布。
4. 对本批每个完整 ID 重复传入 `--select`，先运行 `bun run decision-records -- sync-index --select <id> ...`
   只读检查。合法差异尚未发布时，该命令返回退出码 1、outcome 为 no-change，并明确说明 selected
   source change 尚不在当前索引；只有这一预期诊断才可用相同选择追加 `--write` 发布。其他错误先处理，
   不把所有非零结果视为可继续。发布后严格 check；无差异时只读检查成功，无需重复写入。
5. 修复过程中失败时暂停其他 mutation；来源合法且只剩已审计差异时重试同批同步，否则在确认没有
   外来变更后仅恢复本批原始字节，再以 CLI 恢复索引。无法证明恢复范围时停写交接。

### Resulting Impacts

#### 证据 owner 与下游交接

用 [Investigation Report](../../skills/investigation-report/SKILL.md) 创建一份 name 为
`recall-historical-decision-alignment` 的报告，实际 ID 由形成日期生成，tag 为 decision-records。
先查同名报告；已存在同轮内容时续写，不重复创建。没有真实直接前序时 relations 为空。

报告正文保存方法、历史语义边界与逐条最终证据表；每条含 ID、判断值、历史 revision、路径、
关键依据、recorded/semantic/inferred 方法、推断项的不确定性、主审结论和实际回填结果。使用 Git revision 定位材料，不链接本 Change 的临时文件。
阶段补证继续完善同一报告，不把每批处理拆成演进报告。

最终报告记录数据验收的代码基线与逐条来源原始字节 SHA-256、目标总数、当前全量空值计数及实际验证结果。
升级执行者通过 name 查得完整报告 ID，读取报告并重新检查当前集合；不能只相信旧统计。
报告及索引建立并通过检查后，Change 内线索可随计划退出；报告是长期证据，不是第二份决策状态源。

#### 验证与范围保护

比较修复前后目标文件：除批准的 alignment 行外字节一致。索引变化只包含相应字段与来源指纹；
报告写入独立按自身 CLI 同步。逐项验证和全量非空统计均通过后运行决策、调查严格检查及
`bun run check`，再按 Change Plan 的 Git 可恢复门禁完成，不自动发布 skill 或操作外部项目。

## Risks / Trade-offs

- 批量迁移曾写入 aligned；恢复历史登记不声称重新证明当时每项实现，遇矛盾证据必须补查。
- 归档前未有 Git 快照或历史环境不可运行时，按直接证据或明确披露的本地推断交付；运行困难本身不产生默认值。
- 当前代码、后继决策或今天测试通过，不能单独证明前序当时完整对齐。
- 尽力重建不等于确定恢复：推断值可能因新材料被更正，风险在报告中逐项保留；没有合理依据的项仍停写。

## Open Questions

无待决设计事项。逐项历史事实的取得和审核属于 Implementation，结果不足按上述停写条件处理。

## Implementation Observations

- 写入过程中有一次未带 `--select` 的 `sync-index` 按默认语义全量重建了当时索引；其余回填批次均有对应 selected 发布与检查。最终按原始字节基线核对全部来源及 CLI 派生索引，确认该例外没有接纳额外来源差异；长期报告保留此边界，不把过程描述为始终仅 selected 同步。
- `mask-non-code-test-syntax` 的初始 aligned 推断因把理论反例误述为已观察实践而被独立审查否决。按直接父树、首次入库时整体替代和完整验证义务作 unaligned/inferred 尽力重建，明确不能排除缺失的未提交开发快照。
