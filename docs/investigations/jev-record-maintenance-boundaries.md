## 形成时背景

本仓库用 Decision Records 保存长期判断，用 Investigation Report 保存形成时认识。两类记录的标签、正文、直接关系和记录边界需要语义维护；结构校验只能证明格式与图形合法，不能证明主题分类、承接范围或当前依据互相一致。

本轮在 2026-10-04 的维护前快照上使用 JEV：361 条决策（138 active、223 archived）和 45 份调查报告，共 406 份。低成本判断用于发现待复核问题，执行 agent 核对正文和当前 owner 后决定维护动作。调查从标签初筛扩展到关系与跨记录判断，以观察实际采用效果。

## 调查目的

区分三类结果：JEV 发现了哪些可行动问题；哪些错误来自模型判断、哪些来自调用设计或采用范围；实际维护与模型有效性各有何证据。

范围限于提供给模型的记录文本及其采用过程，不评估模型内部机制或重跑历史实验。复核意见也可能有误，不能作为独立金标。

## 调查范围与依据

### 输入与判断

- 全文标签初筛：每份记录在 95 个候选标签上分别评分主题贴合与检索价值，另评 8 个正文质量维度，共 812 次请求；两项 Score 均至少为 3 时进入标签候选。输入要求按正文主题而非文档体裁分类。`gpt-6.1-sol` 复核分层随机 42 份与重点 18 份，两组分开统计。
- 内部问题：全部 406 份分别判断同条件矛盾、必要上下文缺失和结论越过依据。它们只回答文本内部条件，不读取当前代码或其他记录。
- 直接关系：317 条边均提供两端全文；42 个 Decision 拆分或纯归并事件提供完整成员全文。所有被标疑的关系、两个事件信号和固定随机 16 条未标疑边得到独立复核。技术失败项取得有效重试后另外复核。
- 跨记录候选：在 active 决策、调查报告各自集合内，以字符二元组与英文 token 的 TF-IDF 近邻各取前三，去重得到 380 对。独立正文审查发现一个近邻漏掉的 active 冲突对，另行补入。固定随机 12 对及已知问题对分别复核；该方法不覆盖全部两两组合。
- 提问修正：原跨记录 Choice 将“有独立维护价值”与“有局部冲突”设为互斥选项。发现两者可同时成立后，保留原答，另用独立的冲突题与重复题判断同一批 381 对。新题明确 active 记录的共同适用性与调查记录的形成条件分别判断。

全部有效调用返回 `typesafe/jev-1.13-20260917`，通道为 OpenRouter System One。补充内部、关系、事件与跨记录判断共调用 1,528 次，1,527 次成功；一次网络失败的远端完成状态未知，保留失败后仅显式重试一次。成功响应合计 4,168,004 input tokens、133,932 output tokens，usage 的 cost 字段合计 `0.175056168`。该字段不自带币种，数值不作为结算账单，不含 Codex 复核或未知失败费用。

随附 JSON 供复核本轮观察：保存方法计数、全部关系摘要字段与响应对照，以及代表性标签、冲突和闭合事件的完整 state、所选原题与原答。省略无关独立问题和 CLI 留存元数据，复核意见另列字段；原始回答保持不变。

## 调查结果与边界

### 标签初筛有用，但概念邻近不等于可采用

随机 42 份中的 120 项新增标签建议，复核为 83 支持、33 不支持、4 不确定；33 项中 29 项集中在 `decision-records`、`investigation-report` 和 `relation-summaries`。该结果只表示此抽样及当时口径的接受性；按已知错误类别过滤同一样本不能证明泛化效果。

输入已限定正文主题，仍出现把测试 Case 决策贴为 `decision-records`、把轻量分发贴为 `lightweight-judgment`、把调查候选的 publish 贴为 `release-publishing`。这些类别需要结合正文对象复核；“主题相关”与“满足同名 skill 启用条件”也应分开，后者过严会造成复核者误删。现有观察不足以证明补充提示即可消除误判。

任务要求检查既有分类时，只筛新增候选并无条件保留旧值，属于采用端覆盖错误。原有标签与新建议应按同一正文依据复核，并分别说明同义标签统一与错误主题移除的理由。

### 确定性前提不能交给语义回答兜底

317 条关系中，302 条没有 `summary` 字段。题目提供了 absent 选项，但这 302 条得到 227 个 supported、65 个 unsupported、10 个 absent。292 个非 absent 回答只作为误判观察保留，未用于补造或修改摘要。

本批题目只写“关系 summary”，未指定嵌套 JSON 的精确 `state.relation.summary` 路径，因此该现象同时受输入设计约束。可采用的分工是由代码判断字段存在性，仅将实际摘要交给语义判断；本批结果不能代表所有缺字段任务。

### 独立维护价值、重复与当前冲突必须分别判断

原 Choice 对 381 对都回答 independent；因选项并非互斥，该回答不能排除局部冲突。修正为两题后，重复题全部回答 distinct；冲突题得到 379 个 no_conflict、2 个 conflict。定向复核结果如下：

| 对象与比较条件 | 模型回答 | 复核判断 |
| --- | --- | --- |
| 锁与原子写库的两轮调查：一轮已放弃 owner-token／stale recovery，但保留安装与提交结果监督；另一轮进一步删除外围监督。 | conflict | 误报；形成条件有明确变化。 |
| 原 owner-token／stale recovery 硬约束与删除该约束后的调查。 | conflict | 误报；不是同条件矛盾。 |
| 两条 active 方向分别将 basename 改变视作身份迁移，以及将 frontmatter ID 与存储位置分离。 | no_conflict | 漏检；当前适用的身份判断冲突。 |
| 两条 active 方向分别限制“关系覆盖只属于 evolve”，以及开放 set-relations 完整替换。 | no_conflict | 漏检；显式共同适用仍未识别。 |

另一个 Schema 案例存在恢复用途歧义，但“读取 Schema”不必然要求手工构造索引，未计为严格冲突。上述定向确认不用于估计 381 对的总体错误率。近邻漏掉一个真实问题对，说明候选发现覆盖与模型判别质量需要分别验证；固定随机 12 对未见问题仅支持该样本。

### 完整事件判断能够发现实际维护缺口

42 个闭合事件中，JEV 标出两个 gap。逐个读取完整成员后，一个是误报：后继已经分别承接历史确认与通用删除／折叠边界；另一个是真实缺口：`260904-current-change-plan-completion` 只承接删除结项，却声明归并了严格 Change metadata、历史调查资源链接边界、最小持久载体路由三项独立方向。

本轮据此更正历史关系，并按当前 owner 为三项仍有效方向分别建立自包含修订后继，保留前序的历史状态。另修正两条仅主题相关的决策修订边、两条未复核前序具体问题的调查复查边。模型信号促成复核，实际维护依据是两端全文、完整事件与当前 owner。

全部 406 份的三个内部条件都返回 clear；这只记录模型回答，不能认证外部事实或跨记录一致性。早先拆分分数引出的 13 个候选经复核后，12 个因已完成真实拆分、历史已退出或共享调查条件而保留，1 个 active 记录拆成恢复／复用方向与帮助投影方向。

### 可采用的维护方式与剩余边界

本轮支持的采用方式是：确定性条件用代码分流；独立维度分别提问；易误判类别定向复核；关系读取两端，归并与拆分读取完整承接集合。当前 active 一致性对照当前 owner，历史报告按形成条件解释。局部判断、候选覆盖、复核意见和实际维护分别留证。

任务覆盖与标签依据已补入 Decision Records，局部判断与整体验收的区别已补入 Lightweight Judgment，JEV 特点引用保留了本轮观察。尚未以独立留出集验证这些改文的行为收益，也未证明全库无漏项、历史外部事实及全部关系正确；服务后续版本需重新验证。
