## 形成时背景

2026-11-07 对 Rust record CLI 候选的定向调查，关注现有职责是否应交给通用库。同轮随后补做完整源码普查，避免将热点观察外推全仓；以下结果以补充普查为依据。Rust 是候选而非生产 TypeScript 入口，既有 JSON、错误通道和实际部分写事实是比较替代方案的边界。

## 调查目的

判断哪些职责值得交给库，哪些应保留领域实现，以及现有依赖的归属是否合适。无需新库的实现改进见[惯用实现普查](./261107-rust-record-idiomatic-implementation-review.md)。

## 调查范围与依据

补充普查的基线是 2026-11-07 10:55 UTC 采集的 commit `e03e9e87e937029c3058456cfb88d600e1f88ed7`。五名 gpt-6.1-terra 按分区全文阅读`tools/record-cli/src` 和 `tools/record-cli/tests` 下受版本控制的 280 个 Rust 文件（分别为 249 和 31 个，共 38,815 行）及 17 个关联输入；另一名同模型 reviewer 逐项复核 13 项发现并抽样。主代理完成路径、哈希和行范围闭合；机械闭合不等于独立重读全部源码或保证零遗漏。

本轮为静态源码普查，资源 `findings.json` 保存各发现的源码定位和后续验证要求。测试运行、替代构建、性能采样与逐测试入口价值审核不在本轮范围，实际行为正确性及替代效果尚未验证。

## 调查结果与边界

13 项发现中有 8 项建议修改、5 项待验证候选。本篇承接 1 项依赖归属修改和 2 项库候选；其余 7 项修改、3 项候选见[实现普查](./261107-rust-record-idiomatic-implementation-review.md)。**目前建议调整已有依赖归属，不建议立即新增或替换通用库。**

### 应改：libc 的直接依赖归属（INFRA-001）

`libc` 当前声明为普通依赖，普查中只有 Unix 测试故障注入直接使用它，生产源码未发现直接引用。建议改为 Unix 条件 dev-dependency，保留生产使用的 `tempfile`。这只调整直接依赖归属，不保证传递依赖消失或性能改善；实施后需核对 lockfile 和相关平台构建、测试。

### 候选：参数机制与图原语

- **CLI-001：比较 clap 或内部单表。** 两域分别处理选项，帮助又单独维护，已有帮助漂移，宜先修正帮助。clap 可作为比较对象，但事件顺序、错误和输出契约以及依赖与构建净成本尚未证明等价或有收益。
- **MODEL-002：比较 petgraph 拓扑排序。** 现有非递归 Kahn 验环与图库能力有重叠，但图索引适配、领域事件预算和稳定顺序的净成本未知。待出现其他图原语复用需要时再比较，不立即引入。

### 保留现有职责

YAML 扫描和 Unicode 规范化已使用通用库，而源文本保真、UTF-16 范围映射和 JS 兼容语义仍由领域代码承担。安全读取与事务已使用能力文件系统、`tempfile` 和 Git 等设施；替代方案仍须保持路径、失败和部分写语义。图的领域选择、历史和资源 owner 等责任也不因使用图库而消失。

最初定向调查曾把 `thiserror`、输出 DTO 和 Debug 映射列为较优先的试点；全量普查未发现足以支持其紧迫性或净收益的跨文件证据，因此撤回该优先级，后续按具体协议需求再评估。本轮尚未实施。
