## 回合 5

### 用户

那这样的话所谓的负向描述对于内容有有逻辑上的问题了。

你的新方向是，一般的负向描述的剪枝效率低于正向描述，所以负向描述需要避免，但这就会引入一个更深层次的讨论了，只要剪枝效率够高，是否负向描述会优于正向描述

### 助手最终答复

是的。**负向描述可以优于正向描述，但“剪枝效率高”只是必要考量之一，不是充分条件。**

这也说明，真正的原理不该是“正向优于负向”，而应当是：

> 选择能以最低上下文成本，最大幅度减少任务相关不确定性，并保留必要选择依据的表达。

设候选空间为 \(U\)：

- 负向描述“不属于 \(X\)”留下 \(U \setminus X\)；
- 正向描述“属于 \(P\)”留下 \(P\)。

哪一个剪枝更强，取决于 \(X\) 和 \(P\) 实际覆盖什么，而不取决于句子是正向还是负向。严格来说，应比较信息增益，而不是正负形式。

例如：

- 已知格式只有 JSON 和 YAML 时，“不要 JSON”已经唯一确定 YAML。
- “除周日外每天运行”比枚举周一至周六更紧凑。
- “不得把凭据写入日志”可以用一个稳定属性排除大量危险实现，通常比枚举所有允许记录的内容更准确。
- 相反，“不要使用微服务”留下的架构空间仍然巨大，也没有提供选择标准，因此信息效率很低。

还需要区分两个语义角色：

1. **可行域约束**：哪些结果允许或禁止。
2. **目标或选择标准**：在允许结果中应该选择什么、如何比较、怎样验收。

高剪枝负向约束可以完整定义可行域；当补集已经是单一或高度一致的目标时，它甚至可以独立确定结果。但如果剩余候选仍然很多，任务又要求选出最佳结果，那么无论约束是正向还是负向，都还需要目标或排序标准。

此外，负向描述还有独立的锚定成本。因此更准确的判断是：

> 当负向描述的信息增益、边界显著性和维护收益，大于它的上下文锚定与误导成本时，负向描述可以优于正向描述。

这意味着当前原则还应该再抽象一层：

- 不再规定“避免负向描述”；
- 改为比较每项约束的信息效率；
- 单独检查目标或选择标准是否完整；
- 最后单独评估负向对象的锚定成本。

甚至“正向/负向”本身只是表层句式：

- “只允许 A、B”看起来是正向描述，语义上却排除了其他全部值；
- “不得使用 A、B 以外的值”是负向句式，却表达了同一个集合。

所以真正稳定的分类不是正向与负向，而是：

- 目标；
- 选择标准；
- 允许条件；
- 禁止边界；
- 偏好与优先级。

你的推论成立：**如果继续以剪枝效率解释，就不能再得出“负向描述原则上应避免”；只能得出“低信息量、缺少选择依据或产生不必要锚定的描述应避免”。**

## 回合 6

### 用户

但信息效率怎么感觉有点太抽象了，我根本没想过这样的改进方式，会不会有点太激进了？还是我原本的想法是有些受限于我自己的固有认知，信息效率才是更加合理的方向

### 助手最终答复

我不建议直接把 skill 改成“信息效率原则”。**它作为上位解释更完整，但作为执行规则确实过于抽象，也会让这次改进扩张得太激进。**

你的原始想法并不是错误或单纯受固有认知限制。你实际抓到的是一个高频现象：

> 在开放问题中，负向描述排除一个方案后，剩余候选通常仍然高度异质；正向描述则更容易形成一个明确、相对一致、可验收的目标范围。

这里真正关键的可能不是“信息效率”，也不是数学上的无穷阶数，而是：

- 剩余候选是否仍然彼此差异很大；
- AI 是否已经知道该往哪个方向生成；
- 剩余结果是否可以使用同一标准验收。

这可以叫作**目标确定性**或**剩余空间的一致性**，比“信息效率”更容易实际判断。

更合适的原则可以写成：

> 负向描述并非天然较弱。若排除后剩余结果已经构成明确、一致且可验收的目标，它可以独立成立，甚至比正向枚举更简洁；若剩余结果仍然高度异质，负向描述只提供边界，不能代替目标状态和选择标准。

这样能同时容纳：

- “不要使用微服务”：剩余架构仍高度异质，需要正向目标。
- “格式只有 JSON 和 YAML，不要 JSON”：剩余结果唯一，负向描述已经足够。
- “不得把凭据写入日志”：禁止属性本身就是完整、稳定的契约。
- “除周日外每天执行”：负向描述比枚举六天更简洁。

因此，比较合理的层次是：

1. **执行原则：目标确定性**
   - 排除后剩余结果是否明确、一致、可验收？
   - 如果不是，补目标状态和选择标准。

2. **辅助取舍：表达经济性**
   - 正向和负向都能完整表达时，哪一种更简洁、稳定、易维护？
   - 不需要引入“信息效率”这个术语。

3. **独立风险：解空间锚定**
   - 即使负向描述已经足够，它是否会让模型继续围绕被排除对象搜索？
   - 锚定成本是否大于它带来的边界价值？

所以我的判断是：

- 你的原始直觉应当保留；
- 需要修正的是它的适用条件，而不是用“信息效率”彻底替换；
- “信息效率”可以作为我们理解例外的后台模型，但不适合直接成为 skill 的主要规则；
- 最终落入 skill 的核心概念，用“目标是否被确定”比“剪枝效率”或“信息效率”更稳。

不对吧，我感觉他作为原理最多只是相对激进，但其本身也是相当到位的描述，原理到动作是另一件事

### 助手最终答复

你说得对。我刚才把“原理是否抽象”和“动作是否可执行”混成了同一个判断，这是不对的。

**信息效率作为原理是成立的，而且比“正向描述通常优于负向描述”更完整。**它之所以显得激进，是因为它把判断从句式偏好提升成了普遍的信息选择原则，而不是因为它不准确。

可以这样分层：

### 原理：任务相关的信息效率

> 在语义、必要边界和风险约束不变的前提下，优先采用能以较少上下文更大程度降低任务相关不确定性的表述。

这里的信息效率不是单纯的：

- 字数更少；
- 集合基数更小；
- 正向或负向句式。

它关心的是表述让 AI 多大程度上恢复了：

- 合法候选范围；
- 目标方向；
- 候选之间的选择依据；
- 成功与失败的验收边界。

这个原理可以自然解释全部情况：

- 开放任务中，逐项负向排除通常信息效率低，因此正向目标通常更好。
- 负向约束能一次排除巨大空间时，它可以比正向枚举更高效。
- 禁止属性本身就是契约时，负向描述可能是最准确的表达。
- 正负表达提供同等信息时，再比较简洁性、稳定性和维护成本。

### 动作：把抽象原理转换成可执行检查

动作层不必要求 agent 计算“信息效率”，而可以检查：

1. 这段话排除或确定了哪些候选？
2. 剩余候选是否仍然高度异质？
3. AI 是否知道如何在剩余候选中选择？
4. 是否已有明确验收标准？
5. 正向和负向表达哪一种能更直接、稳定地传递这些信息？

因此：

- **信息效率**是解释“为什么”的原理；
- **目标确定性、剩余空间一致性、选择标准完整性**是落地动作；
- **正向描述优先**只是开放任务中的常见推论；
- **高剪枝负向描述可以更优**是该原理自然允许的例外；
- **解空间锚定**仍是另一个独立原理，用于计算负向对象进入上下文后的额外代价。

更准确地说，你原本的想法不是错误，而是捕捉到了信息效率原则下最常见的一种分布：

> 在开放问题中，目标实现通常比非目标空间更集中，因此正向目标往往比逐项排除提供更多任务相关信息。

现在发现“高剪枝负向描述可能更优”，并不是推翻原想法，而是把它从普遍原理降为有适用条件的常见规律。真正的上位原理确实更接近**信息效率**。

### 用户

但这样的话我怎么感觉会启发他的负向剪枝策略。

怎么感觉很难有负向剪枝真的比正向描述好，你这些推论是否只是数学理论上的可能

### 助手最终答复

你的担心是对的。它暴露出一个关键问题：**信息效率不能直接拿来比较“目标信息”和“路径边界信息”，因为两者承担的责任不同。**

可以把任务看成搜索问题：

- 正向描述定义目标集合或评价函数：**往哪里走、什么算接近目标**。
- 负向描述定义禁止集合：**哪些路径或状态不能进入**。

正向目标类似导航终点和距离函数；负向边界类似道路封闭信息。道路封闭得再精准，也不能告诉你目的地在哪里；目的地再明确，也不保证途中不会经过危险道路。

因此，“高剪枝负向描述优于正向描述”这个说法过宽了。更准确的是：

> 高价值负向描述可以是表达某项边界的最佳方式，但通常不能替代正向目标。

真实情况可以分成四类：

1. **独立的开放任务**

   “不要使用微服务”不能确定应该采用什么架构。
   这种情况下，负向描述几乎不会优于正向目标。

2. **目标已经明确，补充关键边界**

   “实现最小可维护修复；不要改变公共 API。”

   后半句非常有价值，因为正向目标没有排除破坏兼容性的路径。但它是补充目标，而不是替代目标。

3. **文档本身就是边界契约**

   “不得将凭据写入日志。”

   这里负向描述可以成为主体，因为这份文档的职责本来就是定义禁止集合，而不是指导完成某个开放任务。

4. **闭合且稳定的候选空间**

   “除周日外每天运行”比枚举六天更简洁。

   这是真实的负向表达优势，但它依赖候选全集清楚、补集简单。它不能推出普遍的负向剪枝策略。

所以，我之前举出的“负向可能更优”并非纯数学可能，但它们主要属于：

- 已有正向目标后的边际约束；
- 专门的禁止契约；
- 闭合空间中的紧凑补集表达。

它们不能支持 agent 主动寻找更多负向剪枝项。

而且你指出的风险确实存在：如果 skill 写成“选择信息效率最高的约束”，agent 可能开始主动枚举错误道路。这会产生三个反效果：

- 补造原文没有的约束，破坏语义保真；
- 把大量失败方案带入上下文，强化解空间锚定；
- 形成不断增长且难以维护的 denylist。

因此更稳的原则应该是：

> 先建立目标状态、选择标准和验收方式。只有已有契约、现实风险或高概率默认错误证明某条路径必须排除，而且正向目标本身不能自然排除它时，才保留负向边界。不得为了提高剪枝率主动发明负向项。

信息效率仍然有用，但应限制在：

> **比较表达同一项语义责任的不同写法。**

例如比较两种目标描述，或者比较两种边界表达；不能用它决定“目标可以被边界替代”。

所以实际关系应当是：

1. **目标指导**：决定往哪里走。
2. **必要边界**：排除已知错误道路。
3. **信息效率**：在同一责任内部选择更有效的表达。
4. **解空间锚定**：检查负向边界进入上下文的额外代价。

从这个角度看，开放任务里“负向剪枝整体优于正向目标”确实极少发生；负向描述真正的现实价值通常是**补充目标没有表达的关键边界**。

对，它们可以组合，而且现在看起来混乱，是因为我们把**模型、语义角色、评价原则和副作用**放在同一层讨论了。

它们并不是四个并列原理，更准确的结构是：

### 1. 共同模型：解空间

文档通过改变 AI 的搜索空间来影响结果：

- **正向引导**提供目标状态、选择标准、推荐路径和验收方式；
- **负向边界**排除不允许的结果或路径。

它们是两种互补的语义职责，不是两个原理。并且“正向/负向”只是常见句式，不完全等于语义角色：

- “只允许 JSON”句式正向，语义上也在划定边界；
- “不得输出 JSON 以外的格式”句式负向，却表达同一个边界。

### 2. 原理一：任务相关的信息效率

每段描述都应尽可能减少与当前任务有关的不确定性。

它用于解释：

- 为什么开放任务中，正向引导通常比逐项排除有效；
- 为什么闭合候选集中，“除 X 外”有时比完整枚举更有效；
- 为什么目标、选择标准、路径和边界不能用字数或正负句式简单比较。

但它只评价**表达是否值得占用上下文**，不能改变语义职责。高效边界不能因为剪枝很多，就自动替代目标引导。

### 3. 原理二：解空间锚定

某个对象一旦被点名，就会激活相关语义，使模型可能继续围绕它搜索。

它解释的是信息进入上下文后的**方向性副作用**，这不是普通信息效率能够完全覆盖的：

- 一条负向边界可能剪枝很多，信息量也很高；
- 但它仍可能把模型吸引到被排除方案附近；
- 因此还要单独判断边界价值是否值得承担锚定成本。

### 组合关系

可以统一成一条因果链：

> 文档以正向引导和必要边界塑造解空间；信息效率决定哪些内容值得表达；解空间锚定校正被点名对象带来的额外搜索偏置。

实际顺序就是：

1. 建立足够的目标状态、选择标准、推荐路径和验收方式；
2. 从既有契约、现实风险或高概率错误中补充必要边界，不主动发明错误道路；
3. 在同一语义职责内选择信息效率更高的表达；
4. 对被点名的排除项额外检查锚定成本；
5. 删除既不增加必要约束、又会激活无关方案的负向项。

所以最终可以整理为：

- **一个模型**：解空间；
- **两种角色**：正向引导与负向边界；
- **两个原理**：任务相关的信息效率、解空间锚定；
- **一个组合规则**：先完成搜索契约，再优化表达，并扣除锚定成本。

这样既保留了你最初“正向描述通常更有效”的观察，也不会误导 agent 主动发展负向剪枝策略。正向通常更强，是开放任务中的高频推论；不是脱离任务结构后永远成立的公理。


第二句话肯定了“一条禁止规则存在”，但没有把禁止变成允许。它是**外层肯定包裹内层否定**，不是“负负得正”。

这说明，如果把“正向描述”定义为“肯定了某件事”，那么几乎所有陈述都会变成正向描述——包括“X 不存在”“规则禁止 X”。这个定义会彻底失去区分能力。语言学和逻辑研究也强调，否定必须结合其**作用域**理解，否定词、否定命题和执行断言的行为不是同一个层次。[Negation](https://plato.stanford.edu/entries/negation/)、[Learning Negation Scope from Syntactic Structure](https://aclanthology.org/2020.starsem-1.15/)、[Assertion](https://plato.stanford.edu/entries/assertion/)

因此，我们此前用一个“正向—负向”二分承载了至少四个不同维度：

1. **表达极性**
   - 肯定式：“输出 A”
   - 否定式：“不输出 X”
   - 只描述句法或命题中有没有否定操作。

2. **规范作用**
   - 要求、允许、禁止、不要求。
   - “不要求 P”不等于“要求不 P”或“禁止 P”，因为否定的作用域不同。

3. **目标参照方向**
   - **目标侧直述**：通过期望结果的性质、原型或合法值定位目标。
   - **排除侧界定**：通过错误区域、禁止事件或补集定位允许范围。
   - 这才是此前关于构造成本、认知压缩和信息效率真正讨论的轴。

4. **描述层级**
   - 对象层：直接执行或规定规则。
   - 元描述层：引用、解释或记录这条规则。
   - 元描述层的肯定不会消除对象层的排除作用。

所以以后不宜再笼统地问“一句话是正向还是负向”，而应分别问：

> 它否定了什么？否定作用域在哪里？它承担什么规范作用？它以目标还是补集作为参照？它是在执行规则还是描述规则？

这也会修正此前的核心命题。更准确的说法不再是：

> 正向描述通常比负向描述高效。

而可能是：

> **当目标侧已经存在稳定且有独立含义的概念时，直接使用该概念，通常比通过多个排除侧条件间接构造它更容易理解、压缩和使用。**

这里的重点不再是有没有“不”字。例如：

- “只允许 A”是肯定句式，却在定义排除边界。
- “无状态服务”具有否定构词，但已经是能直接组织架构选择的稳定目标概念。
- “采用非 X 方案”虽然没有写成“不要 X”，却可能仍然只是给补集换了名字，没有告诉我们该选择哪个非 X 方案。

因此下一步最值得讨论的是：

> **一个从否定或补集形成的概念，什么时候已经成为能够组织选择、产生推论和支持验收的“目标侧原语”；什么时候所谓正向改写只是给 `非 X` 起了新名字？**

更准确地说，安全主线具有纵向展开：

```text
目标概念：安全
    ↓
组成属性：机密性、完整性、授权、可审计性
    ↓
具体规则：不得泄露、不得越权、不得绕过审计
```

`安全`负责说明这些规则为什么属于同一个目标；具体负向规则则负责把抽象目标变得可判断、可执行。它们不是“正向主线与负向附录”，而是**同一条主线在不同抽象层的表达**。

这也产生了真正的反例：

- “系统必须安全”是正向描述，但信息极少。
- “秘密不得进入日志”是负向描述，却给出了明确违规条件。
- 如果为了追求正向表达，把后者改成“系统应妥善处理秘密”，反而重新变得模糊。
- 如果试图完整枚举所有允许写入日志的内容，还可能比直接禁止秘密复杂得多。

某些形式化安全属性确实可以通过有限的“坏前缀”识别失败，因此失败侧天然比全部合法执行更容易描述和监控。[Enforceable Security Policies](https://www.cs.virginia.edu/~soffa/cs851/p30-schneider.pdf)

所以，目前可以把结论修正为：

> 当目标侧存在同样精确、直接的描述时，正向描述通常更容易组织理解；但当目标只是抽象名称，而失败条件更具体、稳定、可观察时，负向描述可以明显优于正向描述。

这也说明最初的“目标实现是低阶无穷、非目标是高阶无穷”不能普遍成立。对于安全目标，合法实现可能极其多样，反而少数禁止事件具有更低的描述复杂度。真正决定表达优势的不是哪一侧集合更大，而是**哪一侧能用更简单、稳定的条件提供所需判断**。

不过，“负向描述证明了安全”仍要限定范围：禁止项可以定义并验证若干安全属性，但不能仅凭已知禁止项证明抽象意义上的整体安全；部分信息流安全甚至需要比较多条执行轨迹，不能化约成独立禁止事件列表。[Hyperproperties](https://www.cs.cornell.edu/fbs/publications/Hyperproperties.pdf)

因此下一步最值得区分的是：

> 一条负向规则是在完整定义目标、给出必要条件、提供可观察的违规证据，还是只覆盖当前已知风险？
