# 本轮采集协议

## 问题与操作单位

调查固定源码 94f792e09efa39700005ace7e05be2bc14fb9579 在十万条正式存量下的全部公开业务命令。命令输入保持单对象、单边、单份候选或小查询窗口；不扩大批次、不枚举参数组合。Decision 18、Investigation 14 个业务命令，按必要成功路径/预算边界及 stage scope 拆为 25+22 个场景。help 不读集合，不作规模计时。

## 数据与状态

每域独立合成 Git 仓库，基线 HEAD 为100000正式对象、2候选。图每10节点一组，9条叶到根边；叶查询/修改无需大图展开。调查正文1024字节，决策正文约1.1KiB；调查域只保留5个96字节附件以覆盖资源路径，资源数量不随存量增长。每条命令前恢复同一基线并准备O(1)改动；成功写入可能使正式数N±1，下一条恢复N。

不调用旧报告资源中的脚本；本轮方法新写。fixture构造/准备/后验验证均不计入业务CLI耗时。涉及同步和stage的前置来源/索引从固定版本serializer构造，计时主体仍为真实公开CLI，不以内部handler或预检替代实际写入。

## 计量

串行运行正式CLI，每场景一次。命令限时600秒；准备/后验分别1800秒。CLI使用Node默认heap，NODE_OPTIONS未设置；辅助准备/验证独立4GiB heap，不传入CLI。os.wait4计量实际Node CLI从启动到退出的wall/user/system/maxrss，stdout/stderr完整落盘并计算SHA256，内存中仅保存256KiB头部供断言。RSS不是同时刻进程树内存总和。未主动清OS缓存，独立CLI不等于冷缓存；运行顺序原样保留。

若超时终止整个隔离进程组；异常停止该域，保存现场、锁/事务/Git差异和内存事件；经人工核对并精确恢复或新建fixture后才继续未尝试场景。任何异常不得自动当成功或默认为其他命令同样失败。缺失metrics独立分类。Node原生heap诊断与cgroup OOM事件分开判定。正常exit0/预期cap exit1还需独立后验，验证完整索引变化、来源路径、候选/附件、pending保护及未知工作树差异；后验失败单独报告。

## 解读

一条样本用于发现数量级卡点，不估计p50/p95或生产SLO。content cap拒绝前可能已经完整验证来源，不能称为扫描十万份正文成功；关系小集合成功也不能把小文本匹配量等同于只读少量来源。源代码、默认heap、计时边界与旧SDK/4GiB测量不同，只在本轮相同协议下对比操作类别；不直接据旧数字计算性能变化。
