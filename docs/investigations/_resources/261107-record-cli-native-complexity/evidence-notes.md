## 长行探针

### 输入与独立预期

从前轮单记录 fixture 复制私有副本，在正文末尾追加 ASCII 测试行。索引为 705 字节，ID 保持 `260101-record-00000`；行长 L 取 4,096、16,384、65,536，最大文件总长 65,907 字节。查询使用 any 模式，词为 `x xx … x^Q`。

| 行形态 | 独立预期 |
| --- | --- |
| 连续 L 个 x | 原始命中合并为 `[0,L)` 一个范围 |
| 一个 x 后接 z | 仅 `[0,1)` 一个范围 |
| 交替 xz | 前三个范围为 `[0,1)`、`[2,3)`、`[4,5)`，因第 4 个分离范围触发命中预览截断 |

预览上限为 24,000 个 UTF-16 单元，长行输出会裁剪。因此 64 KiB 连续行的实际 JSON 直接观察到的是 `[0,24000)`；完整终点由输入与合并机制推导。

每次核对：命中身份、精确 matched=1、scan/results 完整、范围、两类预览截断标志及 warning，并检查同单元输出 SHA-256 稳定。追加测试行后保留原索引 revision，使用 content 查询的 `published-index+current-text / currentness: unchecked` 语义：发布索引提供选择范围，当前正文提供文本，读取核对 ID。

### 推导与补充观测

对于连续 x 行，第 j 个词有 `L-j+1` 个命中；原始命中总数 R 为其求和。每次推进一个命中时遍历 Q 个 head，末次空检查再遍历一次。

| L=65,536 | Q=1 | Q=8 | Q=16 | Q=32 | Q=64 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 源码推导 R | 65,536 | 524,260 | 1,048,456 | 2,096,656 | 4,192,288 |
| head 槽遍历推导 | 65,537 | 4,194,088 | 16,775,312 | 67,093,024 | 268,306,496 |

上表是源码级逻辑计数，Rust `str::find` 内部比较次数另属运行时实现。查询文字从 1 增至 2,143 字节；64 KiB 时 stdout 为 145,214–147,357 字节，包含转义为 `\uXXXX` 的 24,000 个预览单元与 query 回显。

| 补充输入 | Q=1 中位数（ms） | Q=8 中位数（ms） | Q=16 中位数（ms） |
| --- | ---: | ---: | ---: |
| L=4,096，连续行 | 1.874 | 2.658 | 3.940 |
| L=16,384，连续行 | 4.089 | 6.472 | 11.854 |

## 批量名称预检

复用前轮 N=5,000 的私有 fixture，索引 2,218,124 字节。原生 `sync-index --preflight --select` 分别接收相同对象的完整日期 ID 或唯一名称，K 为 1、100、500、1,000；预期身份从 `260101-record-04000` 连续选取 K 条。

每次核对 selectedIds、checkedIds、reportCount=5000、state=unchanged、changed=false、changedIds 为空及 warning 为空。公开预检分支只准备计划，fixture 全树首尾摘要相同。单元按 K 和类型顺序执行。

| K | ID 输出字节 | 名称输出字节 |
| ---: | ---: | ---: |
| 1 | 501 | 494 |
| 100 | 7,035 | 6,335 |
| 500 | 33,435 | 29,935 |
| 1,000 | 66,435 | 59,435 |

名称与 ID 解析后的对象及检查集合相同，选择器回显不同。全部耗时还包含基线验证、图准备、所选来源读取、投影和输出。

源码入口为 `cli/mutation/investigation/services.rs:45–73`，经 `mutations/sync/selected_sync/baseline.rs:220–233,261–274`，逐选择器调用 `domains/mod.rs:184–213`。名称分支逐次过滤 N 条，日期 ID 分支使用 BTreeMap。

## 其他源码候选

### 全集统计、排序与结果窗口

- `queries/load.rs:10–25` 捕获并解析完整索引，需读入 B 字节。
- IR `investigation/list.rs:55–60,122–160` 构建全集 facets，过滤后保存 M 条匹配引用并排序，再分页；准确 total 与 facets 有全集观察义务。全排序和 O(M) 引用保留可与有界 top-(offset+limit) 比较，需保持 UTF-16 稳定顺序；大 offset 会改变取舍。
- IR `investigation/metadata.rs:72–94` 先按 source path 排序 N 条再过滤匹配，准确计数仍遍历候选，DTO 只保留 limit 内结果。过滤与排序的先后可结合顺序契约评估。
- `investigation/search.rs:66–79` 选候选，`queries/content.rs:44–63` 再按来源路径排序。content 的截断要求返回预算满后继续寻找首个额外命中，应在同一语义下比较扫描方案。

这些是形成时源码推导，局部排序成本尚未独立计时；两域具体过滤和预算由各自入口拥有。

### 图准备与事件聚合

`investigation/trace.rs:39–57` 取得完整有效图后作有界选择；`domains/graph.rs:7–39,81–90` 建邻接并排序，工作量受 N、E、节点度和字符串比较影响。`trace/selection.rs:71–82,123–195,275–311` 按 BFS 层遍历，完整事件成员、frontier 与输出各有必要工作。

现行事件路径通过 IR `investigation_events.rs:25–53` 的 seen、DR `decision_events.rs:121–155` 的事件指针表及 `trace/selection.rs:14–36` 的 HashMap 聚合。历史原型的普通 unit 两两查重已由现行结构收敛；复杂事件、长共同前缀和 DR 重划仍需独立计数。

### 身份更正、stage 与临时保留量

- `stage/index_scope/selection.rs:19–27,58–75` 对每个选择器在最多三个快照中调用相同解析函数，并扫描 extra_ids。本轮动态覆盖的是同步预检。
- `mutations/sync/selected_sync.rs:47–76,90–105` 的 `validate_update` 只在“新 ID 且有当前值”时遍历 updates 寻找同选旧 ID 删除，存在特定批量组合的 K² 候选；完整 CLI 能否一次产生该组合仍待验证。
- 同文件 56、239–284 行构造基线和候选投影副本，保留量取决于状态字节及生命周期。
- `preview.rs:43–59,153–194` 与 `matcher.rs:123–180` 构造整行规范化、映射和 UTF-16 向量，即使预览较短仍有随行长或规范化字节线性增长的临时表示。IR 文件预算为 2,000 个候选、单文件 2 MiB、累计 20 MiB；DR 为 10,000、2 MiB、20 MiB，两域预览额度也不同。

副本与长行中间表示是源码保留量判断；实际 RSS、同时活跃字节和真实负载收益另需测量。
