# 一万条存量全入口测量协议

本文说明 2026-10-24 本轮测量实际采用的方法。覆盖与结论见[调查报告](../../record-tools-entry-matrix-10k.md)，精确场景见两域矩阵，代码实现按[方法导航](measurement-methods.md)读取。

## 输入与采样

源码固定为 Git `70c1a2555f5da48eea6013e7a7cab4aeb3cb2441`，使用 Decision 93、Investigation 83 的公开生成 CLI。源码与已安装依赖复制为独立输入；开始／结束指纹及运行时外部 optional 依赖边界见[环境与输入](environment-and-inputs.json)。正常运行使用冻结源码，probe 使用记录了来源和转换的插桩副本。

两域各用无 remote、停用 hook、隔离系统与用户 Git 配置的合成仓库。每场景从固定 setup 恢复同字节输入：一万条正式记录、九千条稀疏关系、常数候选及资源；四个零正式边界单列。生命周期、资源、恢复状态、历史门禁与操作范围按矩阵区分。输入恢复、指纹和独立后验均在计时外。

每场景三个正常样本按矩阵正序、反序、正序执行，再单独采集一次 probe；保存全部样本和实际时序。正式命令串行，其他重型测试与输入构造暂停。输入核对预热 OS 缓存，宿主外部负载仍可能存在；三次采样用于观察离散程度，结果不代表冷缓存、整机隔离或生产 p95。

## 进程指标

每次启动全新 Node 26.8.2 进程，使用默认 heap，清空继承的 `NODE_OPTIONS`、`NODE_PATH`、覆盖率及编译缓存配置。共同采集器通过 Linux `os.wait4` 记录以下字段，范围包括进程启动、模块加载、业务、输出和退出。

| 字段 | 定义 |
| --- | --- |
| `wallSeconds` | 启动前至退出并被回收的单调时钟秒数 |
| `userSeconds`／`systemSeconds` | `wait4` 返回的 user／system CPU 秒数，可包含该口径计入的已等待后代成本 |
| `cpuSeconds` | user 与 system 之和；CPU／wall 不等于单线程利用率 |
| `maxRssKiB` | Linux `wait4` 峰值 RSS，可能体现已等待子进程的最大值；区别于 JS heap 和子树同时 RSS 之和 |
| `exitCode`／`timedOut`／`outcome` | 分别保存退出、信号、超时与启动失败；启动失败的 CPU／RSS 为 null |

stdout／stderr 保存完整字节和摘要。单次限时 600 秒，超时仅终止本次独立进程组；既有输出禁止覆盖。采集器已独立核验成功、非零、大输出、超时组收束、启动失败、重复输出保护及输入范围检查。probe 的 wall／CPU／RSS 单列，正常排名仅使用未插桩样本。

## 工作量口径

| 对象 | 已观测内容 | 解释边界 |
| --- | --- | --- |
| 正式正文、候选、索引、资源 | 成功完成的 Node 读写 API 次数、返回字节和 unique 路径，覆盖同步 worker、异步 FileHandle | 这是 API 层数据工作量；零字节 EOF 也可形成调用。内核 syscall、物理 I/O 和 loader 读取另属边界。 |
| Git `cat-file` | 实际批次、对象、完整 payload 与 framing 字节 | prefix 保留量只表示消费量；HEAD／pending 来自初态 OID 成员关系，可双归属，不代表精确阶段。 |
| 解析与关系处理 | 来源解析、索引解析、关系上下文与实际构图次数 | 各层分别解释，嵌套调用不相加为唯一解析总量。 |
| 文件写入与状态变化 | 成功写 API 及字节、最终文件增删、移位和 mode | 写入包含临时文件；rename／unlink／mkdir／chmod 次数和 Git 内部文件 I/O 未采集。最终持久效果以独立后验为准。 |

stdout／stderr 的 fd 1／2 单列；索引、候选的临时文件可能归 `other`，分类 write=0 不能证明零写入。Git 重叠角色不重复求和；无法覆盖或可靠归属的事实保留 unknown／未测。

计数器经过已知小输入自证与独立 worker、FS、Git framing、去重边界核验。调用次数用于比较工作量，阶段耗时占比需另取证据。

## 独立效果核验

每场景以领域契约和独立输入模型计算预期，核对完整工作区字节与 mode、身份／关系／生命周期、索引 envelope、完整版本化 sourceRevision、候选／资源、Git pending 与未选保护。被测 parser／check 不作为唯一判据。预检、拒绝、no-op 和 unchanged 分别核对零持久变化。

正常／probe 的完整 stdout、stderr 逐字节比较；IR 初末状态不归一化，DR 仅精确归一首次建立的 `createdAt` 及其派生 v2 revision，并保留原始身份与替换记录。等价判断限定于这些已声明差异。

首次异常保留原始现场并区分方法错误与产品结果；方法纠正另记原因和版本。正式采样保留所有结果，分类为预期成功、预期拒绝、产品异常、方法无效或未完成。准备阶段纠正及最终通过证据保存在来源与审计材料中。

## 资源处理

随附材料保存场景矩阵、全部样本指标、输出身份及去重展示、后验摘要、计数、来源指纹和形成时方法。展示路径统一标记化，原始字节身份与展示身份分别保存；长列表以 count＋SHA 代替。完整合成仓库、依赖、大索引及逐样本完整 maps 未随附。

这些材料用于复核测量与结论。方法代码是形成时阅读副本，未登记为长期维护入口或测试 Case；被测产品接口、实现、版本和分发保持不变。
