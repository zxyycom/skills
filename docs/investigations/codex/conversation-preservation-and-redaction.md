#### 形成时背景
[AI 文档目标、边界、信息效率与解空间锚定调查](../ai-ready-docs/target-boundary-information-and-anchoring.md)的十九份认识快照来自同一段连续 Codex 会话。用户认为这段讨论本身具有较高保存价值，希望保留两种可继续处理的形成时材料：一份尽可能保留公开对话和操作脉络、但移除本机细节与低价值运行数据的 JSONL；一份只保留用户消息和每回合最终答复、供后续人工删减的简单对话初稿。

保存会话的对象、证据和风险边界不同于原报告研究的正负描述原理，因此本主题独立记录归档、脱敏和派生版本之间的关系，不把保存过程作为概念调查的新认识追加到原主题。

原始会话不能直接进入仓库。它同时包含运行时指令、本机环境、内部推理、原始命令与输出、重复事件和 token 等数据，既超过后续复核需要，也扩大敏感信息与临时状态的长期暴露面。因此，处理过程先对原始文件建立逐字节一致的私有工作副本，再只从副本生成仓库资源；原始文件与工作副本均不作为仓库内容。

#### 调查目的
本轮要保存能够复核相关讨论形成过程的最小充分材料，并明确两个派生版本各自的承诺和不可外推边界。近全量版服务于恢复公开对话顺序和“发生了什么”；对话初稿服务于后续阅读与人工精选。二者都不能冒充原始 JSONL，也不取代相关概念调查已经整理出的结论。

本轮不继续回答正负描述原理，不修改 `skills/ai-ready-docs/`，不对简单对话初稿做主观删节，也不把一次性生成脚本建立为仓库长期工具。主观精选版本留待后续单独形成，不覆盖本轮机械初稿。

#### 调查范围与依据
来源为 `codex://threads/019ff59c-ec2a-7c43-ae78-cd5ca8e49d7e` 对应的原始 JSONL。原始文件共 1,759 条可解析记录、4,919,798 字节，SHA-256 为 `406c8630afb049f2a26f707571a4161798ecb8999981e063a64894bcbc54a2d8`。处理脚本以流式方式解析工作副本，没有把原始全文直接载入对话上下文。

近全量版保留 35 条用户消息、75 条助手 commentary、34 条助手最终答复，并把 144 次工具活动各保留为一条 `<发生了什么>` 风格的摘要。35 条用户消息中有 15 条使用 Codex 的 response annotation 包装，共包含 16 个批注项；生成时把这些传输层包装拆为 `annotations` 结构化数组与 `text` 中的补充请求，分别保留批注索引、选中的助手原文和用户批注，不再把包装标签埋在正文里。111 条规则明确的读取、检查、等待、索引维护与 Git 活动由脚本确定性概括；23 次补丁和 10 次网页检索先经过路径、运行 ID、秘密模式与长内容截断，再由 `gpt-5.6-luna` 分六批概括。Luna 没有接收完整原始 JSONL，六次调用也都没有使用工具。近全量资源共 289 行、152,886 字节，SHA-256 为 `3142abcbcdc02aa2d2ef1d228dadde537f3353b9b9e152714110c2761e8a2f88`。

对话初稿从相同公开消息中机械选择用户消息与每回合唯一最终答复，保留 34 个回合、35 条用户消息和 34 条最终答复；commentary、工具活动与运行数据全部排除。15 条带批注的用户消息以可见 Markdown 分别呈现选中的助手原文、用户批注和补充请求，最终答复中的对应位置显示为 `〔回应批注 N〕`，共覆盖 16 个批注项。该资源共 93,056 字节，SHA-256 为 `fdb272e85fe065db28085ccde79d1f331175dece3e2081f8fff74c1d2ee6e3e6`。

两个资源都把仓库绝对路径转换为相对链接或 `<repo>`；三条指向后来已删除决策草案的原链接改为带路径的“目标现已不存在”说明，避免把历史对话中的暂态链接伪装成当前有效入口。带批注用户消息的传输层包装被转换为明确字段或可见 Markdown，语义内容没有删减；Markdown 初稿还机械去除了行尾空白，其他消息词句没有改写。随后扫描常见秘密格式、本机绝对路径、运行 ID、数据 URI 和时间戳，未发现残留匹配；JSONL 的顺序、回合覆盖、记录计数、逐行 JSON 解析，以及 16 个批注项与最终答复中对应索引的一一配对也已核对。上述扫描只覆盖声明的模式与抽样语义审阅，不构成对所有潜在敏感信息的形式化证明。

#### 调查结果与边界
仓库保存了两种职责不同的派生材料。近全量 JSONL 是**语义近全量档案**：普通公开消息除本机路径规范化外机械保留；15 条带批注的用户消息保留全部语义内容，但移除传输层样板并拆成 `annotations` 与 `text`；工具活动则保留目的与已证实结果。重复消息事件、session 与 turn 元数据、world state、内部推理、token 统计、时间戳、原始命令和原始输出被删除。它能够恢复讨论和工作脉络，但不能重建原始运行时，也不能用于证明某条工具摘要与原输出逐字等价。

Markdown 是**机械对话初稿**：它解决流式输出和重复事件造成的阅读噪声，并把 `Response annotations` 传输包装转换为可见的选中文本、用户批注、补充请求和对应回应标记；尚未主观删除重复确认、提交过程或后来可能判断为无关的讨论。后续精选应使用新的资源 ID，并以整条消息或显式 `<省略：原因>` 为删减单位，避免覆盖形成时初稿，也避免把分散句子拼成原会话中不存在的表述。

Luna 生成的 33 条活动摘要属于解释性压缩，可能遗漏补丁或网页结果的次要细节；公开用户与助手消息没有交给 Luna 改写。若未来判断工具细节影响某项调查结论，应回到原始 SHA 对应的私有原件重新核对，而不能把摘要当作唯一证据。原始会话继续留在仓库外，仓库资源不会扩大 Git 中的本机状态或内部运行数据。

本主题暂时停在“近全量脱敏版与机械对话初稿已经形成并验证”的状态。以后开始人工精选、改变脱敏规则或需要逐条区分脚本摘要与 Luna 摘要时，应追加新的完整报告和新的形成时资源，而不是回写本轮结果。
