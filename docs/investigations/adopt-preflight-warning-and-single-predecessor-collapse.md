## 形成时背景

前一份报告已经确认：Git 路径存在性足以发现一部分同一未提交变更内的演进候选，但不能证明中间判断是否有长期价值，也不能替调用者合成删除中间节点后的关系。本轮讨论进一步比较了单独删除命令、复用 `discard`、扩展 `evolve`，以及事前或事后 warning 的调用成本。

用户最终确认采用事前 warning，并以扩展 `evolve` 的方式承接简单折叠；归档类动作也应在未提交决策退出活动状态前提醒，避免无意义演进。`discard` 的候选边界保持不变，不新增通用删除命令。

## 调查目的

本轮把原候选规则收敛为可实施契约，回答：

1. 哪些命令需要在写入前检查 Git 基线。
2. 首次警告后如何显式选择保留或折叠，且不增加第三次调用。
3. 折叠中间记录时，哪些关系仍能机械校验，哪些必须由调用者决定。
4. 非 Git 集合、复杂关系图和既有 `discard` 应保持什么边界。

## 调查范围与依据

本轮复核了当前 decision-records 生命周期服务、可恢复事务、CLI 参数解析、共享 `VersionControlRepository`、skill 行为入口和领域契约，并通过 change `guard-unrecorded-decision-evolution` 实施已确认方向。

实现证据包括：

- `tools/decision-records/src/decision-history-baseline.ts` 从决策根发现 Git 工作树并读取当前 `HEAD` 中的决策路径；非 Git 或决策根在工作树外时返回无基线。
- `tools/decision-records/src/decision-lifecycle-service.ts` 在事务前产生可区分的暂停结果，并在显式折叠时校验目标状态、`HEAD` 路径、其他引用和最终关系边界。
- `tools/decision-records/tests/unrecorded-history.test.ts` 集中覆盖 warning 无写入、显式保留、非法上游拒绝、成功折叠和 archive 门禁。
- 完整 decision-records 测试入口共 36 个原生测试节点通过，生成 CLI 已从工具源码同步。

本轮没有尝试支持自定义基线、一次折叠多个中间记录、自动关系合成、部分暂存或提交重写。

## 调查结果与边界

已采用并实现的结论如下：

1. Git `HEAD` 只提供归档前发现证据。它不参与候选、建立、生效、对齐或索引成员判断，`createdAt` 的生命周期语义保持不变。
2. `evolve`、带关系的 `activate` 和 `archive` 即将归档一个不在 `HEAD` 的已建立记录时，首次调用返回“命令已暂停”的 warning 和退出码 1，且不修改决策 Markdown 或派生索引。
3. 调用者确认中间记录仍有长期价值时，以 `--keep-unrecorded-history` 重试。该选项只承接本次显式判断，不放宽其他生命周期、关系或事务校验。
4. 调用者判断中间记录没有长期价值时，以 `evolve --collapse-unrecorded <decision-path>` 重试。该动作只折叠一个活动、已建立且不在 `HEAD` 的前序，并把零个或多个 `--relation` 视为后继的完整最终关系集合。
5. CLI 不组合关系类型，也不默认继承上游。最终关系中的活动目标按普通演进归档；已经归档的目标只有在它原本就是被折叠记录的直接前序时才允许。调用者可以明确选择不再连接某个上游。
6. 折叠删除、活动最终前序归档、后继建立和索引重建使用同一个可恢复事务。已进入 `HEAD`、目标非活动、目标仍被其他记录引用或最终归档目标越过直接前序边界时，命令拒绝且不写入。
7. 非 Git 决策集合继续执行原有生命周期命令；缺少版本证据时不能使用 `--collapse-unrecorded`。Git 仓库已发现但基线读取失败时停止维护，不静默跳过预检。
8. `discard` 仍只删除未激活候选。复杂分叉、多层中间链、多个折叠目标或最终直接关系不清楚时，不提供简单断链或通用删除，由维护者保留现场并设计真实演进。

事前与事后 warning 在需要显式选择时都至少需要两次调用；事前 warning 的优势是第一次调用保证无写入。扩展 `evolve` 后，保留与简单折叠都能在第二次调用完成，不需要先 `discard` 再第三次激活。

当前实现固定使用当前 `HEAD`，因此只能识别尚未进入当前提交基线的记录。已经分多次提交但仍属于一个更大逻辑变更的历史、自定义比较基线和部分暂存视图不在本轮结论内。

## 后续复核条件

本调查已经形成长期决策、实施计划、行为实现和测试证据，因此结束。出现以下任一情况时另开或追加调查：

1. 需要让调用方选择非 `HEAD` 的版本基线，或把部分暂存内容作为交付边界。
2. 获得真实的多层未提交链、分叉或多后继样本，需要判断是否值得扩展折叠能力。
3. 发现当前单前序关系门禁仍允许错误的直接关系，或阻止了具有明确语义的安全折叠。
4. 非 Git 环境需要等价的可验证持久基线，而不再接受保守保留历史。
