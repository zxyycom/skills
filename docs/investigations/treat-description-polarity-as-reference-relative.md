## 形成时背景

在重新通读原始 `ai-ready-docs` skill 与本主题全部历史报告后，上一轮把后续问题收敛为：正向描述的通常优势，是否只是“直接承载文档主承诺”的常见表现。用户随即提出一个更基础的问题：**对一个负向描述进行描述，这个描述本身是否已经是一种正向描述？** 如果答案是肯定的，那么此前长期使用的“正向描述”和“负向描述”可能并不是两个能够脱离层级独立判断的内容类别。

例如，“不要输出 X”在对象层表达禁止；“本文规定了‘不要输出 X’”却在报告层肯定一条禁止规则的存在。后一句并没有把禁止改成允许，但整个句子的外层形式确实是在肯定一个事实。这个嵌套结构说明，同一段文本可以同时包含外层肯定和内层否定；若只给整句贴一个正向或负向标签，就会丢失否定究竟作用于什么、文本是在执行规则还是描述规则等关键信息。

## 调查目的

本轮要重新检查“正向描述”和“负向描述”的分类单位：极性究竟是整段内容的固有属性，还是某个操作符相对于特定命题、对象与描述层级的关系；并形成一套足以继续讨论、但不会把所有陈述都空泛归为正向描述的暂定词汇。

本轮不决定 skill 的最终术语或动作，不因为发现层级嵌套就否定此前关于补集构造成本、对象角色绑定和关联激活的全部讨论，也不修改 `skills/ai-ready-docs/`。重点只是校正分类基础，检查哪些旧结论仍然成立、哪些结论必须增加层级和参照条件。

## 调查范围与依据

本轮依据包括用户提出的元描述反例、本主题此前关于表达能力等价、目标侧认知压缩、对象角色绑定和文档主承诺的完整讨论，以及当前提交版本的 `skills/ai-ready-docs/SKILL.md` 与 `references/principles.md`。仓库基线为 Git commit `75c8b5edefe768ace29c7f960a163016218486c0`；工作区既有的 skill 与决策文件阶段性改动继续保持原状，不作为本轮已经确认的规则。

概念核对还参考了 Stanford Encyclopedia of Philosophy 的 [Negation](https://plato.stanford.edu/entries/negation/) 与 [Assertion](https://plato.stanford.edu/entries/assertion/) 条目，以及 *SEM 2020 的 [Learning Negation Scope from Syntactic Structure](https://aclanthology.org/2020.starsem-1.15/)；这些资料支持否定具有作用域、自然语言的否定形式和否定含义之间存在复杂映射，也说明识别否定线索并不足以确定被否定的完整内容。它们不直接证明某种文档写法对当前 LLM 的生成效果。本轮没有进行模型实验、语料计量或跨语言比较。

## 调查结果与边界

用户提出的问题可以得到一个有限的肯定答案：**对负向描述的描述，可以在更高层成为一条肯定陈述；但它不是把原来的负向内容转换成了正向内容，而是把负向命题嵌入了一个外层肯定关系。** 可以把两层粗略写成：

`规则层：Forbid(X)`

`元描述层：RecordedIn(Document, Forbid(X))`

第二式肯定 `RecordedIn` 关系成立，第一式中的禁止角色仍然存在。这里发生的是嵌套，不是双重否定；“文档描述了禁止 X”并不推出“文档允许 X”。如果把“正向”定义为“说出或肯定了某个命题”，那么几乎所有陈述句——包括对禁止、缺失、失败和反例的陈述——都会被归为正向描述，这个定义虽然在言语行为层可以成立，却已经失去解释 AI-ready 文档差异的能力。

因此，**正负极性不是一份描述脱离参照后的全局标签，而是一个否定或肯定操作相对于特定作用域、基础命题和描述层级的局部属性。** 至少需要分清四件事：

1. **表达极性**：句子或子句是否显式使用否定操作，如“不”“不得”“没有”或逻辑上的 `¬`。这一层必须标明否定作用域，不能仅按是否出现否定词判断整句。
2. **规范作用与作用域**：文档是在要求、允许、禁止还是取消要求某项内容。`¬Require(P)`、`Require(¬P)` 与 `Forbid(P)` 不能仅因都出现否定关系就视为同一规则；对 AI 指令而言，必须知道否定落在行为命题还是义务、许可等模态之上。
3. **目标参照方向**：文本主要以可接受结果的性质、原型和合法值为参照，还是以不接受区域、错误模式和禁止事件为参照，再通过排除恢复允许范围。这是此前认知压缩与补集构造讨论真正关心的轴，但它受概念选择影响，不与语法极性一一对应。
4. **描述层级与使用方式**：文本是在直接规定目标或边界，还是把既有规定作为对象进行引用、解释、审查或历史记录。外层元描述的肯定不会抹去内层规则的方向；引用负向内容也仍然会把相应对象带入上下文。

这四层解释了大量此前容易混淆的例子。“只允许 A”没有明显否定词，却通过允许集合排除了非 A；“不要求输出 A”只是取消义务，并不等于“禁止输出 A”；“结果不得泄露秘密”使用否定形式，却可以是目标不可缺少的不变量；“本文包含一条不得泄密的规则”在元描述层是肯定事实，在规则层仍是禁止；“无状态服务”具有否定形态的构词来源，却可能已经成为领域中可以直接定位目标结构的稳定正向概念。因此，表层肯定句不必是目标侧描述，表层否定句也不必只是次要边界。

更进一步，目标侧与排除侧本身也不是完全不依赖表示方式的数学属性。若定义 `SecretFree(x) ≡ ¬ContainsSecret(x)`，那么“要求结果满足 `SecretFree`”可以直接以目标性质组织理解，也可以展开成对泄密结果的补集排除。两种写法在给定定义下可能集合等价，但并不必然具有相同的认知构造成本、概念成熟度、上下文激活和角色绑定负担。一个由大量否定修正压缩而成、已经获得稳定名称和判定含义的概念，可能在实际使用中成为新的目标侧原语；仅仅为规避否定句临时发明一个正向名称，则只是把补集隐藏在未定义标签中。

这意味着此前结论需要分成保留与修正两类：

- 仍可保留：完整补集与目标集合在形式上可以等价；人通常更容易从已有目标认识出发并把多项修正压缩成较少概念；点名被排除对象仍可能带来关联激活；直接执行负向规则还需要把对象绑定为检查或抑制对象。
- 必须修正：不能再把“正向描述”“负向描述”当作整句或整段文档唯一且稳定的语义类别，不能通过统计否定词判断哪一侧是主线，也不能把目标主线天然等同于语法上的肯定表达。
- 尚未确认：目标参照方向能否形成足够可重复的判断标准；稳定的负向构词概念在什么条件下已经成为目标侧原语；不同层级的否定与元描述对 LLM 输出概率分别产生多大影响。

作为后续讨论的暂定词汇，可以先把**“肯定式/否定式”只用于表达形式，把“要求/允许/禁止/不要求”用于规范作用，把“目标侧直述/排除侧界定”用于参照与构造路径，把“对象层规则/规则元描述”用于描述层级**。这不是最终分类，而是为了避免继续让“正向”和“负向”在语法、模态、集合、目标责任与元语言之间滑动。

下一步最值得讨论的问题也因此改变为：**一个从否定或补集形成的概念，什么时候已经获得足够独立、稳定的含义，可以作为目标侧原语被直接使用；什么时候所谓的“正向改写”只是给原有排除逻辑换了一个名称，并没有真正增加目标信息？** 这个问题能继续检验正向描述的实际优势，而不再假设正负是无需参照即可判定的两类句子。
