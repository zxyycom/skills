## 形成时背景

本轮以 Git 基线 `87c39c9541089cb33b027ba771da9f47c5bc6815` 为准，发现 92 条已归档决策的 `alignment` 为 `null`。历史归档会清空该字段，或更早记录从未保存字段；因此 `null` 本身不能推断最后对齐状态。

本轮获准一次性原位恢复这 92 条的历史对齐字段，不重新激活记录，也不改变正文、状态、ID、路径、形成时间、tags 或关系。恢复不是新的对齐事件，也不评价这些方向今天是否仍适用。

## 调查目的

判断这 92 条决策能否依据各自历史证据恢复最后对齐状态，记录实际恢复结果，并区分历史直接记录、语义核对与合理推断的证明强度。

主报告保存关键认识与验收边界；随附资源保存逐条完整采用方向、历史 `revision:path`、修复前字节指纹与具体依据，使读者能够回到 Git 独立复核。

## 调查范围与依据

- **对象**：上述冻结基线中的全部 92 个 archived/null 对象，不扩展到其他决策。
- **直接历史记录（`recorded`）**：从历史 frontmatter 读取 active/aligned，并核对同一身份在归档时变为 archived/null；证明历史已记录的对齐值，不等于本轮独立验证当时实现。
- **历史语义核对（`semantic`）**：在列明的同一历史 tree 中，同时核对完整决策及实现、配置、规范或验证材料；不能用当前工作树或仅有采用声明替代。
- **本地合理推断（`inferred`）**：在用户授权范围内使用本地可得材料；历史仓库或原始实现无法完整重读时，不表述为已验证原始实现。
- **审查与修复**：每条经独立主审批准后写入。写前核对原始字节哈希；写后归一 alignment 行再逐字节比较，验证其余字节未变。后续正文核对用于排除同一身份的实质方向变化，不能单独证明 alignment。

随附资源按三种方法分组，保存全部 92 条的来源定位、证据和局限，以及分批同步的核验方法。本轮不以“未找到证据”、后继状态或当前测试替代相应历史时点的对齐判断。

### 形成时的验证与未证明边界

- **集合验收**：召回完成时共 338 条决策，124 active、214 archived；321 aligned、17 unaligned、0 null。这是本轮形成时的集合计数，不是后续仓库的实时统计。
- **改动范围**：92 个目标相对基线仅 alignment 行不同；246 个非目标来源的原始 SHA-256 未变。决策目录 diff 精确为这 92 个 archive 文件与派生索引，没有其他来源差异。
- **索引核验与过程例外**：全部批次完成同一选择的 dry-run、写入、严格检查与新鲜度复核。期间一次 writer 未带 `--select`，实际全量重建了当时索引；最终全量来源字节与索引不变量证明没有接纳额外来源，不能将过程描述为始终仅做 selected 同步。
