## 目的

- 为 `lightweight-judgment` 的直接调用保留独立于 CLI 进程生命周期的依据，支持中断后核对、结果恢复与只读统计，同时让本地留存保持显式选择。

## 背景

- 适用 skill 为 `lightweight-judgment`，当前路径为 `skills/lightweight-judgment/`。批量组织大量单次调用时，stdout 与进程内状态不足以证明哪些调用已发送、哪些结果已返回；CLI 退出或被终止后仍需读取这些依据。
- 当前调用模型是每个 CLI 执行一次请求，不需要引入提交／消费队列、后台 worker 或自动恢复执行。远端没有本工具可验证的恰好一次承诺，记录缺失或超时也不能证明服务未处理或未计费。
- 请求与响应正文可能包含敏感材料。留存价值、磁盘容量与数据权限应由调用者选择，不能因为新增数据库而默认留存所有调用。

## 决策

- 采用: 默认关闭调用日志；显式启用后，使用 Node 内置 SQLite 在发送前提交调用意图，收到完整正文后、协议解析与输出前更新记录，最终保存成功、失败或远端结果不确定的状态。数据库按配置位置首次需要时创建，不随 skill 安装或更新移动。
- 请求与响应正文留存独立配置；即使关闭正文，仍保留统计所需的调用摘要。凭据和鉴权头不作为日志字段保存，原始正文不做可能破坏证据的替换。精确字段、默认值、路径和隐私边界由[调用日志](../../skills/lightweight-judgment/references/call-logging.md)承接。
- 发送前无法提交记录时不发送；发送后持久化失败不丢弃已知服务结果，使用独立持久化状态与退出码报告，防止把日志失败误当作安全重试信号。
- SQLite 只承接记录，不成为执行队列。进程中断后读取已提交记录，不自动重放；不完整状态保留不确定性，后续调用和结果采用继续由调用方决定。统计与分析使用普通 SQLite 只读入口，不额外维护后台查询服务。
- 通过独立进程的并发追加与强制终止验证进程级恢复；不将该证据扩张为断电、介质损坏或远端恰好一次保证。
