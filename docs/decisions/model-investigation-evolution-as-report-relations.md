## 目的
- 让报告能够准确表达对一个或多个直接前序的补充、复核、纠正、推翻、整合或分解。
- 让读者通过关系图恢复调查认识演进，而不把目录、形成时间、共享 tags 或普通链接误作关系。
- 保留被修正或推翻报告的完整可发现历史，避免关系被解释为当前事实、任务或生命周期。

## 背景
- 原主题文件将新报告按 H3 顺序追加，只能隐含同一主题内的时间关系，既不能覆盖跨主题认识，也不能判断后续报告与前序的真实语义。
- 报告保存形成时认识，不自动成为长期采用方向或当前事实；Decision Records 的 archive 生命周期不能移植到报告领域。
- 关系维护需要在保留 Markdown 为事实源的同时防止手工局部调整造成图形状或索引漂移。

## 决策
- 采用: 每份报告在 frontmatter 中以完整 `relations` 集合指向真实直接前序，并只使用 `补充`、`复查`、`修正`、`推翻`、`归并` 和 `拆分` 六种关系类型。
- 采用: 关系 target 必须是已存在且不晚于 source 的 Investigation ID；禁止重复 target、自环和全图环。普通关系只指向一个前序，归并只整合至少两个前序，拆分以至少两个只指向同一前序的独立后继闭合。
- 采用: 关系不从主题、时间相邻、相同 tags、资源复用或普通 Markdown 链接推断；间接祖先和后继由 trace 恢复，不重复写入 Markdown。
- 采用: 推翻、修正及其他后继关系不移动、隐藏、归档或删除前序报告。所有已建立报告永久位于同一正式集合，叶节点和最新时间都不自动表示当前认识。
- 采用: 新报告可在首次写入时声明合法关系；既有报告关系调整使用一次事务中的完整替换组并同步索引，预演失败或来源漂移时不写入。
