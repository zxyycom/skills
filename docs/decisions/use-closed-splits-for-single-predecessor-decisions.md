## 目的

- 让每条活动决策都能作为整体独立修订、替代、归档和判断对齐。
- 让单一过粗前序在实际演进中重建为多个稳定判断，而不引入含义不清的部分对齐状态。

## 背景

- `alignment` 描述完整方向是否已经成为当前事实；同一记录只有一个值，无法准确表达其中一些方向已经落地、另一些仍面向未来。
- 如果这些方向可以独立演进，继续保留粗记录会让后续修订互相牵连，也会阻止已成为事实的部分建立独立基线。
- 一个直接前序分成多个后继，与多个前序重新分配给多个后继是不同的长期边界；后者由[闭合重划决策 owner 边界](support-closed-reallocation-of-decision-owners.md)独立承接。

## 决策

- 采用: 对齐状态始终作用于整条决策，不增加 `partially-aligned`、比例或子字段状态；只有完整方向成为当前事实并通过核对后，该记录才是 `aligned`。
- 采用: 候选包含多个可以分别修订、替代、归档或对齐的判断时，在首次建立前拆成多条；已建立的单一粗决策暴露这种粒度问题时，使用决策拆分重建边界。
- 采用: 对一个直接前序，拆分是把可独立维护的部分重建为自包含后继的闭合演进。agent 必须确认后继覆盖前序中继续有效的长期含义，并明确处理被放弃、改写或判定无效的含义，不能因归档前序而静默悬空。
- 采用: 每条后继分别与当前事实来源核对并保存自己的 `aligned` 或 `unaligned`；已经落地和仍面向未来的方向因此可以独立继续演进。
- 采用: 拆分后继以从新到旧的 `拆分` 关系指向同一直接前序，并通过 `evolve` 与前序归档、索引重建共同维护。完整集合的机器检查由[决策记录规则](../../skills/decision-records/references/decision-record-rules.md)拥有。
- 采用: `归并` 继续表达多个直接前序收敛为一个后继；引用、依赖和实施关系不属于决策语义演进。真实的多前序、多后继边界由 `重划` 承接，不扩张拆分的单前序含义。
