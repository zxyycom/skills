## 目的

- 让常规决策目录和文件搜索结果聚焦候选与活动判断，避免归档记录持续干扰当前材料的定位。
- 让 `rg` 等不理解决策 frontmatter 的通用工具能够通过一个统一路径前缀排除归档记录，并从命中路径直接识别历史内容。
- 在降低常规搜索干扰的同时，保留归档记录的长期回放、显式查询和关系追踪能力。

## 背景

- CLI 是恢复决策状态和关系的常规入口，但仓库级术语搜索、影响调查、引用核对和临时定位仍会直接使用 `rg` 等通用文件工具。
- 通用文件工具主要按目录、路径和文本工作，不读取决策 frontmatter 的生命周期语义。活动、候选与归档 Markdown 混放时，普通搜索会命中已经退出当前依据的判断，结果路径又不能直接说明其状态。
- 随着归档记录累积，使用者需要反复打开正文或调用 CLI 才能区分当前判断与历史材料；逻辑状态筛选不能改善这条通用读取路径。
- 统一物理路径边界能够同时提供整体排除条件和可见状态前缀，但现行契约还让路径承担身份、领域归属、关系目标和直接引用。实现物理归档前必须闭合这些责任，不能把生命周期变化简化为普通文件移动。

## 决策

- 采用: 已归档决策进入统一、可识别且可整体排除的物理路径边界；常规领域目录不再继续混放归档 Markdown。
- 采用: 物理归档继续属于可移植、可校验的完整决策集合，并保留 Markdown 正文、生命周期、索引投影和演进历史。显式历史查询、单条读取、关系追踪和严格检查仍须覆盖归档记录。
- 采用: 物理位置向通用文件工具投影生命周期边界。后续设计必须确定唯一权威状态，并机械保证状态、来源位置和派生索引一致，不能形成两份可独立漂移的生命周期事实。
- 采用: 本决策只确认物理归档的目标结果和维护边界，不固定目录布局、保留名称或 CLI 参数。后续设计必须闭合稳定身份与来源路径、领域解析与索引定位、关系与外部直接引用、归档与重新激活事务、待提交快照、既有记录迁移及失败恢复。
- 采用: 只有物理布局、维护协议和既有记录迁移均已完成并通过核对、完整方向已成为当前事实后，才能将本决策标记为 aligned；它不自行产生实施任务或授权。
