## 目的

- 在不默认放大资源压力的前提下并行运行已经选择且可独立执行的前置检查。
- 通过稳定领取顺序减少 full 档中少数长任务造成的尾部等待。

## 背景

- 顶层检查可能各自启动测试 runner、临时仓库和多个子进程，并发数不能直接等同于机器核心数。
- 默认串行会浪费独立任务的等待时间，默认高并发则会在普通维护环境中制造不可预测的资源竞争。
- Full-only 集成任务通常明显更慢，若最后领取会延长保守并发下的总耗时。

## 决策

- 采用: 本次已选择的前置检查默认最多同时运行两个。
- 采用: 调用方可用 `CHECK_CONCURRENCY=<正整数>` 显式覆盖并发上限；非法值在任何前置检查启动前失败，不静默回退或推断。
- 采用: Full-only 长任务在已选任务中优先领取，以减少尾部等待；领取顺序不改变任务的 profile 或验证范围。
- 采用: 本记录的调度输入止于已选择的前置检查集合，输出止于这些检查的独立结果，不决定其他计划步骤的进入条件或时机。
