## 目的
- 让 `test-design` 的设计与审查首先决定哪些自动化保护值得承担，避免将已有测试或其缺陷直接转化为保留和修复义务。
- 在保留有效保护与控制投入之间作明确取舍，允许契约仍然重要但当前不承担自动化成本。

## 背景
- 从旧测试的意图出发，可以为大量样例构造辨错理由，却不能据此判断这些错误是否值得持续自动拦截；只强化断言或换用稳定探针，仍可能维护低价值目标。
- 契约的重要性与自动化方案的收益、可行性和总成本是不同判断。关键行为可能依赖昂贵、脆弱的 GUI 或环境准备，最便宜的可行自动化仍可能超出可接受投入。
- 局部职责的证明范围不因成本判断而扩大；将计算、执行与交互混成单条测试的义务，会同时扭曲必要性和成本。

## 决策
- 采用: 在 `skills/test-design/` 以“识别行为与风险、裁定自动化投入、仅为入选目标选择与改进测试、验证裁决并交付”组织主流程。新增与存量采用同一投入标准；目标未入选时，不继续设计修补方案。
- 采用: 将不自动化作为正式裁决，在授权内说明减少的保护及接受的风险；契约仍有效，人工检查或补测待办不作为必然承接。已有硬性验收要求由其 owner 决定，不能以成本理由自行绕过。
- 采用: 入选后才比较有效性与实现成本，保留充分且经济的方案，精简重复或过重项，必要时设计、修复或替换。测试只承担当前保护点，成本比较不扩张其证明范围；合理实现替换仍应通过。
- 采用: 在该 skill 的参考材料中集中维护可区分裁决的最小反例与边界，设计方法按入选目标读取；不积累逐次执行流水账或为最近发现建立专用规则。
- 采用: 以具体投入裁决及保护变化作为审查完成依据，事实未查清与举证不成立分别处置，不设删除配额。仅有质量修补清单、机械引用有效或测试全绿不足以完成取舍；测试证据账本与 Gate 仍由各自 owner 承接。
