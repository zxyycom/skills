## 目的
- 为目标、governing contract、责任 owner 和检查范围已经明确的工程任务提供最小实现取舍基线。
- 让实现前选择、当前 diff review 和独立 complexity audit 使用同一正确性与维护面标准。

## 背景
- 依赖、抽象、配置、扩展点、运行状态、跨 owner 协调和长期 ownership 都可能增加维护面，代码行数只能作为调查信号。
- 删除、复用、标准库、平台能力、成熟依赖和局部实现各有适用条件，固定排序不能替代对现实 contract 与消费者的核对。
- 产品价值、架构责任、共享契约和测试证据由相邻 owner 判断；这些前置缺失时，本能力没有依据补造结论。

## 决策
- 采用: 只有目标、governing contract、责任 owner 和检查范围已经明确时才比较实现候选；缺失前置会改变结论时，完成最小调查后暴露缺口，不代替相邻 owner 作出决定。
- 采用: 按省略或删除、同语义同 owner 复用、标准库或平台能力、成熟依赖和局部自定义实现进行有界搜索；这些是启发式入口，不是绝对排名。
- 采用: 候选必须完整兑现当前目标、契约、兼容性、安全与运行约束，并具有匹配验证路径，只有通过正确性门槛后才进入最小性比较。
- 采用: 比较会改变选择的整体维护面，包括概念、分支、模块、依赖、配置、状态、跨 owner 协调、验证、升级和长期认知责任；选择总维护面更小且责任更直接的正确方案，不以局部行数代替整体判断。
- 采用: 调查和证据深度与候选差异及风险相称，已有证据足以稳定选择且继续搜索不会合理改变结论时停止。
- 采用: 修改、只读报告或保留待确认问题沿用当前任务授权；普通 review 服从宿主契约，独立 complexity audit 只报告具有直接依据的可删除、复用、标准库、平台原生或 YAGNI 维护面。
- 采用: 本能力不接管产品架构、共享契约或测试证据 owner，相邻 skill 也不构成安装前提；当前项目已经提供前置事实时可以独立完成比较。
