## 目的
- 让安装 skill 的项目使用同一套可直接查找、同步和校验的测试账本位置与身份协议。
- 减少配置解析、路径别名、兼容迁移和无消费方说明文件带来的行为分支。
- 保留受控 topic、单 case 文件和派生索引的职责，不改变最小原生测试入口粒度。

## 背景
- `catalogPath`、`indexPath` 和 `caseIdPattern` 在实际仓库中始终采用内置值，没有形成需要项目自行选择的有效差异。
- 项目级配置迫使工具维护配置 Schema、CLI 参数、导入选项、路径归一化、冲突身份和升级兼容，增加了与账本核心无关的失败面。
- 根目录说明文件不参与 case 读取、索引、revision 或查询，其内容已经由 skill、仓库协作规则和工具链 owner 承接。
- 工作区根目录已经足以定位测试账本；固定路径可以让 agent 和工具无需先恢复另一层配置。

## 决策
- 采用: 测试证据根目录固定为 `docs/test-evidence`，topic 表和派生索引使用目录内固定文件名；CLI 只用 `--root`，导入 API 只接收 `workspaceRoot` 及各操作自身参数。
- 采用: case ID 使用工具内置统一格式；目录、索引路径和 ID 正则不接受项目级覆盖，也不发布配置 Schema、配置类型或配置加载接口。
- 采用: 根目录只允许受控 topic 表、固定派生索引和已定义 topic 目录；其他根成员按非法目录处理，不为独立说明文件建立特例。
- 采用: 固定索引仍必须与 topic 表和全部 case 保持不同文件身份，防止硬链接让派生写入覆盖权威源。
- 采用: 遗留配置只作为迁移时需要删除的旧输入，不提供运行时双读、隐式兼容或自定义路径回退。
- 不采用: 继续保留等同于默认值的空配置、只删除仓库配置文件但保留公共配置能力，或为未被工具消费的目录说明建立白名单。
