## 目的
- 让每份报告无需依赖同主题其他内容即可回放其形成时背景、目的、依据和结果边界。
- 保留跨时间、对象状态、假设和证据范围比较所需的共同记录核心。
- 让计量、诊断、方案或变更等真实场景信息归入对应核心，而不建立替代结构。

## 背景
- 原记录同时决定四个固定章节和稳定主题文件中的追加方式；两项责任现在分别需要独立演进。
- 一份报告应以 Investigation ID 成为完整、独立的形成时认识，而不是主题 Markdown 中依靠序号和顺序定位的 H3 片段。
- 背景、目的、调查范围与依据及结果边界仍是所有可复核调查共同不可缺少的内容，场景支撑仍取决于实际需要，但必须归入相应核心。

## 决策
- 采用: 每个 Investigation ID Markdown 只保存一份形成时报告，并依次使用唯一且非空的 `形成时背景`、`调查目的`、`调查范围与依据` 与 `调查结果与边界` 四个核心 H2。
- 采用: 形成时背景说明处境、已知条件、假设、未知与约束；调查目的说明本轮直接问题和预定边界；调查范围与依据说明实际检查对象、来源、时点、方法和未覆盖内容；调查结果与边界区分事实、推断、建议、动作与未知。
- 采用: 计量、假设、反证、时序、方案、授权、恢复或验证等场景支撑归入对应核心；其他可选语义 H2 只能位于四项固定核心之后；声明资源时，`随附资源` 必须是第五个 H2，其他可选语义 H2 只能位于其后。
- 采用: 新证据或实质认识变化形成新的完整报告；只在原报告未准确保存当时认识、格式或链接错误时原地修正，不再在主题文件追加 H3 报告或以最新报告推断当前认识。
- 采用: 检查器验证单报告 frontmatter、四项核心的存在、唯一、非空和顺序；内容充分性、场景义务和是否应另立报告继续由人工审阅。
