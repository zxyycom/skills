## 目的

让 `skills/decision-records/` 与 `skills/investigation-report/` 的日常维护只承担本次操作需要的事实，区分发布图合法、所选来源当前和全集当前健康三种保证。

## 背景

- Markdown 是内容事实源，合法索引是普通操作使用的发布快照。全量检查与同步有理由读取全集，单条维护则不必替其他尚未同步的工作证明当前性。
- [前序判断](archive/separate-record-local-operations-from-collection-audits.md)已为普通维护采用发布基线，但删除、更名仍承担全集来源验收，候选及历史发现也可能读取无关正文。这些额外义务与实际写入范围并不一致。
- 未选候选没有正式索引。自动维护所有候选的引用与严格局部读取不能同时成立；为此新增候选索引或持久缓存又会增加独立一致性责任。

## 决策

- 采用: 普通维护，包括删除、身份更正及其组合，使用合法发布索引确认正式身份、位置、状态、关系与引用者，只读取所选来源和实际改写来源。纯索引依赖不额外读取正文，实际资源访问按所选或受影响 owner 范围安全验证。
- 所选已发布来源须符合适用的身份、投影与 revision；漂移时明确停止并要求同步。未选来源的手改、损坏、未知移动、重复身份或新引用不构成本次局部保证，调用方通过显式 check／sync 发现与处理。
- 删除与更名根据发布索引处理正式引用。未选候选不自动检查、阻断或改写，其后续发布须通过当时的完整发布图和资源验证；共同选择限于现有事务能表达的范围，不新增自动草稿修复层。
- 候选按明确位置或排除正式路径后的候选范围定位。已有集合的索引缺失、损坏或不兼容时明确恢复，不隐式全源扫描重建；首次无正式成员的集合走独立初始化分支。
- Git 历史以固定 revision 的索引定位必要对象，不读取无关 blob 推断身份。无法可靠定位的历史明确诊断，不冒充“从未记录”；高风险操作仍需要覆盖精确对象和影响的授权及相应历史确认。
- 保留每阶段实际保护：预检零写且不保存凭据，正式执行在锁内重新准备，写前独立核对局部事实和索引，写后验收实际 bytes、identity、mode 与写集；unchanged 也不跳过适用保护。提交后不确定性如实报告，恢复只撤销仍能证明归属的写入并以 CAS 保护后来修改。
- 显式全文发现、候选列表、全量 check／sync 保留各自读取范围；[选择性同步](bound-selected-record-sync-currentness.md)继续验收其声明的所选来源与必要依赖。全量只读 check 证明首次取得的同份来源事实，不宣称结束时当前性或跨文件原子快照。
- 同 ID、同位置更名保留真正零写语义，末条正式删除保留合法空索引。读取责任收敛不引入新索引格式、跨调用缓存或通用事务框架；完整 JSON、内存图和 Git 元数据仍可能具有集合成本。
