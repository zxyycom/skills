## 目的
- 让每个提交形成可独立理解、审查和回滚的语义单元。
- 让提交拆分反映行为与责任关系，而不是文件后缀或目录布局。

## 背景
- 同一功能、修复或规格变化可能同时需要代码、测试、文档和示例才能完整成立，把这些文件机械拆开会产生不能独立验证的提交。
- 同一批工作也可能包含彼此无依赖的行为、规格、配置或构建变化，把它们合并后会增加审查和回滚成本。
- 提交范围归属、提交类型和消息格式各有独立 owner，不能用其中任一项代替语义单元判断。

## 决策
- 采用: 一个提交只表达一个可以独立理解、审查和回滚的语义单元。
- 采用: 多个互不依赖的语义变化分别形成提交，每个单元独立复核范围、类型、消息和验证。
- 采用: 共同兑现同一行为或契约所必需的实现、测试、文档与示例可以保留在同一单元，不按文件类型机械拆分。
- 采用: 无法可靠判断语义边界时先暴露拆分风险并取得当前任务选择，不用任意文件边界制造表面独立性。
