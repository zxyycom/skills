## 目的

让 `image-creation`（`skills/image-creation/`）以提示词工程为核心，持续以用户所求图像及其用途为验收对象；实际输入、可选结构引导和逐次回看记录共同支撑改写，而不另行实现不断变化的生成服务协议。

## 背景

图像生成工具可以成功返回文件，但这不证明用户想要的状态、角色身份、局部设计或非目标保留已经落实。参考图的文字描述也不证明生成器收到了该位图；局部样稿可读，不等于全图回填成功。提示词需要承担意图到可执行视觉关系的编译，又必须通过真实输出、失败诊断和历史原词检验；仅转交工具或仅润色提示都不足以兑现目标。

生成工具或宿主执行 skill 已经拥有附件、模型参数、输出位置及调用失败处理等约定。视觉流程应提供独立接口使用指南，但动态协议仍向当前入口核对，避免把旧语法和历史经验误用为现行能力。实际提示、目的与检查结果比重复存放全部大图更重要；节省存储仍须保住原件与派生图身份，以及回查精度边界。

## 决策

- 采用：建立独立的 `image-creation`，以“目的与验收 → 提示词构建 → 实际参考／可选结构引导 → 获授权的生成／编辑 → 逐次回看与记录 → 改写和交图”为主线。独立提示词指南承接构建、优先级、失败改写与完整模板；用户只要提示词或诊断时止于该交付。
- 该 skill 拥有视觉任务、提示工程、参考职责、结构策略、逐次记录和结果验收；独立接口指南承接常见入口操作链，实际调用协议仍由当前工具及执行 skill（如 `imagegen`）承接。不存在默认必装组合，不内置另一套API、模型安装或收费回退。
- 每次实际调用都保存目的、完整实际词、附图／输出身份与回看结果；一次预览可用可回读对话承接，项目／多轮用文件恢复。简单任务不强制问卷或数据库，但不能免掉最低证据。源图可引用，历史淘汰图可按授权策略轻量保留结构代理；代理不证明精细保真，也不授权删除已有原件。
- 三视图与简易3D体块／骨架用于需要时统一大致连接、姿态与机位；渲染实际传图并检查最终结果，不升级为固定投影／骨长阈值或完整3D工程。
- 共同规则围绕可见关系、输入事实和验收组织；分支知识按缺口读取。模型专属语法、数值与版本限制在执行时向当前 owner 核对，不将教程配方、固定参考数量或个案比例升级为通用契约。
- 缺执行能力时可交付提示及输入说明，但必须标明尚未成图；局部成功、代理暂选与用户认可分别解释。该选择不承诺跨模型收益或像素级保留，实际质量需要获授权的输入—调用—输出验证。
