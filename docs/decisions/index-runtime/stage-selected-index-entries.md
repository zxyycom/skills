## 目的

- 让共用一个完整索引文件的并行任务，能够只暂存本次选择的索引条目。
- 让调用方只声明选中条目，不重复实现索引合并、投影、校验和序列化。
- 保持索引文件、领域文件和版本管理写入边界各自的责任归属。

## 背景

- state index 用一个确定性文件保存一个领域的全部条目；普通文件级暂存会把同一文件中的全部工作区变化一起带入。
- index-runtime 已拥有稳定条目 id、完整索引 definition、投影、校验和序列化，能够根据 revision 索引与工作区索引识别选中条目的目标状态。
- 接入方拥有 Markdown、目录表、topic 表、代码等领域文件；通用索引不能从条目 id 推断这些文件，也不应替接入方决定提交范围。
- 选择后的索引会同时包含 revision 条目和工作区条目，因此索引 revision 必须能从最终完整投影确定，不能要求调用方另外提供领域 revision。
- 共享 version-control 已拥有 `pending` 写入锁、冲突检查和失败恢复，索引运行时不应直接依赖底层版本系统。

## 决策

- 采用: index-runtime 提供按稳定条目 id 暂存单文件索引的操作。配置完成的运行时只接收非空且不重复的选中 id，不接收领域文件、基线条目、变化类型、metadata、revision 或完整目标索引。
- 采用: 操作以 current revision 中的完整索引为基线，以工作区完整索引为候选；选中且工作区存在的条目采用工作区状态，选中且只在基线存在的条目被删除，未选中条目保持基线状态。重命名由调用方同时选择旧、新 id。
- 采用: 目标索引从选定 state 完整重新投影、校验和确定性序列化。索引 revision 由排除自身 revision 字段后的完整规范化投影统一派生，使混合结果不依赖领域源或调用方补充输入。
- 采用: 条目级暂存不选择 metadata、definition 或任意 JSON 片段；这些集合级契约相对 revision 发生变化时拒绝条目级操作。
- 采用: 操作只写目标索引的 `pending` 内容，不读取或写入任何领域文件，也不承诺索引与领域文件的跨 owner 原子事务。接入方自行决定是否以及怎样暂存领域文件，并负责核对最终提交范围。
- 采用: 同一索引的 `pending` 内容已经不同于 current revision 时直接拒绝，不合并、不覆盖。期望内容核对与替换由共享 version-control 在同一写入锁内完成，其他待提交路径保持不变。
