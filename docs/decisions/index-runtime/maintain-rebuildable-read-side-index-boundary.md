## 目的

- 让领域以较小接入面获得稳定、可重建的状态查询与索引同步能力。
- 让共享运行时保持读侧派生边界，不因复用查询和持久化机制而取得领域事实或写入责任。

## 背景

- 多个领域都需要从权威来源生成确定性查询投影，并在来源变化后检查或重建该投影。
- 领域之间只共同拥有派生索引、查询和同步问题；来源文件、合法状态、稳定身份、写入事务与领域语义并不相同。
- 若共享层解释领域生命周期或修改领域来源，接入成本和故障范围会随领域数量持续扩大。

## 决策

- 采用: `tools/index-runtime/` 承接可删除重建的共享读侧索引，提供通用结构校验、确定性序列化、reader、结构化查询、漂移检查、同步和从权威来源重建的协议。
- 采用: 领域 definition 继续提供来源读取、领域解析、稳定身份、查询 key、来源新鲜度和完整领域校验；共享运行时只调用这些明确入口，不解释其业务含义。
- 采用: 领域源继续拥有事实和全部写入规则。Index Runtime 只写派生索引，不修改领域源；领域 writer 完成事实写入后按自身事务边界触发或要求同步。
- 采用: 查询时可以使用同一定义产生的临时条目覆盖，但覆盖只影响当前 reader 的派生视图，不改变持久索引、集合 metadata 或领域事实。
- 不采用: 在共享层提供跨领域 federation、通用领域 CLI、领域详情解释、领域源写入、图语义或可插拔存储平台。
