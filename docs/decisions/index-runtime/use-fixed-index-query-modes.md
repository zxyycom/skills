## 目的

- 让领域只声明可查询 key 及其有限模式，由通用运行时提供确定、可复用的查询行为。
- 让过滤、排序和分页使用同一组固定语义，不因消费者或领域不同而重新解释 key。

## 背景

- 多个领域都需要按 ID 或领域 key 定位、过滤和排序状态，但各自实现同类算法会重复输入校验、顺序和分页责任。
- 精确集合条件、有序范围和文本包含具有不同的比较语义，不能让调用方根据值形状临时猜测。
- 时间等领域值的真实顺序不能从展示文本普遍推出，需要由领域在 key 投影阶段转换为保持顺序的标量。

## 决策

- 采用: 每个领域定义声明一个或多个 key 策略，并为每个 key 显式选择 `exact`、`range` 或 `text` 模式；未声明的 key 不进入通用查询。
- 采用: `exact` 支持规范化值的相等及 all、any、none 集合条件，`range` 比较具有固定全序的数值或文本标量，`text` 使用固定文本包含语义；模式不根据查询输入动态切换。
- 采用: 通用查询可以按 ID、已声明 key 和存在性组合过滤，并在过滤后按一个或多个可排序字段形成确定顺序；领域顺序由领域先投影为可正确比较的标量。
- 采用: Offset 和带上限的 limit 只在过滤与排序完成后作用；输入校验、比较和分页结果不依赖来源遍历顺序。
- 采用: Runtime overlay 使用与持久条目相同的 key 策略和查询语义，不为临时条目开放第二套模式。
- 不采用: 任意表达式语言、领域回调式过滤、跨领域 federation、相关性权重、隐式类型转换或由查询输入创建新 key 模式。
