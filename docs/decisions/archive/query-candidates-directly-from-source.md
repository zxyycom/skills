## 目的

- 让维护者能够发现和审核结构完整但尚未建立的决策，而不把候选混入正式查询结果。
- 让一条暂时非法的候选产生局部诊断，同时继续返回同一合法集合中的其他候选。

## 背景

- 候选在激活前不进入 `decision-index.json`，因此不能通过正式索引恢复其身份或正文。
- 候选目录可能暂时包含一条结构、状态或关系非法的源码；让该错误阻断全部候选查询会妨碍维护者继续审核和修复。
- 决策根、领域目录表和目录布局界定完整集合；这些集合级边界损坏时，局部跳过不能形成可信结果。
- 已建立决策的 `list`、`show` 和 `trace` 由持久索引查询决策独立拥有，本记录不重复其读取、同步或恢复语义。

## 决策

- 采用: `candidates` 和 `show-candidate` 直接扫描决策 Markdown 源发现候选，不从正式索引、归档记录或 Git 历史补造候选身份。
- 采用: 候选集合查询逐文件容错，跳过结构、状态或关系非法的非目标候选并报告 warning，同时继续返回其他合法候选。
- 采用: `show-candidate` 显式请求的目标自身非法或不存在时失败并返回目标诊断，不以其他记录替代目标。
- 采用: 决策根、根目录成员、领域目录表或领域目录布局非法属于集合级错误，候选查询整体失败且不返回部分集合。
- 采用: 严格 `check` 继续从源码验证候选结构、身份和前瞻性关系；合法候选未进入正式索引不构成失败，非法候选仍阻断验收。
- 不采用: 为了候选可发现性而把它们混入正式索引，或因查询容错而降低严格建立门禁。
