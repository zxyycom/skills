## 目的

- 用一个已经发生且可独立复核的边界重划案例，判断现有决策关系和演进事务能否忠实表达多前序到多后继的语义分配。
- 把“等待真实案例”收敛为有明确证据范围的评估，同时继续阻止评估自动升级为协议设计或实施承诺。

## 背景

- Task Graph 的决策粒度重建同时处理了多个语义重叠的直接前序，并把结果语义、版本锚点、目标集成、终态纠正、拓扑关系、祖先控制、父项聚合、锁定位、原子写入结果、JSON 事实源、任务保留和执行器中立重新分配给多个自包含后继。
- 该案例至少具有两个直接前序和两个后继，且后继边界不是逐字继承原有边界，已经满足真实多前序、多后继和语义重新分配的评估门槛。
- 现有记录通过多个独立的拆分或修订事务建立了结果；这些边能够保存各自直接前序，但不能仅凭关系形状证明跨前序语义已经完整、直接且无重复地分配。
- 真实案例的出现只证明应当评估，不证明必须增加 `重组` 关系、建立 Change 或修改运行时协议。

## 决策

- 采用: 将 Task Graph 决策粒度重建作为首个决策重组评估案例，复原完整直接前序集合、完整后继集合及每项继续有效、被改写或被放弃的语义分配。
- 采用: 当前只用一个明确 Task 承接案例复核；该 Task 应先判断现有 `修订`、`替代`、`判定无效`、`归并` 和 `拆分` 是否能够在不制造无独立意义中间决策的前提下忠实表达该案例。
- 采用: 只有复核证明现有关系会丢失真实直接语义、产生不完整中间状态或无法在一次可恢复事务中闭合完整前序与后继，才另行提出受该案例约束的 Change 和协议候选。
- 采用: 重组仍是尚未成为当前能力的未来方向；本次确认不授权创建实施 Change、预设关系名称、修改索引格式、扩展 CLI 或实现事务协议。
- 采用: 若现有关系已经能够忠实表达该案例，则以复核结论收敛当前 Task，不为理论完整性继续设计专用协议。
