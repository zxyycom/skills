## 目的

- 让每条活动决策都能作为一个整体独立修订、替代、归档和判断对齐。
- 让粗决策在实际演进中可以重建为多个稳定判断，而不引入含义不清的部分对齐状态。

## 背景

- `alignment` 描述完整方向是否已经成为当前事实；同一记录只有一个值，无法准确表达其中一些方向已经落地、另一些仍面向未来。
- 如果这些方向本来可以独立演进，继续保留粗记录会让后续修订互相牵连，也会阻止已经成为事实的部分建立独立基线。
- 现有 `归并` 可以把多个直接前序收敛为一个后继，但缺少把一个直接前序同时重建为多个后继的闭合事务和关系语义。

## 决策

- 采用: 对齐状态始终作用于一整条决策，不增加 `partially-aligned`、比例或子字段状态；只有完整方向成为当前事实并通过核对后，该记录才是 `aligned`。
- 采用: 候选包含多个可以分别修订、替代、归档或对齐的判断时，在首次建立前拆成多条；已建立的粗决策暴露这种粒度问题时，使用决策拆分重建边界。
- 采用: 拆分是一项闭合的一对多演进，必须同时归档一个活动直接前序并建立至少两个自包含后继；后继集合覆盖前序中继续有效的全部长期含义，被放弃、改写或判定无效的内容也必须明确交代，不能因归档前序而静默悬空。
- 采用: 每条后继分别与当前事实来源核对并保存自己的 `aligned` 或 `unaligned`；已经落地和仍面向未来的方向因此可以独立继续演进。
- 采用: 每条拆分后继使用从新到旧的 `拆分` 关系指向同一个直接前序；CLI 在一次可恢复事务中写入完整后继集合、归档前序并重建索引，单独一条 `拆分` 边属于不完整集合。
- 采用: 当前只为已经出现的一对多场景增加 `拆分`。`归并` 继续表达多前序收敛为一个后继；引用、依赖和实施关系不属于决策语义演进，多前序到多后继的重组在出现可复核实例前不新增专用关系。
