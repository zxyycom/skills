## 目的

- 让 agent 在当前工作中持续恢复有哪些短期任务、哪些已经就绪、哪些仍被阻塞，以及哪些可以安全并行。
- 让短期任务编排拥有独立行为入口和确定性状态工具，不依赖 agent 临场记忆完整恢复任务集合。
- 保持短期任务图、持久 change 计划和子代理委派各自拥有清楚的责任边界。

## 背景

- 线性步骤适合表达一个简单执行顺序，但不能稳定表达同时存在的候选任务、前置依赖、父子结构和并发排斥。
- `change-plan` 拥有可版本化、可审阅和可交接的 change 计划，不适合承接频繁变化且完成后即可消失的运行时任务。
- `subagent-orchestration` 拥有已经决定委派后的任务切面、代理配置、写入所有权和结果审计，不拥有委派前后持续存在的通用任务状态库。
- 只把这些关系留在对话上下文中，会让 agent 在上下文压缩、任务追加或并行执行后重新推演并产生不一致。

## 决策

- 采用: 新建 `task-graph` skill，作为短期任务编排的协调与入口型能力，维护当前工作中的任务发现、显式关系、状态查询、领取、完成和清理流程。
- 采用: `task-graph` 与兑现其行为所需的专用状态工具属于同一分发单元；工具提供确定性状态和拓扑操作，skill 负责触发、判断、权限、交接和完成验收。
- 采用: `task-graph` 不拥有持久 change 的目标、设计和实施计划；需要长期交接或大量上下文时，把任务引用交给 `change-plan` 或其他稳定 owner。
- 采用: `task-graph` 不拥有子代理的创建、模型选择、上下文配置和结果审计；需要委派时可以把已就绪任务及其边界交给 `subagent-orchestration`，缺少该外部能力时仍可由当前 agent 顺序执行任务图。
