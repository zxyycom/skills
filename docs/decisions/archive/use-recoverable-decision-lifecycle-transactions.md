## 目的

- 让真实演进通过一个命令切换全部直接前序和当前判断，并尽量保持文件组合一致。
- 让生命周期、直接关系和正式索引只在完整组合验证后共同生效。
- 让 agent 能够区分正常失败回滚与需要人工恢复的中断状态，不依赖无法兑现的严格原子性。

## 背景

- 一次演进会修改一个或多个后继、直接前序以及派生索引，拆成独立命令会产生不完整中间状态。
- 关系目标需要在最终组合中归档，而后继需要同时建立；单独校验任一中间步骤可能互相阻断。
- 普通文件系统上的顺序写入可以预检、验证并在可处理失败后尝试恢复，却不能覆盖进程中断、介质故障或恢复写入再次失败。

## 决策

- 采用: 普通 `activate` 建立一个审核通过的候选，或重新激活已归档记录并保留原建立时间和既有关系；只有新候选可以通过关系参数发起演进。
- 采用: `evolve`、`split` 或带关系的候选激活把调用方给出的关系和后继集合视为完整事务输入；每个直接前序目标只出现一次并使用一个关系类型。
- 采用: 演进先验证全部候选、对齐选择、活动直接前序和最终关系，再在一次事务中归档前序、写入关系、建立后继、重建正式索引并读回检查。
- 采用: 对命令能够捕获的失败，事务尽力恢复命令前的全部受影响 Markdown 和索引；成功返回只表示最终组合已经通过验证。
- 采用: 不承诺进程中断或恢复写入失败时仍严格原子；出现不完整恢复时停止后续维护，保留权威来源并按恢复手册核对完整组合。
- 采用: 正式索引始终由领域定义和全部合法已建立 Markdown 派生，不通过直接编辑索引制造生命周期、关系或建立状态。
