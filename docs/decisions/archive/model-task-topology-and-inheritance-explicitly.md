## 目的

- 让任务的结构分解、硬执行顺序和同时执行限制拥有彼此独立且可机械验证的语义。
- 让多个 agent 只依据已经写入的拓扑作出调度选择，不把临场猜测当作共享事实。
- 让子任务默认继承主任务的控制和约束，同时保留必要的局部差异表达。

## 背景

- 父子关系决定结构、状态继承和完成聚合；依赖关系决定一个任务何时具备输入；排斥关系只禁止同时运行，不建立完成顺序。
- 把三类关系放进同一种无约束 edge 会掩盖单父节点、有向无环和对称关系等不同不变量。
- 子任务若复制父任务的实际执行状态，会出现父任务运行即全部子任务运行、父任务完成但子任务未完成等矛盾。
- 子任务若完全不继承父任务约束，又可能绕过主任务的等待、暂停、前置依赖或并发边界。

## 决策

- 采用: 在任务显式状态中分别维护层级、顺序和并发关系；层级使用单一 `parentId` 形成无环森林，顺序使用 `dependsOn` 形成有向无环图，并发使用对称且无自环的 `excludes`。
- 采用: agent 可以发现并建议关系，但只有通过工具写入索引的关系才构成调度事实；关系缺失或尚未审定的候选不能靠 agent 推演直接进入执行。
- 采用: 子任务默认继承祖先的软控制状态、前置依赖和排斥约束。子任务可以用本地 control 显式覆盖继承的候选、排队、等待或暂停等软控制，也可以增加局部依赖和排斥；control 覆盖不能删除祖先依赖、祖先排斥或终态屏障。
- 采用: 运行、完成、失败和取消等实际执行状态只属于当前任务，不向子任务复制；父任务的完成依据子任务完成策略向上聚合。
- 采用: children、dependents、反向排斥、展开后的有效约束和阻塞路径从完整索引确定性派生，不作为需要双向手工同步的独立事实。
