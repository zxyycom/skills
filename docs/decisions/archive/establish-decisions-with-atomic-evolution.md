## 目的

- 让每条 Markdown 自身足以回答它是尚未生效的候选，还是已经建立并按生命周期生效的决策。
- 让普通激活保持单一目标，让真实演进能够显式且原子地切换全部直接前序和当前判断。
- 让查询索引始终是领域定义与全部已建立 Markdown 的完整派生视图，不拥有独立生命周期。

## 背景

- `createdAt` 已经能够在 Markdown 内稳定区分候选和已建立记录，Git 历史与旧索引都不应参与成员判断。
- 演进关系要求目标最终归档，但把归档前序、写入关系和激活候选拆成多个命令，会让候选关系与活动前序在中间状态互相阻断。
- 一次真实演进同时改变多份权威 Markdown 和派生索引，只有完整事务才能避免失败后留下部分生效的组合。

## 决策

- 采用: 合法候选是合法的新身份路径、当前完整格式、`status: active`、非空 `alignment` 且 `createdAt: null` 的 Markdown；候选不生效、不进入索引，存在时严格 `check` 继续失败。
- 采用: 合法非空 `createdAt` Markdown 是已建立记录的唯一集合；活动记录立即生效，归档记录只保留历史。
- 采用: 普通 `activate` 只建立目标候选并写入秒级 `createdAt`；重新激活归档记录保留原时间，不隐式改变其他记录。
- 采用: `evolve` 或显式携带直接关系的 `activate` 把调用方给出的关系作为候选的完整关系集合，并在一次事务中归档全部活动直接前序、写入关系、激活候选和重建索引。
- 采用: 演进事务只接受完整新候选和当前活动的已建立前序；最终关系继续拒绝缺失、候选、活动、重复、自环和环路目标。
- 采用: 查询先从当前全部 Markdown 得到已建立路径集合，再校验索引；`sync-index --write` 始终从领域定义和全部合法已建立 Markdown 完整重建索引。
- 采用: `discard` 只删除完整合法且未被引用的候选；已建立记录通过普通归档或真实演进退出当前依据。
- 采用: 写事务保存原 Markdown 与索引，应用全部目标变化后验证完整来源、同步索引并读回检查；普通失败恢复本次命令改动。
- 采用: 路径仍是当前集合内的稳定身份；明确结构迁移由维护者协调移动 Markdown、更新全部关系并重建索引，不生成兼容映射。
