## 目的

让 `investigation-report`（`skills/investigation-report/`）在起草、发布和检查的日常入口主动暴露资料成本与重复风险，不依赖维护者恰好想起另跑审计命令。让提示支持取舍，而不替代对形成时证据的语义判断。

## 背景

资源已有必要性、等价文本优先、节选与去重约定，但只写文档不能保证问题被注意。现实材料中，同一结果、完整 stdout、长路径列表会被多次观测反复展开；逐次耗时、条件、顺序和反例仍有保留价值，重复载荷则可以独立保存再引用。

文件大小、格式和压缩率都不能单独裁决证据价值。非文本材料可能不可替代，结构化数据也确实可能重复；为了降低提示数量而统一收紧到极端压缩阈值，会漏掉值得审阅的材料。无界内容扫描又会把日常小操作变成全集负担。

## 决策

- 采用: 候选查看、发布及检查默认提供有界、非阻断资源诊断，覆盖体积、数量、类型、完全相同副本及内部重复性信号。维护者依证据用途决定保留、节选或共享，资源合法性与历史保真继续由原契约约束。
- 同一 CLI 使用统一项目／本地配置，来源组与资源策略各有字段。配置装载与多来源路由分离，显式定位仍加载策略；发现、合并及字段规则由[来源配置契约](../../../skills/investigation-report/references/source-selection.md#配置发现与合并)维护。
- 压缩率作为重复信息启发值，按大小分档，小文件全文、大文件抽样。副本须经完整字节确认，共享引用与副本分别计量；内容类型和压缩采用现成库，通过安全文件边界取得有限输入。
- 单次内容读取、文件数及结果量有明确上限；关闭、抽样、预算耗尽、失败和截断均可观察。参数、输出字段及覆盖含义由[资源诊断](../../../skills/investigation-report/references/resource-review.md)维护，数值随使用证据调整。
