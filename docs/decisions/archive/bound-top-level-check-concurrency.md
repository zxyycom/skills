## 目的

- 在不默认放大资源压力的前提下并行运行彼此独立的检查任务。
- 通过稳定调度顺序减少 full 档中少数长任务造成的尾部等待。

## 背景

- 顶层检查可能各自启动测试 runner、临时仓库和多个子进程，顶层并发数不能直接等同于机器可用核心数。
- 默认串行会浪费彼此独立任务的等待时间，默认高并发又会在普通维护环境中制造不可预测的资源竞争。
- Full-only 集成任务通常明显慢于其他任务，若最后才领取会延长保守并发下的总耗时。

## 决策

- 采用: 本次已选择的前置检查默认最多同时运行两个，保持保守且跨环境可用的顶层资源边界。
- 采用: 调用方可以用 `CHECK_CONCURRENCY=<正整数>` 显式覆盖并发上限；非法值在任务启动前失败，不静默回退或推断。
- 采用: Full-only 长任务在计划中优先领取，以减少保守并发下的尾部等待；该顺序不改变任务档位或失败语义。
- 采用: 打包步骤不与前置检查并发，只有检查调度完全收敛后才可能开始。
- 不采用: 默认按 CPU 数量无限放大顶层并发，或为缩短等待而改变任务自身的验证范围。
