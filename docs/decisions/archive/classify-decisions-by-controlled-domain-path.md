## 目的

- 让领域 ID、责任边界、决策稳定身份和唯一主要 owner 共享一组可校验来源。
- 消除 frontmatter、逻辑分类与物理路径各自表达一级领域所产生的漂移。
- 让领域纠正、拆分、归并或责任重划以完整结构迁移保持路径、关系和引用闭合。

## 背景

- 受控领域表达一条决策主要改变的稳定责任边界；一条记录同时声明多个一级领域会掩盖应当独立演进的判断。
- 路径已经承担决策稳定身份和关系目标，另设领域字段或与领域无关的一级分组会让分类与身份分别演进。
- 领域变化会联动 Markdown 位置、直接关系和仓库引用，不能只改目录名或历史正文中的词汇。

## 决策

- 采用: `decision-domains.json` 是领域 ID 和责任描述的唯一事实源；领域定义使用唯一 kebab-case ID 并按 ID 稳定排序。
- 采用: 每条决策 Markdown 直接位于 `<domain-id>/<semantic-slug>.md`；路径第一段是唯一领域归属和稳定身份的一部分，不保留并行主题分组或 frontmatter `domain` 字段。
- 采用: 一条判断选择拥有被改变契约的主要领域；可以独立演进的跨领域判断分别记录，其他影响保留在正文而不扩展多领域字段。
- 采用: 未定义、嵌套、空的领域目录和领域目录中的非 Markdown 文件均无效；已定义但暂时没有记录的领域只留在目录表，不创建空目录。
- 采用: 领域归类纠正或结构演进同时移动 Markdown、更新全部直接关系与仓库引用并重建索引；归档正文保留当时判断，不为当前分类重写历史证据。
- 不采用: 在路径之外维护可漂移的一级领域字段、自由 tag 或并行物理分类。
