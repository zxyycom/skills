## 目的

- 让 `bun run check` 产生的 skill 制品只来自已经通过本次所选前置检查的仓库状态。
- 保持检查档位选择、前置任务调度和最终打包之间的顺序及失败边界明确。

## 背景

- `pack:skills` 生成交付制品，但不证明类型、行为、生成漂移或仓库结构已经通过所选门禁。
- Quick 与 full 选择的前置任务集合不同，打包仍应等待本次实际选择的完整集合收敛。
- 在任一前置失败后继续打包会留下未经当前检查命令证明的产物，并让成功日志掩盖门禁失败。

## 决策

- 采用: `pack:skills` 不属于 quick 或 full 前置任务档位；它只在本次所选前置检查全部完成后进入一次串行步骤。
- 采用: 任一所选前置检查失败时不执行打包，并在正常报告中显式输出打包 `skipped`。
- 采用: 全部所选前置检查通过后运行一次打包；打包成功进入最终 passed 计数，打包失败使整次检查失败。
- 采用: 打包结果与前置检查共同进入统一最终摘要和退出状态，不建立只看检查或只看制品的第二完成信号。
- 不采用: 与前置检查并发打包、在失败后保留一次“尽力打包”，或让 quick 档自动扩大为 full 档后才允许打包。
