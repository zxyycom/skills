## 目的

- 让 agent 直接判断一项当前决策是否已经完整执行，而不是从正文或实现状态中猜测。
- 让尚未执行的已确认方向提前约束相关工作，避免实现继续固化冲突方向。
- 让已执行决策成为后续工作必须遵守的明确基线，并在归档后保留其历史执行状态。

## 背景

- `active` 只能说明该决策已经确认并且当前适用，不能单独说明执行程度。
- 有些决策已经确定但尚未开始或尚未完整执行；相关实现仍需考虑它将会落地。
- 有些决策已经通过当前事实来源验证；后续相关工作必须遵守，偏离属于一致性问题。
- 归档时把 `alignment` 清空会丢失该决策退出当前集合前是否已经执行的信息。
- 已有归档记录中的 `alignment: null` 无法可靠恢复，只能作为历史未知状态兼容。

## 决策

- 采用: `active + unaligned` 表示决策已经确认且当前适用，但尚未完整执行并验证；所有相关工作必须把其后续落地作为约束，不得明知冲突仍继续固化相反方向。
- 采用: `active + aligned` 表示决策已经完整执行并通过当前事实来源验证；后续相关工作必须遵守该基线。
- 采用: `mark-aligned` 只在完整目标已经执行并验证后使用；已对齐决策发生偏离时按一致性问题处理，或通过新的长期决策改变方向，不把字段退回 `unaligned`。
- 采用: 归档表示决策不再属于当前约束集合，但保留归档前最后一个 `alignment` 值，以便回放当时是否已经执行。
- 采用: 新归档必须保留 `aligned` 或 `unaligned`；继续接受既有归档记录的 `alignment: null`，其含义仅为历史执行状态未知。
- 采用: candidate 仍表示尚未建立的记录，不用于承载已经确认但尚未执行的决策；后一种状态必须建立为 `active + unaligned`。
