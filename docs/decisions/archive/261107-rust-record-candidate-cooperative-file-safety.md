## 目的

- 为 Decision Records 和 Investigation Report 的 Rust CLI 候选确定与本地工作区风险相称的文件、事务和恢复边界，使数据保护与维护成本都可解释。

## 背景

- 原候选围绕强身份、父链和多阶段恢复证明保护每次写入，但这些证明仍无法提供非合作进程的跨文件原子隔离；多层证明和整树备份增加实现与维护成本。
- 正文、未提交资源以及不能从当前正文无歧义重建的发布身份和成员需要保护；Git pending 是待提交快照，不是工作区备份。资源迁移和多个文件的写入可能部分完成，失败信息必须反映实际结果。
- [两域共用候选并隔离生产接线](../261106-isolate-shared-native-record-candidate.md)决定共同底座及候选与生产的责任边界，本判断另行限定候选文件事务的风险取舍，不替代该判断。

## 决策

- 采用: 对合作型本地 CLI，持合作锁并以内容和普通权限比较局部冲突；普通文件先完整写同目录临时文件，再原子替换并回读。比较到替换之间仍有非合作编辑窗口，不将其称为 CAS 或跨文件隔离。同内容同权限的 inode 替换可接受；路径、链接、只读权限和写集别名仍须安全处理。
- 采用: 资源先独占复制并验证，再更新引用和必要索引，最后核对旧源并退出。覆盖或删除不可重建旧数据前保留并验证必要恢复副本；操作失败时提供已完成、未知、原因及备份线索，允许人工对账，不引入 WAL、自动重放或强制完整自动回滚。仅在完整恢复有证明时报告回滚。
- 采用: 保留真实 Git 锁、备用 index、HEAD 与 pending 检查及精确范围保护；Git 不代替工作区备份。字段和索引 schema 的兼容边界与各操作提交点由候选协议承接。
- 采用: 该取舍只约束 `tools/record-cli/` 两域 Rust 候选，平台验收以实际证据为限；现行 TypeScript 实现、生产分发和 updater 保持各自契约。候选完成、平台验收与生产切换分别判断。
