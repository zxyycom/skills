## 目的

- 为正式索引外的完整候选提供可发现、可定位和可逐条审核的查询入口。
- 让单条非法候选源码不遮蔽其他合法候选，同时不降低完整集合的严格验收门槛。

## 背景

- 常规 `list`、`show` 和 `trace` 使用正式索引，不能发现有意排除在索引外的候选。
- 候选目录中可能暂时出现一条结构、状态或关系非法的源码；若查询整体失败，维护者也难以继续审阅其他合法候选。
- 决策根、领域目录表和目录布局决定完整集合边界，其损坏不能像单个候选内容错误一样局部跳过。
- 容错读取只服务恢复与审核，最终交付仍需严格证明全部源码、正式索引和关系一致。

## 决策

- 采用: `candidates` 和 `show-candidate` 直接从决策 Markdown 源发现完整候选；`list`、`show` 和 `trace` 继续只读取正式索引。
- 采用: 候选集合查询逐文件容错，跳过结构、状态或关系非法的单条源码并报告 warning，同时继续返回其他合法候选。
- 采用: `show-candidate` 显式请求的目标自身非法时失败并返回目标诊断；目标不存在时也不从正式索引或历史猜测候选。
- 采用: 决策根、根目录成员、领域目录表或领域目录布局非法属于集合级错误，候选查询整体失败且不返回部分集合。
- 采用: 严格 `check` 从源码发现并计数合法候选；合法候选未进入正式索引不构成失败，但不完整结构、非法状态组合、身份冲突或无效关系继续阻断验收。
- 不采用: 因查询容错而跳过严格检查，或把候选混入正式索引查询以换取可发现性。
