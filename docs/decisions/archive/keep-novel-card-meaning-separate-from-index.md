## 目的

- 适用于 `novel-cards` 与当前 `skills/novel-cards/`，让小说规划自由递归、来源可追溯，且后续维护能恢复作者规划与机械工具的责任分工。

## 背景

- 同一小说的卷、册、弧线、章可能采用不同组合，人物观念和设定历史也需要不同压缩层。固定层级会迫使规划迎合工具而不是表达故事。
- 总结可以先承接完整远期意图，尚无下级；也可以只压缩已有来源，而不拥有那些剧情节点。将依据当作包含会导致伪造下级或复制第二套事件事实。
- 预期是作者安排但尚未发生，待展开是规划完整度；当前状态、独立原作参考与模拟读者判断有不同权威性。正文自动回写或索引同步自动确认摘要，会将工具推断替代作者选择。
- 使用者需要确定引用的卡确实存在，但文件存在、图无环及索引当前都不能证明因果与文学语义正确。

## 决策

- 采用：详情卡与任意递归总结卡作为单个 skill 的核心模型；剧情、人物、设定和历史复用包含/依据边界但保留领域职责。组织标签不固定层级，历史详情由实际剧情节点承担，不另建事件源。
- `children` 只表达组成展开，`sources` 只表达依据；远期意图没有实际下级时允许空组成，仅依据来源完成的总结也可以已展开。摘要由作者与 agent 复核因果、转折、条件和残余矛盾，工具不从引用数量推断语义完整度。
- Markdown frontmatter ID 是身份事实，派生索引只定位。选择全扫有界集合并核对索引，使查询直接验证身份与来源；无效或陈旧输入保持失败，查询预算返回未读边界，供后续显式读取。
- 卡片先改并从最高受影响处向下传播；正文反推先提取证据再对照目标，只出报告，不自动覆盖当前状态或回写卡片。参考内容显式读取且不默认采用。
- 采用已有本地索引协议承担机械可靠性，把文学语义与作者选择留给写作流程。自动语义能力或外部接口须以真实作者使用证据、独立契约与当前授权为前提，不预建通用图引擎、事件溯源或远端审稿平台。
