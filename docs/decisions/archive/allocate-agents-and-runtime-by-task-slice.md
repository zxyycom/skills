## 目的
- 让每个子代理完成边界清楚且可独立验收的工作，并使代理能力、思考上限和写入边界与切面匹配。

## 背景
- 本决策仅适用于 `subagent-orchestration`，当前行为 owner 是 `skills/subagent-orchestration/SKILL.md`。
- 主代理需要把主要调查、实现、验证和审查交给子代理，同时保持整体目标、依赖和最终交付责任。
- 持续使用同一子代理处理不同目标或角色会混合局部上下文、所有权和验收责任；切面过小又会让交接成本超过隔离价值。
- 独立调查、验证和审查可能需要创建临时脚本、测试 fixture、分析输出或其他辅助物；独立性来自不同代理不修改被评估对象，而不是禁止它对任何文件进行有限写入。
- 模型决定代理具备的能力，思考强度决定所选模型面对困难问题时可使用的思考预算上限；把两者绑定为同一档位或依赖统一起始配置，会掩盖任务究竟缺少能力还是需要更深思考。

## 决策
- 采用: 任务按最小可独立交付和验收的切面拆分，每个子代理只承担一个主要切面；代理按主要交付责任而不是切面内单个动作区分，实现代理完成自验证，独立交叉验证与审查由不同代理承担；同一切面的继续实现和定向修复优先延续原代理，无法延续时显式交接上下文和写入所有权。
- 采用: 改变交付物、共享项目状态或外部状态的写入所有权保持互斥。独立调查、验证和审查代理不得修改被评估对象，但可以在明确、隔离的范围内创建完成任务所需的临时脚本、fixture、输出或其他辅助物，并在结果中区分辅助写入与交付改动。
- 采用: 在工具支持时，先根据理解、知识与上下文利用、工具使用、跨范围综合和约束遵守等能力要求选择模型，再根据问题对该模型而言所需的多步推理、约束处理、证据消歧、探索和自检空间选择思考强度。提高思考强度会提高所选模型可使用的思考预算上限，但不会改变模型或补足其能力边界。
- 采用: 不规定统一起始档位，也不按子代理角色固定模型或思考强度。工具不支持独立配置时，把实际提供的配置视为当前约束，并通过调整切面、上下文和验证降低误判风险。
