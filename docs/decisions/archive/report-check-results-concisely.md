## 目的

- 让正常检查输出能够快速扫描，同时确保失败任务的 stdout、stderr 和最终状态足以诊断。
- 在一个任务失败后继续收集其他独立任务结果，并用统一摘要表达整次计划的真实完成状态。

## 背景

- 测试工具可能把大量成功明细写入 stdout 或 stderr；默认保留这些内容会产生噪音和摘要错序。
- 只报告简短失败会丢失根因，遇到首个失败立即退出又会迫使维护者多轮运行才能发现独立问题。
- 调用方需要依赖最终退出状态，而不能从 warning 文本或日志出现顺序猜测检查是否通过。

## 决策

- 采用: 成功任务默认只输出名称、`passed` 和耗时；计划内未选择的任务使用单行 `skipped`，不展开捕获日志。
- 采用: 失败任务无论是否启用 verbose 都完整展开自身捕获日志并输出 `failed`；该失败不阻止其他已经选择的独立检查继续执行。
- 采用: `--verbose` 可以与任一档位组合，并在每个已执行任务的摘要前展开其完整捕获 stdout 与 stderr。
- 采用: 最终摘要报告 profile、计划总数、passed、skipped、failed 和总耗时；任一已执行检查或后续打包步骤失败时，整体状态失败并退出非零。
- 采用: 正常人类报告和捕获日志写入 stdout；任务启动前的参数或并发配置错误写入 stderr，并在不启动检查的情况下失败。
- 不采用: 在成功路径默认打印测试明细，或让已经失败的所选任务仍产生成功退出状态。
