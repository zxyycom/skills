## 目的
- 让每份报告无需原对话或同主题其他报告，即可复核本轮背景、问题、实际依据、结果与适用边界。
- 保留值得独立比较的历史轮次，同时让同轮补证、纠错和结果收敛集中在原报告。

## 背景
- 本决策适用于 `investigation-report`，当前行为 owner 为 `skills/investigation-report/`。
- 四项固定核心是各类可复核调查的共同最低结构；计量、因果、方案或验证信息仍需按实际场景补足。
- 以新证据或实质认识变化直接触发新报告，会把同轮中间结论固化成独立历史；Git 提交只保存版本，不能证明独立复核价值。
- 一律原地覆盖又会丢失真实历史轮次，因此分篇和关系需要分别判断，不能由时间、修改次数或关系类型倒推。

## 决策
- 采用: 每个 Investigation ID Markdown 保存一轮值得独立复核的完整认识，依次使用唯一且非空的 `形成时背景`、`调查目的`、`调查范围与依据`、`调查结果与边界` 四个核心 H2。
- 采用: 背景说明处境、已知条件、假设、未知与约束；目的说明本轮问题和预定边界；范围与依据说明实际对象、来源、时点、方法及未覆盖内容；结果与边界区分事实、推断、建议、实际动作和未知。
- 采用: 计量、假设、反证、时序、方案、授权、恢复与验证等场景支撑归入相应核心。其他可选语义 H2 位于固定核心之后；声明资源时，非空 `随附资源` 必须为第五个 H2，其他可选语义 H2 位于其后。
- 采用: 同轮补证、纠正推断、解释遗漏和结果收敛，且中间版本没有独立保留价值时，完善原报告或候选；已提交或产生新认识都不足以另立报告。新增依据须标明实际来源和时点，不伪装成原先已取得的证据。
- 采用: 只有问题、条件、依据和结果边界需要独立复核、且不能合理归于原轮次完善时，才新建报告。承接旧认识时还须说明旧轮次为何值得独立保留，再判断真实直接演进；主题相近、时间先后和普通引用不构成演进关系。
- 采用: 记录误述在原报告恢复准确内容；真实且有独立保留价值的历史轮次不得借纠错覆盖。报告不作为主题容器追加多轮 H3 片段，也不以最新一份报告代替当前事实 owner。
- 采用: 检查器验证结构、关系和资源等机械条件；agent 在当前授权内自行审查内容充分性、场景义务、独立轮次、直接关系与发布条件。仅在缺失关键事实或取舍、超出范围或明确要求人工确认时询问；高风险操作仍须精确授权。
