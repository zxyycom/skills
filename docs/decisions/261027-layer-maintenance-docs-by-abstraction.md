## 目的

- 让维护者先理解目标、主体责任、关系和不变量，再为当前任务读取必要的精确契约，减少从实现术语反推整体设计的负担。
- 保留确有使用、排障和复核价值的信息，同时让不改变外部行为的内部重构无需同步维护多份实现镜像。

## 背景

- 项目工具链、共同记录操作及部分 skill 文档混合了整体规则、公开协议和当前内部步骤；仅删字或把长段搬进另一份参考，不能补足缺失的上层理解。
- 文档长度和术语密集度是需要调查的结构信号。有效信息可能需要独立的抽象汇总和按需细节层，重复或无独立责任的内容则需要收敛。
- 仓库导航已统一维护任务路由；本判断补充被路由文档的阅读层次，不替代导航的既有责任，也不改变实现、授权和验收标准。

## 决策

- 采用: 按实际阅读任务区分稳定模型、精确契约和维护依据。模型表达目标、责任、关系、主流程和关键边界；精确契约承接调用者必须依赖的输入、输出、格式、兼容和失败语义；私有模块、缓存编码和内部调优由源码与测试承接。
- 采用: 长度或术语负担明显时，允许新增抽象汇总、重新分层、拆分、合并、改写和删减的组合。新文档必须有独立的消费任务与 owner，不为每个主题强制建立固定层数，不把缩短副本当作新的理解模型。
- 采用: 项目验证模型由 [validation-model.md](../validation-model.md) 承接，运行诊断由 [gate-runtime.md](../gate-runtime.md) 承接，操作和质量政策继续由项目工具链维护；共同记录操作的主体与事务模型由 [record-operations/model.md](../../tools/record-operations/model.md) 承接，领域与共享工具仍拥有各自精确契约。导航连接各层，不复写完整规则。
- 采用: skill 行为入口保留任务骨架和必要边界，精确协议按需引用包内 owner；安装后的读取路径必须自包含。公开协议、安全、授权、文件与状态保护、迁移兼容及验收保证不得借文档抽象而削弱，真实行为变化另按对应 owner 与决策规则处理。
- 采用: 历史决策、形成时调查、原始快照和测试证据按自身职责保留，不因术语多或篇幅长而批量改写。
