## 目的

- 为决策关系的建立、完整修订和后继集合变化提供一个稳定、可扩展的事务 owner。
- 让新增关系类型通过自身拓扑与闭合策略接入，而不继续增加同级生命周期命令。
- 让关系、前序生命周期、后继建立和派生索引只在完整最终组合通过验证后共同生效。

## 背景

- 当前 `evolve` 只建立一个后继，闭合一对多关系由独立 `split` 承接，带关系的 `activate` 又提供单后继并行入口。
- `拆分` 的正确性不只取决于最终存在至少两条边，还取决于调用方是否把同一前序的完整最终后继集合放入一次事务；单后继命令不能证明这一点。
- `归并`、`拆分` 和未来可能出现的其他关系具有不同拓扑，但它们共享先验证完整成员、再修改生命周期和索引的事务责任。
- 普通文件系统能够在可处理失败后尽力恢复原文件组合，却不能承诺进程中断或恢复写入失败时仍严格原子。

## 决策

- 采用: `evolve` 是决策关系事务的统一公开入口和内部 owner；调用方显式提供完整后继集合，事务从每个后继的最终关系集合恢复直接前序、拓扑和全部受影响记录。
- 采用: `activate --relation` 永久保留为新候选的单后继便捷入口；候选自身已经声明关系时，普通 `activate` 也把该关系翻译为一次统一建立事务，不要求等待或随后再调用 `evolve`。关系来源与完整覆盖优先级由[以完整集合审核和替换决策关系](replace-decision-relations-as-complete-sets.md)拥有。
- 采用: 关系类型通过策略声明允许的前序数量、后继数量、关系分布和闭合条件。当前非 `拆分` 关系只建立或调整一个后继；`拆分` 要求同一前序至少两个后继，并要求显式集合等于事务后的全部直接拆分后继。
- 采用: 单后继 `拆分`、遗漏既有拆分后继、多个拆分前序、拆分与其他类型混合以及没有已确认策略的多后继形状均在任何写入前失败。多前序到多后继的重组继续等待真实案例，不预设协议。
- 采用: 不再保留独立 `split` 命令，也不为后续关系类型增加同级命令；命令参数是否需要更丰富的逐后继输入，只由出现的真实关系策略决定。
- 采用: 演进在写入前验证全部后继、最终关系、直接前序、对齐选择、未记录历史和最终关系图，再归档新增活动前序、写入关系、建立候选、重建索引并读回检查。
- 采用: 对可处理失败，事务尽力恢复命令前的全部受影响 Markdown 和索引；进程中断或恢复不完整时停止后续维护并进入恢复流程，不以“原子”名义承诺普通文件系统无法保证的结果。
- 采用: 本决策只拥有事务成员、关系策略、拓扑闭合、写入顺序和恢复边界；候选关系、CLI 覆盖、完整替换及已建立记录的可变字段由完整集合决策拥有，不能据此绕过本决策要求的完整后继集合。
- 采用: 单后继未记录中间决策的显式折叠继续由 `evolve` 承接；折叠不自动继承关系，也不扩展到缺少现实需求的多后继场景。
- 采用: 正式索引始终从领域定义和全部合法已建立 Markdown 派生；最终静态检查证明当前关系图闭合，但不增加事务 ID 来反向证明历史命令来源。
