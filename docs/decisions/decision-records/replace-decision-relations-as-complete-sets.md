## 目的

- 让关系意图与候选正文一起接受审核，并在激活时直接成为完整事务输入。
- 允许纠正已建立记录的错误直接关系，而不要求伪造新的决策判断或原地改写正文语义。
- 消除单边追加、参数与源码隐式合并以及关系移除后自动改变旧记录生命周期的不确定性。

## 背景

- 候选与已建立记录使用相同的 `relations` 结构；要求候选始终保存空关系，会把重要演进意图推迟到命令调用时才出现，削弱审核材料的完整性。
- 调用方有时需要在激活时一次声明或修正完整关系，`activate --relation` 因此是有价值的便捷入口，而不是应被移除的重复命令。
- 已建立记录可能存在缺失、类型错误或目标错误的关系；只允许创建新决策会把关系纠正误写成不存在的判断演进。
- 关系影响前序归档和多后继闭合，任何修改都不能退化为对现有数组追加一条边。

## 决策

- 采用: 合法候选可以声明零个或多个完整预期关系；候选关系接受路径、类型、重复、自环和目标存在性等前瞻性校验，但在候选建立前不进入正式关系图，也不要求活动前序提前归档。
- 采用: 未提供 CLI 关系覆盖时，候选或所选记录自身的 `relations` 是最终关系集合；提供一个或多个 `--relation` 时，它们完整替换所选后继的关系；显式空集合使用独立参数表达。任何入口都不把 CLI 与源码关系自动追加或合并。
- 采用: 带有效关系的候选激活通过[统一关系事务](unify-closed-decision-relation-evolution.md)一次完成前序处理、关系写入、建立和索引重建；`activate --relation` 继续承接新候选的单后继完整覆盖，但不能绕过要求多个后继的关系策略。
- 采用: `evolve` 可以选择候选或已经建立的后继。候选按显式 alignment 建立；已建立记录的关系可以完整替换，但其正文、`status`、`alignment` 和 `createdAt` 必须保持不变。
- 采用: 最终关系新增的活动直接前序在同一事务中归档，已经归档的目标保持归档；从完整集合移除的旧目标不会自动重新激活、删除或改变对齐状态。
- 采用: 已建立关系修订只纠正或重组直接关系，不授权修改记录的目的、范围、背景、采用方向或理由；决策含义变化继续通过自包含的新判断和真实演进关系表达。
- 采用: 完整集合替换只确定每个所选后继的最终关系，不放宽事务成员或拓扑。多后继调整必须满足统一演进决策要求的完整最终后继集合，包括本次内容不变的既有后继；不能以单后继完整替换绕过拆分或未来其他闭合策略。
- 采用: 历史 `archived + alignment: null`、无法恢复完整目标集合或关系语义不清楚的记录不进入普通关系修订，保留现场并按恢复或结构迁移边界处理。
