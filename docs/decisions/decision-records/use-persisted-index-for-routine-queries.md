## 目的

- 让 `decision-index.json` 成为 agent 可直接查询和查看的正式读取模型。
- 让常规查询成本主要由索引大小和查询结果决定，而不是每次遍历全部决策正文。
- 保持 Markdown 作为权威写入源，同时明确索引读取与完整源校验各自的入口。

## 背景

- 大项目可能快速积累一千条及以上决策，逐文件遍历和解析会形成明显的固定查询成本。
- 当前索引已经包含状态、对齐、领域、投影和关系，但常规查询仍先扫描全部 Markdown 并重新计算源 revision。
- 生命周期命令会在同一事务中更新 Markdown 与索引；手工编辑则本来就需要显式检查或同步。
- `show` 仍需要读取目标 Markdown 正文，但没有必要先读取其余全部正文。
- CLI 的主要调用者是 agent；列表入口应优先支持定位，再由 `show` 展开完整内容。

## 决策

- 采用: `list`、`show` 和 `trace` 直接加载并验证持久索引结构，不在每次查询前遍历全部 Markdown 或重算完整源 revision。
- 采用: `list` 默认只输出定位所需的状态、路径、标题和目的；完整背景、决策投影与正文通过 `show` 获取。
- 采用: `show` 根据索引定位后只读取目标 Markdown；目标正文缺失时明确失败。
- 采用: 生命周期写入继续在可恢复事务中同步索引；`check` 负责完整源、关系和索引一致性校验，`sync-index --write` 负责手工编辑后的重建。
- 采用: 未通过当前工具完成的 Markdown 修改，在执行 `check` 或 `sync-index` 前不承诺常规查询立即反映；索引是最近一次成功维护或同步后的集合快照。
- 采用: `domains` 继续直接读取领域目录，因为领域目录本身是该入口的权威且读取成本固定。
