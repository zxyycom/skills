## 目的

- 让每条 Markdown 自身足以区分尚未生效的候选与已经建立的决策。
- 让真实演进通过一个命令切换全部直接前序和当前判断，并尽量保持文件组合一致。
- 让 agent 能够区分正常失败回滚与需要人工恢复的中断状态，不依赖无法兑现的严格原子性。

## 背景

- `createdAt` 已经能够稳定表达候选和已建立记录，Git 历史与派生索引不应参与成员判断。
- 一次演进会修改新候选、一个或多个直接前序以及派生索引，拆成独立命令会产生不完整中间状态。
- 普通文件系统上的顺序写入可以预检、验证并在可处理失败后尝试恢复，却不能覆盖进程中断、介质故障或恢复写入再次失败。

## 决策

- 采用: `createdAt: null` 的完整新身份记录是未生效候选；非空 `createdAt` 的合法 Markdown 是已建立记录，活动记录生效，归档记录只保留历史。
- 采用: 普通 `activate` 建立新候选，或重新激活已归档记录并保留原建立时间和既有关系；只有新候选可以通过关系参数发起演进。
- 采用: `evolve` 或带关系的候选激活把调用方给出的关系作为完整直接前序集合；每个前序目标只出现一次并使用一个关系类型。
- 采用: 演进先确认新候选和全部活动前序，再在一次事务中归档前序、写入关系、激活候选、重建索引并读回验证。
- 采用: 对命令能够捕获的失败，事务尽力恢复命令前的全部受影响 Markdown 和索引；成功返回只表示最终组合已通过验证。
- 采用: 不承诺进程中断或恢复写入失败时仍严格原子；出现不完整恢复时停止后续维护，保留权威来源并按恢复手册核对完整组合。
- 采用: 索引始终由领域定义和全部合法已建立 Markdown 派生，不通过直接编辑索引制造生命周期、关系或建立状态。
- 采用: `discard` 只删除完整、未建立且未被引用的候选；已建立记录通过归档、重新激活或真实演进改变生命周期。
