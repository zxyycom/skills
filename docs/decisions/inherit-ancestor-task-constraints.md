## 目的

- 让子 task 在没有重复配置时继续遵守祖先的控制、前置依赖和并发边界。
- 保持控制继承与各 task 自身的实际执行状态分离，避免父子状态互相冒充。

## 背景

- 子 task 若完全不继承祖先边界，可能绕过主任务的等待、暂停、前置依赖、排斥或终态屏障。
- 子 task 若复制祖先的 running、成功、失败或取消状态，又会产生父任务运行即全部子任务运行等矛盾。
- 局部任务有时需要从祖先的候选、排队、等待或暂停意图中作出更具体选择，但不能借覆盖删除硬约束。

## 决策

- 采用: 子 task 默认继承祖先的软控制状态、完成依赖和并发排斥；顶层 task 不使用继承控制。
- 采用: 子 task 可以用本地 control 显式覆盖继承的候选、排队、等待或暂停等软控制，并可以增加局部依赖和排斥。
- 采用: 本地覆盖不能删除祖先依赖、祖先排斥或终态屏障；完整有效控制、关系来源和阻塞路径从索引确定性投影。
- 采用: running、成功、失败和取消等实际执行状态只属于当前 task，不沿父子关系向下复制。
- 不采用: 通过复制祖先状态维持多份有效控制，或允许子 task 静默绕过祖先硬约束。
