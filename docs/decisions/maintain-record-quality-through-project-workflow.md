## 目的

- 让本项目对决策与调查报告的集合级维护有可执行入口，能从发现的问题推进到有依据的修正，而不是停留在模型评分或反复试验。
- 用实际维护反馈改进流程，同时保持领域契约和辅助判断工具的责任独立。

## 背景

- 两类记录已有独立的语义规则、查询与写入事务；集合维护还需要决定本轮覆盖哪些对象与维度、如何取得证据、复核哪些结果，以及如何交付剩余项。
- [既有 JEV 调查](../investigations/jev-record-maintenance-boundaries.md)显示局部语义判断能提供有用信号，也可能漏检当前冲突；结构有效、模型回答和实际可采用结果不能合并为一种通过状态。
- 项目内先运行并调整流程，能依据实际发现和复核开销识别可复用边界；仅凭问题常见就建立跨项目工具，会提前固定尚未验证的假设。

## 决策

- 采用：[记录维护工作流](../record-maintenance-workflow.md)作为本项目集合级维护的编排与验收 owner，连接范围确认、取证、辅助判断、复核、领域修正与验证；仓库导航提供任务入口。
- Decision Records 与 Investigation Report 继续拥有各自的记录语义、生命周期、关系和维护事务。Lightweight Judgment 只在显式选择及相应授权下承担局部判断，不成为普通记录维护的隐式外发依赖。
- 维护同时覆盖所选维度中的既有内容与拟议变更；主代理对每项形成有依据的判断或未决项，拟采用变更回到来源核对。具体步骤和可调整工作量只在工作流维护。
- 决策与调查报告分别维护任务模板、主代理审查清单、处置和验收：前者恢复采用方向、独立演进与对齐依据，后者恢复形成时问题、证据、认识边界与资源用途。两者虽共享记录形式，但不能由同一套语义问题和动作规则完整覆盖。
- 完整审查清单与 JEV 局部题库分开：主代理拥有取证、候选覆盖、复杂推理与领域结论，代码处理确定性前提；JEV 只接收必要原文与明确局部命题。模型能力与可用上下文不同，不能只切换执行者而沿用整项审查任务。
- 局部辅助按实际模型、材料和答案用途验证后采用，缺上下文或总开销不划算时直接由主代理处理；局部原答、主代理判断和实际动作分别留证。公共层承接该辅助边界、授权、留存、执行状态与对账；每个 run 绑定一个领域，版本与原始输入使每轮可回放。
- 每轮把可复用的纠正回写工作流，个案证据与运行明细按自身留存价值归位。先稳定项目内重复步骤，再据真实跨项目使用决定通用化；工作流建立不同时启用定时调用或自动写入。
