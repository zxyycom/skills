## 目的

- 在不改变 Markdown 生命周期事实源的前提下，防止同一未提交变更中的已建立判断被无意归档。
- 让关系演进保持可恢复事务，并把最终直接关系的语义选择留给调用者。

## 背景

- 首次激活立即建立并使决策生效，Git 提交、暂存和历史不参与成员身份或生命周期判断。
- 待归档前序尚未进入当前 Git `HEAD` 时，可能只是本次变更内部的收敛过程，也可能仍应作为长期历史保留。
- 关系类型不能通过链路机械合成；删除、断链和关系迁移不能由通用演进动作推断。

## 决策

- 采用: 当前 Git `HEAD` 只作为归档前的路径存在性证据；同一决策根相对路径存在即视为已经记录，文件内容、Git index 和工作区差异不参与判断。尚无提交时全部路径都视为未记录。
- 采用: 只有确认决策集合不在 Git 工作树内时跳过预检；仓库发现或基线读取失败时停止且不写入。
- 采用: `evolve`、带关系的 `activate` 和 `archive` 即将归档不在 `HEAD` 的已建立记录时，先暂停并警告且不写入；调用者必须显式重试并选择保留未提交历史。
- 采用: 后继的完整最终关系集合由调用者显式提供；CLI 不自动继承、组合或改写关系类型。
- 采用: 最终关系中的活动目标按正常演进归档；事务失败时尽力恢复命令前的 Markdown 与索引组合。
- 不采用: 用 Git 历史决定决策是否建立或生效，或自动推断关系迁移语义。
