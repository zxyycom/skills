## 目的

- 让 agent 区分必须遵守的当前基线与需要为未来保留空间的演进方向。
- 让未来方向在尚未成为当前事实时影响相关选择，同时不取代任务 owner 对范围、优先级和实施授权的判断。

## 背景

- 把 `alignment` 解释为执行进度，会把长期方向、当前事实和任务进度混在同一个状态里。
- 一项未来方向即使不属于当前任务，也可能影响接口、结构或局部实现的选择；完全忽略会形成不必要的迁移阻碍。
- 未对齐方向既不能被忽略，也不能被当成必然实施目标；需要明确它何时只影响方案选择、何时可以局部调整、何时才进入任务范围。

## 决策

- 采用: `active + unaligned` 表示已经确认但尚未成为当前事实的未来方向，不表示未完成任务或尚待确认的候选，也不保证最终一定实施；它可以在成为基线前被实施、修订或归档。
- 采用: 相关工作必须读取未对齐方向。在同样满足当前要求、约束和验收标准，且不引入新的外部依赖、数据迁移或兼容性风险的方案中，优先选择兼容该方向并保留未来接入路径的方案。
- 采用: 只有局部调整位于当前任务已授权修改的对象和责任边界内、不增加独立验收目标，且不引入上述额外风险时，才能作为兼容性微调一并完成；`alignment` 本身不创建实施任务、优先级、授权或范围。
- 采用: 没有满足当前要求的兼容方案时，按当前任务要求完成并说明不兼容点；不得在存在同样可行的兼容方案时选择会固化相反路径或增加长期阻碍的方案。
- 采用: `active + aligned` 表示完整方向已经成为当前事实、通过核对并建立为当前基线。描述当前事实的已对齐基线可以与面向未来的未对齐方向并存，二者的差异本身不是冲突；多个当前基线或多个未来方向彼此不能兼容时才属于一致性问题。
- 采用: 部分落地仍保持 `unaligned`。只有完整方向成为当前事实后才能使用 `mark-aligned`；若它同时取代既有长期方向，先按真实演进关系处理前序，避免留下互相冲突的活动基线。
- 采用: 归档保留最后对齐状态，用于回放记录退出当前集合时是基线还是未来方向，不用于表达任务进度。
