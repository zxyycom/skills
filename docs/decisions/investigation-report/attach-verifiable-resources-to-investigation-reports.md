## 目的
- 允许有复核需要的报告在保持正文独立可读的同时，按需直接引用不适合完整嵌入正文的原始、摘录或二进制材料；报告可以完全不声明资源。
- 让报告到资源的关系、资源内容以及查询与完整性投影分别拥有明确 owner，避免依赖目录猜测或维护第二份人工清单。
- 让资源缺失、替换、重命名和索引陈旧能够被确定性发现，并在诊断中定位具体资源。
- 保持调查主题作为发现、续接和生命周期管理单位，不把随附材料扩张为独立制品系统。

## 背景
- 一个主题 Markdown 可以包含多份时点报告，同一资源也可能被多个报告或主题共享；只有报告自身具备声明精确关系的上下文。
- 接口完整参数、原始响应、日志、规范原文和图片全部写入正文会削弱主线，只保留摘要又可能丢失未来复核所需的高保真依据。
- 当前主题索引已经是可删除重建的读取侧，能够投影 Markdown 中的关系并保存集合级 metadata，无需新增资源 manifest 或第二套索引。
- 资源内容可以在不改变 Markdown 的情况下变化；只投影资源 ID 不能证明当前文件仍与生成索引时一致。
- 哈希能够暴露内容变化，但不能判断材料来源是否可信、是否包含敏感信息或一次修改是否符合历史语义。

## 决策
- 采用: 调查根目录使用可选的统一 `_resources/` 保存随附材料；相对目录的安全 POSIX 路径是资源 ID，资源可以平级或嵌套，目录结构只承担组织和身份。
- 采用: H3 报告可以按需在形成时间后用固定 Markdown 元数据声明资源链接；没有资源的报告省略整个字段，只有字段存在时才要求至少一个链接。报告 Markdown 是精确关系和展示文字的唯一事实源；一个资源允许被多份报告或主题共享。
- 采用: 调查主索引继续让每个主题只产生一个 entry，并在主题 state 中投影报告到资源的关系；索引 metadata 对每个被引用资源保存一次 ID 与 SHA-256。资源不产生独立 entry，索引仍可从 Markdown 与资源完整重建。
- 采用: 完整领域快照同时覆盖主题 Markdown 和按 ID 排序的资源哈希；资源成员或内容变化必须改变 `sourceRevision`。同步写入、默认检查和查询前新鲜度核对使用同一快照，并提供资源级不一致诊断。
- 采用: 资源池中的普通文件必须至少被一份报告引用；这项约束只管理资源池文件，不要求每份报告拥有资源。维护入口拒绝绝对或逃逸路径、路径不规范、任一路径分量为符号链接、非普通文件、缺失引用和孤儿资源。资源目录中的 Markdown 只作为资源，不作为调查主题发现。
- 采用: 正文仍说明资源来源、观测条件、处理方式及其与结果的关系，并概括影响结论的关键事实；随附资源不能替代四项固定核心。已有稳定事实 owner 足以复核时直接引用 owner，只在需要形成时快照时复制最小非敏感材料。
- 采用: 历史报告引用的资源属于该报告的形成时证据。新的实质材料使用新资源并追加报告；原地修改只用于修正当时材料未被准确保存、无语义格式问题或移除不必要敏感信息，且哈希和 revision 必须显式暴露变化。
