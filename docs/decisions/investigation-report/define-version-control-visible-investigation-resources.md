## 目的
- 允许调查资源直接使用常见中文、英文、数字和经验证的常用符号形成可读名称，不要求为了进入报告而改成小写 ASCII 别名。
- 让项目已经通过版本控制 ignore 排除的未跟踪缓存、编译产物和本地噪声不进入调查资源的孤儿检查、摘要和来源 revision。
- 保持报告引用可分发、名称边界可逐项审查、路径可验证，并避免从宽泛 Unicode 类别或内置生成文件名单推断资源成员。

## 背景
- 调查资源的路径逃逸防护主要由相对路径结构、精确链接目标、符号链接拒绝、规范根约束和普通文件身份校验承担；原有小写 ASCII 白名单额外排除了中文、大写英文和常见安全符号，却没有独立承担这些核心安全责任。
- 任意可打印 Unicode 或整个字符类别又过于宽泛，会纳入双向文本控制符、不可见字符、URL 与路径控制字符及未经验证的 Markdown 边界；资源名称需要可复核的正向清单。
- `_resources/` 可能保存需要脚本处理的形成时材料；递归文件系统扫描会发现 `__pycache__` 和 `.pyc` 等项目已明确忽略的未跟踪文件，使它们成为孤儿资源或无意义地改变集合 revision。
- 内置语言或工具缓存名单无法覆盖各项目的真实生成文件，也可能静默排除用户有意保存的材料；项目版本控制可见性已经提供可复用的成员边界。

## 决策
- 采用: 每个资源 ID 路径段只接受常用汉字 `U+4E00..U+9FFF`、`〇`、大小写 ASCII 英文、ASCII 数字，以及固定契约逐项列出的点、连接符、括号、方括号、书名号和中英文常用标点；以后只根据现实名称与解析验证逐项扩充，不自动接受全部 Unicode 字母、数字、标点或可打印字符。
- 采用: 路径段不能以点开头或结尾，必须至少包含一个汉字、英文字母或数字，并拒绝 Windows 保留设备名及其带扩展名形式；ASCII 圆括号必须成对，允许空内容和最多 32 层嵌套。括号门禁只对应 Markdown 解析的现实深度边界，不额外禁止已经可以无歧义解析的空括号或嵌套。
- 采用: 绝对路径、空段、`.`、`..`、反斜杠、查询、片段、百分号编码、空白、路径或 URL 控制字符、符号链接、非普通文件和越过资源根目录继续被拒绝；扩大名称白名单不削弱文件身份与路径收口。
- 采用: Git 工作区以 `git ls-files --cached --others --exclude-standard` 在 `_resources/` 范围内返回的文件作为受管资源；ignore 排除的未跟踪文件不参与孤儿检查、metadata 或 source revision，已经跟踪的文件即使命中 ignore 仍保持受管。
- 采用: 报告显式引用存在但因 Git ignore 退出版本控制可见集合的未跟踪文件时失败，避免本地不可分发材料成为调查证据；非 Git 工作区没有可复用的项目 ignore 语义时继续完整发现 `_resources/` 文件系统成员。
- 采用: 调查领域 `definitionVersion` 升为 `4`，因为资源 ID 接受集合和受管资源成员规则都会改变索引 metadata、source revision 与新鲜度判断；通用 JSON 外壳没有变化，`schemaVersion` 继续为 `3`，已有调查索引只需由当前 CLI 重建。
- 不采用: 任意可打印 Unicode、宽泛 Unicode 字符类别、静默字符归一化、百分号编码别名、调查工具内置缓存名单或独立 `.investigationignore`。
