## 目的

- 让 task 及其拓扑在仍参与选择、阻塞、交接或执行协调时跨上下文保持可恢复。
- 让删除成为调用方明确确认结果交付与关系闭合后的受控动作，而不是时间驱动的后台行为。

## 背景

- Task 内容是临时协调信息，不等于 task 必须在短时间内消失；较长工作周期中的关系和终态结果仍可能影响当前选择。
- 经过时间或进入终态都不能单独证明结果已经交付、引用已经消费或拓扑边界已经闭合。
- 自动 GC 或按年龄归档会在调用方尚未完成交接时移除权威协调事实。

## 决策

- 采用: Task 可以按实际协调需要跨上下文或长期保留；创建时间、经过时长和终态本身都不触发删除。
- 采用: 只有显式选中的 task 已经成功或取消、结果已经交付、不再承担协调价值，并且父子、依赖和排斥关系在删除集合边界内闭合时，才允许原子批量清理。
- 采用: 工具不运行后台 GC，不自动选择清理对象；任一门禁失败使整个显式批次保持不变。
- 采用: 已分配的 task ID 不复用，避免旧引用在清理后指向另一个任务。
- 不采用: 按固定时长、终态年龄或归档目录自动迁移或删除 task。
