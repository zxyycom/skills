## 目的

- 让一个长期可发现的索引稳定保存当前仍有协调价值的任务，并支持低成本查询和事务更新。
- 让任务身份、必要内容、显式状态、拓扑关系和执行结果只有一个权威表示。
- 避免为任务建立逐项文档、派生索引或默认历史，从而保持任务协调工具的维护面有限。

## 背景

- Task 通常只需要目标、少量上下文、显式状态、关系和结果摘要；长期需求、完整设计和历史证据已有各自的文档 owner。
- Task 内容有限不代表任务必须很快删除。一个任务及其拓扑只要仍影响选择、阻塞、交接或执行，就可能需要跨越较长工作周期持续存在。
- 为每个 task 创建 Markdown，再从这些文件派生查询索引，会增加文件发现、同步、新鲜度和双重 owner 的维护成本。
- 把清理绑定到时间或终态会丢失仍有协调价值的任务；是否删除需要由调用方根据结果交付和关系闭合显式判断。

## 决策

- 采用: 使用一个受工具管理的 JSON task index 作为任务身份、内容、显式状态、拓扑关系和执行租约的唯一协调事实源；它不是从逐任务文件生成的派生索引。
- 采用: 每个任务直接作为索引中的 JSON entry 存在，不创建 task Markdown、物理归档目录或默认事件历史。
- 采用: Task entry 只保存任务协调所需的本地内容和稳定引用；大量背景、长期理由、正式审阅与跨阶段知识继续由对应稳定 owner 承接。
- 采用: 终态和经过时间都不自动触发删除。只有显式选中的任务不再承担协调价值、结果已经交付且清理门禁满足时，工具才从索引删除；任务 ID 不复用。
