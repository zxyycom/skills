## 目的

- 让 task 的成功事实与其完整目标一致，避免把实现分支上的中间交付误作协调终点。
- 让即时集成与异步集成使用可恢复且责任清楚的任务边界。

## 背景

- 分支实现、自验证和提交可以证明一个实现切面已经准备好，但不能证明包含主线集成、发布或外部确认的目标已经完成。
- 同一执行上下文能够立即完成集成时，另建 task 会增加不必要的协调面；集成由其他时间或 owner 承担时，继续占用原租约又会模糊交接责任。

## 决策

- 采用: 只有 task goal 的全部交付边界已经达成时才写入成功终态；goal 包含主线集成、发布或外部确认时，分支实现、自验证和提交只是中间交付。
- 采用: 调用方能够即时完成集成时，续租并交接同一 task，在集成完成后收敛该 task。
- 采用: 集成异步发生或拥有独立责任时，分别建立实现 task 与集成 task，并只在真实结果消费关系成立时记录显式完成依赖。
- 不采用: 为了释放当前执行者而提前完成仍包含未交付集成目标的 task。
