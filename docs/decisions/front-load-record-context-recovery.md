## 目的

- 让 Decision Records 与 Investigation Report 在建立新记录或重新开展调查前，先以最小查询恢复可复用的已有认识，再决定是否需要新工作。
- 让普通“调查一下”请求在已有报告大致回答同一问题时，先获得形成时认识的概述，再由用户选择复用既有结论或按当前事实复查。
- 让 `list` 与 `search` 的命令级 help 成为自足的普通发现入口，调用者不离开运行时帮助也能理解结果边界和后续读取方式。

## 背景

- Decision Records 已要求触发后恢复相关 active 判断，但查询入口的选择、停止条件与准备新建前排除既有记录的要求未在两域对齐表达。
- Investigation Report 的“查找与阅读”位于主工作流之后，普通调查请求可能先创建候选或重新调查，之后才发现已有报告已经回答同一问题。
- 调查报告保存形成时认识，当前事实由代码、配置、规范和运行结果等 owner 承接；已有报告可能直接回答原问题，也可能需要按当前事实复查。
- 命令级 help 已列出主要参数，但筛选组合、匹配范围、candidate 边界、截断结果与后续读取方式仍主要散落在固定契约中；Help 与固定契约并列会造成语义漂移。

## 决策

- 采用: 两个 skill 按当前已知信息选择信息损失最小的查询入口，不固定 candidate-first 或正式记录优先；查询在足以区分继续候选、完善原记录、建立独立记录或无需记录时停止。
- 采用: 准备建立新记录前，同时排除相关 candidate 与已有正式记录，并据此选择继续候选、完善原记录、建立独立记录或停止维护。
- 采用: Investigation Report 在已有报告大致回答同一问题且用户未表达当前性意图时，先概述报告的身份、形成时间、原问题、关键结果、主要依据、适用范围、未覆盖内容与剩余未知，再询问复用既有结论还是按当前事实复查。
- 采用: 用户明确要求查找、总结或审阅已有材料时直接交付已有结果及其形成时边界；明确要求重新调查、最新结果或当前事实，或项目规则要求当次调查时，以旧报告为背景直接复查。
- 采用: `list` 与 `search` 的命令级 help 以紧凑 Semantics 与 Examples 投影普通发现所需的边界、筛选组合、关系参数依赖、结果上限、warning 与 `show` 后续入口；精确查询、降级与机器结构继续由固定契约承接。
- 不采用: 把复用/复查询问作为正确性门禁，硬编码默认选择，或让 help 复制固定契约的完整规则。
