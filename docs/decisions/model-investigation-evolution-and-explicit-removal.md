## 目的

- 保留报告关系只描述形成时认识演进、不描述当前有效性或生命周期的边界。
- 让明确不应继续保留的报告可以安全退出集合，而不是为了没有归档语义就只能永久保存。
- 让关系引用、拆分闭包、资源 owner、派生索引和 Git 记录在删除前得到同一机械事务保护。

## 背景

- 调查报告保存一轮形成时认识；被补充、复查、修正或推翻不意味着前序报告应当隐藏或归档。
- 报告仍可能因错误建立、敏感信息、重复内容或明确维护要求而需要删除。删除是破坏性维护，不是认识演进关系的结果。
- 每份报告可能拥有形成时资源，其他报告也可以复用这些资源；裸删 Markdown 会留下悬空关系、无 owner 资源或陈旧索引。
- 已进入 Git 历史的报告和资源具有更明确的记录删除边界，但 Git 不决定报告是否建立或是否有效。

## 决策

- 采用: 报告继续只用`补充`、`复查`、`修正`、`推翻`、`归并`和`拆分`指向真实直接前序；关系不归档、隐藏、自动替代或自动删除任何报告。
- 采用: 所有未被显式剔除的报告留在同一正式集合；删除只由 `discard <investigation-id>` 表达，不新增报告生命周期或归档目录。
- 采用: `discard` 在写入前预演移除目标后的完整关系图和索引；目标仍被关系引用、删除会破坏拆分闭包或索引不是当前投影时拒绝。
- 采用: 目标拥有资源时由调用方显式确认一起删除；资源仍被其他报告引用时拒绝，不自动转移 owner。Ignored、不安全、非普通或发生漂移的 owner 成员不进入递归删除。
- 采用: 目标报告或将删资源已进入 Git `HEAD` 时，首次调用零写入暂停并要求机械确认参数；非 Git 或 unborn `HEAD` 不增加该门禁，Git 检查异常则 fail closed。
- 采用: `discard`、关系维护与完整索引同步共用集合写锁，并以同文件系统 tombstone 和索引原子发布保护删除；索引发布是领域提交点，发布前失败恢复原状态，发布后的安全清理异常保留残留并报告已提交状态。它不写 Git pending；删除最后一份报告后保留可检查、可查询的空派生索引。
