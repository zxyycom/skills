## 目的

- 让测试执行结构与证据语义边界分别确定，并准确表达一个结论由多个测试共同证明或一个测试同时支持多个结论。
- 让账本从测试侧和 Case 侧查询同一组完整关系，不留下无法归属的测试实体或没有当前测试证据的 Case。

## 背景

- 本决策中的测试实体，是测试框架能够独立选择并单独报告的最小原生测试入口；测试文件、package script、聚合容器和测试内部环节不属于测试实体。
- 测试实体服务运行和报告，语义 Case 服务证据复核；两者并不天然一一对应。
- 一个语义契约可能需要多个测试实体共同证明，一个测试实体也可能同时覆盖多个可独立检索的语义结论。
- 单向或重复维护映射容易漂移，重命名、拆分、合并和删除后可能留下只在一侧存在的悬空内容。

## 决策

- 采用: 进入测试账本受控范围的测试实体与当前语义 Case 建立双向多对多关系；从任一侧都查询同一组权威关系，不分别维护可能漂移的两套映射。
- 采用: 一个 Case 可以关联一个或多个测试实体，一个测试实体也可以关联一个或多个 Case；Case 的边界由可独立说明和复核的语义契约决定，不再由测试节点数量机械决定。
- 采用: 关系必须闭合。每个受控测试实体至少关联一个当前 Case，每个当前 Case 至少关联一个真实存在的受控测试实体，每条关系的两个端点都必须存在于当前受控范围。
- 采用: 测试或 Case 的新增、重命名、拆分、合并和删除必须在同一次维护中恢复闭合关系；查询和检查应能从两侧发现未映射端点、未知端点和不一致关系。
- 采用: 不建立没有当前测试证据的未来 Case，也不借闭合要求推导“每条 owner 规则都必须新增测试”；闭合只约束进入当前测试账本受控范围的测试实体和 Case。
- 采用: 关系的物理存储位置、schema、CLI 和迁移方式由后续实施设计选择，但只能有一个关系事实 owner，并必须保持上述双向查询和无悬空不变量。
