## 目的
- 让 `skills/test-design/` 只建立和保留通过举证的关键、必要、低成本测试，保留成为审核结果而非存量默认状态。
- 将误删控制放在事实、职责和处置复核，避免因维持既有保护而保留未举证形态。

## 背景
- 前序方向已用于约束测试设计：先按行为收益与成本选择自动化目标，再设计或修复入选目标，并允许重要契约不自动化。
- 目标先入选的阶段划分仍容易把目标的重要性转成必须维持覆盖的承诺；具体测试形态未获举证时，继续寻找修复或替代，而不是允许它退出。有效性与目标价值也不足以证明全部场景、断言和执行开销必要。
- 新增设计需要形成候选，存量审查需要重新取得保留资格；两者应共用具体方案的准入门槛，而不是让存量继承目标或账本授予的义务。更严格的准入需要复核误删，但不以保护总量不减少作为约束。

## 决策
- 采用: 在 `skills/test-design/` 以候选准入修订目标先入选的两阶段流程。新增从行为、消费者与独立缺陷形成最小方案，存量全部作为待审候选；共同证明有效性、保护价值、当前形态与开销必要性，三项均成立才可建立或保留。
- 采用: 三项依据落实到实际输入、独立预期、观察、场景和边界。重要大类不能授予整组资格，有争议时细分到断言，判断相同可以成组说明；不设删除配额、逐条长证明或专用账本。设计方法允许在准入前按需参考，以比较真实可行性与成本。
- 采用: 区分准入、不准入和具体未决。已核对事实却没有依据者不准入，不自动修复或等待等价替代；修复、精简、降级和替代方案作为新候选重新举证。未完成读取不等于无必要，也不能算已证明应保留；方案通过不冒充实现已验证。
- 采用: 继续允许关键契约不自动化，在授权内说明失去的保护与风险，不自动追加人工检查或补测任务。硬性自动化要求由 owner 决定处置，不自行绕过，也不当作三项门槛已经通过的证据。测试只在自身职责内举证，不扩成全链路证明。
- 采用: 保持按需实现反馈，比较实现与测试的整体成本、行为与兼容性及新增风险；生产改动和契约变化服从相应授权，实际变化后仅对受影响候选重新准入。未落地方案不能计作保障，不将测试设计扩成全局架构审查。
- 采用: 结项以最终准入集合及各组依据、不准入处置和风险、具体未决及实际验证范围为主，不以缺陷清单或全绿代替。处置前复核真实产品缺陷、局部职责、不同责任及最终保留项，防止误删和循环承接；方法范式与易错校准仍按需引用，证据账本与 Gate 继续由各自 owner 承接。
