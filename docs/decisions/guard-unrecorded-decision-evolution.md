## 目的
- 在不改变 Markdown 生命周期事实源的前提下，防止同一未提交变更中的中间判断被无意保存为长期演进历史。
- 让简单折叠保持可恢复事务，同时把最终直接关系的语义选择留给调用者。

## 背景
- 首次激活立即建立并使决策生效，Git 提交、暂存和历史不参与成员身份或生命周期判断。
- 当新候选归档一个尚未进入当前 Git `HEAD` 的活动前序时，该前序可能只是本次变更内部的收敛过程；普通归档也可能留下没有长期回放价值的失活记录。
- 被折叠记录可能承接更早上游，关系类型不能通过链路机械合成；通用删除命令会把历史重写、断链和关系迁移混成一个不安全动作。

## 决策
- 采用: 当前 Git `HEAD` 只作为归档前的路径存在性证据；同一决策根相对路径存在即视为已经记录，文件内容、Git index 和工作区差异不参与判断。尚无提交时全部路径都视为未记录。
- 采用: 只有确认决策集合不在 Git 工作树内时跳过预检；仓库发现或基线读取失败时停止且不写入。
- 采用: `evolve`、带关系的 `activate` 和 `archive` 即将归档不在 `HEAD` 的已建立记录时，先暂停并警告且不写入；调用者必须显式重试并选择保留未提交历史，或在适用时折叠中间前序。
- 采用: `evolve` 可以显式折叠一个不在 `HEAD` 的活动已建立直接前序；调用者给出的零个或多个关系共同构成后继的完整最终关系集合，CLI 不自动继承、组合或改写关系类型。
- 采用: 最终关系中的活动目标按正常演进归档；已归档目标只允许来自被折叠记录原有的直接前序。折叠记录仍被其他记录引用、已经进入 `HEAD` 或关系边界不清楚时拒绝自动处理。
- 采用: 折叠删除、最终前序归档、后继建立和索引重建属于同一可恢复事务；可处理失败尽力恢复命令前的 Markdown 与索引组合。
- 采用: 非 Git 决策集合继续使用既有生命周期；`discard` 只删除未激活候选，不新增通用的已建立决策删除命令。复杂分叉、多层链路或无法确定最终关系时保留现场并由维护者判断。
