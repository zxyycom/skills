## 目的

- 让 Decision Records 与 Investigation Report 在建立新记录或重新开展调查前，先以最小查询恢复可复用的已有认识，再决定是否需要新工作。
- 让普通“调查一下”请求在已有报告大致回答同一问题时，先获得形成时认识的概述，再由用户选择复用既有结论或按当前事实复查。

## 背景

- Decision Records 已要求恢复相关 active 判断，但查询入口选择、停止条件与准备新建前排除既有记录的要求曾未在两域对齐表达。
- Investigation Report 的查找路径未前置时，普通请求可能先创建候选或重新调查，之后才发现已有报告已回答同一问题。
- 报告保存形成时认识，当前事实由代码、配置、规范和运行结果等来源承接；两者回答相同问题不表示旧认识已经证明当前事实。
- 查询的运行时帮助如何表达属于独立消费入口，不决定是否需要复用或重新调查。

## 决策

- 采用: 两域按当前已知信息选择信息损失最小的查询入口，候选与正式记录的读取次序由任务决定。查询在足以区分继续候选、完善原记录、建立独立记录或无需记录时停止；准备新建前核对相关 candidate 与正式记录是否已覆盖本次要保存的判断或认识，再决定是否需要新记录。
- Investigation Report 命中大致回答同一问题的已有报告，且用户未表达当前性意图时，先概述身份、形成时间、原问题、关键结果、主要依据、适用范围、未覆盖内容与剩余未知，再询问复用既有结论还是按当前事实复查。
- 用户只要求查找、总结或审阅已有材料时，直接交付已有结果及其形成时边界；明确要求重新调查、最新结果或当前事实，或项目规则要求当次调查时，以旧报告为背景直接复查。
- 复用/复查询问用于减少重复调查，不是正确性门禁，也不预设用户选择；记录写入与实施仍须各自授权。
