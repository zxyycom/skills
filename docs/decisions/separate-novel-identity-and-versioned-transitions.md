## 目的

- 适用于 `novel-cards` 与当前 `skills/novel-cards/`：章节按人类习惯定位，人物和设定沿明确关系恢复变化前后内容，改名、重排与归档保持对象身份。
- 递归规划与文学判断由作者和 agent 复核，确定性的定位、版本保存与跨卡关系维护由本地工具承担。

## 背景

- 章节标题可以重用，编号会随插章或重排调整；两者用于日常定位，不能承担永久身份。稳定引用也不应要求使用者记忆内部 ID。
- 普通历史摘要能压缩解释，却缺少对象前后版本端点，无法让多个受影响对象自动找到同一次变化。
- 演进和修订都需要保存旧内容、关联新内容并解释原因，可以共享结构；但真实过去阶段与作者否定的旧设定效力不同，混作经历会误用废弃事实。
- 来源、发生状态与版本分别表达作者采用、故事阶段和修订历史；正文只承担叙事，维护性对应由外部报告保存。

## 决策

- 采用：稳定 ID 与章节计数范围、编号、标题分别维护。标题或范围内章号查询返回实际候选，选择后使用稳定身份，歧义不猜测。
- 采用：完整旧卡快照与锁版本变迁连接一个或多个对象的前后状态。演进保留真实故事阶段，修订明确内容替代；两者复用维护流程，历史总结继续压缩解释。
- 明确关系是自动历史反查的依据。修改或撤回变迁保存旧记录，当前查询按有效版本和替代关系返回；预期保留计划身份，不替代已发生事实，不应用对象更新。整条演进被替代时，仍成立的多对象关系须由修订完整承接，工具不局部猜测。
- 批量变迁在显式授权下预检完整集合，统一维护快照、新卡、变迁与索引，并保留失败恢复边界。恢复失败保持可见，机械成功不证明文学因果或作者判断。
- 详情与总结保持自由递归，`children` 表示组成，`sources` 表示依据；远期规划与来源型总结按语义判断完整度。发生状态、故事位置、关系态度与人物所知分别表达。
- 本作卡与独立来源分开，未来预期写在卡内。正文反推先提取再对照、缺漏回查，对应记录在外部报告；修改卡片及传播由作者决定。
- Markdown 是事实源，索引提供定位和当前性核对，关系查询从显式记录派生，读取预算与未读边界可见。同一对象的完整快照使用版本限定身份，由该领域 owner 声明索引键并在读取时核对 ID 与版本；这一局部能力不自动扩展其他领域的身份模型。
- 锁版本才保证快照所引内容的历史版本；未锁引用仍指当前，工具不能伪造历史展开。维护以可信本地单写者为前提，不提供防篡改审计、通用事件溯源或自动文学评分；外部审稿仍须独立授权。
