## 目的

- 让 `skills/video-understanding/` 程序包可以独立复制、更新和恢复，而不覆盖使用者配置、媒体运行时或既有证据。
- 使同一独立 CLI 与宿主适配入口共享明确、可检验的位置选择规则，不隐式绑定某个工作目录或项目仓库。

## 背景

- 程序更新会覆盖正式同路径文件，使用者配置和证据却需要跨版本保留；将其作为分发内容会混淆产品、机器接入和数据的生命周期。
- 使用者需要跨项目缺省，同时某个项目可能只覆盖媒体根或数据根。按字段继承避免仅因项目未指定某一根就丢失用户缺省。
- 自动搜索项目配置或加载环境文件会让 cwd 改变调用结果，也可能隐藏实际来源。严格读取已选层可以在高优先级覆盖下继续暴露损坏配置。

## 决策

- 采用: 默认用户配置为 `os.homedir()/.config/video-understanding/config.json`，项目以 `--config` 显式选择绝对本地 JSON。CLI 只读这两类来源；固定来源使调用不受 cwd、项目搜索或环境文件影响，本次参数不写回配置。
- 采用: `appRoot`、`dataRoot` 按字段继承，省略与 `null` 保留低层值；优先级为显式参数、显式项目、用户、宿主适配缺省，独立 CLI 没有宿主层。路径取字面值，配置与两类根按物理位置位于包外，从而同时支持跨项目缺省、局部覆盖和程序更新保留。
- 采用: 每个已读配置层独立校验，较高层覆盖不隐藏低层损坏。用户文件可缺失，显式项目文件须存在；help 跳过配置读取，其他命令按操作需要核对媒体环境，使纯读取和复用保持独立。
- 采用: 程序更新、依赖准备、配置建立／合并及数据迁移分别授权和验收。换机显式核对路径，改根后旧证据仍用原 output 访问；恢复保留成套程序、原配置和必要依赖，验证等效读取后才退场精确旧文件。updater 保留额外文件，媒体、模型、缓存、素材与证据保持原位。

字段限制、失败阶段与复制／恢复步骤由[本地工具入口](../../skills/video-understanding/references/local-tools.md)承接。
