## 目的

- 让 `skills/video-understanding/` 程序包可以独立复制、更新和恢复，而不覆盖使用者配置、媒体运行时或既有证据。
- 使同一独立 CLI 与宿主适配入口共享明确、可检验的位置选择规则，不隐式绑定某个工作目录或项目仓库。

## 背景

- 程序更新会覆盖正式同路径文件，使用者配置和证据却需要跨版本保留；将其作为分发内容会混淆产品、机器接入和数据的生命周期。
- 使用者需要跨项目缺省，同时某个项目可能只覆盖媒体根或数据根。按字段继承避免仅因项目未指定某一根就丢失用户缺省。
- 自动搜索项目配置或加载环境文件会让 cwd 改变调用结果，也可能隐藏实际来源。严格读取已选层可以在高优先级覆盖下继续暴露损坏配置。

## 决策

- 采用: 用户配置位于 `os.homedir()/.config/video-understanding/config.json`；项目仅通过 `--config` 的绝对本地 JSON 路径选择。CLI 只读配置，不自动搜索项目根、加载环境文件或写回本次参数。
- 采用: JSON 仅允许可省略的 `appRoot`、`dataRoot`；省略和 `null` 均继承低优先级值。根按字段依次选择显式位置参数、项目配置、用户配置和宿主适配缺省；独立 CLI 没有宿主层。路径按字面值处理，不进行环境变量插值。
- 采用: 配置文件、媒体根和数据根在物理位置上均须位于安装包外。用户配置缺失表示未配置；显式项目文件缺失或任何已读层非法都在参数阶段失败，即使较高层提供覆盖。help 跳过配置读取，其他命令按需核对媒体环境，纯读取和复用不要求未使用的媒体依赖。
- 采用: 更新、重装和依赖准备各自结算。使用者自行授权建立或合并配置；复制到新机器后显式核对路径。改变根不迁移旧证据，旧证据仍按原 output 读取；媒体、模型、缓存、素材与证据保持原位。
- 采用: 恢复时保留成套程序、原配置与必要依赖，验证等效读取后才退场明确的旧文件；updater 保留其他本地文件的行为不承担旧源码或配置的自动清理责任。精确读取与恢复契约由[本地工具入口](../../skills/video-understanding/references/local-tools.md)拥有。
