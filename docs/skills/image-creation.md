# Image Creation

Image Creation 以提示词工程为核心，把用户意图变成可执行画面，并连接实际参考、可选结构引导、调用、回看和逐次记录，直到交付图像。用户只要提示词或诊断时，也能停在相应结果；用户要成图时，提示词和骨架都不是任务终点。

## 它解决什么

“主体出现了”不代表关系正确，“局部很好”不代表全图落实，“只改这里”也不意味着其他像素锁住。这个 skill 关注这些容易被漂亮画面掩盖的差异：

- 通过精简核心提示词指南，把用途、空间、材料、状态、身份、多图职责与编辑不变量编译为实际原词；按任务展开风格／产品设计、编辑实例、系列版面等专题，不要求全部通读。
- 给身份、姿态、材料和构图参考分工，并检查生成器实际收到的图。
- 必要时从三视图、简单3D体块／骨架统一大致连接、姿态和机位，再让生成端完成自然形态与材料。
- 区分输入错误、提示遗漏、路线限制、回填弱化和非目标区域回归。
- 每次调用保存目的、完整实际提示词、实际输入／输出及回看结果；文字记录优先，原图可引用，结构缩略图标清精度边界，不自动删除原件。
- 保持当前基准、候选用途与用户认可范围可恢复，不让最新图自动成为定稿。

## 与图像工具怎样配合

本体位于 [`skills/image-creation/`](../../skills/image-creation/)，主要是流程与产出型指令，不包含生成 API、模型权重或专用执行脚本。独立的[接口说明](../../skills/image-creation/references/image-interfaces.md)给出Codex原生、OpenAI API、Gemini与已有ComfyUI工作流的最小操作链，动态参数仍向当前契约和官方文档核对，不把旧版说明硬化为工具限制。它可与环境中的 `imagegen` 等执行能力协作；没有执行能力时可以交付提示与输入说明，但不宣称已完成成图。

单个 skill 独立获取、版本化与更新；不要求同时安装其他仓库 skill。指令使用不需要安装 updater 依赖，也不自动启用收费服务或改变用户全局安装。

## 按缺口读取

[主入口](../../skills/image-creation/SKILL.md)维护从意图到交图的顺序、完成义务和完整读取策略。提示构建从[提示词指南](../../skills/image-creation/references/prompting-guide.md)进入，实际调用按[生成记录](../../skills/image-creation/references/generation-records.md)留存；编辑、风格、系列与其他专题按主入口指引选读。专题示意可供改写，不代表已验证模型收益。简单请求不要求先填完整表单；一次预览可由对话承接记录，项目／多轮使用可恢复文件。

## 验证与发展边界

文档结构、链接、独立打包和 updater 检查证明可分发性；代表请求的阅读走查证明规则能否区分路径。这些不等于已经验证模型收益。后续实际评估应覆盖从零生成、身份／姿态分工、局部回填、非目标回归、系列和精确文字，并以获授权的输入—实际调用—输出对照检验，不预先承诺跨模型成功率。

当前不维护模型专属参数大全或实时生成服务。提示模板用于改写与执行，不预先承诺跨模型效果；三视图和简单3D只约束任务需要的大致框架。需要精确数据、原生矢量、精确三维重建或视频连续性时，交给能兑现其验收的对应能力；静态图像不替代这些证明。
