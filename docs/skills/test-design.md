# Test Design

`test-design` 选择经得起举证的关键、必要、低成本测试。保留是准入结果，不是存量测试的默认状态；已有测试、Case 或覆盖率不能直接取得保留资格。

新增与存量共同证明三项：测试确实有效、保护值得承担、当前形态与开销必要。重要行为不自动产生必须维持覆盖的义务，最便宜的可行自动化仍太贵时可以不自动化，契约本身仍有效。

## 使用方式

适用于功能与 Bug 回归测试设计、存量测试审查和精简，例如“审核这些测试是否值得保留”“评估这项 GUI 测试是否值得自动化”。只运行测试、维护账本或调整 Gate 调度交给相应入口。

两个入口共用准入门槛：

- **新增**：从行为与风险形成最小候选方案，比较方法可以先于准入，实施只投入已选方案。
- **存量**：从实际测试恢复输入、观察和有限职责，再举证进入保留集合；依据一致时成组说明，有争议时细分到场景或断言。

结果区分准入、不准入和具体未决。不准入可直接退出，无需等价替代；改进方案作为新候选重新举证。硬性自动化要求交 owner 决定处置，不视为已通过准入。

准备、职责或边界问题可触发[设计反馈](../../skills/test-design/SKILL.md#设计反馈与重新裁决)，比较实现与测试的整体得失。授权调整后，受影响测试和新风险重新举证；未实施建议只支持条件方案。

处置前复核真实缺陷、局部职责和误判重复，避免误删有效保护；不设删除配额，也不要求保护总量不减少。[易错判断集](../../skills/test-design/references/judgment-pitfalls.md)帮助校准这些边界。

## 与测试证据账本的分工

本 skill 负责候选准入与测试设计；[Test Evidence Review](test-evidence-review.md) 负责实际证据、Case 与引用。项目同时采用时，以最终入口、实际证明范围和保护变化交接。

## 验证边界

结构和链接检查不证明实际取舍有效。效果使用未收录材料验证：未举证者能否退出、有效保护是否误删、当前形态是否单独举证，以及设计变化后是否重新准入；静态判断与执行结果分别报告。
