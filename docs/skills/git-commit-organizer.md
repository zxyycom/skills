# Git Commit Organizer

`git-commit-organizer` 的核心是用一套稳定、有明确偏好的项目级风格组织 Git 提交，让提交历史更清楚、更统一、更容易管理。

实际使用从 [SKILL.md](../../skills/git-commit-organizer/SKILL.md) 开始，按其流程核对提交范围、暂存快照和验证证据。

## 风格定位

这套 skill 面向已经理解其作用、主动安装或显式调用的使用者。选择使用表示希望后续提交默认按它定义的提交粒度、类型、标题和正文格式收敛，而不是在每次执行时重新选择一套表达方式。

这里的“风格”表示一组主动选择的稳定默认，不宣称它是所有 Git 仓库都必须采用的通用规范。为了让 agent 的结果可预期，行为入口仍会用明确规则约束类型、中文全角冒号、中文标题和正文 bullet；用户或项目对当前任务给出更具体要求时，以该要求为准。

## 为什么需要它

提交历史长期服务于代码审查、问题追踪、回滚判断、发布说明和后来 agent 对项目演进的理解。好的提交应让读者恢复：这次改变了什么，以及为什么这些改动应该放在一起。

在多个会话、人员或自动化共享同一工作区时，“看到的 diff”也不等于“当前任务有权提交的 diff”。Git 状态不会记录每处工作区改动由哪个会话产生；如果把一句泛化的“提交 Git”理解成提交整个工作区，其他任务的 staged、unstaged 或 untracked 内容就可能被误带入历史。

## 风格内容

这套风格围绕三个结果组织提交：

1. **范围可靠**：依据当前任务的写入记录、用户授权和初始状态恢复归属，精确隔离提交快照；无法隔离时停止并请求选择。
2. **语义清楚**：按可独立审查和回滚的语义分组，用稳定类型、中文全角冒号、中文标题与正文 bullet 表达意图。
3. **证据真实**：复核实际 diff 与快照，正文只描述真实改动和实际验证；未运行验证、无关残留与范围风险留在交付说明中。

精确的类型、暂存方式、消息格式和检查流程由 [SKILL.md](../../skills/git-commit-organizer/SKILL.md) 承接。

## 发展方向

后续发展优先提高变更归类、提交边界和结果复核的稳定性。只有真实、重复出现的问题才进入主流程，避免低频 Git 场景稀释日常提交整理。
