# Investigation Report

`investigation-report` 将每轮可独立汇报的调查认识保存为一个根目录直属的报告 Markdown。每份报告以稳定 Investigation ID 定位，通过 tags 分类，通过直接前序关系表达补充、复查、修正、推翻、归并或拆分；所有报告都留在同一正常集合。

本页面向人说明用途，不是执行入口或格式规范。实际使用、审阅与维护从 [`skills/investigation-report/SKILL.md`](../../skills/investigation-report/SKILL.md) 开始；[`investigation-report-contract.md`](../../skills/investigation-report/references/investigation-report-contract.md) 是身份、目录、字段、资源引用、关系事务、检查严重性、索引和 CLI 的唯一精确 owner。

## 什么时候使用

仅在用户明确要求记录、沉淀、创建、更新或审阅调查报告时使用。普通调查、排障和问答不会主动建议建报告。

## 一份报告保存什么

每份报告固定保存：

1. `形成时背景`：当时发生了什么，基于哪些事实、假设、未知和约束意识到需要调查。
2. `调查目的`：本轮具体要回答什么问题、支持什么判断以及预定边界是什么。
3. `调查范围与依据`：实际检查了什么、证据来自哪里、采用什么方法、实际覆盖到哪里，以及没有检查什么。
4. `调查结果与边界`：确认、推断、建议、实际动作和未知分别是什么，结果适用于什么条件，何时需要重新调查。

这四项是调查记录的最小公约数，且均为固定非空 H2。计量、因果、方案、授权、恢复和验证等场景信息写入对应核心。其他可选语义 H2 只能位于四项固定核心之后；报告声明资源时，`随附资源` 必须是第五节，其他可选语义 H2 只能位于其后。

报告的 frontmatter 还保存标题、形成时间、本轮问题、非空 tags 和完整直接前序关系。tags 只表达分类；关系只表达认识演进，不能推断当前结论、优先级、任务或实施授权。

## 怎样保存演进

新证据或实质认识变化创建一份新报告，而不是修改前序或依赖相邻顺序。新报告可声明：`补充`、`复查`、`修正`、`推翻`、`归并` 或 `拆分`。关系从后继指向真实直接前序；相同 tags、时间相邻、共享资源和普通链接都不自动形成关系。

被修正或推翻的报告仍正常发现，最新时间或叶节点都不自动代表累积当前口径。需要当前口径时，应显式综合相关报告和当前事实 owner。

创建时可直接声明合法关系。调整既有报告关系时使用 `set-relations`，以每个 source 的完整集合或显式清空组成一次原子图预演与写入；它不修改报告的其他字段、正文、资源或 Git pending。

## 怎样按需引用资源

资源引用是可选能力。正文和稳定事实 owner 已足以复核结论时，不需要资源。只有接口参数、原始响应、日志、截图、规范摘录或二进制样本不适合完整放进正文，且未来复核需要保留形成时内容时，才保存最小必要的非敏感材料并由报告声明引用。

资源用于支撑报告，不能替代正文：报告仍需说明材料来源、观测或处理条件，以及它怎样支撑结论，并概括影响结论的关键事实。资源 owner 由 Investigation ID stem 的路径前缀确定，其他报告可以复用同一资源而不改变 owner。

资源的精确路径、链接写法、可见性和 warnings/errors 分类都由[固定契约](../../skills/investigation-report/references/investigation-report-contract.md)承接。不要从本页推断这些精确规则。

## 高层维护路径

1. 先按 skill 流程写入或审阅单报告 Markdown，并在需要时处理报告声明的资源。
2. 创建、删除、改名报告或改变资源引用后，重建派生索引并完成全量检查；只改资源文件时按固定契约运行全量检查。
3. 多份报告共享索引但只交付其中一部分时，先完成上述维护，再由 `stage-index` 选择对应 Investigation ID 的索引变化；报告 Markdown 与资源仍按实际提交范围单独处理。
4. 对固定字段、全量与 scoped 的证明范围、命令前置条件、索引新鲜度、warnings/errors 和版本升级，一律以[固定契约](../../skills/investigation-report/references/investigation-report-contract.md)为准。

## 审阅重点

任取一份报告，读者都应能恢复形成时背景、目的、调查依据和结果边界，不需要补入默认前提。关键主张应有可定位证据，结论强度不能超过证据，推荐、执行和验证状态不能混淆。tags 应有内容依据，关系应确属直接前序；报告不替代决定、实施计划或当前事实 owner。
