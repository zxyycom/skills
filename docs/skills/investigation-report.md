# Investigation Report

`investigation-report` 用一个稳定主题文件持续追踪同一核心问题。每次形成新认识时追加一份完整报告，让不同时间、背景和证据条件下的结果可以独立阅读、汇报和比较；报告可以按需引用形成时资源。

本页是面向人的用途说明，不是执行入口或格式规范。实际使用、审阅与维护从 [`skills/investigation-report/SKILL.md`](../../skills/investigation-report/SKILL.md) 开始；[`investigation-report-contract.md`](../../skills/investigation-report/references/investigation-report-contract.md) 是目录、字段、资源引用、检查严重性、索引和 CLI 的唯一精确 owner。

## 什么时候使用

仅在用户明确要求记录、沉淀、创建、更新或审阅调查报告时使用。普通调查、排障和问答不会主动建议建报告。

## 每份报告固定保存什么

每份报告使用同一个固定核心：

1. `形成时背景`：当时发生了什么，基于哪些事实、假设、未知和约束意识到需要调查。
2. `调查目的`：本轮具体要回答什么问题、支持什么判断以及预定边界是什么。
3. `调查范围与依据`：实际检查了什么、证据来自哪里、采用什么方法、实际覆盖到哪里，以及没有检查什么。
4. `调查结果与边界`：确认、推断、建议、实际动作和未知分别是什么，结果适用于什么条件，何时需要重新调查。

这四项是调查记录的最小公约数。每项篇幅由本轮实际信息决定；支撑材料需要独立组织才能复核结论时，再增加时间线、证据、对照、状态模型、恢复或验收等有语义名称的章节。

计量或比较需要补足口径、样本和误差，因果或机制判断需要补足证据链和未闭合环节，候选方案需要区分推荐、采用和验证，实际变更还要记录授权、影响、恢复与验证。这些义务由当前结论所依赖的场景触发。

## 怎样按需引用资源

资源引用是可选能力。正文和稳定事实 owner 已经足以复核结论时，不需要资源。只有接口参数、原始响应、日志、截图、规范摘录或二进制样本不适合完整放进正文，且未来复核需要保留形成时内容时，才保存最小必要的非敏感材料并由报告声明引用。

资源用于支撑报告，不能替代正文：报告仍需说明材料来源、观测或处理条件，以及它怎样支撑结论，并概括影响结论的关键事实。同一资源可以在合乎归属约束的前提下被多份报告或主题复用；形成时材料有实质更新时，通过新资源和追加报告表达新认识。

资源的精确路径、链接写法、owner 约束、可见性和 warnings/errors 分类都由[固定契约](../../skills/investigation-report/references/investigation-report-contract.md)承接。不要从本页推断这些精确规则。

## 怎样保存演进

同一核心问题的新认识追加为完整报告，并重新写清本轮四项核心，不能写“同上”。背景或目的不同但结果相同，仍分别保留，供以后比较适用条件。

最后一份报告只表示最近形成的认识，不自动汇总旧报告或成为累积当前口径；需要当前口径时应显式综合相关报告与当前事实 owner。后来取得的新认识通过追加表达；旧报告没有准确记录当时认识的误写、漏写或格式问题可以原地修正。能够独立调查和结束的新问题另建主题文件。

## 高层维护路径

1. 先按 skill 流程写入或审阅主题 Markdown，并在需要时处理报告声明的资源。
2. 主题或资源引用关系变化后，重建派生索引并完成全量检查；只有资源文件变化时，按固定契约运行相应的全量检查即可。
3. 多个主题共享索引但只交付其中一部分时，先完成上述维护，再由 `stage-index` 选择对应主题的索引变化；主题 Markdown 与资源仍按实际提交范围单独处理。
4. 对固定字段、全量与 scoped 的证明范围、命令前置条件、索引新鲜度、warnings/errors 和版本升级，一律以[固定契约](../../skills/investigation-report/references/investigation-report-contract.md)为准。

## 审阅重点

任取一份报告，读者都应能恢复形成时背景、目的、调查依据和结果边界，不需要补入默认前提。关键主张应有可定位证据，结论强度不能超过证据，推荐、执行和验证状态不能混淆；报告不替代决定、实施计划或当前事实 owner。
