# JEV 局部判断

本页定义记录维护中的 JEV 委托、输入和采用条件。完整审查见[维护入口](../record-maintenance-workflow.md)；模型原语与协议由 [Lightweight Judgment](../../skills/lightweight-judgment/SKILL.md)及其[使用边界](../../skills/lightweight-judgment/references/jev-characteristics.md)承接。

## 委托条件

材料读取与综合判断由主代理负责。JEV 的每道题独立依据本次输入回答，适合同时满足以下条件的局部任务：

1. 一个明确命题，有确定的答案用途和原文复核路径。
2. 一个片段或一组紧邻原文已保留主体、时点、否定、条件和指代。
3. 准备后仍有待判断内容，重复量和预期收益足以抵偿调用、复核与回退。
4. 模板已启用，材料外发、接收方、规模与费用在授权内，输入符合实际服务限制。

记录门槛、跨记录冲突、独立演进、真实关系、因果成立、完整事件和对齐由主代理直接判断。复杂任务拆成多次调用后也须逐项满足委托条件；局部材料不足以保真时直接审查完整材料。

## 局部题库

[jev-probes.json](jev-probes.json)提供两种候选模板，每次请求一个对象、一题。两类记录共享局部文本判断，领域结论各自维护。

| 模板 | 输入 | 局部输出 |
| --- | --- | --- |
| `topic_match` | 一个已定义主题与原文片段 | 主题在片段中是否有实质依据：`supported` / `not_shown` / `uncertain` |
| `statement_support` | 一条陈述与局部来源原文 | 表述是否得到直接支持：`supported` / `contradicted` / `not_shown` / `uncertain` |

主代理另行判断整篇主题、检索收益、来源可靠性及论证充分性。`not_shown` 表示片段未直接支持，`contradicted` 表示片段有明确相反表述；采用前核对选段和未覆盖材料，不能据此直接判整篇错误或删除内容。`uncertain` 进入补证、补判或明确放弃辅助的处理路径。

## 准备最小充分输入

1. 读取完整审查所需材料，在 `run.probes` 保存关联 `checkKeys`、来源 hash、原文定位和选取理由。
2. 选取原文。主题定义使用实际含义；`context` 只补背景和指代，不含预期类别或主代理结论。
3. 每个 `statement` 只含一个可比较断言；算术、计数、日期与精确匹配交给代码。
4. 按自然语义单元保留否定、例外、时点与对比对象。必要上下文超出可可靠处理的范围时重新选段或直接审查，不以固定字数截断。
5. 替换全部占位值，按[执行参考](execution-reference.md#准备与调用局部请求)预览并调用。保持题意和选项原样，不同 `state` 分开请求。

## 验证与采用

题库标记为 `unvalidated`，默认关闭。`run.jev` 按本轮证据选择模式：

| 模式 | 行为 |
| --- | --- |
| `off` | 主代理完成检查，无 JEV 调用 |
| `trial` | 获准小样本先形成参考判断，再逐项对照模型原答；领域结论由主代理独立形成 |
| `assist` | 在 `validationEvidence` 覆盖的模板、实际模型、语言、输入范围和答案用途内辅助；其余退回 `trial` 或直接审查 |

每个模板分别验证支持、不支持、明确相反（适用时）、缺上下文和易混淆样本；参考意见有分歧时保留未知。调题后使用未参与调整的新样本，记录接受范围与误判风险；候选发现覆盖和来源真实性另行验收。格式、`confidence` 与重复同答不能替代任务验证。收益比较计入准备、调用、复核和回退，无收益或不稳定的任务交回主代理。

## 复核与回退

- `trial` 逐项复核。`assist` 中拟用于变更的答案与 `uncertain` 回原文核对；局部未见支持仍须完成对应领域检查。
- 借助 JEV 得到 `clear` 且未计划变更的 selected 记录进入抽样池。按领域分层各取默认 5 份、不足全取；以 `SHA256(seed + "\n" + recordKey)` 升序、同 hash 按 `recordKey` 排序。保存完整池和入选 ID，检查局部答案、选段充分性和领域采用；该数量是初始工作量，不是错误率保证。
- 误报或漏检按候选遗漏、选段、题意、模型或采用错误归因，扩查同条件下两类结果；无法维持采用范围时停用模板。模型、题意、材料范围或依赖事实变化后重新验证采用资格。
- 失败后主代理继续无依赖审查；补判完成可将 probe 记为 `bypassed`，保留失败调用和回退理由；仍待处理的项保持 `pending`。
